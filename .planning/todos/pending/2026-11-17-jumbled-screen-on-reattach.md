## Problem

User report (2026-11-17, screenshot): after the office Mac's shared session (Claude Code running) had produced lots of output, reattaching from the home Mac showed text with each line starting where the previous one ended, alternating left/right — and the tab did not respond.

Likely cause: once the 256 KiB raw ring wraps, the old `RenderSnapshot` replay joined rows with a bare `\n` (no `\r`) and did not restore the cursor (found in 05-RESEARCH). Phase 5 plan 05-03 (commits 9cf509e3, c92cc05e) rewrote the wrapped replay: CRLF rows, full-height screen, cursor position, DEC mode restores. The replay is generated by the HOST daemon, so the office Mac needs the new build too.

## Solution / verification (must not be skipped)

1. Confirm 05-03's fix covers this case: a test that wraps the ring with Claude-Code-like output (wide lines, colors, cursor moves, alt-screen off) and checks the replay renders identically in a headless xterm/vt grid vs the host grid.
2. Check for a second cause: guest grid cols vs host cols mismatch on attach (the guest must render at host cols before the replay is written).
3. Check the "wouldn't respond" part: input after a wrapped replay reaches the PTY.
4. Manual: two-Mac reattach after a long Claude Code session with both Macs on the new build (add to Phase 5 UAT / M-84).
