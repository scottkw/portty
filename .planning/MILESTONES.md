# Milestones

## v1.0 Portty v1.0 (Shipped: 2026-11-18)

**Phases completed:** 6 phases, 61 plans, 50 tasks

**Delivered:** AgentHub stripped to a plain macOS terminal, rebranded Portty, with tabs + sidebar, one-click tailnet sharing (peers + browser link), sessions that survive sleep, network changes and daemon death, and a verified GitHub-release update flow.

**Closeout:** override_closeout. Known verification overrides: 34 newly acknowledged, 0 carried forward from a prior close (see STATE.md Deferred Items).

### Known Gaps
- VERF-01: overnight two-Mac end-to-end test (M-84; M-85 lid sleep / AP switch). Code and two-VM evidence complete; physical run deferred by the user on 2026-11-18.
- Phases 2-6 verification human_needed: two-Mac UI checks (Phases 2-4) and first-real-release checks M-93 (Phase 6). Audit: milestones/v1.0-MILESTONE-AUDIT.md.

**Key accomplishments:**
- Every new session, from the New Session modal or `agenthub new [dir]`, now runs `GetShellPath()` with exactly `-l`. A real-zsh test proves it is a login shell. The modal is now a directory picker plus a read-only shell line, and the OpenCode theme/config code is gone.
- The shell shown in the New Session modal and Settings is now the exact binary the daemon spawns, resolved by one checked function: settings shellPath, else `$SHELL` if it is an absolute path to an existing executable file, else `/bin/zsh`. Agent-CLI detection and shell discovery are gone from the daemon, the Wails bindings and the UI. Settings → Paths now has exactly two rows: shell and tailscale.
- The daemon, webserver, tailnet peer metadata, CLI list and attach bar no longer carry cli/cli_type, and the webserver resolver now returns an explicit `ok` flag, so unknown sessions still 404 on `/api/sessions/{id}/info`.
- One app-wide 500 ms exit watcher (no deadline) closes the tab and removes the session on every shell exit; the exit toast, countdown, Keep Open, auto-close setting, tab dots, quit-dialog status, Hub status/attention UI and the briefing modal are deleted.
- Hidden-inset translucent window (HiddenInset ships, click-tested on macOS 27.2), 52px drag strips with no-drag controls, and a rebuilt native menu bar where Cmd+T opens New Session, Cmd+, opens Settings and Help > Portty Help opens https://portty.app.
- Chat, presence, typing, alias and self frames (0x30-0x37) are retired on both WebSocket read pumps, and the daemon chat/alias stores, the webserver chat routes and WhoIs identity, the relay presence hub, the sanitizer and the chat-only CORS helpers are deleted. Old clients' frames are dropped and their sockets keep working.
- The sidebar is now a macOS source list: a "This Mac" group fed by an always-on 3 s ListSessions poll, one group per tailnet peer that attaches through the unchanged capability handshake in a `<host> › <session>` tab, and a Tailscale footer. App launches straight into sidebar plus tabs with no Hub, Welcome or Help tab, and the sidebar hides and shows from its button, the tab bar and ⌃⌘S.
- Closing a tab now only detaches (the shell stays in the sidebar), a confirmed End Session... kills it, rename works in place on the tab and the sidebar row from one session list, and Share moved from the deleted status bar into a 52px pill-tab toolbar. While Tailscale is off, Share uses aria-disabled with aria-describedby pointing at the banner sentence, so the reason is visible on screen.
- Every dialog is now a light/dark macOS-style sheet under the toolbar, with no header ×, the buttons bottom-right and the primary on the accent. Focus is trapped by one `useDialogFocus` hook (Esc cancels, a scrim click does nothing, focus returns to the invoker). The Share dialog closes with a footer Done, and its Funnel consent gate is untouched.
- Homebrew distribution removed, the release pipeline builds and codesigns a `portty-<tag>-darwin-universal.dmg` with hdiutil, a brand gate (tests/check-brand.sh) runs in CI, README/CHANGELOG are rewritten for Portty, and the old product name now has zero hits in tracked files outside .planning/.
- Funnel, the public-write gate, join codes, QR codes, read-only links and the one-time shell share warning are deleted from every Go layer, the web pages and the Playwright fixture; each share now mints one read,write capability, and go-qrcode is gone from the module.
- The daemon now owns one in-memory share record per session behind `PUT /sessions/{id}/share`: share-on starts the tailnet share server once and returns a full-control link, share-off revokes, disconnects and stops the server when nothing is shared, and `portty share` / `portty unshare` and two new App bindings flip that same state. No server starts at boot and the password-gated LAN fallback is gone.
- Peers signed in to the same Tailscale account now get the host's shared sessions and the share's own capability through a WhoIs check that fails closed. Turning Share off disconnects every viewer with close code 1000 and the fixed reason `share stopped`. A dead link now opens a static "Link No Longer Works" page.
- `portty attach <host>:<session>` now works from any terminal: the local daemon finds the Mac in Tailscale's own peer list, gets the shared session and its capability through the same-account routes from 04-03, and the CLI attaches through the daemon's relay proxy. When the host turns Share off, the CLI prints `Portty: <host> stopped sharing <session>.` and exits 0. The GUI gets the same path as `ConnectPeerSession`.
- In-process harness of the real CLI attach path, one variant per hypothesis, and a fix for the one that went red: the catch-up replay no longer carries terminal queries, whose answers a joining terminal used to type into the shared shell. UAT gap 1's root cause is still not pinned.
- The detached daemon now writes to a 0600 daemon.log in its config dir instead of /dev/null. The host hub, the share server's read pump and the viewing daemon's proxy write `viewer-diag:` lines at each point where H-grid or H-net would show. The lines carry counts and sizes only, never tokens, links or typed bytes. TESTING.md M-83 says which lines to collect from both Macs.
- The share server now names the host by its MagicDNS short name (one `magicDNSLabel` rule shared with `peerShortName`), and with Tailscale off a shared session's Shared button opens the popover so its switch can stop sharing.
- The viewing daemon's proxy upstream conn and the CLI attach conn now read host frames up to `relay.ViewerReadLimit` (1 MiB, 4x the 256 KiB ring), so a GUI tab or `portty attach` joining a shared session with more than 32 KiB of history gets the whole replay instead of being dropped after the grid frame (UAT gap 4).
- Real xterm.js renders the Go wrapped replay exactly like the host. Guest resets and host grid changes now go through xterm's write queue (RIS, empty-write callback), so they apply in stream order. The scaled guest terminal is stretched so its scrollbar sits at the pane edge. Two VMs showed identical rows (29/29) after 390 KB of Claude-like output.
- The 05-10 wake/network detector now runs inside the GUI app and reaches every guest view as a Wails `system:wake` event, which App.tsx re-dispatches as a window `portty:wake` event. RelayClient handles it: if a backoff wait is pending, it redials at once and restarts the schedule; if the socket is open, it sends a probe. Browser views get the same handling when a watchdog tick arrives more than 5 s late. A WebSocket constructor that throws no longer kills the loop. Folded in: the sidebar's peer list now refreshes every 5 s while the window is visible and at once on focus or wake, instead of every 30 s.
- Matrix rows R1 to R8, plus the orchestrator's extra row R9, were run on the real tailnet (DERP-relayed) between two Tart VMs on build `39b0153e`. In each row the home VM watched the office session through both the GUI tab and `portty attach`. 8 rows pass and 1 fails. R6 FAIL: nothing restarts the viewing Mac's daemon, so after it dies both home viewers retry forever. The ECONNREFUSED question is answered with PASS: no transient condition made the host refuse a connection, so no viewer was falsely told sharing had stopped.
- When the viewing Mac's daemon dies, the GUI's 5 s poller or `portty attach` now starts it again in-process. GUI tabs, the CLI and new local tabs recover on their own in 1.4 to 5 s. R6 passes on the two Tart VMs.
