## Flagged decisions and assumptions

- **O-2 (CONTEXT [Socket hardening]).** `os.Chmod(path, 0o600)` right after a successful `net.Listen("unix", ...)` in `listenDaemonSocket` (only caller: `API.Start` in internal/daemon/api.go). Chosen over a umask change because umask is process-global and races other goroutines creating files (RESEARCH Alternatives). The short window between listen and chmod is harmless: the parent directory is 0700. A chmod failure closes the listener and returns the error (CLAUDE.md "let it crash"; never serve wider silently).
- **Post-COMMIT tighten (CONTEXT post-research [Socket hardening]; RESEARCH Open Question 3 RESOLVED).** A takeover receives the old daemon's listener fd, so a socket created by a pre-fix daemon keeps 0755 through the upgrade. `takeover.commit` calls `tightenSocketMode(t.socketPath)` right before it returns `takeoverCommitted` (covers both commit paths: with COMMITTED and the old-daemon-died path). It logs a failure and never fails the takeover: the sessions have already moved, and failing now would cost them.
- **Real-process check (plan check 2026-11-22, verification_derivation).** The tests here are in-process. The tighten across real processes (a pre-phase daemon upgraded twice) is TESTING.md M-155, which 15-09 records and /gsd-verify-work runs in the Tart VM `portty-test` before ship. TestHandoffIT and real daemons from two builds never run on the host (its own skip message and M-114).
- **Split (plan check 2026-11-22, scope_sanity).** This plan was the first third of the original socket-hardening plan; O-6 and O-1 moved to 15-08 unchanged. Threat IDs T-15-06 and T-15-09 stay here; T-15-07 and T-15-08 moved with their items.
