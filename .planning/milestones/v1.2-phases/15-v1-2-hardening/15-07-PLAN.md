## Flagged decisions and assumptions

- **Sidebar (CONTEXT post-research [Sidebar]; UI-SPEC Interaction row 2 and UI Considerations error row; RESEARCH Open Question 4 RESOLVED).** No time-based grace. Research found the cause: `unshareLocked` (internal/daemon/share.go) stops the host's share server when its last share ends, and the viewer's peer discovery cache lives 30 s, so the live meta fetch is refused. A refused connection (TCP reset: the host answered, nothing listens on the share port) now means reachable with 0 shared sessions; only a timeout, no route or other failure stays "Can't reach this Mac". Once the cache expires (up to 30 s), the host is no longer probed as Portty and its group disappears, as today.
- **Refused is reliably distinguishable at the fetch site.** The GUI's meta fetch uses Go's net/http over the OS network stack, which surfaces a reset as `syscall.ECONNREFUSED` through `url.Error`/`net.OpError` (`errors.Is` sees it). Precedent: internal/daemon/peer_connect.go already maps `errors.Is(ferr, syscall.ECONNREFUSED)` to "not sharing" (Phase 4 RESEARCH Pitfall 5), and Phase 5 matrix row R9 found that only a real host-daemon stop or reboot made the host refuse. A test against a closed local port pins the classification; the live tailnet confirmation is TESTING.md M-154 (recorded by 15-09), run in the Tart VMs, never against the host's tailnet. If the executor finds the refusal cannot be told apart reliably, the CONTEXT fallback applies: stop, write a new pending todo for the sidebar flash, and add no grace (15-09 then names that todo in the ended-peer-tab todo's Resolution).
- **The SUMMARY names the branch taken (plan check 2026-11-22, requirement_coverage).** 15-07-SUMMARY.md carries exactly one line, either `Sidebar branch: fixed` (Tasks 1-2 landed, MetaRefused) or `Sidebar branch: split (<path of the new pending todo>)` (the CONTEXT fallback ran). 15-09 reads this line: ROADMAP SC2 counts as COVERED only for `fixed`; for `split` it is reported partially met (the ended tab is delivered by 15-05, the sidebar flash stays open in the new todo).
- **Accepted consequence:** a Mac whose Portty daemon is down but which is awake also refuses, so it shows "Nothing shared" (accurate: nothing is shared) until the cache drops it, instead of "Can't reach this Mac".
- **IP fallback.** `FetchPeerSessionsMeta` keeps falling back to the Tailscale IP only for `MetaUnreachable`; a refusal by the DNS name is the host's own answer, so it is not retried by IP. Say so in a comment.
- **peer_connect.go unchanged (Chesterton).** `doFetchSessionsMeta` still returns the transport error together with `MetaRefused`, so the daemon's existing `errors.Is(ferr, syscall.ECONNREFUSED)` branch keeps working. The refused row of `TestMetaStatus_TriState` asserts both the status and the kept error.
- **Not in scope:** `sidebarPeers.peerView` synthesizing an unreachable row for a host whose tab is reconnecting (it is the amber reconnecting state, not this flash; an ended tab no longer reconnects after 15-05).
