## Flagged decisions and assumptions

- **Root cause (Research A1, from reading, unconfirmed).** The spy backend's session has no PTY (`spyBackend.Create` in engine_test.go returns a `pty.Session` with no master), so the hub's first Read errors, Run calls Shutdown, and the exit watcher CreateSession starts sets `StateStopped` within microseconds. The test's first `ListSessions()` ("running, ExitCode nil") therefore races the watcher, and its manual `SetState` races it too. Task 1 confirms or refutes this with the full-package repro; if the captured message points elsewhere, fix that cause instead and record why (do not loosen an assertion to make it pass).
- **Hermetic shape (Research "INPT-05 hermetic shape").** Split the one racy test into two:
  - `TestExitEvent_ListSessions_RunningHasNoExitCode`: `newCatEngine()` with its real backend (a real `/bin/cat` on a real PTY stays running); create a session, `t.Cleanup` kills it; ListSessions has the id with `ExitCode == nil` and `Duration == nil`.
  - `TestExitEvent_ListSessions_ExitCodePopulatedForStopped` (same name, so SC5's literal name still exists): spy backend; create; `testutil.WaitFor(t, 3*time.Second, ...)` until the registry's session reports `pty.StateStopped` (set by the exit watcher, no manual SetState); then ListSessions has `ExitCode != nil`, `*ExitCode == 0`, and `Duration != nil`.
  - Keep the other two tests in the file unchanged unless the repro implicates them.
- **Test runs (each test binary fires a firewall alert for the user).** Task 1: the whole-package `-count=20` repro CONTEXT requires (before the change) and the targeted `-run 'TestExitEvent'` stress loop. Task 2: exactly one `go test -race -short ./...` over the whole repo as the plan's gate. No full-package `-count=20` proof here: 10-07 runs SC5's literal command once at the final tree.
- **The repro uses SC5's literal command, without `-short`.** `go test -race -count=20 -timeout 60m ./internal/daemon/` (the default 10 m binary timeout is too short for 20 passes). Only `TestRemoteSessionWS_LongLived` is gated by `-short` in this package, and it runs there; `TestHandoffIT` skips by its env gate (that skip is expected).
