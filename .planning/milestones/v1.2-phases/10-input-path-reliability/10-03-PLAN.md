## Flagged decisions and assumptions

- **Input FIFO (Research Pattern 1; use its skeleton as the starting point).**
  - `internal/relay/input.go`: `InputMaxFrames = 1024`, `InputMaxBytes = 32 << 20` (per connection), `ErrInputClosed`, `type InputConn`, `func (h *Hub) OpenInput(sub *Subscriber) *InputConn` (the sub only tags diag lines with its conn id), `func (c *InputConn) Write(b []byte) error`, `func (c *InputConn) Close()`, `func (h *Hub) WaitInputIdle(timeout time.Duration) (idle bool, queued int)`.
  - Hub fields (hub.go, near the other locks, with a comment): `inMu sync.Mutex`, `inCond *sync.Cond` (made in NewHub, which NewHubFromState also uses), the queue, `inDead`, `inWriting`, `inStarted`. Pop in O(1) (a head index with periodic compaction, or a ring); never `inq = inq[1:]` on a long-lived slice.
  - One writer goroutine per hub, started on the first Write; it also starts a watcher that marks the input dead when `h.done` closes. It calls `h.writer.Write` with no lock held. On a write error or `done`: mark dead, drop the queue, Broadcast (blocked pumps get ErrInputClosed), and log once `viewer-diag: input writer stopped session=%s queued=%d err=%v` (counts only).
  - `Write` blocks only while this connection is at quota, and never takes the handler context (Research Pitfall 4: a frame already read must not be dropped because its socket died). It returns only when queued or when the input is dead. Comment: the caller must not reuse `b` (Pitfall 5; `InputAbsorber.Filter` allocates per call).
  - `Close` (pump exit) marks the connection closed; its queued frames are still delivered. If frames remain, log `viewer-diag: input backlog session=%s conn=%d frames=%d bytes=%d`; when a closed connection's last frame is written, log `viewer-diag: input backlog drained session=%s conn=%d`. These lines are 10-07's evidence for "dropped while the backlog drains". Never log payloads.
  - `shortcut:` comment (CONTEXT "Accepted limits"): past 32 MiB queued for one connection its pump blocks again, so a paste over the quota into a slow reader can still drop that viewer; the DEBT-05 notice then shows.
  - `Hub.WriteInput` stays as the direct writer (engine_test.go:346, TestHubWriteInput use it); no production caller remains.
  - Consequence to document in input.go's header: input is in arrival order across viewers, so a Ctrl-C typed after a large backlog waits behind it (Research Pitfall 3), as it did behind the paste in the TCP stream before.
- **Pong (Research Pattern 2) and the shared write pump (planner's choice).**
  - `internal/relay/pong.go`: `type PongOwed struct` with an `atomic.Int32` count and a one-slot kick channel; `NewPongOwed`, `Owe`, `Kick`, `Take`. A counter, not a flag: relayClient matches pongs by count (`pongsReceived >= paste.ackPing`), so two pings must get two pongs.
  - `func WritePump(ctx context.Context, conn *websocket.Conn, hub *Hub, sub *Subscriber, pongs *PongOwed, readDone <-chan struct{})`: the two servers' write loops are the same code today, so moving them here removes a duplicate (CLAUDE.md premature-abstraction rule: this is two identical copies, not a speculative abstraction). Each iteration first checks `pongs.Kick()` without blocking and writes `Take()` pongs, then selects on `sub.Msgs`, the kick, `ctx.Done()`, `hub.Done()` (close 1000 with `CloseReasonSessionEnded`, as both do today) and `readDone`. Keep the BUG-02 comment.
  - Both read pumps: `case MsgPing: pongs.Owe()`; the old non-blocking pong send into the subscriber's queue goes.
  - The webserver keeps its heartbeat goroutine, its viewer-diag counters (`inFrames`, `inBytes`, `resizes`), the `first input` line and the input total line unchanged.
- **Both pumps' MsgInput case** becomes: filter as today; if anything is left, `in.Write(filtered)`; on `ErrInputClosed` return (the session is ending). `in := hub.OpenInput(sub)` is made before the read goroutine starts and `in.Close()` runs when it exits. Read-only discards stay first (MC-03). No typing or claim logic here (10-06 adds it).
- **Proxy (after-research A5; Research Open Question 4).** Add `TestRemoteWSProxy_PasteBackpressureStaysOpen` to remote_ws_proxy_test.go: a fixture peer (variant of `newFixtureRemotePeerWithWS`) that keeps reading every frame and answering pings while it drains received input to a slow sink; `proxyWithHeartbeat` (50 ms / 100 ms); send 8 MiB as 32767-byte frames through the proxy; hold for at least 3x the heartbeat timeout; assert the client conn stays open and the sink received every byte in order (sha256).
