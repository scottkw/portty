Lifecycle groundwork for the session handoff, and the two requirements that need no handoff:

1. UPGR-04: `/health` reports an integer API version (2; v1.1 is implicitly 1). A GUI or CLI that needs a higher version shows a clear "update needed" state instead of failing calls.

Output: the API version on /health with the CLI and GUI "update needed" paths, ctx-aware EnsureDaemon with Quit All cancel, the couldn't-move copy, clean SIGTERM and logout quits, and one modal at a time.

- **EnsureDaemon contract (CONTEXT: "Quit All vs an in-flight restart (IN-07)"):**
  - `func EnsureDaemon(ctx context.Context, socketPath string, opts EnsureOptions) error` with `type EnsureOptions struct { Restart RestartPolicy; NoHandoff bool }`.
  - `type RestartPolicy func(RestartQuestion) bool` and `type RestartQuestion struct { DaemonVersion string; Sessions int; MoveFailed string }`. Sessions is -1 when unknown (unchanged meaning). MoveFailed is empty unless a handoff was tried and failed; it holds the short reason for the copy.

  - Cancellation rules: cancelled before a spawn, never spawn (return ctx.Err()). Cancelled after spawning a fresh (non-takeover) daemon, kill that child: it owns no sessions. startDaemon's lock wait and waitForDaemon's poll check ctx on every 50 ms tick. The takeover rule (never kill a takeover child) is 09-05's, on its own spawn path.

- **503 retry (Research Pattern 9, 09-04's freeze gate).** A daemon in a handoff freeze answers mutating routes with 503 and `Retry-After: 1`. doJSON for POST/PUT/PATCH/DELETE and ShutdownDaemon retry a 503: sleep Retry-After (default 1 s, capped at 2 s), up to a total of 20 s (`var frozenRetryBudget = 20 * time.Second`, a var so tests can shrink it), then return the 503 as an error (ShutdownDaemon returns it too: the caller decides). GET calls never retry (a frozen daemon still serves reads). Quit All therefore waits out a handoff, then stops whichever daemon owns the socket, which is the CONTEXT rule "after READY or COMMIT, Quit All waits for the handoff to finish, then stops the daemon normally".
  - Why 20 s (plan check W3): the budget must outlast the longest freeze 09-04 allows, which is the hub freeze wait (2 s) + the old daemon's READY timeout (5 s) + the takeover's COMMIT-to-COMMITTED watchdog (5 s) + transfer time, about 12 s, so 20 s leaves margin. Put that sum in a comment next to frozenRetryBudget naming 09-04's `freezeTimeout`, `readyTimeout` and `committedWatchdog`; 09-04 adds a test that fails if its timeouts ever add up to more than this budget. A normal handoff freezes for well under a second, so Quit All still quits within a few seconds in practice.

- **SIGTERM (CONTEXT: "UPGR-05 SIGTERM"; Research "Wails SIGTERM root cause and fix").** Wails v2.10.2 calls `signal.Notify` for SIGTERM in `signal.Start()` before `application.Run()`, which then calls OnStartup, so a `signal.Reset(syscall.SIGTERM)` in App.startup undoes it. Then Portty's own `signal.Notify` on SIGTERM runs a handler seam `a.onTerminate()`: `a.quitting.Store(true)`, then the Wails quit through a seam (`runtime.Quit` in production). beforeClose already allows the quit when quitting is set, and shutdown() leaves the daemon running. SIGINT stays with Wails (dev Ctrl-C).
- **macOS logout/restart/shutdown (CONTEXT: "Wails cancels a system logout ..."; Research Open Question 6).**
  - Root cause, read in wails v2.10.2 internal/frontend/desktop/darwin/AppDelegate.m: `applicationShouldTerminate:` always calls `processMessage("Q")` and returns `NSTerminateCancel`. Any terminate request is therefore cancelled at the AppKit level, so a logout, restart or shutdown is cancelled by Portty even when the quit modal would agree.
  - Fix in new terminate_darwin.m (cgo, house pattern of appearance_darwin.go/.m):
    1. Observe `NSWorkspaceWillPowerOffNotification` on `[[NSWorkspace sharedWorkspace] notificationCenter]` and set a static flag.
    2. Replace the delegate class's `applicationShouldTerminate:` implementation once (`class_getInstanceMethod` on `[[NSApp delegate] class]`, keep the original IMP, `method_setImplementation`). The replacement returns `NSTerminateNow` after calling the exported Go callback when the flag is set, or when `[[NSAppleEventManager sharedAppleEventManager] currentAppleEvent]` is a quit event whose `keyAEQuitReason` is one of kAELogOut, kAEReallyLogOut, kAEShowRestartDialog, kAERestart, kAEShowShutdownDialog, kAEShutDown. Otherwise it calls the original IMP (Wails' modal path, unchanged for Cmd-Q and the menu).
    3. The exported Go callback (`//export porttySystemWillPowerOff`) calls `appInstance.onSystemPowerOff()`, which sets quitting. The daemon is left alone (logout ends it anyway).
  - Installed from App.startup after the window exists. The Go side is unit-tested; the AppKit behaviour is a VM check in 09-07 (a VM restart issued while the GUI is open must reboot the VM).
  - Swizzling one delegate method is the smallest change that does not fork Wails. Record it with a `shortcut:` comment naming the Wails file and line it works around, so a Wails upgrade re-checks it.
