# 09-07 fix 2: rejoining local viewers no longer move an imported hub's grid

## The failure

In V-02, 4 of the 5 viewers that reconnected after the handoff got a full replay instead of a delta. The home `portty attach` file repeats TICK-s1 0..77. Both runs showed the same pattern:

- conn=1 local (the office attach, 100x30) rejoined first: delta, then `grid 85x29 -> 100x30`.
- conn=2 local (the office GUI tab, 85x29) rejoined 12 ms later: `mode=full`, then `grid 100x30 -> 85x29`.
- conn=3..5 (web): `mode=full`.

## The cause

- The grid arbiter `applyGridLocked` (internal/relay/hub.go:510) takes the minimum over the local viewers that are connected at that moment (D-02). Before the upgrade that was min(GUI tab 85x29, attach 100x30) = 85x29. On the new daemon the viewers come back one at a time. The attach was alone for 12 ms, so the grid grew to 100x30, and then the GUI tab shrank it back.
- Neither change starts from the unknown grid, so both count as genuine. `resizeLiveEmulator` (hub.go:1350) sets `geomEnd` to the ring end.
- `joinLocked` (hub.go:1734) sends a delta only when `resume > geomEnd`. Every later viewer resumed at exactly that end, because no output came in between, so each one got a full replay.
- The CLI clears the screen before a full replay (`ClearOnFull`, internal/attach/loop.go:314). The repaint then writes the history a second time into a real terminal's scrollback.
- The result depends on which local viewer reconnects first, so it is a race. In the first pass the GUI tab happened to win.

## The fix

The fix is in internal/relay/hub.go and internal/relay/handoff_state.go.

- `NewHubFromState` (handoff_state.go:218) records the imported grid in `settleCols`/`settleRows`.
- During the settle window, `applyGridLocked` treats the imported grid as one more local size in the D-02 minimum. So the grid can shrink at once, and it can grow back up to the imported grid, but never past it. If no real local viewer is connected, nothing changes (D-01, as before).
- In the V-02 order (attach 100x30 first, then GUI 85x29), the minimum stays 85x29 at every step. The grid never changes, so there is no grid frame and no `geomEnd` bump, and both resumes stay deltas.
- `Start` (hub.go:723) arms `time.AfterFunc(handoffSettle, h.endSettle)`. `handoffSettle` is 3 s (hub.go:719): local viewers rejoined within 1.6 s in V-02. Hubs that are only staged, for example after a failed takeover, never arm the timer.
- `endSettle` (hub.go:736) clears the cap and re-runs the arbiter once. It uses the same lock order as every other path: gridMu, then mu, with IO only after mu is released inside `applyGridLocked`.
  - On a frozen hub it skips the arbiter, so it never resizes a hub that is being exported. If the handoff rolls back, `Thaw` re-runs the arbiter.
  - On a closed hub it does nothing.
- `Shutdown` stops the timer.
- Normal hubs have `settleCols`/`settleRows` at 0, so their arbiter does exactly what it did before. The new `local` flag only repeats the old rule that a grid is never set without a local size.

The grid can still only grow after the window ends. If a user widens the window within 3 s of an upgrade, the grow lands up to 3 s late, when `endSettle` runs.
