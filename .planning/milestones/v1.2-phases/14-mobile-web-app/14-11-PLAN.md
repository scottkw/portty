## Flagged decisions and assumptions

- **Pinch (CONTEXT; RESEARCH Pattern 4; UI-SPEC, Pinch to Zoom).** `attachPinchZoom(container, { getSize(): number; setSize(px: number): void; onEnd(): void }): () => void`, shaped like `attachTouchScroll` (header doc block, module constants, returned cleanup). Exactly two touches: on the first two-touch move record `d0` and `size0`; live size `clamp(round(size0 * d / d0), 6, 32)`; `setSize` only when it changes; `preventDefault()` on every two-touch touchmove (listener `{ passive: false }`); when the last finger lifts after a pinch, `onEnd` once after 250 ms (a new pinch inside the window restarts it). Add a `gesturestart` `preventDefault` listener on document, removed by the cleanup. One-finger events are untouched (touchScrollHandler keeps them; its header says multi-touch is released to the browser today).
- **Font state (web mode).** App passes no font props in web mode (App.tsx ~1328-1329), so WebShareSessionView keeps `pinchFontSize: number | null` in React state: the effective size is `fontSize ?? pinchFontSize ?? hostFont?.size ?? DEFAULT_TERMINAL_FONT_SIZE`, and its `onFontSizeChange` fallback for the browser guest sets `pinchFontSize` to the clamped `effective + delta` (6..32, the clamp `handleFontSizeChange` already uses). Nothing is stored on the phone (per-device saving is deferred).
- **One claim (INPT-06 kept).** TerminalPanel's font effect claims when a shown panel's font changes. During a pinch it must only lay out and report: a `pinchingRef` set while two fingers are down and until `onEnd`; the effect calls `relayout()` and skips `claimFit()` while it is set; `onEnd` clears it and calls `claimFit()` once. A capability without write still sends that claim; the server ignores claims from such subscribers.
- **Keyboard inset (Decided autonomously, Layout; RESEARCH Pattern 3).** `useVisualViewportInset(enabled: boolean): { keyboardUp: boolean }` in visualViewportInset.ts. When enabled (App: `mode === 'web' && usePhone()`): on `visualViewport` `resize` and `scroll`, inside `requestAnimationFrame`, set the app root's height to `visualViewport.height` and its top offset to `visualViewport.offsetTop` (CSS variables on the root or inline style; the root is the `.app` element), and compute `keyboardUp = window.innerHeight - visualViewport.height > 100`. Stuck-viewport heal: track the largest `innerHeight` seen; about 140 ms after `.xterm-helper-textarea` loses focus with no textarea focused, if `visualViewport.height` is still more than 100 px under that maximum, toggle the root's `display` off and on once. Both are [ASSUMED] to hold on iOS 26 standalone (A3) until 14-13 and the real phone show it. Nothing resizes xterm here: the existing ResizeObserver reports and the next keystroke claims.
- **Phone chrome (UI-SPEC, Phone Layout).** TabBar adds `tab-bar--single` when `webMode` and exactly one tab; CSS under `@media (pointer: coarse) and (hover: none)`: `.tab-bar--single { display: none }`, tab strip side padding `max(12px, env(safe-area-inset-left))` / right, `.terminal-session-container { padding: 4px 8px }`, the root's `padding-top: env(safe-area-inset-top)`, `html { touch-action: pan-x pan-y }`, `.keybar--kb-up { padding-bottom: 0 }`; and under `@media (pointer: coarse)`: `input, textarea, select, .xterm-helper-textarea { font-size: 16px }` (use `!important` only if xterm sets the helper textarea's font-size inline; check in the iphone e2e). Desktop rules untouched.
