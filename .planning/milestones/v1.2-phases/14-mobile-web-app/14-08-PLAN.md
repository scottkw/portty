## Flagged decisions and assumptions

- **Phone and standalone tests (UI-SPEC, What "phone" means).** `frontend/src/lib/phoneQuery.ts` exports `PHONE_QUERY = '(pointer: coarse) and (hover: none)'`, `isPhone()` (`window.matchMedia(PHONE_QUERY).matches`, no fallback branch: the test setup stubs matchMedia), `usePhone()` (state plus a `change` listener with cleanup, shaped like `useColorScheme.ts`), and `isStandalone()` (`window.matchMedia('(display-mode: standalone)').matches` or `navigator.standalone === true`, the iOS flag). 14-10 and 14-11 reuse it.
- **Reload (UI-SPEC, Reload on Phones).** `SessionEndedBanner` gets an optional `onReload`; it renders `<button type="button" className="banner__action">Reload</button>` before the dismiss button only for kinds `share-stopped`, `ended`, `unreachable` and `reconnecting`, never for the paste, path or port kinds. TerminalPanel passes `onReload={() => location.reload()}` only when `usePhone()` is true, and for `reconnecting` only while 14-04's `connectStuck` is true. CSS: under the phone media query `.banner__action` gets `min-height: 44px; min-width: 44px; padding: 0 8px` (the visible text stays 12px).
- **ErrorBoundary.** A new optional `webMode` prop: the fallback reads "This view hit an error. Reload to try again." plus a Reload button when `isPhone()`; App passes `webMode={mode === 'web'}` to the `web-session` boundary only. Keep `role="status"`, the icon and the error-type-only log.
- **Open PDF way back (W9; UI-SPEC style, minimal, no CSP change).** Today the browser viewer's Open PDF calls `window.open(blob)` (11-SPIKE S-04); in a standalone web app that may replace the app's only window with no way back. When `isStandalone()` is true, Open PDF instead opens an in-app view rendered by PdfPreview itself:
  - a fixed full-screen layer (`role="dialog"`, `aria-modal="true"`, `aria-label` the file name) on `--color-window`;
  - a top bar on `--color-toolbar` with a 1px `--color-separator` bottom edge, `padding-top: env(safe-area-inset-top)` and side safe-area padding, holding the file name (13px/600, truncated with an ellipsis), an "Open full PDF" text button (calls the existing `window.open` path, for the whole document) and a "Done" text button; both are `<button type="button">`, 44 x 44 pt minimum, text colour `--color-text` (accent is reserved, UI-SPEC);
  - the PDF drawn with `<img src={url} alt={name}>` at the layer's width with vertical scroll (img-src already allows blob:, Amendment 3);
  - focus moves to Done on open; Done or Esc closes the layer and returns focus to Open PDF.
  - [ASSUMED] iOS WebKit draws the PDF in an `<img>` (possibly only its first page); 14-13's S-06 records what shows. Done is the way back whatever the image shows; "Open full PDF" keeps the whole document reachable.
- **Wording gate.** tests/check-share-removal.sh flags read-only wording paired with link, share or tab; say "a capability without write".
