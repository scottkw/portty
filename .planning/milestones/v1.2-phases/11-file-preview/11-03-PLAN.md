## Flagged decisions and assumptions

- **Session id (CONTEXT "Session id"; RESEARCH Pattern 5).** In `NativePTYBackend.Create` call `generateID()` before `cmd.Env` is built (today it runs after `cmd.Start()`, native.go:83) and pass `"PORTTY_SESSION_ID="+id` as a required value to `mergeEnv` beside TERM and COLORTERM; the Session keeps that same id. Every error path after the move still cancels and closes as today. Ids are 32-hex `crypto/rand` strings; they are not secrets (shares use separate capability tokens) and any same-UID process can already list them over the socket.
  - Known limits, documented in the SUMMARY (not fixed): a session created before this build, including one moved by a Phase 9 handoff, has no id (the CLI says so in one line, 11-08); a `tmux` or `screen` server started in session A and attached from session B carries A's id.
- **PATH entry (CONTEXT "PATH entry"; RESEARCH "PREV-05 detail").** `binDir = filepath.Join(e.configDir, "bin")`, created 0700; link `binDir/portty` → `filepath.EvalSymlinks(os.Executable())`, through a package-level seam so tests can point it at a temp file. Refresh on every CreateSession: if the link already resolves to the target, do nothing; otherwise create a symlink under a unique temporary name in binDir and `os.Rename` it over `binDir/portty` (no window without a link while sessions spawn; concurrent CreateSessions never see a broken link). Refuse a target that resolves inside binDir (self-loop guard). On any failure log `cli link: <reason>` and return no PATH entry; the session starts anyway (rock-solid: a convenience never blocks a shell).
  - Session env: `PATH=<binDir>:<daemon's PATH>` through `pty.CreateRequest.Env` (mergeEnv lets extras override the inherited PATH). The daemon's own PATH was already augmented at launch (internal/daemon/path.go AugmentServicePath), so nothing else changes.
  - Why not `…/Portty.app/Contents/MacOS`: that dir holds `Portty` (capital P), works for `portty` only on case-insensitive APFS and breaks tab completion; the per-user dir gives the proper lowercase name and heals itself after app moves, updates and dev builds (RESEARCH Open Question 4).
  - "Application Support" has a space; PATH entries with spaces are fine for zsh and execvp.
  - Verified by research (RESEARCH Sec. 7): `/etc/zprofile` runs `path_helper -s`, which keeps pre-existing entries and appends them after the system entries, so the entry survives at the end. Pitfall 11 (an rc file that assigns PATH without `$PATH`) is an accepted, documented limit.
- **engine.go is touched only by this plan in the phase** (RESEARCH overlap rule): do the id and the PATH env here together.
- **Test runs (each test binary fires a firewall alert for the user).** TDD loops: `go test -race -short -run 'Env' ./internal/pty/` and `go test -race -short -run 'CLILink' ./internal/daemon/`. The plan's gate (Task 3) runs exactly one `go test -race -short -count=1 ./...`. Every daemon test that creates a session kills it in cleanup (the pty-fd-leak lesson in TESTING.md: `testDaemon` and `killSessions`). The daemon test binary already runs in a temp HOME (testmain_test.go); still use `ConfigDirForTest(t.TempDir())`.
