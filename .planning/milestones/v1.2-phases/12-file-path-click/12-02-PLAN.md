## Flagged decisions and assumptions

- **The shim is one file, `.zshenv` (RESEARCH Pattern 1, verified on this Mac's zsh 5.9).** Copy the script in 12-RESEARCH.md Pattern 1 (the block starting "# Portty zsh shell integration", lines 178-213) verbatim into internal/daemon/zshshim.zsh. It restores ZDOTDIR from PORTTY_ZSH_ZDOTDIR (or unsets it), unsets PORTTY_ZSH_ZDOTDIR, sources the user's `${ZDOTDIR-$HOME}/.zshenv` inside an `always` block, and only for interactive shells defines `__portty_osc7` (emulate -L zsh, ZSH_SUBSHELL guard, LC_ALL=C percent-encoding, printf to /dev/tty with `2>/dev/null` first), adds it to chpwd_functions, adds `__portty_precmd` (re-adds the chpwd hook if missing, then emits) to precmd_functions, and emits once. zsh then reads .zprofile, .zshrc, .zlogin and /etc/zshrc's HISTFILE from the restored directory by itself; nothing else is needed. Quoted builtins, the `always` block and plain array appends (no `autoload add-zsh-hook`) each answer a verified failure mode; do not "simplify" them.
  - **precmd emission (CONTEXT "Decided at planning" [Shell], the one addition to "chpwd hook plus one initial emit").** It heals a user .zshrc that empties chpwd_functions and re-publishes the cwd after an upgrade handoff. If an rc file also empties precmd_functions, tracking degrades to "no cwd" (relative clicks do nothing), the locked fallback.
  - **The OSC 7 host part is empty** (`file:///path`), so a Mac rename can never desync the hub's host check (12-03).
  - Verified this session (planning): macOS zsh 5.9 does not run zsh-newuser-install for a user with no dotfiles, with or without the shim, so the shim changes nothing for brand-new users.
- **Reversibility (CONTEXT "Shell integration"): costly, user-approved in discuss.** It runs inside every new session's startup. The shim is rewritten from the embedded script at each CreateSession, so a fix ships with the next build for new sessions; sessions started earlier keep the ZDOTDIR they were spawned with (fixed at exec), which is harmless because the restore runs first.
- **Writer and env (PATTERNS "zshshim.go"; clilink.go is the analog).** `refreshZshShim(dir string) error`: `os.MkdirAll(dir, 0700)`; read `dir/.zshenv`, and if it already equals the embedded bytes return nil (no rewrite); else write the bytes to a unique temporary name in dir (random hex suffix as refreshCLILink does, mode 0600), `os.Rename` it to `.zshenv` (remove the temporary on any error), then re-read `.zshenv` and return an error unless it equals the embedded bytes. `(e *SessionEngine) zshEnv() []string`: refuse an empty or non-absolute `e.configDir` (log, nil: never write relative to the daemon's cwd); `refreshZshShim(filepath.Join(e.configDir, "zsh"))`; on error `log.Printf("zsh shim: %v", err)` and return nil; else return `ZDOTDIR=<dir>` and `PORTTY_ZSH_ZDOTDIR=<os.Getenv("ZDOTDIR")>`, the second always present (empty means unset in the shim), so an inherited stale value is overwritten by mergeEnv's extra entries (internal/pty/native.go: extras override the inherited environment).
  - Why verify before setting: a ZDOTDIR pointing at a directory without a readable .zshenv silently skips every user startup file (RESEARCH failure-mode table, last row). Setting nothing on failure is the safe direction.
  - The config dir path contains a space (`Application Support`); verified to work.
- **Wiring (engine.go CreateSession, ~234).** Build the env as `e.cliPathEnv()` and, only when `cliPath == sessionShell`, append `e.zshEnv()...`; pass it as `Env`. Nothing else in CreateSession changes. Every test that spawns `/bin/cat`, `/usr/bin/env` or another binary through SetSpawnCommandForTest is untouched. Sessions always run `/bin/zsh -l` ($SHELL is ignored, engine.go:178-198), so CONTEXT's "a login shell that isn't zsh" cannot occur at spawn; bash and fish run only inside the session, where nothing is injected (CONTEXT [Shells]).
  - The existing TestCreateSession_LoginShell (engine_test.go ~321) sets a custom ZDOTDIR with an empty .zshrc: it now passes through the shim's restore and must keep passing.
- **Tests run the real /bin/zsh through CreateSession.** Reuse `hubReadUntil` (engine_test.go ~213) and `hub.OpenInput(nil).Write` (as TestCreateSession_LoginShell does) to type commands and wait for markers; read the raw output (OSC 7 bytes are in the hub's ScrollbackSnapshot and the subscriber frames, not in rendered tail lines).
