## Flagged decisions and assumptions

- **Where the provider lives (CONTEXT [Click detection]; RESEARCH Pattern 7).** frontend/src/lib/pathLinks.ts calls the xterm 6 link-provider registration; TerminalPanel.tsx only calls `registerPathLinks`. TerminalPanel.web-links.test.tsx's Plan B test (~126-134) exists to keep TerminalPanel from walking OSC 8 hyperlink ids (the accessor is absent from xterm 6 typings); it is unrelated to path links. Edit it in place, do not delete it: rename it to say there is no OSC 8 provider and that Phase 12 path links live in lib/pathLinks.ts; keep the hyperlink-id assertion; keep the assertion that TerminalPanel.tsx has no provider registration; add assertions that TerminalPanel imports pathLinks and that, among non-test files under src, only lib/pathLinks.ts registers a link provider. Update the matching comment above the web-links arm in TerminalPanel.tsx (~813-823) so it no longer says no provider is registered: the OSC 8 secondary provider is still absent, path links come from lib/pathLinks.ts.
- **Gating (CONTEXT "Decided at planning" [Gating]; UI-SPEC "Where it exists").** Register once per terminal inside the existing `if (pluginConfig?.webLinks) { … } else { … }` hot-swap arm (~825), hold the IDisposable in a ref, dispose in the else branch and in the unmount cleanup next to webLinksAddonRef. `provideLinks` returns no links unless `pathClickEnabledRef.current` is true; RelayClient sets it from the replay meta's `pathClick === true` and clears it on close and on abandon (next to both onPreviewReset calls). UI-SPEC's "no link provider is registered" for read-only viewers and older hosts is met observably (nothing underlines, nothing is clickable) without re-registering on every reconnect. Peer tabs and browser viewers get the host's plugin config (WebShareSessionView fetches it), so path links follow the host's web-links toggle there, as URLs do.
- **Detection (UI-SPEC "What counts as a path link"; the regex is Claude's discretion, pinned by the fixture).** Path alphabet: Unicode letters and digits, `_ . ~ @ % + # -`, plus `/` (the host's token alphabet, 12-04). A candidate starts where the previous character is absent or outside the alphabet, and is the maximal run of alphabet characters. It is a link when it starts with `/`, `~/`, `./` or `../` followed by at least one alphabet character, or (bare form) contains at least one `/`, does not start with `/`, and its last segment has an extension (a `.` followed by letters or digits). Trailing `.` characters are trimmed. A `:digits(:digits)?` directly after the token is added to the underlined text but not to the request (`stripLineCol`). Candidates overlapping any match of a scheme URL (letters, then `://`, then non-space) or `mailto:` plus non-space are dropped. No quote parsing (a path with a space is detected only after the space). `findPathLinks(text)` is pure and returns `{start, end, text, request}` string offsets; it must produce every `detect` case of frontend/src/lib/__tests__/fixtures/path-click.json exactly (12-04 already proved the host accepts each request). Do not edit the fixture; if a case cannot be met, stop and report (RULE 0), since the host and viewer must agree.
- **Rows to links (RESEARCH Pattern 7 "Text and ranges").** For buffer line y, walk up while `isWrapped` to the logical start and down while the next line `isWrapped`, up to 2048 characters; build the string from `getCell(x)` (skip width-0 spacer cells of wide characters; an empty cell is a space) with a parallel map from string offset to 1-based cell x and y; run findPathLinks; keep matches touching row y; convert to `{start: {x, y}, end: {x, y}}` (1-based, end inclusive). xterm's WebLinkProvider rejoins wrapped rows the same way; its LinkComputer is not exported, so a local version is written (about 60 lines).
- **Underline toggle (RESEARCH Pattern 7; UI-SPEC "Pointer behavior" and its planner note).** Links are provided with `decorations: {underline: modDown, pointerCursor: modDown}`. registerPathLinks owns a small tracker: window `keydown`/`keyup` listeners in the capture phase and `mousemove` on the terminal element update modDown with `isModifierPressed(event, mode)`; `blur` and `visibilitychange` reset it to false (a Cmd keyup is lost on Cmd-Tab). On a change it writes `link.decorations.underline` and `pointerCursor` on the currently hovered link (tracked from the link's hover and leave callbacks; always write through `link.decorations`, never a cached object, because xterm replaces it with a tracked one after hover). `activate(event, text)` calls onClick only when `isModifierPressed(event, mode)`; mode is `(webLinksConfigRef.current?.modifier || 'platform')`, read at event time, exactly as the URL handler does. `isModifierPressed` in openLink.ts widens its parameter to `Pick<MouseEvent, 'metaKey' | 'ctrlKey'>` so key events use the same rule (MouseEvent callers are unaffected). The listeners are removed when the returned IDisposable is disposed. Accepted fallback, decided only by 12-07's VM check: if WKWebView does not deliver the key events, underline on plain hover with the same modifier-gated click (today's URL behaviour); that change is not made here.
- **Wire (12-04 SUMMARY; RESEARCH Pattern 8).** `MSG_PATH_CLICK = 0x13`; `sendPathClick(text)` sends `[0x13, …utf8]` only when the socket is open (the same two guards as sendClaim: never queued, so a click is never replayed after a reconnect), and drops empty text or text over 1024 bytes. `handleMeta` also destructures `pathClick` (only `=== true` counts) and `notice` (only the exact strings `path-unsupported` and `path-too-large` call onPathNotice; anything else is ignored); a notice meta carries no replay or offset, so the resume logic is untouched. Tests decode the frames from path-click.json's `frames`.
- **Notice (UI-SPEC "Notice" and "Copywriting Contract"; RESEARCH Pattern 8).** Two SessionEndedBanner kinds with the exact copy above (straight apostrophe), the existing info banner, InformationCircleIcon and Dismiss button; no new styles. TerminalPanel keeps `pathNotice` state, a `PATH_NOTICE_MS = 5000` timer that restarts on each notice and is cleared on unmount, a ref telling whether another banner holds the slot (paste notice, reconnecting or unreachable, ended or share-stopped) so an arriving notice is dropped then, renders the notice last in the slot only when no other banner shows, and clears it when the panel's isActive turns false. Focus never moves.
- **Existing mocks.** The six `class MockTerminal` suites (contextLoss, guestClose, preview, reconnect, scale, tabSwitch) never enable webLinks (contextLoss passes `webLinks: false`, the others pass no pluginConfig), so the provider is never registered there and their mocks need no change (verified at planning; RESEARCH Pitfall 10 assumed otherwise).
