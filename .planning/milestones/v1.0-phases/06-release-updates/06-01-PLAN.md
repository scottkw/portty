## Flagged decisions and assumptions

- **Source to port.** `~/dev/gifsmith/internal/update/update.go`, `install.go`, `update_test.go`, `install_test.go` and `real_darwin_test.go` (outside this repo; read them directly). Port them nearly line for line. The changes are:
  - `Repo = "scottkw/portty"`, User-Agent `Portty`, `TeamID = "S2K7P43927"` (CONTEXT user decision).
  - `DMGAssetName(v)` returns `"portty-v" + v + "-darwin-universal.dmg"`. That is release.yml's `portty-${GITHUB_REF_NAME}-darwin-universal.dmg` for a `vX.Y.Z` tag.
  - `Clean` matches `portty-v*-darwin-universal.dmg` and `.part`.
  - The quarantine agent name is `Portty`.
- **New in the port:**
  - `ErrRateLimited`: `Checker.Latest` returns it for 403 and 429, so the caller can word a rate-limit error differently. Other non-200/304/404 statuses keep GIFsmith's `status %d` error.
  - `Reveal(ctx, run Runner, path string) error` runs `/usr/bin/open -R path`. A failure wraps a new `ErrReveal`. CONTEXT "After verify": Portty reveals, GIFsmith opened. Reveal never removes the quarantine flag.
  - `NewCheckClient(api string) *http.Client`: a 30 s timeout. Redirects are allowed only to the same scheme and host as `api`, at most 5. This keeps the check talking to api.github.com only (security constraint: outbound HTTPS only to api.github.com and the release-asset hosts).
- **Old code stays for now.** `internal/updater/updater.go` and `updater_test.go` (go-selfupdate) remain until 06-02. The new files share the package, so check for clashing identifiers. The old file defines `Check`, `UpdateInfo`, `DetectFunc`, `DefaultDetect`, `detectLatestFrom`, `withinRateLimit`, `persistTimestamp`. The old test helpers are `fakeDetect`, `writeTimestamp`, `fakeSource`, `fakeRelease`, `fakeAsset`, `detectFrom`. Rename a new helper if `go vet` reports a clash. Two package doc comments exist until 06-02 deletes the old file; that is harmless.
- **Brand gate.** `tests/check-brand.sh` fails on any `github.com/scottkw/<repo>` other than portty in tracked files outside .planning. When porting tests, replace every GIFsmith repo slug and asset name with Portty's. Write the "other repo" allowlist cases with another owner, such as `https://github.com/other/repo/...` and `https://github.com/someone/portty/...`. Never use a scottkw repo other than portty, and never a `scottkw/portty-...` variant.
- **Real-tools test inputs (grounded on the host, 2026-11-18).**
  - GIFsmith's public release `v1.0.1` asset `Gifsmith-1.0.1-arm64.dmg` (6,136,820 bytes, sha256 `4119ccd13d2ee4a84c28c0d0a630ec4b830c23a712219eeaac7ba0ab32b3faa1`) is signed by Team S2K7P43927, notarized and stapled. `spctl` reports `accepted` and `source=Notarized Developer ID`. It is the positive real-tools case.
  - An `hdiutil` UDZO image is the unsigned case: codesign says "code object is not signed at all".
  - The same image after `codesign -s -` is the ad-hoc case: codesign verify passes, `TeamIdentifier=not set`.
  - A Developer-ID-signed but un-notarized DMG is not made here. Signing with the host's Developer ID key can raise a keychain prompt on the host. The spctl-reject branch is covered by the fake-Runner tests with real-format output.
  - Verify only ever runs on temp copies. The test never opens Finder on the host: the UPDATE_REAL_REVEAL switch is for the user only.
- **release.yml (costly, user-approved in CONTEXT "Notarization", no extra checkpoint).** The DMG step builds `build/bin/portty-${GITHUB_REF_NAME}-darwin-universal.dmg` and codesigns it. The notarytool profile `portty-notarize` lives in `build.keychain`, which "Cleanup keychain" deletes. So the new steps go between "Create and sign DMG" and "Cleanup keychain". Stapling changes the DMG's bytes, and the publish job computes checksums after download, so the order stays correct. The job's 90-minute timeout assumed one 60-minute notarization wait. With two waits it becomes 150 minutes.
- **No live pipeline run here.** scottkw/portty is private and has no Actions secrets and no `release` environment (checked 2026-11-18 with `gh secret list` and the environments API). The pipeline can only be checked statically in this phase: YAML parse, the contract test and the brand gate. The first tagged release is TESTING.md M-93 (06-04).
- **Toolchain.** Every Go command runs with `GOTOOLCHAIN=go1.26.11` (toolchain_guard.go fails go1.27 builds).
- **TESTING.md** is updated once, in 06-04, so the wave-1 plans share no file.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub API → updater | release JSON (tag, flags, asset name, size, digest, URL) is untrusted input |
| release-asset hosts → disk | DMG bytes and redirects are untrusted until digest and signature checks pass |
| updater → system tools | codesign, spctl, xattr and open run with a path the updater built |
| CI secrets → release artifacts | the sign-macos job holds the Developer ID certificate and notarization credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | Download + Verify (a swapped or modified DMG) | high | mitigate | SHA-256 from the API's asset digest over HTTPS; exact byte count; exact-host allowlist checked on the asset URL and on every redirect (NewDownloadClient); codesign --verify --strict, TeamIdentifier=S2K7P43927 and spctl "source=Notarized Developer ID"; any failure deletes the file (TestDownloadDigestMismatch, TestVerifyFailures, TestRealDMG) |
