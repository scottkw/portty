## Contract with 06-03 (frontend) and 06-04 (VM seam). Keep it exact.

- **Status JSON** (Go `updater.Status`, json tags lowercase):
  - `state`: one of idle, checking, current, available, downloading, verifying, revealed.
  - `current`: the running version without a leading v.
  - `latest`: the newer version, set while available, downloading, verifying or revealed.
  - `done` and `total`: bytes, while downloading.
  - `error`: readable text after a failed download, verify or reveal. The state is then available. Never a URL or a path.
- **Event** `update:status` with one Status payload, on every state change. That includes checking, and progress at most every 100 ms.
- **Bindings** (exported App methods, the only update methods JS can call):
  - `GetUpdateStatus() updater.Status`.
  - `DownloadUpdate() updater.Status`. It returns the current status unchanged unless the state is available or revealed. Otherwise it runs the whole download, verify and reveal before it returns.
  - The old `GetLastUpdateInfo` and `CheckForUpdates` bindings are gone after Task 3 (06-03 removes them from the JS stubs).
- **VM seam vars** (package main, in app_update.go; the VM-only vmpreview build in 06-04 overrides them in init):
  - `updateAPI string = updater.GitHubAPI`
  - `updateAllow func(*url.URL) bool = updater.GitHubAllow`
  - `updateFirstDelay = 10 * time.Second`
  - `updateTick = time.Hour`
  - `updateEvery = 24 * time.Hour`
- **Log lines** (stderr; the 06-04 VM check reads them from `open --stderr`): `update: <version> available`, `update: up to date`, `update: no published release`, `update: release v<version> not installable: <err>`, `update: check failed: <err>`, `update: notified <version>`, plus the existing `notification: dispatching native notification for identifier portty.update-available`.

## Flagged decisions and assumptions

- **Service (port of GIFsmith UpdateService, Wails-free, in internal/updater/service.go).**
  - Fields: Checker, Current, Emit `func(Status)`, Dir, Client (NewDownloadClient), Run, Now. Unexported fields: a mutex, the status, the available Release, and a separate check mutex.
  - `Check(ctx)` holds the check mutex for its whole run. A second Check waits behind one in flight, then runs its own; the ETag makes it a cheap 304. This deviates from GIFsmith, which returned the "checking" status at once. With the change, a manual click during the launch check still gets a real answer.
  - Check returns the current status at once while downloading or verifying.
  - Outcomes follow GIFsmith:
    - not installable → current, logged;
    - error → restore the previous status and return `*Error{Kind: "check"}`;
    - not found → current;
    - newer → available;
    - otherwise current.
  - `Download()` follows GIFsmith's Download. Differences: it runs on its own `context.WithTimeout(context.Background(), 10*time.Minute)`, Reveal replaces Open, the end state is revealed, and every failure returns to available with Status.Error set.
  - Emit runs under the mutex so events keep their order. Emit must not block: emitEvent and the tray setter both return at once.
- **Error texts (Claude's discretion: copy beyond the CONTEXT strings).** `updater.Error{Kind, Text}` implements error with Text.
  - check, rate limited (ErrRateLimited): "GitHub is limiting update checks from this network. Try again in an hour."
  - check, other: "Portty couldn't reach GitHub. Check your internet connection and try again."
  - download: "Portty couldn't download version X. Try again later."
  - verify, digest: "The download didn't match the release's checksum, so Portty deleted it."
  - verify, signature: "The download didn't pass the signature check, so Portty deleted it."
  - reveal: "Portty couldn't show the download in Finder."
  - A test asserts that no text contains "://" or the downloads folder path.
- **Cadence (CONTEXT user decision "Cadence" and autonomous "Throttle", with one refinement).**
  - The first check runs updateFirstDelay after startup.
  - After that, the loop wakes every updateTick (1 h). It checks when 24 h of wall-clock time have passed since the last completed check, or when the last check failed. Compare with `time.Now().Round(0)` so the monotonic reading is dropped.
  - Why not a plain 24 h ticker: Go timers on macOS stop while the Mac sleeps, so a laptop that sleeps every night would stretch "every 24 h" to days. Retrying failures hourly keeps a launch with no network from waiting a whole day.
  - A completed check is 200, 304, or 404 and the other not-found cases. A rate limit counts as a failure and is retried hourly, which stays far below GitHub's 60 requests an hour.
  - No setting and no persisted throttle (CONTEXT deferred: the settings toggle).
  - The test seams are App fields `updateAfter func(time.Duration) <-chan time.Time` and `updateNow func() time.Time` (nil means time.After and time.Now).
- **Version gate (CONTEXT "Version").** `updater.ParseVersion(Version)` failing (dev, -beta, empty) means startUpdatePoller starts nothing, and the manual check shows "This build doesn't check for updates." Service.Current is `strings.TrimPrefix(Version, "v")`.
- **Notification (CONTEXT "Notification").**
  - Only automatic checks notify: one call to sendNotificationFunc("portty.update-available", "Portty", "Version X is available.") when X differs from the trimmed content of `configDir()/update_notified`. Then write X there (0600) and log `update: notified X`.
  - A read error counts as not yet notified: at worst one extra notification.
  - A manual check that finds X writes the file without notifying, because the alert already told the user.
- **Tray item.**
  - `setTrayUpdateItem(const char *title)` follows setTraySessionData's pattern: copy the string synchronously, then dispatch_async to the main queue. The file uses MRC, so retain the new string and release the old one.
  - menuWillOpen adds the item right after "Open Portty" when the title is not empty. Its action `updateClicked:` calls the exported Go `onTrayUpdate`, which runs `trayCallbackApp.offerUpdate()` on a goroutine.
  - The App seam `setTrayUpdateFunc func(title string)`: nil means the C call, made only when a.trayInit is true, so tests never call cgo by accident.
  - onUpdateStatus sets "Update Available…" while Latest is set, "" for current and idle, and leaves the item alone during checking.
  - Leave BuildMenuItems in tray_common.go alone: the ObjC delegate does not use it.
- **Alerts (CONTEXT "Manual check feedback"; Claude's discretion: Wails runtime.MessageDialog).** Wails v2.10.2's darwin MessageDialog runs an app-modal NSAlert at floating level and waits on a channel. Call it only from a goroutine, never from the main thread or a menu callback directly. The App seam is `messageDialogFunc func(runtime.MessageDialogOptions) (string, error)`; nil means runtime.MessageDialog(a.ctx, opts), skipped when a.ctx is nil. Title is the NSAlert message text, Message is the informative text:
  - up to date: "Portty is up to date." / "Version {current} is the newest version." [OK]
  - available: "Version {latest} is available." / "You have version {current}." [Download (default), Later (cancel)]
  - check failed: "Couldn't check for updates." / the Error text [OK]
  - downloading or verifying: "Portty is downloading version {latest}." / "It will be shown in Finder once it's verified." [OK]
  - dev build: "This build doesn't check for updates." / "Only release builds of Portty check GitHub for new versions." [OK]
  - "Download" calls the window-show path (the showWindowFunc seam, nil means runtime.WindowShow plus setDockVisible(true)), then DownloadUpdate. The banner (06-03) shows progress.
- **offerUpdate** (tray click and manual check):
  - available or revealed: the available alert;
  - downloading or verifying: show the window;
  - anything else: do nothing.
- **Cache dir.** `filepath.Join(os.UserCacheDir(), "app.portty.Portty", "updates")`. If os.UserCacheDir fails, Dir is "", and Download fails with the download error. There is no silent fallback folder.
- **Chesterton's Fence on deletions.**
  - internal/updater/updater.go (go-selfupdate detect, 1 h persisted throttle, error swallowing): replaced by 06-01's Checker, the Service, and the in-process cadence (CONTEXT "Library" and "Throttle").
  - app.go's startUpdatePoller, runUpdateCheck, the last-update getter, the exported check method, updateSlug and the lastUpdate fields: replaced in app_update.go.
  - main.go keeps checkForUpdatesCallback's goroutine, which already exists to keep the UI thread free.
  - Stale update_check.json files from dev runs are left on disk. No release ever wrote one.
- **Modules.** After the deletion, `go mod tidy` drops github.com/creativeprojects/go-selfupdate and its tree (gitea SDK, yaml.v3 and others). github.com/Masterminds/semver/v3 stops being a direct requirement. tailscale.com and wails need semver, so it may stay as `// indirect`, which is fine.
- **Toolchain.** `GOTOOLCHAIN=go1.26.11` for every Go command. TESTING.md is updated in 06-04.
