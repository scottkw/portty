## Flagged decisions and assumptions

- **Seam = the existing `vmpreview` tag.** It is already VM-only and already guarded: tests/check-brand.sh fails if the tag appears, tracked or untracked, in .github, build.sh or scripts, and build.yml runs that gate.
  - `updates_vmpreview.go` (package main, `//go:build vmpreview`) sets the 06-02 contract vars in init():
    - `updateAPI = "http://127.0.0.1:8788"`;
    - `updateAllow` accepts only scheme http, host exactly 127.0.0.1:8788, no userinfo, a path starting /download/ and no "..";
    - `updateTick = 15 * time.Second`;
    - `updateEvery = 2 * time.Minute`.
  - updateFirstDelay stays 10 s, so the launch timing is the release timing.
  - Its header comment says it is a VM-only fake update feed for M-92 and never part of a release build. Like tailscale_vmpreview.go, it notes that the vmpreview build also fakes Tailscale and sharing, which the update checks do not use.
  - A separate tag would need its own guard, so it was not added.
- **No verification bypass.** The user brief allowed a test-build seam that skips spctl "where possible". It is not built: GIFsmith v1.0.1's DMG passes the real codesign, Team and spctl checks (checked on the host 2026-11-18). That gives a stronger reveal check than a bypass, and it keeps a verification-weakening switch out of the code entirely.
- **cmd/fakegh (committed VM tool, stdlib only).**
  - Flags:
    - `-addr` (default 127.0.0.1:8788). It exits with an error unless the host is 127.0.0.1, ::1 or localhost.
    - `-scenario`.
    - `-version` (default 9.9.9).
    - `-dmg` (the file to serve; required for newer and baddigest).
  - `GET /repos/scottkw/portty/releases/latest` by scenario:
    - newer and current: 200 with tag "v"+version, draft false, prerelease false, and one asset. The asset has name portty-v{version}-darwin-universal.dmg, the file's size, state uploaded, digest sha256 of the file, and browser_download_url http://{addr}/download/{name}. For current, the executor passes the running version.
    - draft / prerelease: the same JSON with that flag true.
    - noasset: no assets.
    - baddigest: the digest of the file with one byte flipped.
    - 404: 404.
    - ratelimit: 403 with X-RateLimit-Remaining: 0.
  - ETag is `"<scenario>-<version>-<size>"`. A matching If-None-Match gets 304.
  - `GET /download/{name}` serves the -dmg bytes for that one name, and 404 for anything else.
  - Each request logs one stdout line: RFC3339 time, method, path, `inm=yes|no`, status.
  - About 120 lines. It is committed (not scratchpad-only) so M-92 can be rerun at every release. It is never imported by the app.
- **Rig (from Phase 5).**
  - Office VM `portty-test` (192.168.64.108) and home VM `portty-test-2` (192.168.64.109). Confirm with `tart ip`.
  - SSH: `ssh -i ~/.ssh/transom_demo_ed25519 admin@<ip>`. Helpers are in ~/.local/share/portty-vm-tools on the host (vm.sh is the office VM; make a home copy with the .109 IP) and in each VM's ~/ptest.
  - Screenshots are blank. Read UI state with `~/ptest/axdump app.portty.Portty`. Native alerts show as a dialog window in that tree. Click web-content buttons with the click helper at the AX-reported centre. Press menu items with axmenu (`axmenu app.portty.Portty Help "Check for Updates…"`; copy the host binary into ~/ptest if missing).
  - Read Finder with `~/ptest/axdump com.apple.finder`. Read notifications with `~/ptest/axdump com.apple.notificationcenterui` while a banner shows, or with `log show --last 10m --predicate 'process == "usernoted"'` filtered for app.portty.Portty.
  - Never click, open apps or change network or power settings on the host. Never put the host's Developer ID key in a VM, and never sign with it here.
- **Build and inputs (host).**
  - `export GOTOOLCHAIN=go1.26.11 && "$(go env GOPATH)/bin/wails" build -platform darwin/arm64 -tags "wailsassets vmpreview" -ldflags "-X main.Version=v0.9.0"`. The Wails CLI v2.16 rewrites frontend/src/wailsjs, so run `git checkout -- frontend/src/wailsjs` right after and confirm `git status --porcelain -- frontend/src/wailsjs` is empty.
  - `GOOS=darwin GOARCH=arm64 go build -o <scratch>/fakegh ./cmd/fakegh`.
  - good.dmg is GIFsmith v1.0.1's DMG. Download it with `gh release download` into a fresh scratch dir and check sha256 `4119ccd13d2ee4a84c28c0d0a630ec4b830c23a712219eeaac7ba0ab32b3faa1`.
  - unsigned.dmg comes from `hdiutil create -format UDZO` of a folder with one text file. adhoc.dmg is a copy after `codesign -s -`.
  - Copy Portty.app, fakegh and the three DMGs into both VMs' ~/ptest.
- **Running Portty in a VM.**
  - Launch: `date +%s > ~/ptest/launch.t; open --stdout ~/ptest/gui.log --stderr ~/ptest/gui.log ~/ptest/Portty.app`. 05-16 used `open --stderr` the same way. The 06-02 log lines land in gui.log.
  - Run the fake as `nohup ~/ptest/fakegh -scenario <s> -version <v> -dmg ~/ptest/<x>.dmg > ~/ptest/fakegh.log 2>&1 &`. Restart it to change scenario.
  - Before each scenario that must start clean: quit Portty with pkill on Portty.app/Contents/MacOS, then remove `~/Library/Application Support/portty/update_notified` and `~/Library/Caches/app.portty.Portty/updates`.
- **Notifications.** The first send may raise macOS's permission request: allow it in the VM through AX and the click helper. The wails build is ad-hoc signed. If macOS will not deliver its notifications, PASS for U-01 and U-02 rests on the Portty side: exactly one `notification: dispatching native notification for identifier portty.update-available` line and one `update: notified X` line per version. The Evidence column then says delivery was not observable on this build, and M-93 checks delivery on the notarized release. Earlier phases ran M-41 (notification delivery) only on signed builds.
- **Evidence file.** `.planning/phases/06-release-updates/06-VM-CHECKS.md` holds:
  - a header with the build commit, tags, Version and DMG sources;
  - a table `| Check | Result | What was checked | Evidence |` with Result exactly PASS or FAIL;
  - evidence as excerpts from fakegh.log, gui.log, AX text and `stat`/`xattr` output.
  The fake has no secrets and Portty sends none, so there is nothing to redact beyond the VM user name.
- **TESTING.md** gets the whole phase in one place, because the wave-1 and wave-2 plans left it alone to stay parallel.
