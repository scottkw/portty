## Flagged decisions and assumptions

- Rig: `portty-test` = office (tailnet `portty-vm-office-2`, 100.x.x.N), `portty-test-2` = home (tailnet `portty-vm-home-3`, 100.x.x.N). Helpers in ~/.local/share/portty-vm-tools copied to your scratchpad with IPs from `tart ip` (they are hard-coded to an old IP and an old scratchpad path). SSH user admin, key ~/.ssh/transom_demo_ed25519. Never click or change network or power settings on the host (user rule); every fault is injected inside a VM and removed afterwards.
- Build: `GOTOOLCHAIN=go1.26.11 "$(go env GOPATH)/bin/wails" build -platform darwin/arm64 -tags wailsassets` (real Tailscale, not vmpreview). Both VMs run the same build (Pitfall 8).
- CLI driver (no human): on the home VM run `script -q /tmp/cli.log ~/ptest/Portty.app/Contents/MacOS/Portty attach portty-vm-office-2:<id> < /tmp/cli.in` with /tmp/cli.in a FIFO held open by a background `sleep` writer; type by writing to the FIFO (`printf 'echo R1-CLI-OK\r' > /tmp/cli.in`), detach with the Ctrl-\ byte; read results from /tmp/cli.log. If `script` cannot drive it, record that and use the GUI tab and daemon.log only.
- GUI driver: screenshots (vshot) and the click helper. It has no string typing; add a `type <text>` command to a scratchpad copy of click.swift (CGEvent keyboardSetUnicodeString), compile it on the host with swiftc and copy the binary into the VM.
- Fault tools inside the VMs: pf with an anchor (`sudo pfctl -a portty-test -f <rules>` plus `sudo pfctl -E`, flushed afterwards with `sudo pfctl -a portty-test -F all`) for drops and silent half-open; `tart suspend` / resume for sleep (fallback `kill -STOP` / `-CONT` of the Portty processes, noted); killing the daemon process for restarts. If sudo needs a password in the VM, record it and use the non-root variants.
- Evidence per row: the office VM's `viewer-diag:` lines (`grep viewer-diag "$HOME/Library/Application Support/portty/daemon.log"`), the home VM's proxy lines, CLI log markers, and screenshots where the GUI matters. Never paste a share link or `cap=` value into the evidence file.
- Evidence file format: 05-VM-MATRIX.md already exists (05-09 created it with a `## Feature checks` table holding V-09, V-12, V-13). This plan adds a `## Resilience matrix` section whose table columns are `| Row | Result | Fault and method | GUI tab | CLI | Browser | Reconnect (s) | Replay mode | Evidence |`. Result is machine-read and must be exactly one of `PASS` (the row behaved as expected, including R7's expected final message), `FAIL`, or `DEFERRED:M-NN` where M-NN is an existing TESTING.md manual item that covers the scenario on two real Macs (for example `DEFERRED:M-85` for a real access-point switch). A row may only be DEFERRED when the VMs cannot reproduce the scenario faithfully, never because it failed.
