## Flagged decisions and assumptions

- Ordering: this plan waits for 05-12 only because both end with a VM check on the same two Tart VMs (a shared resource, not shared files); it needs 05-09 for App.tsx and 05-10 for the detector. The VM result goes into the shared evidence file `.planning/phases/05-overnight-survival/05-VM-MATRIX.md` (Feature checks table `| Check | Result | What was checked | Evidence |`, Result exactly `PASS` or `FAIL`, no share links or cap values; create it in that format if missing).

- Interface from 05-10: `wakewatch.Watch(ctx context.Context) <-chan wakewatch.Reason` with `Woke = "wake"` and `NetworkChanged = "network"`.
- Wake semantics mirror 05-04 and 05-10: reconnecting with a pending backoff timer → clear it, attempt = 0, redial now; reconnecting with a redial in flight → attempt = 0 only; open → attempt = 0 and send a probe (the existing checkLiveness abandons it after probeGraceMs if pongSeen and visible, and abandonment already dials at once). A system wake is not gated on page visibility for the redial (a hidden window reconnects in the background and is ready when shown); the probe-kill path keeps the 05-04 visibility rule.
- Debounce: RECONNECT.wakeMinGapMs = 5_000 between acted-on wake events, whatever their source (Wails event, timer gap).
- Timer gap: RECONNECT.wakeGapMs = 5_000 on the existing 1 s watchdog tick (wall-clock Date.now()). Chrome throttles hidden tabs to one timer per minute, so a hidden browser tab triggers this about once a minute; the effect is one ping or one early redial, which is harmless.
- Bridge: App.tsx subscribes next to its other EventsOn calls and re-dispatches `new CustomEvent('portty:wake', { detail: reason })` on window; RelayClient never imports the Wails runtime (it also runs in the browser).
- RelayClient never logs a URL (it can carry ?cap=). Existing 05-04 behavior (online / visibilitychange, watchdog, generation counter, stdin gating via onStateChange) is unchanged.
- Go commands use `GOTOOLCHAIN=go1.26.11`. VM: `portty-test` (office, tailnet `portty-vm-office-2`, 100.x.x.N) and `portty-test-2` (home, `portty-vm-home-3`, 100.x.x.N), helpers from ~/.local/share/portty-vm-tools with IPs from `tart ip`; never click on the host. The click helper has no string typing: add a `type <text>` command to a scratchpad copy of click.swift (CGEvent keyboardSetUnicodeString), compile it on the host with swiftc and copy the binary into the VM (05-12 may already have built one).
