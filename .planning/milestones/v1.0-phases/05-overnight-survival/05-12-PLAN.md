## Flagged decisions and assumptions

- Ordered resize (Claude's discretion): applyHostGrid queues the resize behind pending output with `term.write('', cb)`; xterm runs a write callback after that chunk is parsed and before later chunks, so the resize lands exactly between old-width and new-width bytes, and recomputeScale runs right after it. On a first attach nothing is queued, so it simply runs before the replay is parsed.
- In-band reset: resetForFullReplay writes the RIS sequence through the write queue; in xterm.js RIS performs the same full reset as the API call (buffer and scrollback cleared, modes reset), in stream order. The hot-swap source guard (05-04) keeps its intent (addon hot-swaps never discard scrollback) and now allows exactly the onReset helper call and no synchronous reset anywhere.
- Unicode widths: the cross-check activates the Unicode 11 addon as TerminalPanel does by default. If xterm and the Go vt emulator disagree on a glyph's width, record the glyph, and contain the damage (05-08 may already render rows so a disagreement cannot shift later rows); do not weaken the comparison silently.
- Scrollbar (todo: keep the host grid; a guest must not resize the host PTY): stretch the scaled xterm element so its scrollable area spans the pane, for example set the element's width (and height) to the container's inner size divided by the current scale when not in the overflow-x branch; the screen canvas stays cols x cellWidth. Confirm where xterm 6 places its scrollbar (Viewport / SmoothScrollableElement in node_modules/@xterm/xterm) before choosing between inline style and a CSS rule.
- Ordering: 05-09 is a dependency only because both plans use the same two Tart VMs and 05-09 creates the shared VM evidence file `.planning/phases/05-overnight-survival/05-VM-MATRIX.md` (its `## Feature checks` table: `| Check | Result | What was checked | Evidence |`, Result exactly `PASS` or `FAIL`, no share links or cap values). If the file or table is missing, create it in that format.
