<objective>
Make dead connections visible. Two layers (RESEARCH Pattern 1): (1) the servers answer the clients' existing app-level MsgPing with a new MsgPong, which is how a browser (JS cannot see WebSocket control frames) and the CLI (its socket ends at the local proxy, which answers control frames itself) learn the far end is alive; (2) every Go endpoint that owns a long-lived socket to a remote peer sends WebSocket-level pings with a deadline and drops a silent peer: the share server toward its viewers, the viewing daemon's proxy toward its upstream.

Purpose: SHAR-07's "detects a dropped or half-open connection". Today nothing pings, so a half-open socket after a sleep sits forever and a zombie subscriber stays in the host's fan-out. The clients' watchdogs (05-04, 05-06) arm on the first MsgPong.
Output: relay.MsgPong/PongFrame, relay.Heartbeat, pong replies on both servers, heartbeats on the share server and the proxy, tests with shortened intervals.
</objective>

## Flagged decisions and assumptions

- [EDGE-UNCLASSIFIED SHAR-07] The spec-less edge probe could not classify SHAR-07 (status unresolved). Planner-authored edge assumptions pinned here: a silent peer is reaped within PingEvery + PingTimeout (45 s at the defaults); a reading peer survives any number of intervals; a full subscriber queue drops pongs rather than blocking.
- Deviation from RESEARCH Testing Strategy item 3: instead of a TCP "blackhole forwarder", the tests use a peer that stops calling Read. coder/websocket answers pings only inside Read, so the server sees the same signal (no pong) with far less test code.
- No WebSocket-level heartbeat on the local relay (127.0.0.1). Its clients are the app's own webview and the local CLI; when one dies its process closes the TCP socket, and a frozen one is kicked by the existing 256-frame "too slow" rule. CONTEXT [Liveness] says "as needed". The local relay still answers MsgPing with MsgPong so every endpoint speaks the same app-level protocol.
- Intervals are overridable per server instance, not through package globals, so tests can shorten them without data races: unexported WebServer fields (zero means relay.PingEvery / relay.PingTimeout) and API.SetHeartbeatForTest, following the existing SetPeerClientForTest seam.
