## Phase Goal

Sharing is one on/off switch per session: shared means tailnet peers and a tailnet web link at once, always full control, with a clean stop and CLI attach from any terminal. Funnel and read-only links are gone. (ROADMAP Phase 4 goal, verbatim.)

This first plan is the Go-side deletion pass. It removes Funnel, the public-write gate, join codes, QR codes, read-only link features and the one-time share warning from the daemon, webserver, capability package, App bindings, CLI, web pages and the playwright fixture. The share switch itself arrives in 04-02. Plans run sequentially on the main tree (branch gsd/phase-04-one-click-share). Build and tests stay green at the plan boundary. Between this plan and 04-05 the GUI's old share dialog is non-functional at runtime (accepted, RESEARCH Open Question 4); the hand-maintained Wails stubs keep `tsc` and vitest green until 04-05 deletes their callers.

<objective>
Delete Funnel and the public-write gate, join codes and QR codes, read-only link features and the one-time share warning from every Go layer, the web pages and the playwright fixture, pin each removed route with a 404 test, drop go-qrcode from the module, and reconcile TESTING.md.

Purpose: SHAR-05 ("Tailscale Funnel public sharing is removed: risk panel, consent gates, hold-to-confirm, public links, Funnel config and their tests"), SHAR-02 ("The read-only link type and its UI are removed"), ROADMAP SC4, CONTEXT ▸ Cleanup and the no-Tailscale case ("Remove the unused public-write consent-gate state (SetRWGate / isRWGated) with Funnel"; "Remove all Funnel, public-link, risk-panel, hold-to-confirm, read-only link code, UI, settings and tests"), CONTEXT ▸ The Share control ("Join codes, the QR code, and the Open button are removed"), UI-SPEC Decisions Made Here (the one-time share warning banner and its Settings switch are removed).
Output: a smaller daemon and webserver, two removed-route test files, a dashboard without the join form, go.mod without go-qrcode, and an updated TESTING.md.

## Flagged decisions and assumptions

- relay.Subscriber.ReadOnly and the webserver's `HasPerm(claims.Perms, "write")` check stay. They are the capability model's write gate, which the CLAUDE.md security constraint keeps. What goes is every way to *create* or *request* a read-only view (minting "read" caps, `--readonly`, the local readonly query, the badge). The webserver capability tests that dial with a "read" cap stay: they prove the gate.
- issueCapabilitiesForSession and POST /sessions/{id}/capabilities survive this plan in reduced form (one full-control grant, no codes) so the old GUI keeps compiling against the hand-maintained stubs. 04-02 replaces them with the share switch.
- Removing ClearLingeringFunnel means Portty no longer clears Funnel serve config that an earlier build may have left in tailscaled (RESEARCH Runtime State Inventory). Task 1 adds manual item M-77 for both Macs instead of keeping serve-config code.
- Wording rule for everything this plan writes outside `.planning/` (TESTING.md Section 4 rows and Section 5 items, code comments, test names and strings, docs): describe removed features by concept — public internet sharing, the consent UI, code-based access, view-only links, the LAN server, the share reminder — never by the words the 04-06 removal gate (`tests/check-share-removal.sh`) checks.
