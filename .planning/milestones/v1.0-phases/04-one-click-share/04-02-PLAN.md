## Phase Goal

Sharing is one on/off switch per session: shared means tailnet peers and a tailnet web link at once, always full control, with a clean stop and CLI attach from any terminal. Funnel and read-only links are gone. (ROADMAP Phase 4 goal, verbatim.)

This plan builds the switch. The daemon owns one share record per session and the share server's lifetime; the CLI and the App reach it through the same route. 04-03 adds the same-account rule for peers and reason-carrying revocation; 04-04 adds remote attach; 04-05/04-06 put it in the GUI. Plans run sequentially on the main tree; build and tests stay green at the boundary. The old GUI share dialog stays non-functional at runtime until 04-05 (accepted, RESEARCH Open Question 4).

<objective>
Add the daemon share registry with `GET`/`PUT /sessions/{id}/share`, start the share server on the first share and stop it when nothing is shared, add `portty share` / `portty unshare`, remove the boot auto-start and the LAN fallback, replace the old web-server/web-serve/capabilities/disconnect-viewers routes and bindings with GetSessionShare/SetSessionShared, keep shares consistent across exit, kill and key regeneration, and add the vmpreview build seam for the VM.

Purpose: SHAR-01 (one on/off state per session), SHAR-02 (always full control), SHAR-03 (link opens an interactive terminal), SHAR-04 (stop disconnects viewers), ROADMAP SC1-SC3 backend half, CONTEXT ▸ Who can use a share, CONTEXT ▸ Cleanup and the no-Tailscale case (LAN fallback removed; server starts on first share; CLI serve/web start removed; portty share/unshare added), UI-SPEC Decisions Made Here (web server starts on the first share and stops when none is shared; CT disclosure recorded by the first share, also via the CLI).
Output: share.go with tests, cmd_share.go with tests, a slimmer process.go/api.go/server.go, two App bindings, vmpreview files, updated stubs and TESTING.md.

## Flagged decisions and assumptions

- Share records are in memory only (CONTEXT, research OQ1 resolution). A daemon restart ends every session anyway.
- Peers will use the same token as the link (RESEARCH Pattern 1: one token per share). 04-03 exposes it to same-account peers.
- Share-off disconnects web viewers with the existing hub.DisconnectWebViewers in this plan; 04-03 replaces it with a reason-carrying revoke. That is a functionality gap fillable without an architectural change.
- Port 7444 is fixed for the share server. A taken port is an error (`port_in_use`), never a random port, because peers only probe 7444 (RESEARCH Pitfall 6). Port 0 stays allowed for tests, which set it explicitly.
- `portty share/unshare/attach` resolve a session by exact name, then exact ID, then a unique ID prefix (Claude's discretion: session naming collisions). Clashing names print the clash error with 8-character ID prefixes.
- vmpreview is a build tag, not an env var, so no released binary can contain the fake. It binds 127.0.0.1 only. tests/check-brand.sh, which build.yml already runs on every push and PR, gains a check that fails if the tag appears in .github, build.sh or scripts, tracked or untracked; the verify step proves its failing direction with a throwaway probe file.
- Wording rule for everything this plan writes outside `.planning/` (TESTING.md Section 4 rows and Section 5 items, code comments, test names and strings, docs): describe removed features by concept — public internet sharing, the consent UI, code-based access, view-only links, the LAN server, the share reminder — never by the words the 04-06 removal gate (`tests/check-share-removal.sh`) checks. TESTING.md Section 2 history notes are outside the gate and may name them.
- The CT acknowledgement is written by the daemon on the first successful share-on (RESEARCH Pitfall 10); the GUI keeps reading it with HasCTDisclosure.
