# Phase 01 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** This phase mostly removes UI. It adds no new design language. Every token below is LOCKED from the existing AgentHub v4.x design system in `frontend/src/style.css` (`--hub-*` tokens, lines ~4700-4880) and existing component CSS. The rule for executors: **delete removed UI and its CSS, edit copy and status mapping where listed, and add no new colors, fonts, or spacing values.**

New or changed UI surface (complete list):
1. New Session modal reduced to a directory picker plus a read-only shell line
2. Session status reduced to running / exited / errored (tab dots, Hub card status, exit toast)
3. Raw-shell web-share warning: still one-time and re-enableable, now gated on every session (all sessions are shells)
4. Settings → Behavior notification toggle relabeled for bell / OSC 9 notifications, plus the native notification copy
5. Copy fixes where removed concepts appear (agent, file browsing, `@session`, Linux/Windows install rows)

Out of scope (later phases): Hub removal and sidebar (Phase 2), all "AgentHub" → "Portty" text, logos, and paths (Phase 3), Share dialog redesign (Phase 4). Leave "AgentHub" strings in place unless this spec gives replacement copy.

## Interaction Contracts

### 1. New Session modal (`NewSessionModal.tsx`)
- Remove the "Select Agent" list (agent buttons and the selectable Shell button) and the "Extra Arguments" section entirely.
- Order: header → **Working Directory** section → **Shell** section → footer.
- Visual anchor: the accent-filled "Create Session" button is the primary focal point. The Working Directory path (accent text once a directory is chosen) is second. The Shell line is deliberately quiet: muted, non-interactive, with no accent.
- The Working Directory section works as it does today: it pre-fills from the last-used directory (localStorage), "Browse…" opens the native folder picker, and a chosen path is persisted as the new last-used directory.
- The Shell section is a **read-only, non-focusable** line. It reuses the `.new-session-modal__folder-display` box with a mono-font modifier (for example `--mono`, which sets only `font-family: var(--hub-font-mono)`). It has no hover state, no button, and no selection border. The helper text (12px, existing muted modal color #9aa5ce) sits 8px below it. The path is re-fetched via `GetShellPath()` on every open (existing behavior).
- "Create Session" is enabled whenever the modal is open and nothing is being created (there is no selection to make). Clicking it creates the shell session in the shown directory. Keyboard and overlay-click behavior is unchanged.
- Width stays 460px. Height shrinks naturally.

### 2. Session status
- Tab dot: shape and color per the Color table. The `title` and `aria-label` carry "Running" / "Exited" / "Error".
- Hub card status row: the icon and label per the Color table. Remove the "Needs input" badge, the attention bell tied to waiting, and agent chips and badges.
- Hub filter bar: **remove the status pill group** (All / Working / Needs input / Complete / Error / Idle and their counts). Keep the search input and the "New session" button. Phase 2 deletes the Hub, so do not redesign it.
- OSC 9;4 progress (tab underline and tray glyph) is unchanged.

### 3. Raw-shell web-share warning
- The trigger condition drops the shell-only check: it fires on the **first web-share of any session** when the warning is enabled and not yet acknowledged. Replace `isShellCli(session.cli) && …` with the enabled-and-not-warned check alone, because the `cli` field is removed and every session is a shell.
- It is still one-time (the daemon-persisted `warned` flag) and can be re-enabled from the Settings → Session Behavior toggle (existing D-03 re-arm). It must not fire on every share.
- Banner placement and role="alert" are unchanged. Focus moves to "Keep sharing off" (formerly "Cancel") at mount, and Esc triggers it.

### 4. Bell / OSC 9 notifications
- Fires only when the Settings toggle is ON (default OFF) **and** the app window is hidden.
- Trigger: BEL outside OSC strings, or OSC 9 with text (OSC 9;4 progress excluded).
- Rate limit: **at most one notification per session per 30 seconds**. Use a stable per-session notification identifier so a newer notification replaces the older one in Notification Center.
- No in-app visual for bells in this phase. Do not add a tab badge or flash.

### 5. Chat (`@session` removal)
- The mention popover drops the "Agent" section label, the `@session` row, and the divider. Participant rows start at index 0.
- The popover renders only when at least 1 participant matches the filter. With zero matches it does not render (no empty-popover state).
- Typed text containing "@session" is sent as an ordinary chat message and is never written to the PTY.

### 6. File browser removal (no replacement UI)
- Remove the "Browse files" items in the Hub card menu and the tab chevron menu, the file-browser tab type, `RemoteBrowseDNSWarning`, the file-browsing toggles in the Share dialog, and the web-share file panels. Leave no placeholder or "removed" notice.

### 7. Welcome tab
- Remove the "Linux" and "Windows" install rows. Keep the macOS row as is (renamed in Phase 3).

## UI Considerations

| Category | Element(s) | Status | Resolution / Reason |

| error | Session status (tab dot, Hub card, exit toast) | ✅ covered | A non-zero exit renders the errored rounded-square tab dot, "Exited {code}" on the Hub card, and "Exited with error" in the exit toast, and the tab stays open |
