## Flagged decisions and assumptions

- **Depends on 08-01.** Both plans edit hub.go. 08-01 also built `renderScreenLocked`'s row-by-row join, the wrap guard (no join unless `h.modes[7]` is true or unset) and softwrap-replay.json. Read 08-01-SUMMARY.md first.
- **IN-06 placement: refinement of the CONTEXT decision ("emit the mode loop before the screen text ... as well as before the CUP").**
  - **Restores go before the history, not just before the screen text, in a rendered Join replay.** joinLocked today sends `history + CRLF + screen`. xterm.js 6 homes the cursor on `?6h` and on `?6l` (InputHandler setModePrivate/resetModePrivate case 6, quoted in 07-REVIEW WR-08), and every RIS puts 6 in h.modes. So restores placed between the history and the screen text would home the cursor to the top of the viewport, and the screen rows would overwrite the last screen-height history rows still in it.
    - Before the history, right after the viewer's `resetForFullReplay` RIS, the cursor is already home, so the home does no harm.
    - Rendered replays send no DECSTBM, so the region stays the full screen and the final CUP stays absolute under DECOM (unchanged from WR-08).
  - **Autowrap (?7) is the one restore that stays after the text, before the CUP.** It decides how the replayed text lays out:
    - `?7l` first would truncate history lines rendered before a host narrowing instead of wrapping them, and would break 08-01's wrap joins.
    - After the text it behaves as today. Toggling DECAWM moves no cursor in xterm.js or vt, and `pendingWrapLocked` already requires autowrap on, so the pending-wrap re-print stays after it.
    - 08-01's join guard stays: it is conservative and harmless.
  - **Resulting byte order:**
    - `renderScreenLocked()` (RenderSnapshot and the rebuild seed): restores without 7, then the alt prefix when in the alt screen, then the screen rows, then `?7`, then the CUP, then the pending-wrap re-print.
    - joinLocked: restores without 7, then the history, then the boundary separator (08-01), then the same body.
    - Split the mode loop into a helper (for example `modeRestoresLocked(skip7 bool)`) and the rest into a body helper, so the two callers cannot drift.
    - Excluded modes are unchanged: 47, 1047, 1048, 1049, 2048, 2026.
  - **vt side (the seed):** vt's `setMode` moves the cursor only for 1048/1049/47, all excluded (vt csi_mode.go:71-107). `?6h` before the seed's text is harmless: the new emulator has no region yet, so CR/LF and the seed's own CUP stay absolute. The rebuild's own `?6l ... ?6h` block runs after the seed, as today.
- **IN-06's original symptom (a ?2027 grapheme row wrapping the seed) may already pass.** vt's flushGrapheme always uses GraphemeWidth (vt utf8.go:30-33), and only `WidthMethod()` reads ModeUnicodeCore (emulator.go:164). The ?2027 reference subtest is a guard. The order assertions and the xterm.js history case are the real proof.
- **IN-08 scope (plan check B-1): rendered replays and the alt-exit rebuild, as REQUIREMENTS DEBT-03 and ROADMAP SC2 state.** Viewers get the hub-tracked state (Task 2). The rebuild gets exact probes and resyncs the tracker from them (Task 3).
- **vt stores OSC 8 params and URI swapped (found at revision time; scratch probe on the pinned vt).**
  - `handleHyperlink` (vt osc.go:127-136) splits the payload `8;params;uri` and stores `parts[1]` (the params) in `Link.URL` and `parts[2]` (the URI) in `Link.Params`. uv's renderLine then emits `SetHyperlink(Link.URL, Link.Params)`, and `ansi.SetHyperlink(uri, params...)` writes `ESC ] 8 ; params ; uri BEL`.
  - So a rendered row reaches viewers with the two fields swapped. Input `ESC]8;id=7;https://example.invalid/x ST` + `LINK` renders as `ESC]8;https://example.invalid/x;id=7 BEL`. For the common link without params, xterm.js sees an empty URI, which closes the link, so every link in a rendered replay is lost today.
  - The same swap makes the rebuild seed store the fields the other way round from the reference. The extended fuzz (Task 3) would catch that as a mismatch once links cover printed text.
  - **Fix:** `fixRenderedLinks(s string) string` swaps the two fields of every `ESC ] 8 ; a ; b BEL` in a vt-rendered string. vt only stores a link whose payload splits into exactly three parts, so neither field contains `;`, and renderLine always ends the sequence with BEL. That makes the match exact.
    - Apply it wherever the hub stores or emits a rendered row: renderScreenLocked's rows, drainScrollbackLocked's history lines and the resize push.
    - Wrap-set keys (08-01) stay on the raw `Line.Render()` at detection and at lookup, so they still match.
    - Comment it with the osc.go reference and the measured example.
- **Hub-side tracker for viewers (Task 2): designations and the link through registered handlers, like the DEC-mode tracking in newLiveEmulator; GL through a byte scan.**
  - New file internal/relay/charstate.go holds an emuMu-guarded `charState` on the Hub: G0 and G1 designation (the final byte; `B` is the default), GL is G1, the open link (params and URI in standard order) and the persisted scan state.
  - **Designations:** in newLiveEmulator, register ESC handlers for `ansi.Command(0, '(', f)` and `ansi.Command(0, ')', f)` for f in `0`, `B` and `A` (the same commands vt registers, handlers.go:381-396). Each records the final byte and returns false, so vt's own handler still runs (vt calls registered handlers last-registered first, handlers.go:196-208). Charsets are emulator-wide in vt, so there is one state for both screens.
  - **Link:** register an OSC 8 handler that parses the payload the way vt does (exactly three `;` parts, or ignored like vt). It stores params and URI in the standard order, treats an empty URI as closed, and returns false.
  - **GL:** SO and SI are C0 controls, and vt's control handlers cannot be hooked (`registerCcHandler` is unexported, handlers.go:94, :275-284). So recordFrameLocked scans the bytes it feeds, in order, with a state machine persisted on the Hub across reads. It uses incompleteTail's states (ground, ESC, CSI, OSC, ST-terminated string, string-ESC; CAN and SUB go to ground).
    - 0x0E sets GL = G1 and 0x0F sets GL = G0 in ground, ESC or CSI state, where vt and xterm.js execute C0. They are ignored inside OSC/DCS/SOS/PM/APC strings.
    - `ESC c` resets GL in byte order. The designations and the link are reset by the existing RIS handler, which runs in order inside the write, so a RIS after an SO in the same read leaves everything at the defaults.
  - **Mirror vt, not xterm:** vt has no DECSTR handler and keeps no charset in its saved cursor (cursor.go:16-25), so the tracker ignores both.
  - **Emission:** the body helper (Task 1) ends, after the CUP and the pending-wrap re-print, with the tracker's suffix:
    - `ESC ( 0` or `ESC ( A` when G0 is not `B`;
    - `ESC ) 0` or `ESC ) A` when G1 is not `B`;
    - `SO` when GL is G1;
    - `ansi.SetHyperlink(uri, params)` when a link is open.
    - The re-printed pending-wrap cell is already a UTF-8 glyph, so the designations after it cannot change it.
    - The same suffix ends the rebuild seed. The rebuild's own probe-based re-emit comes after it and is authoritative.
  - **Residuals (`shortcut:` comment in charstate.go):**
    - A link that DECRC or an alt-screen switch restores in vt, which keeps the link in each screen's cursor, is not seen until the next alt-exit rebuild resyncs the tracker from its probes.
    - G2/G3, LS2/LS3, single shifts and GR are not tracked.
- **IN-08 rebuild probes (Task 3; CONTEXT: "probe the G1 designation and the SO state, and re-emit them; track an open OSC 8 link via a vt callback or a probe").**
  - After today's current-pen probe `q` (which prints through whatever GL is), print `SI q` and then `SO q` into the old emulator, which is discarded anyway, copying each cell at the position it printed to (CellAt points into the buffer). These are c0 and c1.
    - G0 is line drawing iff c0 is `─`. G1 is line drawing iff c1 is `─`.
    - GL is G1 iff the current probe cell equals c1's content and c0 differs from c1.
    - Re-emit after the seed: `ESC ( 0` if G0 is line drawing, `ESC ) 0` if G1 is, then `SO` if GL is G1. This replaces today's single `ESC ( 0` test.
  - **OSC 8:** vt prints each cell with the cursor's link (handleGrapheme sets `Link: e.scr.cursorLink()`, utf8.go:46-51), so the probe cells already carry it, with vt's swapped fields.
    - The current link is the current-pen probe cell's `Link`. Re-open it after the pen, last, with the fields un-swapped: `ansi.SetHyperlink(cell.Link.Params, cell.Link.URL)`.
    - The saved cursor's link is `savedCell.Link`. Emit it the same way before the `ESC 7` in the saved-cursor block, then reset it with `ansi.ResetHyperlink()` before the current link is re-opened. Add a non-empty saved link to the `keepSaved` condition.
    - The seed's rows already carry their links (through fixRenderedLinks), so only the open link needs re-opening.
  - **Resync:** after the probes, set the tracker's G0, G1, GL and link from the probed values (G0/G1 line drawing or ASCII), so any tracker drift ends at every alt exit.
  - **Probe ordering constraint:** the SI/SO probes run after the current-pen probe (so it still reads the real GL) and before `ESC 8` (vt's Cursor holds no charset, so DECRC does not undo them). The saved-pen probe then prints with GL = G1. That is fine: only its Style and Link are read.
  - **Still lost, keep in the `shortcut:` list:** tab stops, G2/G3 and single shifts, the UK national set, the saved cursor's visibility, and vt's zero-width cells. Remove SO/G1 and the OSC 8 links from the list.
