# Phase 18 VM checks (self-installing updates)

- **Build:** rig builds of the 18-08 tree on top of `32b69fc3` (the 18-01 tracer, no later code plan) with `-tags "wailsassets vmpreview"`, ad-hoc signed by Wails; `-ldflags "-X main.Version=v1.8.0"` and `v1.8.1`, with `wails.json` productVersion patched per build and restored after (the rig's `build` step).
- **18-03 rows (R2-A to R2-D, A9-fix):** rig builds of the 18-03 tree at `b968a6ef` (rollback, relaunch retry, consumeInstallResult and the VM-only fault hooks in, on top of 18-10's whole-bundle installer copy), same tags and `-ldflags`, N = 1.8.0 and N+1 = 1.8.1, ad-hoc signed, `verify-mode` `adhoc`, un-granted (no App Management grant was made at any point; R1-lite and P2a showed an ad-hoc swap needs none). The Developer ID evidence for this installer is P2d-bundle. Each row starts from a fresh `deploy-n` of N. Per row three VM-side pollers ran from 2 s before the click: a 0.4 s process poller (GUI pids, daemon pids, the installer's pid, installed version, daemon `/health` version; finer than the plan's 2 s `state` poll and sampling the same fields), a 1 s window lister and a ~1 s `axdump app.portty.Portty` grep for the banner, `Restart`, `background service`, `AXDialog` and `AXSheet`. Their transitions are kept in `evidence/ROW-timeline.log`. The fault file is `~/p18/fault`, written before the click and removed after the row.
- **VM:** Tart `portty-test` (the office VM), macOS 27.2 (build 26B123), arm64, user `admin`. Already running; never stopped or recreated by this plan.
- **Method:** `.planning/phases/18-self-installing-updates/rig/p18-rig.sh` (`build`, `deploy-n`, `dmg`, `feed`, `state ROW`, `quit-gui`, `clean`). The fake feed is `cmd/fakegh` on `127.0.0.1:8788` inside the VM; the `vmpreview` build's `$HOME/p18/verify-mode` file (`adhoc`) fakes only the codesign and spctl answers, every other tool runs for real. Sessions are made with the installed CLI (`portty new`, `portty rename`) and typed into through the 09 expect driver (`cli.exp`, pointed at `/Applications/Portty.app`); the second session runs `vim -u NONE -N -S ~/p18/vtick.vim` (a timer appends a `VTICK n` line every second). A VM-side poller samples the GUI pids, the daemon `/health` version and the installed version every 0.4 s, and a second poller lists the on-screen windows (CGWindowList through `osascript -l JavaScript`) every second. The GUI is read with `~/ptest/axdump`, clicks use `~/ptest/click`.
- **Host safety:** every `rm`, `hdiutil`, `ditto`, `open` and DMG creation ran inside the VM through `vm.sh`. The host built, wrote evidence files and sent tar streams over ssh. Nothing on the host was mounted, opened or copied from `~/Downloads` or `/Applications`; the host's `/Applications/Portty.app` was never touched; no host tailscaled or 100.x address was contacted.
- **Evidence:** `evidence/ROW.state` files are written verbatim by `p18-rig.sh state ROW` (VM home shown as `~`, no hand edits). Header line `p18-state row=ROW vm_utc=TIME`.
