## Flagged decisions and assumptions

- **O1 (asset name), user-confirmed, no checkpoint:** user answer "portty-vX.Y.Z-darwin-arm64.dmg (Recommended)", 2026-11-25, recorded under [Assets] in 18-CONTEXT.md and in 18-RESEARCH.md O1. The name is still a one-way door (installed builds search for exactly these names), but the human has settled it, so Task 2 keeps its one-way rating and implements the two-name list directly. This also removes the earlier checkpoint option that would have dropped the second name against the [Assets] decision.
- **Unreadable skip record (checker round 2, UPD-07; CLAUDE.md forbids silent fallbacks):** 18-03's `skippedVersion()` returns `("", nil)` only when the record does not exist and returns an error for any other read failure or a content that is not a valid version. Check treats that error as "the failed version is unknown": no automatic offer of any version while it lasts, one log line per check naming the failure (no path), and a manual check still offers the latest version. Cost: automatic offers pause until the record is readable again or the user checks by hand; this is preferred over re-offering a version that may just have failed on an unattended Mac.
- **P7:** Task 1 reads the P7 row in 18-VM-CHECKS.md (written by 18-08) and uses the recorded Identifier value for AppIdentifier; app.portty.Portty is the expected value (A8).
- **P8:** if the P8 row is CONTRADICTED (staging into a new `.app` directory refused), CopyApp stages into `STAGINGDIR/Portty.staged` (no .app extension) and Swap is unchanged (it exchanges whatever path it is given); 18-03, an earlier wave, already widened ReadJob's staged-basename check to `Portty.staged` from the same verdict. If P8 is CONFIRMED or OBSERVED, staging stays `Portty.app`.
- **A2 (EPERM means App Management):** assumption. EPERM from mkdir, ditto output "Operation not permitted" or rename while unix.Access says the parent is writable maps to the App Management text; EACCES maps to the permission text. A wrong mapping only changes the wording; both reveal.
- **A13 (newer-macOS build):** the LSMinimumSystemVersion check plus the smoke run keep a build the Mac cannot run from ever being swapped in.
- **Failed version not re-offered (checker verification_derivation):** 18-03's ShowResult records the failed or rolled-back version in the update cache folder even when the DMG is gone, and this plan's Check reads it. The mechanism is smaller than a new state: an automatic check of that exact version keeps the failure status the relaunched GUI set (revealed with an Error) or, after a restart or without the DMG, settles on current with no Latest, so the banner, the tray item and the notification all stay quiet; a newer version is offered as usual. A manual check (ManualCheck context) bypasses the skip so the user can still retry on purpose. The tray rule for a revealed status with an Error is 18-04's. This needs 18-03's outcome.go, so this plan now runs after 18-03 (wave 4, alongside 18-05) instead of beside it.
- This plan does not use the VM (its failure rows run in 18-07), so it never contends with 18-05 for portty-test.
- Test helper names added here start with `ai` (appinstall) so they never collide with the `rb` helpers of 18-03 and 18-05 in the same package.
