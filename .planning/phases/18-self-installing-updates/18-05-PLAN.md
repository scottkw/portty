Purpose: no hidden tens-of-MB folders in /Applications, no dangling mounts, the user can recover the old app from the Trash.

## Flagged decisions and assumptions

- **Plan-check residual (final round, force-proceeded 2026-11-25, W1):** Task 2's P3, R1-trash and S1 PASS rows must each cite an `evidence/ROW.state` capture (same rule as 18-07); S1 is not re-run on the final build, so the closure record labels it pre-final evidence unless re-run.
- **O4 (Trash fails), resolved without an irreversible step:** the research proposed deleting the aside copy after a day; that would break the locked "Trash, not deleted" rule. Instead the copy stays aside and the next sweep retries the Trash. Cost: tens of MB remain if the Trash keeps refusing; logged each time. No checkpoint needed because nothing irreversible is introduced. 18-RESEARCH.md O4 is marked RESOLVED with this choice.
- **A4 (trashItem without AppKit):** confirmed or refuted by P3 here. If P3 shows a permission prompt or a refusal, the copy stays aside (the fallback above) and the row records it; the plan does not switch to a Finder AppleEvent (that prompts for Automation on an unattended Mac).
- **Mount sweep has no age limit:** no staging runs in a process that is just starting, and mover mode never sweeps, so detaching any mnt-* under the update cache at startup cannot interrupt a live stage.
- **A5 (DMG in ~/Downloads):** exercised in 18-06's mover rows, where the installer trashes the downloaded DMG.
- **Run folders hold a whole app copy (revision 2026-11-25, 18-10):** the installer now runs from `update/run-*/Portty.app`, a ditto copy of the running bundle that Portty made itself, so an installer killed before its final cleanup leaves tens of MB behind. The sweep's existing run-dir rule removes it with RemoveAll once older than 1 hour; it is Portty's private copy in the config dir, not the user's app, so the Trash rule does not apply and trashItemFunc is never called for it. The 1 hour floor also keeps the sweep off a live installer's run dir: an installer lives at most QuitWait + HealthTimeout + 2 minutes (its context), and its run dir's mtime is the time its last entry (the started marker) was made.
