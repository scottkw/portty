- **Split (checker round 2, scope_sanity):** the old single matrix task (about twelve scenarios plus tuning, estimate 95000) is now two tasks here, update path and rollback (Task 1) and the failure matrix (Task 2); the mover matrix and TESTING.md moved to 18-09, which runs next on the same build.
- **Captures decide completion (checker round 2):** a row's verdict text is executor-written, so every PASS row here cites `evidence/ROW.state`, the rig's raw `state ROW` output taken right after the row, and each task's verify checks the capture exists, carries the rig's header line and shows the outcome the row claims (one GUI; the expected installed version where the row's target is /Applications/Portty.app).
- **R2 windows (checker round 2):** W = this build's R1 click-to-new-GUI seconds + HealthTimeout + StopWait + KillWait + 30 s, written in the row before the click; each row records its measured click-to-rollback seconds (method in 18-03 Task 3).
- **Grant rule (from 18-08):** if 18-08 recorded R1-lite-granted (App Management refused the ad-hoc swap), the ad-hoc rows here grant it at their start, say "granted (rig-only)" in their evidence, and are not cited for "no dialog" on an unattended Mac; R3 runs with the grant revoked first, so its "no dialog" is un-granted evidence.
- **R3 runs for real:** 18-08's identity check found a Developer ID identity for S2K7P43927 on this host at planning time; R3 may be BLOCKED only if 18-08's P2d row says identity=none.
- **History across the update (checker verification_derivation, ROADMAP SC1):** R1 seeds 300 numbered HIST lines in session 1 before the click and, after the update, counts them in a fresh viewer's replay with SOH stripped, the 09-VM-CHECKS V-01 method.
- **App Management and copy failure in the VM (checker requirement_coverage, ROADMAP SC4):** a real App Management denial cannot be forced on ad-hoc rig builds, so F5 forces the same errno (EPERM) at both points where a denial can surface: the installer's swap (`chflags uchg` on the bundle, the R2-C mechanism) and the GUI's staging folder (`chflags uchg` on /Applications in the VM). F7 forces a copy failure with an unreadable file inside the N+1 app. The residual risk, the genuine Developer-ID App Management denial, is recorded in M-168 and covered by P2d or R3.
