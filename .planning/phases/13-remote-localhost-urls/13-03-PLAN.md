## Phase 13 interface contract (identical in 13-02, 13-03, 13-04, 13-05)

**Host share server** (tailnet listener, HTTPS, HTTP/1.1 only; built by this plan):
- Grant: `POST /api/peer/sessions/{id}/ports`. Request headers `Content-Type: application/json` and `X-Portty-Cap: <session capability>`; body at most 1 KiB, `{"port": <int>}`. Success 200 `{"token": "<port token>"}` with `Content-Type: application/json` and `Cache-Control: no-store`.
- Proxy: methods GET (covers HEAD), POST, PUT, PATCH, DELETE, OPTIONS on `/api/peer/sessions/{id}/ports/{port}`. Request headers `X-Portty-Cap`, `X-Portty-Port-Token`, `X-Portty-Target` (the browser request's origin-form target, starting with `/`, at most 8192 bytes). The response is the dev server's, with every `X-Portty*` header removed by the host.
- Every host refusal on both routes: status 403, header `X-Portty: 1`, body `forbidden` plus newline, identical bytes whatever the cause. A local tailscaled fault on the host: 503 with no marker. A dev server not answering on the host's loopback: 502 with `X-Portty: 1` and a fixed body.
- An old host (API 4 or lower) answers a POST to the grant path with 405 (`Allow: GET, HEAD`) and no `X-Portty` header.

**Viewing daemon** (unix socket only; built by 13-02): `POST /peers/ports` with `PortOpenRequest{sessionId, url, consent}`; 200 `PortOpenResponse{status "open"|"consent", url, host, port}`; errors `bad_url` 400, `no_cap` 404, `refused` 403, `host_outdated` 409, `port_in_use` 409, `unreachable` 502; `daemon_outdated` for the client and binding only.

**App binding** (13-04 Go, 13-05 TypeScript stub): `OpenRemotePort(sessionID, rawURL, consent) RemotePortResult{status, url, host, port, errorCode}`; never throws.

**Classifier**: frontend/src/lib/__tests__/fixtures/localhost-url.json (13-02) pins Go and TypeScript.

## Flagged decisions and assumptions

- **Check order (RESEARCH "Token design"; CONTEXT "Security contract").** Grant: requireSameUser (existing wrapper: 403 plus marker for another user or no peer, 503 without marker for a local tailscaled fault) → JSON content type → body at most 1 KiB decodes to an integer port in 1..65535 → `verifyCapabilityToken(r.Header.Get("X-Portty-Cap"), id)` succeeds and `capability.HasPerm(claims.Perms, "write")` → `!ws.portDenied(port)` → `ws.manager.Get(id)` exists and `hub.PortPrinted(port)` → mint `capability.SignPort(PortClaims{SID: id, Port: port, IAT: now, GrantID: claims.GrantID, Kind: capability.PortTokenKind, V: 1}, ws.currentSigningKey())`. Proxy: requireSameUser → `{port}` is a decimal 1..65535 with no leading zero → capability as for the grant → `capability.VerifyPort(r.Header.Get("X-Portty-Port-Token"), key)` with `SID == id`, `Port == {port}`, `GrantID == cap claims GrantID`, grant active → `!portDenied` → target non-empty, at most 8192 bytes, starts with `/`, parses with `url.ParseRequestURI` → revoke-bound context → proxy. No dial, log of the target, or allocation proportional to the body happens before the last check passes.
- **Identical refusals.** One `refusePort(w)` that writes exactly what `refuseOtherUser` writes (403, `X-Portty: 1`, `http.Error` body `forbidden`). Every refusal on both routes goes through it; the only other statuses are the wrapper's 503 and the upstream 502.
- **Deny list (CONTEXT "Scope and failures"; RESEARCH "Deny list").** `portDenied(port)`: 0, the port of the share server's own listener (`ws.Addr()`), `tailnet.DefaultProbePort`, and every port passed to `SetDeniedPorts(ports ...int)` (set once before Start; the daemon passes its relay port, because the relay accepts `http://localhost:<its port>` Origins and a proxied request would satisfy that check). No extra list of well-known ports (CONTEXT "Post-research refinements": recorded as a residual risk in 13-06).
- **Host-side reverse proxy (RESEARCH Pattern 1; CONTEXT "Decided autonomously", refined).** `httputil.ReverseProxy` with `Rewrite` (which strips inbound `Forwarded` and `X-Forwarded-*`): URL `http://localhost:<P>` (the dialer ignores the host), Path, RawPath and RawQuery copied from the parsed target, outbound Host `localhost:<P>`, every outbound header whose canonical name starts with `X-Portty` deleted, and Origin set to `http://localhost:<P>` only when it is exactly `http://127.0.0.1:<P>`. **Refinement of the autonomous "Origin on upgrades" choice:** a blanket rewrite would turn a cross-site page's WebSocket into a same-origin one at the dev server, defeating the dev server's own Origin check; the browser's Origin for the forward is already `http://localhost:<P>`, so only the typed-127.0.0.1 case needs it (RESEARCH Finding 2, "Typed 127.0.0.1"). No body or cookie rewriting. `FlushInterval: -1`. `ModifyResponse` deletes every `X-Portty*` header the dev server sent (so a dev server cannot forge the marker). `ErrorHandler`: 502, `X-Portty: 1`, fixed body `nothing is answering` plus newline, one log line `portproxy: upstream session=<id8> port=<P> outcome=nothing-answering`, never the dial error text. `ErrorLog` discards. Transport: `DialContext` ignores the address and calls `ws.dialLoopback(ctx, port)`; `DisableCompression: true`; `ForceAttemptHTTP2` false; `MaxIdleConnsPerHost: 8`; `IdleConnTimeout: 30 * time.Second`; no response-header timeout.
- **dialLoopback.** `[::1]:P` then `127.0.0.1:P`, each with a 3 s timeout, never any other address; a test-only `SetPortDialerForTest(func(ctx context.Context, port int) (net.Conn, error))` replaces it (the cross-daemon test runs both Macs on one machine, so the browser-facing port N and the dev server's real port differ).
- **Revoke-bound context (RESEARCH Pattern 2; CONTEXT "Decided autonomously").** Take `ws.revokeSignal(id)`, re-check `isGrantActive`, then cancel the request context when that channel closes (ClearGrants: share off, session exit, key regeneration's re-mint) or when the new `stopCh` closes (closed once by `Stop`, which handoff and shutdown call without ClearGrants). `ReverseProxy` closes the upstream and the hijacked connection when the request context ends. 13-06 pins this for WebSocket and SSE.
- **Placement.** The routes register next to `POST /api/peer/sessions/{id}/cap`, behind `ws.requireSameUser`, and are not wrapped in the share page's CSP middleware or the marker middleware (the proxied app's own CSP must reach the browser untouched). Per-method registration, because a method-less pattern panics against the existing `GET /` (RESEARCH Pitfall 3).
- **Logging.** Grant: one line `portproxy: grant session=<relay.DiagID(id)> port=<P> outcome=granted|refused`. Proxy: nothing per request except the upstream failure line. Never a target, capability, token or peer address.
- **Reversibility.** Route paths, header names, the 403/502 marker rules and the grant JSON are the one-way cross-Mac contract tied to API 5 (CONTEXT "Proxy wire contract"/"Security contract", human-settled; exact names delegated to the planner before API 5 ships). The Origin refinement is host-internal and reversible. No new checkpoint.
