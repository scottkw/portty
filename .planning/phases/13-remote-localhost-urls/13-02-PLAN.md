## Phase 13 interface contract (identical in 13-02, 13-03, 13-04, 13-05)

**Host share server** (tailnet listener, HTTPS, HTTP/1.1 only; built by 13-03):
- Grant: `POST /api/peer/sessions/{id}/ports`. Request headers `Content-Type: application/json` and `X-Portty-Cap: <session capability>`; body at most 1 KiB, `{"port": <int>}`. Success 200 `{"token": "<port token>"}` with `Content-Type: application/json` and `Cache-Control: no-store`.
- Proxy: methods GET (covers HEAD), POST, PUT, PATCH, DELETE, OPTIONS on `/api/peer/sessions/{id}/ports/{port}`. Request headers `X-Portty-Cap`, `X-Portty-Port-Token`, `X-Portty-Target` (the browser request's origin-form target, starting with `/`, at most 8192 bytes). The response is the dev server's, with every `X-Portty*` header removed by the host.
- Every host refusal on both routes: status 403, header `X-Portty: 1`, body `forbidden` plus newline, identical bytes whatever the cause. A local tailscaled fault on the host: 503 with no marker. A dev server not answering on the host's loopback: 502 with `X-Portty: 1` and a fixed body.
- An old host (API 4 or lower) answers a POST to the grant path with 405 (`Allow: GET, HEAD`) and no `X-Portty` header.

**Viewing daemon** (unix socket only, never the loopback relay port; built by this plan):
- `POST /peers/ports`, body `PortOpenRequest{SessionID "sessionId", URL "url", Consent "consent"}`.
- 200 `PortOpenResponse{Status "status", URL "url,omitempty", Host "host", Port "port"}` where Status is `PortStatusOpen` (`open`, URL set to `http://localhost:<P><rest>`) or `PortStatusConsent` (`consent`, nothing bound). Host is the MagicDNS short label of the session's base URL host (`magicDNSLabel`), the Mac the daemon will contact.
- Errors: `PortOpenErrorResponse{Error "error"}` with `PortErrBadURL` `bad_url` (400), `PortErrNoCap` `no_cap` (404), `PortErrRefused` `refused` (403), `PortErrHostOutdated` `host_outdated` (409), `PortErrPortInUse` `port_in_use` (409), `PortErrUnreachable` `unreachable` (502). `PortErrDaemonOutdated` `daemon_outdated` is defined here for the client and binding (13-04); this route never sends it.

**App binding** (13-04 Go, 13-05 TypeScript stub): `OpenRemotePort(sessionID string, rawURL string, consent bool) RemotePortResult` with JSON fields `status`, `url`, `host`, `port`, `errorCode`; never throws; `daemon_outdated` when the GUI's own daemon reports an API below `PortProxyAPI` (5) or lacks the route.

**Classifier** (Go `classifyLoopbackURL` here, TypeScript `classifyLoopbackUrl` in 13-05, both pinned by frontend/src/lib/__tests__/fixtures/localhost-url.json):
1. Trim trailing characters while the last one is one of `] } > , ; . ' "`, or is `)` while the string holds fewer `(` than `)`.
2. Match `http://` + host + `:` + port + rest, host exactly one of `localhost`, `127.0.0.1`, `[::1]`, `0.0.0.0`, `[::]` (lower case, no folding); port 1 to 5 digits, no leading zero, 1..65535; rest empty or starting with `/`, `?` or `#`, and holding no whitespace or control character.
3. Result: port and rest. The opened URL is `http://localhost:<port>` followed by rest, or `/` when rest is empty.

## Flagged decisions and assumptions

- **Request flow of `handlePortOpen`, in order:** decode (8 KiB cap) → classify (bad_url) → `a.remoteCaps.Get(sid)` (no_cap) → grant from the host through `a.peerClient(fqdn, ip)` with `X-Portty-Cap` and `{"port":P}` (refused / host_outdated / unreachable mapping above) → if a forward already holds P: same Mac (case-insensitive hostname) updates its session and token and answers open; another Mac answers port_in_use → else dial-probe (port_in_use) → if no approval for (hostname, P) and not consent: answer consent → record the approval when consent → bind both loopbacks (port_in_use) → start the forward → open. The grant runs before consent on purpose: the sheet is never shown for a port the host would refuse (RESEARCH system diagram). A second click on an open forward re-grants, so a re-share's new token is picked up.
- **Probe then bind (RESEARCH Pattern 3; CONTEXT "Post-research refinements").** Dial `127.0.0.1:P` and `[::1]:P` with a 500 ms timeout each: connected means taken; ECONNREFUSED means free for that family; EADDRNOTAVAIL, ENETUNREACH or EAFNOSUPPORT are tolerated for `[::1]` only; anything else is taken (fail closed). Then `net.Listen("tcp4", "127.0.0.1:P")` and `net.Listen("tcp6", "[::1]:P")` with default options (EADDRNOTAVAIL on the second is tolerated); EADDRINUSE on either closes whatever opened and answers port_in_use. A strict `SO_REUSEADDR=0` bind is not used (it fails for about 30 s after the forward's own connections close; RESEARCH Finding 1).
- **Host check (CONTEXT "Viewing-side listener"; RESEARCH Pattern 4).** A pure `forwardHostAllowed(host string, port int) bool`: exactly `localhost:P` or `127.0.0.1:P`; bare `localhost` and `127.0.0.1` only when P is 80; `[::1]:P` is not accepted (the browser always opens `localhost`).
- **Cross-site hardening (planner discretion, reversible).** Refuse a request whose `Sec-Fetch-Site` is `cross-site` unless its `Sec-Fetch-Mode` is `navigate`; requests without the header pass. Reason: a page on another site would otherwise drive the remote dev server through the forward (no-cors requests, WebSocket hijacking), which the remote dev server's own same-origin checks cannot see once Host and Origin look local. OAuth callbacks are cross-site navigations and still pass. Recorded in the security review (13-06).
- **Hop-1 proxy (RESEARCH "Viewing-side request rewrite").** `httputil.ReverseProxy` with `Rewrite`: delete every inbound header whose canonical name starts with `X-Portty`, then set the URL to `https://<fqdn>`, path `/api/peer/sessions/<url.PathEscape(sid)>/ports/<P>` with empty RawPath and RawQuery, `X-Portty-Target` to `pr.In.URL.RequestURI()`, `X-Portty-Cap` to the capability read from `a.remoteCaps.Get(sid)` at request time (a peer-tab redial refreshes it), `X-Portty-Port-Token` to the forward's token, and an empty outbound Host. `FlushInterval: -1`. `ModifyResponse`: a 403 with `X-Portty` is "stopped"; a 502 with `X-Portty` is "nothing answering"; otherwise delete every `X-Portty*` response header and pass the response through untouched (status, body, cookies, the dev server's own CSP, 101 upgrades). `ErrorHandler`: stopped and ECONNREFUSED give the stopped page and close the forward and its approval; nothing-answering gives its page and keeps the forward; any other transport error gives the "Couldn't reach" page and keeps the forward. `ErrorLog` discards.
- **Transport (RESEARCH Finding 3).** `peerTransport(fqdn, addr)` (extracted from `peerHTTPClient`, behaviour unchanged for its callers) cloned with `DisableCompression: true`, `TLSHandshakeTimeout: 10 * time.Second`, `IdleConnTimeout: 30 * time.Second`, `MaxIdleConnsPerHost: 8`, no `ResponseHeaderTimeout`, no total timeout, `ForceAttemptHTTP2` false. In tests, a clone of `peerClientForTest.Transport`; in a test binary with no test client, a transport whose every dial fails with `tailnet.ErrLiveTailnetInTest` (the WR-07 rule in `a.peerClient`).
- **Error pages (CONTEXT "Scope and failures").** Status 502, `Content-Type: text/html; charset=utf-8`, `Content-Security-Policy: default-src 'none'`, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`. Fixed copy with the host label HTML-escaped and the numeric port, nothing from the request:
  - stopped: title and heading `{host} stopped sharing`; paragraph `Pages from {host}'s port {port} are closed. Click the link in Portty again once {host} shares the session.`
  - nothing answering: heading `Nothing is answering on {host}'s port {port}`; paragraph `Start the server on {host}, then reload this page.`
  - unreachable: heading `Couldn't reach {host}`; paragraph `Check that both Macs are on your tailnet, then reload this page.`
  The forward's own Host or cross-site refusal is 403 `forbidden` plus newline in text/plain.
- **Lifetimes (CONTEXT "Consent", "Decided autonomously").** Approvals and forwards live in memory in `PortForwards` on the API. A forward closes (listeners closed at once, `http.Server.Shutdown` with a 2 s bound in a goroutine, then `Close`) when the host refuses it or its share port refuses connections (the approval for that (Mac, P) is dropped too), on `API.Stop`, and on a handoff (`closeListenerCopies`); the next click after a handoff asks again. Nothing is written to disk.
- **Logging.** One line per outcome, `port forward: session=<relay.DiagID(sid)> port=<P> outcome=<code>` (`open`, `consent`, `refused`, `host-outdated`, `unreachable`, `port-in-use`, `no-cap`, `bad-url`, `stopped`, `nothing-answering`, `closed`). Never a request target (Vite's HMR URL carries `?token=`), a capability, a port token or a host URL.
