- **R-1 is one-way and settled** (user "Accept all", 2026-11-25), so Task 2 keeps `rating="one-way"` with no checkpoint. Its precondition is Phase 18's 18-02 (`DMGAssetNames` in internal/updater/update.go), which the orchestrator requires before the pipeline publishes the arm64 name as an install path. The check is Task 2's hard first step: if 18-02 has not landed, Task 1 still lands, and Task 2 edits nothing and returns "blocked on Phase 18 plan 18-02" (no hard-coded name list as a stand-in).
- **app_update_release_test.go is out of this phase's hands (CONTEXT scope item "app_update_release_test.go ... where they assert darwin/universal"):** the file belongs to Phase 18 (app_update*.go is Phase 18-owned on this branch), and it asserts no build target. Its only universal-name use is a download-URL allowlist example (lines 23-24), which still holds because the universal name is still published (18.1-RESEARCH Gap 3). So it needs no edit; this plan leaves it alone.
- **SC2 rehearsal (checker revision 1):** Task 2's verify runs release.yml's own "Create and sign DMG" body, pulled from the YAML, in a mktemp directory holding a copy of the bundle signed with the host Developer ID. It never touches ~/Downloads or /Applications and never notarizes. This proves the loop, the copy and the identifier-per-name signing on real codesign before any tag.
- **Keep step names; loop inside each step** (18.1-RESEARCH Gap 3 "Test coupling"): TestReleaseWorkflow_NotarizesAndStaplesDMG checks step order and the `"$DMG"` literals, and `step()` splits on "- name: ", so no step body may contain that text.
- **Create once, copy, then sign each** (18.1-RESEARCH correction to Pattern 7): no intermediate image file exists, so the upload glob and `sha256sum *.dmg` can only see the published names. Each DMG gets its own notarization because its identifier changes its signature (A3).
- **Release body inline, not body_path:** the publish job has no checkout (18.1-RESEARCH Gap 6). The line is true of every release this pipeline builds; Phase 23 writes the v2.0 text below it. generate_release_notes is not added.
- **validate runs the bundle gate tests:** a v* tag can point at a commit that never passed build.yml (the existing validate comment), and the gates are only trustworthy if their fixture tests pass.
- **Timeout 210:** three waits at `--timeout 60m` is 180 minutes; the v1.2.0 run took under 10 minutes, so this is a guard (23-RESEARCH Pitfall 21).
