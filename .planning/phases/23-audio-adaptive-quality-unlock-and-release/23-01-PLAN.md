### Wire contract (Phase 23 additions, all additive)

1. Viewer hello caps gain `audio: 1` when the viewer added an audio recvonly transceiver.
2. Server hello caps gain `audio: 1` (this daemon sends audio) and `unlock: 1` only for an own-account viewer (Mode own), set once at hello and never changed afterwards; a guest hello never carries it (23-04).
3. The answer to an offer with an audio m-line carries `opus/48000/2` with fmtp `minptime=10;useinbandfec=1;stereo=1;sprop-stereo=1`; the audio track has track id `audio` and stream id `portty-desktop`.
4. The state message gains `"audio":"failed"` while audio capture or encode has failed (omitted otherwise).
5. Signalling `{"type":"quality","slow":true|false}` goes to one viewer when it enters or leaves the slow set (23-02).
6. Signalling `{"type":"unlock","state":S,"failures":N,"wait_ms":N,"reason":R,"by_portty":B}` goes to every viewer holding the unlock cap on each change, and once to a joining one while locked (23-04). S is one of idle, unlocking, retrying, unlocked, failed, rate_limited, paused, refused, unavailable, error. R is caps_lock or unmappable (refused), accessibility (unavailable), or empty. failures is the consecutive failed-submit count 0 to 3. wait_ms is the remaining wait for rate_limited and paused.
7. On the `input` data channel, a binary message whose byte 0 is 0x01 carries an unlock password as UTF-8 in bytes 1..n, n at most 1024. Any other binary message, or a longer one, is dropped and counted malformed. The daemon never builds a Go string from it (23-04).

## Decisions implemented

CONTEXT [Audio] all five (A-audio), Specifics (AudioConverter, no libopus; same SCStream, existing grant; starts muted on the viewer), Claude's Discretion (guests hear audio like the picture), RESEARCH Patterns 1 and 3, Pitfalls 8 and 10.

Recorded deviation (A/V timestamps, reversible): CONTEXT [Audio] sync says both tracks are stamped from SCK presentation timestamps on the host clock. This plan stamps audio from the host wall clock at packet arrival (a 48 kHz sample counter resynced past 60 ms), because the existing video track already stamps capture time from wall-clock arrival (internal/desktop/manager.go packetize, lines 936-946, WR-02, pinned by TestFanout_RTPTimestampFollowsCaptureTime) and both clocks must be the same one for sender-report lip sync. Arrival time trails the SCK presentation time by the capture and encode delay only; carrying CMSampleBuffer PTS on AudioPacket and AccessUnit is the route back to the letter of the decision if 23-09 or M-162 shows an audible offset. The executor states this deviation in the 23-01 SUMMARY.

Planner notes (reversible): AudioSource is an optional interface (`interface { AudioPackets() <-chan AudioPacket; AudioErrors() <-chan error }`) so every existing fake Source keeps compiling; audio is added to a viewer only when it both sends caps audio 1 and offers an audio m-line, so pion never has to add an unoffered m-line.
