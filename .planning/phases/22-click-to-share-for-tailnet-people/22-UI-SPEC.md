# Phase 22 — UI Design Contract

> Visual and interaction contract for Phase 22 (Click-to-Share for Tailnet People: DSHR-03..07, DCTL-04). Generated by gsd-ui-researcher in auto mode (the user delegated every product and UX choice), to be verified by gsd-ui-checker. Phase 22 **adds screens on the shared Mac** (a Share Desktop sheet, an Admit sheet, a viewer list, a tray indicator, two banners) and **guest states on the Phase 19/20 viewer page**. It adds no design system, no token, no npm package and no CSP directive.

**Sources, in priority order:**
1. `22-CONTEXT.md`: the locked decisions (who may join, identity shown only on the shared Mac, GUI-only admit, one active share, grants keyed to person and node, audit log, 2 s lease) and the "Claude's Discretion" list that fixes the surfaces, including the five "After research" bullets that supersede the earlier ones (listen-only tap, Secure Event Input warning, guest asset route, join and leave signal in the Admit sheet, tray icon and tray line rather than banners, name sanitizing, per-user pending cap of 2).
2. `22-RESEARCH.md`: Finding 3 (keyboard blind spot under Secure Event Input), Finding 6 (banners may be silenced while the display is captured), Finding 9 (the live tray menu is built in `tray_objc_darwin.m`, not in `BuildMenuItems`), Pattern 3 (admission states and limits), Pattern 6 (tray and notifications: default click only, no action buttons), Pitfall 7 (names as attack surface), Pitfall 8 (prompt spam), Pitfall 9 (click-through Admit), Pitfall 12 (share ends silently on daemon restart).
3. `19-UI-SPEC.md` (approved and **built**: the real code is the source of truth), `20-UI-SPEC.md` (approved, partly built) and `21-UI-SPEC.md` (approved, planned): every token, sheet, chip, card and copy rule, the `CARDS` copy table in `frontend/src/components/DesktopView.tsx`, the Phase 19 tray desktop line (`setTrayDesktopTitle`, built), and the Phase 20 notice slot, bar and capability model. Inherited unchanged unless a section below says it supersedes one.
4. ROADMAP Phase 22 SC1-SC5 and REQUIREMENTS DSHR-03..07, DCTL-04.
5. Existing code, scanned 2026-11-26: `components/SharePopover.tsx` and `lib/shareCopy.ts` (switch, Copy, CT line, error pattern), `components/DesktopSetupSheet.tsx` (sheet shell, `.dialog--setup`), `components/QuitConfirmModal.tsx`, `components/TailscaleBanner.tsx` and the `.banner*` CSS, `lib/useDialogFocus.ts` (`data-dialog-cancel`, `data-dialog-primary`, Esc handling, topmost-modal rule), `LinkNoLongerWorks.tsx`, `UserRefused.tsx`, `web/link-invalid.html`, `tray.go` (`trayIconBytesForState`), `tray_objc_darwin.m` (`menuWillOpen`), and the token blocks in `style.css`.
6. Project memories: macOS-native look (system font, system accent, light and dark follow the system live), radical simplicity, rock-solid (users can't get in to fix the remote Mac, so every failure is visible in words and no key is left held), colorblind user (color is never the only signal), no developer paths or real tailnet addresses in committed text (`tests/check-brand.sh`). All people, logins and devices below are made-up placeholders on `example.com`.

**Scope.** Seven surfaces: (1) entry points: tray item, Settings row, Quit warning; (2) the Share Desktop sheet with its viewer list; (3) the Admit sheet; (4) the tray indicator (icon variant, line, Stop Sharing); (5) notifications and banners (join, leave, Secure Event Input, share stopped); (6) the guest page states in the browser viewer; (7) three static pages. Out of scope and not designed here: the input, clipboard, display-picker wire (Phase 20), the Desktop tab and iPhone touch viewer (Phase 21), audio, quality and unlock (Phase 23), always-available mode (Phase 19, settled), and anything about the audit log's contents beyond what the sharer sees (the log has no UI). Every item marked **[default]** is a detail CONTEXT did not fix; it is the simplest choice that fits the house style, and the planner may adjust it without asking.

**Who sees what.** The sharer sees identities (display name, login name, device) on the shared Mac only. The guest page never shows the guest's own identity and never shows the sharer's. The one name a guest page may show is the **display name of another person who holds control** ("<name> is controlling"), already decided in CONTEXT (signalling carries the lease holder name). Names are sanitized before display (see Names).

## Names (applies to every surface)

| Rule | Contract |
|------|----------|
| Source | The WhoIs display name, login name and node name, **sanitized in the daemon** before they reach the GUI, a notification, the audit log or a signalling message: drop Unicode categories Cc and Cf (bidi overrides, zero-width), collapse whitespace, cap at 128 runes. The GUI sanitizes again (cheap, belt and braces) |
| Login name | **Always visible** wherever a person is named on the shared Mac, never truncated: it wraps (`overflow-wrap: anywhere`) rather than ends in an ellipsis. It is the identity that counts; display names can imitate someone |
| Display name | Shown first and bold, wrapped the same way. If it is empty after sanitizing, or equals the login name, the bold line shows the login name and the separate login line is omitted **[default]** (the login name is still on screen) |
| Device name | Shown with the label **Device**; it may end with an ellipsis on one line, with the full text in `title` |
| Rendering | Text only, in `<bdi>`, never markup, never a link. A name is never rendered into a served page or a refusal; the single exception is "<name> is controlling" on the guest page, which carries the display name only, never the login name |
| Notifications | Use the **login name** (guest) or the **device name** (own account): both are short, unique and hard to imitate |

## Surface 2: Share Desktop sheet

A modal `.dialog.dialog--setup.dialog--share`, `role="dialog"` `aria-modal="true"` `aria-labelledby` the title, built like `DesktopSetupSheet`. It mounts its content only while open, so state is fresh on every open. Closing it never stops the share.

### States

| State | When | Content |
|-------|------|---------|
| **Not sharing** | The sheet opens, the share has not started, and either the CT acknowledgement is missing, or the last start failed, or Tailscale is not connected | Title, description, CT line, error or reason line, buttons **Not Now** and **Start Sharing** |
| **Starting** | A share is starting | The description is replaced by **Getting a link…** (no dot); buttons disabled (`aria-disabled`) |
| **Sharing** | The share is active | Link row, optional status row, Watching list, footnote, footer |

**One click for the common case.** If the CT acknowledgement is already recorded and Tailscale is connected, opening the sheet from any entry point **starts the share at once** (Starting, then Sharing): that is the "click to share". The first time ever (no acknowledgement) the sheet opens in **Not sharing** with the CT line visible and waits for **Start Sharing**, which records the acknowledgement as the first enable does (the Phase 4 and 19 rule: the disclosure is read before the click, the click is the consent). A failed start returns to **Not sharing** with the error line and the button enabled. Opening the sheet while a share is active shows **Sharing** with the same link (one active share, CONTEXT).

### Link row

Label **Link**; description **Anyone on your tailnet who opens it waits for you to let them in. It stops working when you stop sharing.**; control the **Copy Link** button (secondary). Click copies through the Wails clipboard API and the label becomes **Copied!** for 2 seconds, then **Copy Link** again (the Phase 4 and 19 pattern, same width rule). If the write fails: inline error **Couldn't copy the link. Try again.** The link is never shown in a field and never as a QR code (the Phase 19 rule). The button is `aria-disabled` while Starting or while Tailscale is not connected.

### Status row (only while the desktop is not ready)

The row appears only for the states a guest would also meet as a card, so the sharer finds out first. It reuses the Phase 19 status table: `.ts-status` dot plus the Phase 19 text, in an `aria-live="polite"` region.

| State | Text (Phase 19, verbatim) | Dot | Button |
|-------|---------------------------|-----|--------|
| `needs_permission` | **Needs permission** | warn | **Set Up Permissions…** (opens the Phase 19 setup sheet, placed after this one) |
| `awaiting_approval` | **Waiting for approval at the Mac** | warn | none |
| `display_asleep` | **Display asleep** | off | none |
| `capture_paused` | **Paused after repeated errors. Run Test Capture to resume.** | warn | none |
| Tailscale not connected | **Waiting for Tailscale** | warn | none |
| Ready, Streaming, Locked | row absent | | |

### Watching list

Header **Watching** (Caption 12/600, secondary) above a `.settings-group`. The list is in an `aria-live="polite"` region; rows appear and disappear at once, with no animation. Order: oldest connection first, so a row never jumps when someone else joins **[default]**.

**Empty:** one row of Caption text, **Nobody is watching yet. Send the link to someone on your tailnet.**

**Guest row** (an admitted person):

| Line | Content |
|------|---------|
| 1 | Display name (13/600, `<bdi>`), then the badge at the end of the line |
| 2 | Login name, then ` · ` and the device name (Caption, secondary). The login name never truncates; the device may |
| 3 | Switch **Allow control**, switch **Allow clipboard**, then the **Disconnect** button at the end |
| 4 | Caption, secondary: **Control lets <name> use this Mac as you, so they can do anything you can. Clipboard lets them copy text to and from this Mac.** `<name>` is the bold name, in `<bdi>`. Both switches point `aria-describedby` at this line |

Badge (words and icon, never color alone):

| Badge | Icon | When |
|-------|------|------|
| **View only** | `EyeIcon` | No control grant (the default after Admit) |
| **Controlling** | `CursorArrowRaysIcon` | The person has a control grant. The badge follows the **grant**, not the moment-to-moment lease: it does not flicker with each keystroke |
| **Own account** | `UserIcon` | An own-account viewer (always-available link). No switches: own devices have full control and clipboard with no grant step (CONTEXT). Line 2 reads **Your own device** (no login line, it is the sharer's own account) |

- **Allow control** and **Allow clipboard** are independent. Both start off. Turning one on or off acts at once, with no confirm: the caption is the consent copy and the switch is reversible. A switch shows `saving` (dimmed, focusable) while the daemon call runs; on failure it returns to its true state and the row shows the inline error **Couldn't change what this person can do. Try again.** (`role="alert"`, under line 4).
- Turning **Allow control** off releases everything that person holds and returns their page to View only (Surface 6).
- **Disconnect** acts at once, with no confirm (DSHR-05: ends the connection at once). For a guest it is final for this share (CONTEXT: a revoked person cannot knock again); the footnote says so. For an own-account row it only disconnects that device, which can reconnect through always-available. On failure: inline error **Couldn't disconnect this person. Try again, or choose Stop Sharing.**
- A guest who drops and reconnects from the same device is re-admitted with their grants (CONTEXT, DESK-03): the row disappears on the drop and returns with the same switch positions.

### Footnote

Caption, secondary, `.settings-sheet__footnote`, 8px below the list:

> **Denying or disconnecting someone is final for this share. To let them back in, stop sharing and share again. Anyone watching sees everything on this screen, including this window. If someone can't open the link, your tailnet's access rules may not let them reach this Mac.**

The second-to-last sentence is deliberate: a guest can see the Admit sheet and this sheet (other people's names and logins) in the picture. It is inherent to sharing a screen (see Decisions).

### Footer

| Element | Contract |
|---------|----------|
| **Stop Sharing** | Secondary, at the left edge of the footer. Acts at once, no confirm, exactly like the tray item (DSHR-06: one-click stop). Every guest is disconnected, the link stops working, the sheet stays open and returns to **Not sharing** without auto-starting again (Stop Sharing was the sharer's choice). Opening the sheet afresh later, from any entry point, starts a new share with a new link. On failure: inline error **Couldn't stop sharing: <detail>. Try again.** The detail is the local binding's text, never a remote peer's |
| **Done** | `.button--primary`, `data-dialog-primary`, right-aligned. Closes the sheet; the share continues |
| **Not Now** | In **Not sharing** only, secondary, left of Start Sharing. Closes the sheet, shares nothing |
| Esc | Closes the sheet exactly as Done or Not Now does. Never stops the share |
| Focus | `useDialogFocus(..., { initialFocus: 'primary' })` (Done, or Start Sharing). On open with an auto-start, focus lands on the dialog's first control until the state settles, then stays put. Tab is trapped. Focus returns to the invoker (the tray cannot hold focus, so it returns to the window) |

### Errors and reasons (Not sharing state)

| Condition | Message | Slot |
|-----------|---------|------|
| Tailscale not connected | The Phase 4 `TAILSCALE_OFF_REASON` replaces the description; Start Sharing is `aria-disabled` with `aria-describedby` the reason | description |

## Surface 5: Notifications and banners

### Native notifications

One path: `sendNotificationFunc`, default click only (no buttons). **Not the primary signal**: macOS may silence banners while the display is being captured (research Finding 6, unmeasured), so the Admit sheet, the tray icon, the tray line and the in-sheet live region carry the load. Names are the sanitized login name (guest) or device name (own account), capped at 80 characters with an end ellipsis.

| Event | Title | Body | Identifier | Sent when |
|-------|-------|------|------------|-----------|
| Admit request | **Portty** | **<login name> wants to see your desktop.** | `portty.desktop-admit` (a repeat replaces it) | A request arrives and Portty is not the frontmost, visible window |
| Join | **Portty** | **<login name> joined your desktop.** (own account: **<device> joined your desktop.**) | `portty.desktop-join` | A viewer's connection comes up (admitted guest or own device) |
| Leave | **Portty** | **<login name> left your desktop.** (own account: **<device> left your desktop.**) | `portty.desktop-leave` | A viewer's connection ends, including Disconnect and Stop Sharing |
| Several at once | **Portty** | **N viewers joined your desktop.** / **N viewers left your desktop.** | the same identifiers | Two or more of the same kind within 5 seconds are coalesced into one that replaces the first **[default]** |

Click on any of them brings Portty forward and, if a share is active and no request is pending, opens the Share Desktop sheet (new IDs are routed in `handleNotificationClick`, which today returns for every ID but the update one).

### In-sheet live region

The Watching list is `aria-live="polite"`; in addition a visually hidden `role="status"` line announces **<name> joined** and **<name> left** (display name, sanitized), so a screen reader hears who came and went even when banners are silenced.

### Banners (`ShareBanner`)

Two variants in the existing `.banner-stack`, using `.banner` with an icon, the message, and the existing action and dismiss patterns. They are mounted by `App` beside `TailscaleBanner`; a banner's own render condition decides when it shows.

| Banner | Variant and icon | Message | Action | Shows | Clears |
|--------|------------------|---------|--------|-------|--------|
| **Secure Event Input** | `.banner--warning`, `ShieldExclamationIcon` | **Typing at this Mac isn't detected right now, because a password field or Secure Keyboard Entry is on. Someone you've allowed to control may type at the same time as you.** | none, no dismiss | While Secure Event Input is on **and** at least one viewer can control (a guest with a control grant, or any own-account device) | When either stops being true. It cannot be dismissed: it states a live condition |
| **Share stopped** | `.banner--info`, `InformationCircleIcon` | **Desktop sharing stopped because Portty restarted. Share Desktop again to get a new link.** | **Share Desktop…** (opens the sheet) and a dismiss (×) | When the GUI's events stream drops while a share was active (daemon restart, upgrade or crash; research Pitfall 12) | On dismiss, or when a new share starts |

The Secure Event Input weakening is CONTEXT's accepted trade-off (the keyboard half of "physical input always wins" is degraded while it is on; the mouse half still works). The banner is the "GUI warning" it asked for. If the Portty window is hidden nobody sees it; the tray icon variant is on screen and the limitation is documented in the docs **(accepted, low)**.

## Accessibility Contract

| Element | Contract |
|---------|----------|
| Share Desktop sheet | `role="dialog"`, `aria-modal="true"`, `aria-labelledby` the title; Tab trapped; Esc closes; focus returns to the invoker. Status row and Watching list are `aria-live="polite"` regions; the dot is `aria-hidden` and the text is the signal |
| Admit sheet | `role="dialog"`, `aria-modal="true"`, `aria-labelledby` the title, `aria-describedby` the two paragraphs; initial focus on the dialog (`tabindex="-1"`), so a screen reader reads the title and description and a stray key does nothing; Tab order Deny, Admit; both buttons `aria-disabled` for the first 600 ms and while an answer is in flight (never `disabled`, so focus order is stable). Esc is inert |
| Names | Every name is in `<bdi>`; the login name is always present as text; the display name is never the only identifier on screen |
| Viewer rows | Each row is a `role="group"` named by the person's name. Each switch's accessible name combines its label and the person (`aria-labelledby` the label and the name), and `aria-describedby` the grant caption; **Disconnect** has `aria-label="Disconnect <name>"`. The badge is text with an `aria-hidden` icon |
| Join and leave | The visually hidden polite live region announces **<name> joined** and **<name> left** |
| Tray | Menu items are plain text; the line is an enabled item (VoiceOver reads it as an actionable item); **Stop Sharing** is a normal item |
| Tray icon | A shape change, not color; the item text carries the same information |
| Notifications | Fixed sentences plus a sanitized name; no action buttons |
| Banners | `role="status"` (the existing `TailscaleBanner` pattern); the Secure Event Input banner has no dismiss because it states a live condition |
| Guest cards and chips | `role="status"` `aria-live="polite"` (the Phase 19 region); every state has an icon and words; Reload Page is a real `<button>`, 44px; the waiting and not-admitted cards need no focus target |
| Guest control | The Phase 20 contract applies unchanged to a controlling guest: the release chord, no keyboard trap, the capture ring as a present-or-absent line |
| Color | Never the only signal (the user is colorblind): badges, chips, cards, the tray variant and every dot have words or a shape |

| Motion | No new animation. Rows appear and disappear at once; chip fades are the Phase 19 150 ms and instant under `prefers-reduced-motion: reduce` |
| Keyboard | Sheet Tab order: Copy Link, Set Up Permissions… (when shown), then each row's two switches and Disconnect, Stop Sharing, Done. Focus ring is the existing 3px `--color-focus-ring` |

## Decisions Made Here (Claude's discretion; the user may override)

| Decision | Choice | Why |
|----------|--------|-----|
| One click to share | After the CT acknowledgement, opening the sheet starts the share at once; the first time waits for **Start Sharing** | "Click-to-share" is the phase name; the CT line is read before the click that consents, as in Phases 4 and 19 |
| Where the viewer list lives | In the Share Desktop sheet, reached from the tray line, the tray item and a Settings button | Matches CONTEXT's discretion item; the toolbar Share is per session; no new always-visible window |
| Tray line is clickable | **Desktop shared with N people** is an enabled item that opens the sheet | The viewer list needs a one-click path from the one always-visible surface; the Phase 19 line is inert because it had nowhere to go |
| Tray count | N counts guests and own-account devices; pending requests are not counted; the icon variant follows N of 1 or more | CONTEXT: the indicator is "while anyone (guest or own account) is watching" |
| Phase 19 tray line unchanged | It stays at its place, so when a share is active both lines show and the counts can repeat | Fewer rules; the two lines answer different questions (capture state, who is watching) |
| Stop Sharing scope | Ends the click-to-share and its guests only; own-account viewers stay | CONTEXT discretion: always-available is separate, and cutting the author's own path from the tray would surprise them |
| Admit sheet: no focus on a button, Esc inert | Focus starts on the dialog; Esc does nothing | Portty is a terminal; Esc, Return and Space are everyday keys and Deny is permanent for the share. Overrides the research suggestion "focus on Deny, Esc = Deny" with a stricter version of its own goal (CONTEXT: no accidental Return) |
| Click guard | About 600 ms on both buttons, reset per person | Research Pitfall 9, applied to Deny too because an accidental Deny locks a colleague out for the share |
| Deny is final | Said in the Admit sheet and the footnote | CONTEXT: a denied or revoked person cannot knock again; recovery is Stop Sharing then share again (new share, new list) |
| No confirm on Stop, Disconnect, Deny, grant off | Act at once | DSHR-05 and DSHR-06 say "at once" and "one-click"; all are reversible by sharing again |
| Grant consent | A switch with the consequence in a caption beside it; no dialog | CONTEXT's wording; radical simplicity; a dialog per grant would train the sharer to click through |
| Badge follows the grant | **View only** / **Controlling** by grant, not by lease | A badge that flips each keystroke is noise; guests see the lease (**<name> is controlling**) |
| Own-account rows | No switches, badge **Own account**, Disconnect only | CONTEXT: own devices have full control with no grant step |
| Names | Login name always visible and never truncated; display name bold; sanitized in the daemon and the GUI; `<bdi>` | CONTEXT and research Pitfall 7: display names can imitate someone |
| Notifications use login or device name | Not the display name | Short, unique, hard to imitate; the display name is bold in the sheet where the login name sits beside it |
| Notifications are secondary | Admit request only when Portty is not frontmost; join, leave coalesced within 5 s; a hidden live region in the sheet | Research Finding 6: banners may be silenced while capturing; the sheet, tray icon and tray line are the load-bearing signals |
| Secure Event Input warning | A non-dismissable banner while it is on and someone can control | CONTEXT: accept the weaker keyboard half and show a GUI warning, not drop all remote keys |
| Share stopped banner | A dismissable info banner with a Share Desktop… action | The GUI must not keep implying a share is live after a daemon restart (research Pitfall 12) |
| Quit names the share | One added sentence in the existing confirm | Quitting ends the share (CONTEXT: GUI liveness); the sharer should not learn that from a guest's reaction |
| Guest cards beyond CONTEXT's list | **You were disconnected**, **Someone is using this Mac**, **This link no longer works**, **Can't reach this Mac** (with the access-rules hint) | A revoked guest must not read "Not admitted"; physical-wins needs a visible state (research Pattern 5); CONTEXT asks for a link-no-longer-works page and an ACL failure state |
| Guests never see the Streaming count | The Phase 19 chip is not shown in guest mode | The count of other viewers is not theirs to know; the mode chip is the useful one |
| Lock Screen for guests | Not offered in the Send Keys menu **[default]** | A guest locking the sharer's Mac mid-share helps no one; unlock is never offered to guests (Phase 23) |
| Guest bar | No display picker; Clipboard menu only with the clipboard grant; View Only / Control segment present | CONTEXT: guests never pick the display; Phase 20 hides what the hello does not grant |
| Static pages | Two new guest pages with guest wording | The existing pages say "only works on your own devices" or send the reader to Portty's Settings, both wrong for a guest |
| Stage of the picture | Everything on screen, including the Admit and Share Desktop sheets, is visible to guests | Inherent to screen sharing; stated in the footnote rather than hidden by a special mode (radical simplicity). A controlling guest can click Admit and Allow control themselves (inherent, CONTEXT); the grant caption says so |
| Own tray icon art | A small filled circle on the normal glyph | A shape cue in a monochrome menu bar; precedence between error and progress per research Pattern 6 |
