## Flagged decisions and assumptions

- **Ended verdict (CONTEXT [Ended peer tab], part 1).** Frontend verdict mapping only: once a tab saw the session-ended close, `no_such_session` maps to `{ kind: 'stop', reason: 'ended' }` (relayClient already turns that into `CLOSE_REASON_SESSION_ENDED`, and `shareInfoVerdict` already returns it for a 404). The flag lives on the `Tab` in App state, so it survives the panel remount that happens when the user switches back to the tab (App renders only the active web tab).
- **Sidebar (CONTEXT post-research [Sidebar], LOCKED; overrides RESEARCH's 35 s grace and UI-SPEC row 2's "short grace" wording).** No time-based grace. Research found the cause: `unshareLocked` (internal/daemon/share.go) stops the host's share server when its last share ends, and the viewer's peer discovery cache lives 30 s, so the live meta fetch is refused. A refused connection (TCP reset: the host answered, nothing listens on the share port) now means reachable with 0 shared sessions; only a timeout, no route or other failure stays "Can't reach this Mac". Once the cache expires (up to 30 s), the host is no longer probed as Portty and its group disappears, as today.
- **Refused is reliably distinguishable at the fetch site.** The GUI's meta fetch uses Go's net/http over the OS network stack, which surfaces a reset as `syscall.ECONNREFUSED` through `url.Error`/`net.OpError` (`errors.Is` sees it). Precedent: internal/daemon/peer_connect.go already maps `errors.Is(ferr, syscall.ECONNREFUSED)` to "not sharing" (Phase 4 RESEARCH Pitfall 5), and Phase 5 matrix row R9 found that only a real host-daemon stop or reboot made the host refuse. A test against a closed local port pins the classification; the live tailnet confirmation is TESTING.md M-154 (15-07), run in the Tart VMs, never against the host's tailnet. If the executor finds the refusal cannot be told apart reliably, the locked fallback applies: stop, write a new pending todo for the sidebar flash, and add no grace.
- **Accepted consequence:** a Mac whose Portty daemon is down but which is awake also refuses, so it shows "Nothing shared" (accurate: nothing is shared) until the cache drops it, instead of "Can't reach this Mac".
- **IP fallback.** `FetchPeerSessionsMeta` keeps falling back to the Tailscale IP only for `MetaUnreachable`; a refusal by the DNS name is the host's own answer, so it is not retried by IP. Say so in a comment.
- **peer_connect.go unchanged (Chesterton).** `doFetchSessionsMeta` still returns the transport error together with `MetaRefused`, so the daemon's existing `errors.Is(ferr, syscall.ECONNREFUSED)` branch keeps working. The refused row of `TestMetaStatus_TriState` asserts both the status and the kept error.
- **Not in scope:** `sidebarPeers.peerView` synthesizing an unreachable row for a host whose tab is reconnecting (it is the amber reconnecting state, not this flash; an ended tab no longer reconnects after this plan).
- **Reversibility:** reversible (an internal enum value and a frontend verdict; the JSON shape the sidebar reads is unchanged).
