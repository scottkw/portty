## Flagged decisions and assumptions

- **Behaviour (CONTEXT "Update notification click", user said "You decide").** Show the window plus the existing banner; never start the download (consent: nothing downloads without the user pressing Download). No new copy, layout or token (UI-SPEC row 3).
- **Un-dismiss (RESEARCH Pitfall 8).** `dismissedUpdate` hides the banner for a version the user dismissed; without clearing it the click would show a window with no banner. `update:show` clears it; `showUpdateBanner` still requires an `available|downloading|verifying|revealed` state, so an idle status shows nothing.
- **Delegate lifetime (RESEARCH Pitfall 9).** `registerNotificationDelegate()` is idempotent and bundle-guarded; it is also called from `initStatusItem`'s main-queue block so the delegate exists from launch. The completion handler is called on every path.
- **[ASSUMED] Apple API (RESEARCH A2, A6):** the selector `userNotificationCenter:didReceiveNotificationResponse:withCompletionHandler:`, `UNNotificationDefaultActionIdentifier` for a click on the notification body, and delivery on any thread. The Go export only copies the string and starts a goroutine, so the calling thread does not matter. `showWindow` reaches `setDockVisible(true)`, which already activates the app (with the Accessory-to-Regular Dock hand-off). An unbundled process (`go test`, `wails dev`) cannot run the delegate (`hasValidBundleIdentifier`), so the live click is verified only by M-152 in the Tart VM with a notarized build (ad-hoc builds cannot post notifications), as the CONTEXT decision says.
- **One identifier constant.** `notifyUpdateOnce` and `handleNotificationClick` must agree on `portty.update-available`; both use `const updateNotificationID`. The existing tests that pin the literal in posted notifications stay as they are (they prove the wire value did not change).
- **Unexported on purpose:** `handleNotificationClick` is unexported so Wails does not bind it to the frontend.
- **Gate note:** Task 1's negative gate is region-scoped to the body of `handleNotificationClick` in app_update.go; Task 2 legitimately names the frontend's download spy in a test file.
