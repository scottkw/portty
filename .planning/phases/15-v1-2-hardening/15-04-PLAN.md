## Flagged decisions and assumptions

- **F-1 fix site (CONTEXT [Path click] F-1, refined by research).** The decision names "the relay cwd log and Hub.PathClick lookup". Research reproduced the bug and found the root cause one step earlier: `clear` writes ED 2 then ED 3 in one write; ED 2 pushes the screen into the emulator's scrollback and ED 3 drops it before it is drained into History, so `History.Pushed()` never counts those lines and absolute rows run backwards onto rows older cwd records already cover. The fix keeps rows monotonic in the relay (`internal/relay/history.go`, `internal/relay/hub.go`); `Hub.PathClick` and `cwdLog.at` stay unchanged because the log is correct for monotonic rows, and changing the lookup would paper over wrong row numbers (RESEARCH Item F "Why not a lookup change"). The required test lives in internal/relay/pathclick_test.go as decided, plus row-level tests in cwd_test.go. Prototyped and reverted in research: with the fix `TestCwd*`, `TestPathClick*`, `TestHistory*` and `TestHub_Handoff*` passed.
- **Handoff format:** `History.pushed` is only a number in the handoff state; `Skip` changes its value, not the format (no API bump).
- **A1 (assumed):** macOS `clear` emits ED 2 and ED 3 in one write. The tests feed the bytes directly, so the fix holds for any write where ED 3 follows undrained scrollback.
- **F-2 (CONTEXT [Path click] F-2).** xterm 6's Linkifier ignores a move to the same cell it last saw and clears its link on mouseleave, so after leave plus a text change, returning to that cell asks for no link. `onLeave` calls the existing `invalidate()`, which resets `_lastBufferCell` and `_activeLine` and does not re-hover because `pointerInside` is false. `invalidate` is a `const` declared after `onLeave`; move the `onLeave` definition and its `mouseleave` registration below `invalidate` (no use before definition).
- **Linkifier flake (CONTEXT [Flakes]).** `renderOnce` resolves on `term.onRender` through `vi.waitFor` (timeout 5000 ms, interval 10 ms); every other wall-clock wait that guards an assertion becomes `vi.waitFor` on that assertion. The one wait that proves nothing happened (the 20 ms window in the mouse-tracking test) stays. Test-only; product render timing is unchanged.
- **Ordering:** Task 2 and Task 3 both edit pathLinks.linkifier.test.ts, so they run in order inside this plan.
- **Reversibility:** reversible.
