## Flagged decisions and assumptions

- **O-2 (CONTEXT [Socket hardening]).** `os.Chmod(path, 0o600)` right after a successful `net.Listen("unix", ...)` in `listenDaemonSocket` (only caller: internal/daemon/api.go). Chosen over a umask change because umask is process-global and races other goroutines creating files (RESEARCH Alternatives). The short window between listen and chmod is harmless: the parent directory is 0700. A chmod failure closes the listener and returns the error (CLAUDE.md "let it crash"; never serve wider silently).
- **Post-COMMIT tighten (CONTEXT post-research [Socket hardening]).** A takeover receives the old daemon's listener fd, so a socket created by a pre-fix daemon keeps 0755 through the upgrade. `takeover.commit` calls `tightenSocketMode(t.socketPath)` right before it returns `takeoverCommitted` (covers both commit paths: with COMMITTED and the old-daemon-died path). It logs a failure and never fails the takeover: the sessions have already moved, and failing now would cost them.
- **O-6 (CONTEXT [Socket hardening]; reliability first).** A new seam `takeoverPeerPID = fdpass.PeerPID` beside the existing ones (RESEARCH Pitfall 6: never reuse `peerPID`, which is the old side's lookup of the takeover and is replaced by tests). Right after HELLO-OK is read and before the `after-hello` step, a lookup error or a pid mismatch returns `t.fail(takeoverRefused, ...)`: ABORT is sent, everything received is closed, the old daemon rolls back and keeps serving, and the caller offers the existing DEBT-08 choice (as for a uid or version refusal). A lookup error refuses, never falls back to trusting HELLO-OK (CLAUDE.md "Silent Fallbacks").
- **Measured, so O-6 cannot break every second upgrade** (RESEARCH Item D): `LOCAL_PEERPID` on a dialing client reports the process that accepted, even when another process created the listener. In tests both daemons share one process, so the real lookup equals HELLO-OK's `os.Getpid()` and existing handoff tests are unaffected.
- **O-1.** The whole-buffer parser in x/sys v0.46.0 returns no messages at all on the first malformed header, so descriptors in earlier messages are never closed. Walk the buffer with `unix.ParseOneSocketControlMessage`, collecting SCM_RIGHTS descriptors as it goes, so an error mid-buffer still returns the earlier ones to `Recv`'s existing close loop. The walk stops when fewer than `unix.CmsgLen(0)` bytes remain, as the whole-buffer parser does. The kernel will not deliver a malformed message through a real socket, hence the pure-function seam `rightsFromOOB` (RESEARCH Item D). Each descriptor is closed exactly once (Pitfall 7; `TestRecv_TruncatedClosesFds` and `TestRecv_CountMismatch` stay green).
- **Reversibility:** reversible (internal; a refused takeover already falls back to the DEBT-08 guard).
