## Interaction Contract

Each row is one behaviour from CONTEXT.md, stated as the observable result.

| # | Surface | Trigger | Required result |
|---|---------|---------|-----------------|
| 1 | Peer tab (`TabBar`, `SessionEndedBanner`, `peerConnectVerdict`) | User clicks a peer tab whose session already ended (the tab saw the session-ended close) | Tab stays in its ended state and shows `Session ended — the owner stopped this session.` A later `no_such_session` maps to "session ended", never "stopped sharing". A tab that has not seen the session-ended close keeps the existing "stopped sharing" mapping. Frontend verdict mapping only; no layout change |
| 2 | Home sidebar peer group (`Sidebar.tsx`, `g.reachable`) | Host kills a session; `ListSessions` races teardown | A reachable host never renders the `PEER_UNREACHABLE` line during the short post-kill window. Keep the last good peer state through a short grace. A genuinely unreachable host still shows the line after the grace. If the race cause cannot be found, split into a new todo rather than guess (CONTEXT decision) |
| 3 | macOS update notification click | User clicks `Portty X is available` | Portty comes forward (window shown if hidden or tray-only). The existing `UpdateBanner` is visible in its `available` state (info variant, message plus `Download`). No download starts; `Downloading…` progress state is not entered until the user presses `Download` |
| 4 | `portty attach` status bar (CLI) | Initial resize and every SIGWINCH | No visual change to the bar. The remote PTY is told rows-1 (bar shown), so full-screen apps do not draw over the bar row, for bottom and `--status-top`. Bar styling, position and content unchanged. No new flag (deferred) |
| 5 | Terminal path links (`pathLinks.ts`) | Cmd-click on a path link, including first click after pointer leave and return to the same cell | No visual change. Link underline/hover styling and the existing `LinkConfirmPopover` and `LinkNoLongerWorks` surfaces are untouched; the click now fires reliably |

Keyboard and accessibility: unchanged. `Download` and `Try Again` remain native `<button type="button">` elements with the existing `:focus-visible` underline. The progress element keeps `aria-label="Download progress"`.

## UI Considerations

Applicable state considerations resolved: 5 covered, 1 backstop, 0 unresolved.

Empty-state and error-state copy lives in `## Copywriting Contract`; rows here reference it and do not restate it.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| populated | `SessionEndedBanner` on an already-ended peer tab | ✅ covered | Clicking an already-ended peer tab renders the "Session ended" row from the Copywriting Contract, not the "stopped sharing" row |
| partial | Peer tab that has not seen the session-ended close | ✅ covered | Still maps `no_such_session` to the existing "stopped sharing" verdict, so the fix does not widen to tabs that never saw the ended close |
| error | Sidebar peer group, host reachable right after a session kill | ✅ covered | The `PEER_UNREACHABLE` line is not rendered for a reachable host during the grace window; it still renders for an unreachable host after it |
| populated | `UpdateBanner` reached via notification click | ✅ covered | Banner shows the `available` state (info variant, `Download` action) and no download is in progress after the click |
| partial | Window hidden or tray-only when the notification is clicked | ✅ covered | Click routes to show-window first, then the banner is visible; handler wiring and routing are asserted by automated test |
| loading | Live notification click on a real notarized build | 🧪 backstop | Ad-hoc builds cannot post notifications; verify in the Tart VM with a notarized build and record as a manual `M-NN` item in TESTING.md Section 5 (per CONTEXT decision) |
