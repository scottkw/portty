## Flagged decisions and assumptions

- **Routing first:** run only the sub-checks the matrix `## Routing` sends to VM; mark frame parts routed elsewhere `ROUTED:host-run`.
- **Clean start:** reset every spike TCC grant first so the daemon's own prompt and attribution are observed, not inherited from the helper or R00.
- **Path B is production's always-on path:** the legacy plist matches what `internal/daemon/service.go` installs through kardianos (no ProcessType). Loading it from SSH with `launchctl bootstrap gui/<uid>` may be refused; then use `sudo launchctl bootstrap gui/<uid>` and record which worked. Either way launchd owns the job, which is what R04 measures.
- **Throttle sub-row (RESEARCH "ProcessType matters"):** an unspecified ProcessType gets launchd's light resource limits. Compare the same 30 s motion workload (the guest's screen saver, `open -a ScreenSaverEngine`, so both runs see identical motion) with and without `ProcessType Interactive` inserted by `plutil -insert ProcessType -string Interactive`.
- **Path D runs from SSH by design:** it is the only GUI-attribution path launched by executing the binary from the SSH shell, because that is the case under test.
- **Rig:** scratchpad copies `vm-office.sh` and `vshot-office.sh`; the executor drives every Settings click.

## Executor constraints (every Phase 17 plan carries these)

- Never run anything on the host that talks to the host's live tailscaled or a 100.x address (only exception: 17-11). Never open Spike.app on the host.
- Never touch `~/Downloads` or `/Applications` on the host. Never stop a Tart VM.
- Evidence: tccd lines filtered to the probe pids, `/Users/<name>` replaced with `/Users/USER`, no tailnet addresses.
- Fail loudly; stage by explicit path only; never stage the root `.gitignore`, `.planning/state.json`, `.ignore`, `agenthub` or milestone `.gitkeep` files.
