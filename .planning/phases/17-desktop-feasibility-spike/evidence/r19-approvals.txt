R19: Screen Recording approval store on macOS 27.2, and what an aged (31 day) approval does to capture
plan 17-09 Task 3, run 2026-11-25 (guest UTC clock, never changed). User paths are redacted to /Users/USER/. The host, portty-test and portty-test-2 were never written and the store was never read on the host. The clone ran as the second macOS VM next to portty-test and was deleted at the end.

== rig notes
- ssh into the clone with the shared VM key, key pushed once over admin/admin with expect. The clone's system TCC database (read with sudo in the clone) already held Full Disk Access for /usr/libexec/sshd-keygen-wrapper and nothing else useful (no Screen Recording, no Accessibility, no PostEvent for the ssh chain), so the click tool, axdump and screencapture over ssh did not work here.
- The screen was driven through the Virtualization.framework VNC server (tart run --vnc-experimental, a one-shot RFB client in the scratchpad, framebuffer 2048x1536). Starting it makes tart open a Screen Sharing window on the host; that window was closed at once and never connected. Passwords typed were the clone's local admin/admin, inside the clone only.
- The clone has a "disk almost full" banner (50 GB image); irrelevant to the rows.
- The clock was not changed: the store was writable, so the plan's clock-jump fallback was not needed.

== grant (as in 17-03)
- open -n Spike.app --args probe --request in the clone raised the first prompt: title "Screen Recording", text: "Spike" would like to record this computer's screen and audio. Grant access to this application in Privacy & Security settings, located in System Settings. Buttons: Open System Settings, Deny.
- System Settings opened on "Screen & System Audio Recording" with a Spike row (off) and a second section "System Audio Recording Only" (empty). Turning Spike on asked for the local password ("Privacy & Security is trying to modify your system settings") and then showed Spike on.
- The next launch of the probe (capture started) raised the second prompt, and this is the monthly one: "Spike" is requesting to bypass the system private window picker and directly access your screen and audio. This will allow Spike to record your screen and system audio, including personal or sensitive information that may be visible or audible. Buttons: Allow, Open System Settings. Frames flowed while it was pending; the dialog stays on screen after the process exits. After Allow, the next launches did not prompt.
- sr_preflight true on the relaunch, Complete frames in every capture.

== the approval store
path: ~/Library/Group Containers/group.com.apple.replayd/ScreenCaptureApprovals.plist (container group.com.apple.replayd; other items in the container: .com.apple.containermanagerd.metadata.plist and an empty Library/ with Application Scripts, Application Support, Caches, Preferences; no other approval file). Mode 600, owned by the login user.
readability: readable over ssh with plutil -p, but only because sshd-keygen-wrapper holds Full Disk Access in this clone. A non-FDA app (Terminal.app running plutil -p on the file) got "you don't have permission to view it" with no prompt. So the product's capture host cannot read the store without Full Disk Access, and this row does not give a store-read detection that works for an ordinary app.
key shape: the key is the app bundle as a file URL with a trailing slash (file:///Users/USER/ptest/Spike.app/), not an executable path. Only the spike's entry existed.
value shape (a dict of five items, other apps' entries not present):
  kScreenCaptureAlertableUsageCount  integer
  kScreenCaptureApprovalLastAlerted  date
  kScreenCaptureApprovalLastUsed     date
  kScreenCapturePrivacyHintDate      date
  kScreenCapturePrivacyHintPolicy    integer 2592000 (30 days in seconds)
first entry, written the moment the first capture started after the grant and the second prompt appeared (04:51:52): UsageCount 1, LastAlerted = LastUsed = 04:51:52, PrivacyHintDate = LastAlerted + 30 days, Policy 2592000. Allow did not change it.

== refresh behaviour
- A relaunch through open (04:53:06) moved LastUsed to the relaunch time and raised UsageCount from 1 to 2. LastAlerted and PrivacyHintDate did not move. Every later capture start raised UsageCount by one and set LastUsed, and nothing else moved while the entry was fresh.
- So the 30 day clock is anchored on LastAlerted (when the prompt was last raised), not on use: using the app does not push the prompt away.
- A test of plutil keypath escaping ran on a copy of the store (/tmp, not the store); plutil -replace with escaped dots in the key (Spike\.app) works.

== reading
- The prompt that comes back monthly is the "bypass the system private window picker" one (second prompt of 17-03), raised on a capture start once the entry's LastAlerted is older than the 30 day policy; the entry is then reset to now.
- The prompt does not stop capture while it is pending: the stream keeps delivering Complete frames. Status counts therefore cannot show "waiting for approval at the Mac".
- A replayd restart freezes a running stream with no error and running still true. The aged entry makes no visible difference to a running stream.

== zero-frame check (no Complete frame for N seconds while the display is awake and unlocked)
- It would NOT have caught the expired approval: with an aged entry a fresh start delivered frames the whole time (R19-b).
- It WOULD catch a replayd restart on a running stream (R19-a and R19-c1 went to 0 Complete and 0 Idle within about 6 s of the restart and never recovered), but it cannot tell that from a still screen: a still screen gives Idle frames for about 6 s and then nothing as well (R19 first run, R22). A usable check needs a nudge: move the pointer or draw something, and treat "no Complete frame within a second of a nudge" as a dead stream, then restart the stream. That design is not measured here.
- A store read is the only signal measured that predicts the prompt (compare LastAlerted plus 30 days with now), and it needs Full Disk Access for the process that reads it; a non-FDA app is refused without a prompt. The prompt itself shows as a dialog window; detecting that window was not measured.

== not claimed
- The real 30 day prompt on the office Mac was not observed; this is a backdated entry in a clone. Whether replayd also raises the prompt in the middle of a stream when the 30 days pass while it runs is not known (backdating a running stream did nothing). Left as a follow-up on the real Mac.
- Nothing here was measured for the in-daemon capture host versus the helper: R19 is measured once, for the app launched with open, and is not a FEAS-02 input.
