== Chrome install in VM home (inside the guest only; the host's Downloads and Applications were not touched)
1. download: curl -fL https://dl.google.com/chrome/mac/universal/stable/GGRO/googlechrome.dmg -> /tmp/chrome.dmg, curl rc 0, 289260301 bytes
2. attach: hdiutil attach -nobrowse -mountpoint /tmp/chromedmg /tmp/chrome.dmg -> ok, volume holds Google Chrome.app
3. signature on the mounted image: `codesign --verify --strict "/tmp/chromedmg/Google Chrome.app"` FAILED (rc 1): "resource fork, Finder information, or similar detritus not allowed" in the Google Chrome Framework subcomponent. This is an extended-attribute complaint about the mounted volume, not a signature mismatch: `codesign --verify --deep` on the same mounted app passed (rc 0), and `codesign -dv` printed Identifier=com.google.Chrome and TeamIdentifier=EQHXZ8M8AV.
4. copy without extended attributes: `ditto --norsrc --noextattr "/tmp/chromedmg/Google Chrome.app" "/tmp/chrome-stage/Google Chrome.app"` rc 0, then `codesign --verify --strict --deep --verbose=2` on the copy: "valid on disk" and "satisfies its Designated Requirement" (rc 0); `codesign -dv` on the copy: Identifier=com.google.Chrome, TeamIdentifier=EQHXZ8M8AV. The copy was verified, not assumed: if stripping attributes had changed signed content, step 4 would have failed.
   spctl -a -t exec on the copy: accepted, source=Notarized Developer ID, override=security disabled (the guest has Gatekeeper assessment switched off, so spctl's "accepted" rests on the notarization source line, not on enforcement).
5. install: `ditto` of the verified copy into the guest's /Applications/Google Chrome.app, rc 0; strict deep verify of the installed app rc 0; TeamIdentifier=EQHXZ8M8AV (checked before Chrome ran); version 158.0.8127.89.
6. cleanup: DMG detached ("disk6" ejected), /tmp/chrome.dmg, /tmp/chrome-stage and the mountpoint deleted.
