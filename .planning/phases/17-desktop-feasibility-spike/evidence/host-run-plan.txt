== The run (offsets in seconds from the moment the capture is running, about 2 s after open)
- Default command: open -n spike/desktop/build/Spike.app --args host-run --bind <this Mac's tailnet IP> --token <fresh token> --evidence-dir <scratch>/hostrun --pattern --dump-at 15s --motion-at 45s --motion-for 60s --sleep-at 120s --wake-after 20s --duration 180s. The first launch adds --request and --duration 150s to raise the prompt, then it is quit; the measured run has no --request.
- Baseline before the run: 30 s of top, pmset -g therm, pmset -g assertions (no network).
- 0-45 s: static test chart; a raw dump and a 3 s H.264 segment at 15 s (for SSIM).
- 45-105 s: the chart's motion region moves.
- 120 s: display sleep. The SCK stream is expected to end (SCError -3815) and not come back, as in the VM. A missing first_frame_after_wake line is the R18-host result, not a failed run.
- 140 s: wake call; because this Mac locks immediately, the wake lands on the lock screen.
- 180 s: the run ends. The user unlocks by hand.
- Viewer: VM home's Safari opens the R01 link at about 5 s (row R01, tag safari-host, ice=lite, 95 s) and the R18 link at about 125 s (row R18, tag safari-host-wake, 45 s). Inside VM home, `tailscale ping -c 5` toward this Mac's address runs once just before the R01 link opens and once just after its report arrives (R01-host path-before, path-after). R01-host is GO only when both read direct.
- Samples: top at about 20 s (static) and 65 s (motion), pmset -g therm at about 110 s. VM office's pipeline is stopped during the perf window; VM home's CPU is recorded separately.
- Do Not Disturb should be on before the run, because a notification banner can sit above the chart and be captured.

== Revoke (inside the go window, right after the run)
- Quit every spike process (matched on the build path only).
- tccutil reset ScreenCapture app.portty.spike
- tccutil reset Accessibility app.portty.spike
- tccutil reset PostEvent app.portty.spike
  Each exits 0 or the plan stops. The helper identity app.portty.spike.helper was not used, so it is not reset.
- Proof, each of which fails on error: `open -n -W spike/desktop/build/Spike.app --args probe --preflight-only` reads all three services false; `spike status` reads NotRegistered or NotFound; pgrep -f 'build/Spike.app' exits 1; launchctl print for app.portty.spike.daemon and .helper says it could not find the service.
- Guard mutations: a sentinel process whose argv contains build/Spike.app is started on this Mac, the exact pgrep gate must exit 0, then the sentinel is killed by PID and the gate must exit 1. The launchctl guard runs only in VM office (a throwaway LaunchAgent, never on this Mac).
- After the revoke the host makes no further tailnet contact.

== What is committed and what is not
- Committed: numbers (R20), the host-run timeline (no address or token), VM home's reports for R01 and the wake window (selectedPair remote address already redacted), a viewer frame of the chart only if it shows nothing else, the iPhone reports, the revoke log.
- Not committed: any frame of this Mac's real desktop, the lock screen (never dumped), any frame showing something other than the chart, any address, token or account or host name. Every frame is read before anything is committed, and every host frame is deleted from the scratchpad.
- The spike never types or logs a password on this Mac.
