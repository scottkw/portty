== sharpness (static window, SSIM) ==
Method: at ready+15 s host-run wrote raw-1.png (the cached Complete frame converted to RGB) and, right after, forced an IDR from the same cached picture into static.h264 (3 s of access units). The segment was copied to the host, the first frame decoded with ffmpeg to decoded.png (2560 x 1440), both scaled to the same size and compared:
  ffmpeg -i raw-1.png -i decoded.png -lavfi "[0:v]scale=2560:1440[a];[1:v]scale=2560:1440[b];[a][b]ssim" -f null -
SSIM R:0.998489 G:0.993309 B:0.998701 All:0.996833
Luma only (format=gray on both inputs): SSIM Y:0.999135
PSNR average 45.55 dB (same inputs, psnr filter)
The picture is the test chart: 9, 11, 13, 16 and 20 pt text black on white and white on black, a one-pixel grid, a 16-step gray ramp. A single IDR of a still picture at 8 Mbps is the best case for sharpness; the motion windows are not scored.
The raw-1.png and static.h264 files are not committed (kept in the session scratchpad); only the numbers are.

== what this does not answer ==
No real display, no real hardware encoder, no thermal data. The guest has no powermetrics (needs root) and pmset -g therm was not read here. The host sub-rows (17-11) carry the real-Mac CPU, latency and SSIM. Apple Silicon timebase for the tick conversion was read at run time (numer/denom from mach_timebase_info).
