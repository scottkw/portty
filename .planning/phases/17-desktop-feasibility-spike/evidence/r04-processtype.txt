## Reading
# The ProcessType key took effect: launchd reports spawn type daemon (3) for the production shape and interactive (4) with the key (the helper runs as interactive (4) in 17-04's r07-A-attribution.txt).
# In this guest the two runs are indistinguishable in throughput: 28.57 against 28.60 Complete frames per second, both close to the 30 fps cap the probe asks for, with no Blank frames.
# Encode latency was a little higher with Interactive (mean 19.1 against 16.9 ms), the opposite of a throttle effect, and within what one run each cannot separate from noise.
# So the VM shows no launchd light-resource-limit throttle on an unspecified ProcessType for a daemon with the GUI closed. It does not show that real hardware behaves the same:
# the guest has no real display or hardware encoder contention, and one 30 s run per setting cannot expose a throttle that engages after minutes or under CPU pressure.
# Consequence for Phase 19: setting ProcessType Interactive is cheap and was harmless here, but nothing in this evidence makes it a requirement for the daemon shape.
