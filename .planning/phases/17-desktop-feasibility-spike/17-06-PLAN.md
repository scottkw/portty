## Flagged decisions and assumptions

- **Office Mac transfer (CONTEXT specifics):** the office Mac runs macOS 27.2.x like the VMs, so these VM lock rows transfer; the host run (17-11) adds a real-Mac lock check on the MacBook Air. Only the lock screen with the user session alive is in scope (pre-login is out of scope).
- **Lock method:** the rig disabled lock and sleep earlier; re-enable only for this plan with `sysadminctl -screenLock immediate -password admin` and lock with the click tool's Ctrl+Cmd+Q (`click key 12 cmd ctrl`). `CGSession -suspend` does not exist on this macOS. Restore `sysadminctl -screenLock off -password admin` at the end.
- **R15/R17 unlock uses the click tool; R16 must not:** R16 measures injection from the capture-host process, so the unlock keys come from `probe-loop --type-after --type-keycodes` inside the helper or daemon. Keycodes for "admin" then Return: 0, 2, 46, 34, 45, 36 (the VM's public password; memory note). Never type any other password.
- **Grants:** 17-05 reset and re-granted only the daemon identity. Before the helper runs, check its grant; if it prompts, grant it by driving Settings and record that it was re-granted.
- **Routing:** if R00 routed lock frames to host-run, record CGSession and continuity here and mark the frame part ROUTED:host-run.
- **Provisional pick reversibility:** costly (CONTEXT: the capture-host result fixes process architecture, bundle layout, signing and TCC identity for later phases). It is flagged, not gated: the rule was written before the evidence, and 17-12 confirms or revises the pick with the remaining rows.
