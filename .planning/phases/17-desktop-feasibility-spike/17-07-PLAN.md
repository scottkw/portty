## Flagged decisions and assumptions

- **Re-key is the user's (CONTEXT, memory):** the VMs use ephemeral keys and Tailnet Lock; the classifier blocks the agent from signing. Task 1 automates everything else and prepares the commands with a `<your key>` placeholder; Task 2 waits for the user.
- **Auth key stays out of the transcript (checker iteration 1, orchestrator direction):** the user runs the re-key in their own terminal outside Claude Code, then signs with `tailscale lock sign`; the checkpoint asks only for "done" plus the two VM node names. The executor never asks for, echoes, stores or runs a command containing a real auth key.
- **Skip path:** if the user replies "skip: reason", append `user skip (tailnet re-key): <reason>` to evidence/rig-tailnet.txt, skip Task 3, and set R01-vm, R11, R22 and R23 to PARTIAL with `basis: user-skip; follow-up: <reason>`, citing evidence/rig-tailnet.txt, each with `shape: none (user-skip)` in its Procedure cell. That line is the phase's tailnet-skip record: every later plan checks `grep -l '^user skip (tailnet re-key):' evidence/*.txt` first and, when it lists a file, closes its tailnet rows PARTIAL user-skip instead of raising another re-key checkpoint.
- **No host tailnet contact:** every tailnet command (`tailscale status`, `tailscale ip -4`, `tailscale ping`, Safari) runs inside a guest over the Tart LAN SSH. The host never opens a 100.x address.
- **Shape:** run the pipeline in the shape on the `Pipeline shape:` line of `## FEAS-02 decision` (17-06 sets it for every provisional outcome, including NO-GO and OPEN; helper: register with agent-A.json; daemon: path B plist with agent-B.json). The agent argv is `serve`. Every row this plan writes records `shape: <helper or daemon>` in its Procedure cell; 17-12 re-runs R01-vm, R22 and R23 if the final decision names the other shape. If R00 routed the browser rows to VM-synthetic, use `--source synthetic` and say so in each row.
- **Direct path is a GO condition for R01-vm (checker iteration 2):** the port filter cannot see a DERP relay (DERP runs over HTTPS to Tailscale's relay servers), so `tailscale ping` from VM home to VM office's tailnet address runs once just before and once just after the Safari session. Each run is classified from its last line: `direct` when the last pong says `via <ip>:<port>`, `derp` when it says `via DERP(...)`, `none` when no pong came back. Both must be `direct` for R01-vm to be GO; otherwise R01-vm is PARTIAL with `basis: ran; follow-up: tailnet path <derp or none>, SC1 clause "no STUN, TURN or cloud server involved" not shown, re-run on a direct path`. The pings run inside VM home, never on the host.
- **Wave order (checker iteration 2):** this plan runs in wave 8, after 17-09 (wave 7). 17-09's R19 clone needs a free macOS VM slot (Virtualization.framework runs at most two macOS guests at once), so portty-test-2 stays stopped until this plan's Task 1 boots it.
- **VMs stay up from here to 17-11:** stopping either VM for hours deletes it from the tailnet and forces another re-key. Tell the user in the checkpoint.
- **Plain http first:** WebKit may restrict some APIs to secure contexts. If Safari refuses RTCPeerConnection on http, record that, then retry over HTTPS with a self-signed certificate created in VM office for its tailnet IP and trusted only in VM home's System keychain (`serve --tls-cert --tls-key`), and record both attempts.
- **Token handling:** generate a fresh 128-bit token on the host (`openssl rand -hex 16`) into the session scratchpad; it lives in the guest's agent JSON and in the URL only; the server never writes it into reports.
