## Flagged decisions and assumptions

- **17-10-SUMMARY is a genuine input:** it carries the rehearsed host-run command line and any flag changes.
- **Never start without go (CONTEXT):** Task 2 is a blocking user checkpoint. The user supplies this Mac's tailnet address from `tailscale ip -4`; the executor never queries the host's tailscaled. Only after "go" may the host bind or reach a 100.x address, and only until Task 3 finishes.
- **Viewer (CONTEXT user answer):** VM home's Safari views the host run; the iPhone views VM office, separately.
- **Prompts on the host:** the user approves the Screen Recording prompt for "Portty Spike" (and Accessibility or PostEvent for the one-character test) in System Settings. The executor detects approval from `log stream --predicate 'subsystem == "com.apple.TCC"'` (AUTHREQ_RESULT with authValue 2 for the spike) instead of polling a TCC API, then relaunches without `--request`.
- **One harmless character (P3):** keycode 7 (x) only, allowed by `--allow-keycodes 7`; the user unlocks by hand afterwards. The spike never types the user's password.
- **Never committed from the host:** the lock-screen frame (it shows the user's name) and any frame showing anything other than the test chart. The executor reads `raw-2.png` (lock screen) to describe it, records mean luma and status counts only, and deletes it.
- **Skip path:** if the user replies skip for the host run, R01-host, R18-host and R20-host become PARTIAL with the VM sub-rows as evidence and `follow-up:` text, and roadmap SC1's real-Mac part is reported to the verifier as not met.
- **Perf confound (RESEARCH):** VM home runs on this Mac as the viewer; its CPU is recorded separately; VM office's pipeline is stopped during the perf window.
