## Flagged decisions and assumptions

- **Test content only (RESEARCH Pitfall 9, P2):** the chart window covers the whole main display above the menu bar, so frames captured on the host show only the chart. The host's lock screen (which shows the user's name) is inspected but never committed (17-11).
- **Scheduled actions instead of clicks:** host-run performs the display sleep (`pmset displaysleepnow`) and the wake (`IOPMAssertionDeclareUserActivity`) itself on a schedule, and the data channel `wake` message does the same on demand. Who triggers the wake does not change what R18 measures, and nobody has to click in a WebKit page the VM cannot screenshot.
- **Own-process CPU undercounts (RESEARCH Pitfall 5):** capture and encode work lands in replayd, WindowServer and the VT service. host-run records its own CPU; the run plans add `top` samples of the top processes and system idle.
- **Main thread:** the chart needs AppKit on the main thread. When argv[1] is host-run, lock the OS thread in init and run the NSApplication loop on it; the server and sampler run on goroutines.
- **VM rehearsal password:** the VM's admin password is public; typing it from host-run in the VM re-checks R16's path. On the host the spike types nothing by default: key input is passed only when the Routing table sends R16 to host-run and the user re-approves typing at 17-11's checkpoint, and then only keycode 7 (checker iteration 1).
- **Schedule fits the CONTEXT budget (about 10 minutes for the whole host window):** the measured host run is 180 s (static chart 0-45 s with a dump at 15 s, motion 45-105 s, display sleep at 120 s, wake 20 s later, end at 180 s). The rehearsal uses the same offsets so the host command is the tested one; only the VM adds a typed unlock at 160 s and runs to 200 s.
- **Wave order:** this plan depends on 17-08 (wave 9); 17-09 now runs earlier, in wave 7, so its Opus build is already in the bundle this plan rebuilds.
- **Tailnet skip (checker iteration 2):** when `grep -l '^user skip (tailnet re-key):' evidence/*.txt` lists a file, the rehearsal does not need the tailnet and raises no re-key checkpoint: host-run binds VM office's Tart LAN address with `--allow-lan` and VM home Safari opens that address; both rows say `viewer path: Tart LAN (tailnet skipped)` in their Procedure cell. The command lines written for 17-11 keep `--bind <IP>`.
- **Launch-path deviation (checker iteration 1):** host-run starts as the GUI app via `open -n`, not in the FEAS-02 picked shape, so the real Mac gets no LaunchAgent or SMAppService registration. Every row measured with host-run (R18-vm, R20-vm here; the host sub-rows in 17-11) states this in its Procedure cell as `launch path: GUI app via open; picked shape <shape> not used` and points to R04-none and R04-interactive for the throttle effect a launchd job would add.
