## Flagged decisions and assumptions

- **Monthly re-approval (CONTEXT Decided autonomously [Monthly re-approval]):** read the stored approval and record observed behaviour; the real 30-day prompt becomes an M-NN item (numbered in 17-12). Backdating the store is the strongest available evidence short of waiting a month.
- **Clock-jump fallback only on a disposable clone (RESEARCH R19, Pitfall 7):** if the approvals file cannot be read or written in VM office, clone the local vanilla image `ghcr.io/cirruslabs/macos-golden-gate-vanilla:27.2` (it has no tailnet identity), give it 4 GB and 2 CPUs, push the SSH key with `/usr/bin/expect` over its admin/admin password, deploy Spike.app, grant it, then jump the clock 31 days. Never clone portty-test or portty-test-2 (a clone duplicates the ephemeral tailnet identity and can knock the original offline). Delete the clone afterwards with `tart delete`.
- **Never on the host:** the approvals plist is never read on the host (App Data prompt risk).
- **Audio in a VM:** the guest may lack a useful audio device. Whatever SCK delivers is the answer; a capture NO-GO in the guest becomes a host-run sub-check only if the Routing table allows it, otherwise a follow-up.
- **Host-safe encode check:** `opusprobe --source sine` calls no TCC API, so the build verify runs it on the host (RESEARCH already proved AudioConverter Opus on this host).
