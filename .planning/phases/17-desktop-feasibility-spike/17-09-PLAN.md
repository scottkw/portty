## Flagged decisions and assumptions

- **Monthly re-approval (CONTEXT Decided autonomously [Monthly re-approval], SUPERSEDED 2026-11-24 by user decision):** backdating the approval record or jumping the clock is allowed, but only inside a disposable VM clone that is off the tailnet; the host and the tailnet VMs are never written. So all of R19 runs in the clone `spike-r19`, and nothing in Task 3 touches portty-test or portty-test-2. The real 30-day prompt becomes an M-NN item (numbered in 17-12). Backdating the store, or a clock jump when the store cannot be written, is the strongest available evidence short of waiting a month.
- **The clone (RESEARCH R19, Pitfall 7):** clone the local vanilla image `ghcr.io/cirruslabs/macos-golden-gate-vanilla:27.2` (present in `tart list`; it has no tailnet identity) as `spike-r19`, give it 4 GB and 2 CPUs, push the SSH key with `/usr/bin/expect` over its admin/admin password, then check it is off the tailnet before anything else: `test ! -e /usr/local/bin/tailscale`, `test ! -e /Applications/Tailscale.app` and `pgrep -x tailscaled` exiting 1; if any check fails, delete the clone and stop with a checkpoint instead of continuing. Never clone portty-test or portty-test-2 (a clone duplicates the ephemeral tailnet identity and can knock the original offline). Delete the clone afterwards with `tart stop` and `tart delete`.
- **Wave order and the two-VM limit (checker iteration 2):** Virtualization.framework runs at most two macOS guests at once, and portty-test-2 must never be stopped once 17-07 has put it on the tailnet. This plan therefore runs in wave 7 (depends on 17-06), before 17-07 (now wave 8) boots portty-test-2: portty-test plus spike-r19 make two. R21 and R19 need no tailnet.
- **R19 is not a FEAS-02 input:** the decision rule's tiebreaker counts only the per-shape R09 entries (17-01, drift item 6), so R19 is measured once, for the app launched with `open`, and informs DPRM-03 only.
- **Never on the host:** the approvals plist is never read on the host (App Data prompt risk).
- **Audio in a VM:** the guest may lack a useful audio device. Whatever SCK delivers is the answer; a capture NO-GO in the guest becomes a host-run sub-check only if the Routing table allows it, otherwise a follow-up.
- **Go hygiene (CLAUDE.md):** the Go-touching verify runs `gofmt -l` (must list nothing) and `golangci-lint run` inside the spike module, next to `go vet`.
- **Host-safe encode check:** `opusprobe --source sine` calls no TCC API, so the build verify runs it on the host (RESEARCH already proved AudioConverter Opus on this host).
