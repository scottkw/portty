## Flagged decisions and assumptions

- **17-01-SUMMARY is a genuine input:** this plan extends `bridge_darwin.go`, `media_darwin.m` and `main.go` from 17-01 and reuses its `startSource` seam.
- **One binary, three signings (RESEARCH Pattern 1):** `Contents/MacOS/spike` is the registrar app and the daemon; `Contents/Helpers/spike-helper` is a signed copy with identifier `app.portty.spike.helper`. Bundle ids `app.portty.spike*`, never `app.portty.Portty`, so no TCC row is shared with a real Portty install.
- **Signing (CONTEXT Decided autonomously [Signing]):** Developer ID Application: Ken Scott (S2K7P43927), hardened runtime, timestamp, inside-out with no deep-signing flag (a dry run of REL-01's nested signing). No notarization (RESEARCH A8: a non-quarantined, Developer ID signed app copied over tar launches without a Gatekeeper dialog; R00 confirms it in the VM).
- **Keychain dialog (RESEARCH A12):** the first `codesign` with the Developer ID key may raise a Keychain access dialog on the host. That is an authentication gate the executor never answers itself: it pauses and asks the user (Task 2 action gives the detection and the checkpoint text), then retries. Not pre-planned as a task because it may not appear.
- **File count (10, at the warn threshold), kept on purpose:** five of the ten paths are small static bundle inputs (Info.plist, entitlements, two launchd plists, build.sh) that only make sense together, and the other five are the probe code the bundle runs. Splitting the bundle from the probe kit would produce a bundle with nothing to launch, or probes with no signed shape to run in.
- **Go hygiene (CLAUDE.md):** each Go-touching verify runs `gofmt -l` (must list nothing) and `golangci-lint run` inside the spike module, next to `go vet`.
- **Launchd entry `agent --config` (Claude's discretion):** both plists start `agent --config <json>`; the JSON holds the argv to run (`probe-loop ...` or `serve ...`). Plists stay static and later plans change behaviour by writing a config file in the guest, with no rebuild.
- **Legacy plist shape:** copies the kardianos v1.2.4 template Portty installs today (`internal/daemon/service.go`: `RunAtLoad` true, `KeepAlive` false; template also writes `Disabled` false and `SessionCreate` false; no `ProcessType`, no `LimitLoadToSessionType`). The R04 `ProcessType Interactive` sub-row inserts the key at deploy time with `plutil`.
- **Host safety:** nothing in this plan launches Spike.app or calls a TCC API on the host. `vmprobe` without `--encoders-only` and `probe` without `--no-tcc` run only in the VMs (17-03 onward). `status` makes no TCC call (it reads SMAppService state), so Task 3 runs it on the host by direct execution as a baseline. `probe --preflight-only` calls TCC preflight APIs, which never prompt, but its answer is only meaningful when the app is launched with `open` (direct execution reads the terminal's grants), so on the host it runs only inside 17-11's go window.
- **Pinned JSON keys (checker iteration 2):** later gates (17-03 to 17-12) read only the keys listed in `## Pinned JSON keys` below and in 17-01's list; the producers here write exactly those names.
- **Spec-less probe:** P4 carried. FEAS-01 concurrency edge: each probe record carries its pid (consumed by 17-03..17-06).

## Pinned JSON keys (extends 17-01's list; 17-03 to 17-12 gates read only these)

A key whose step did not run is omitted, never null, so `has()` tells whether a step ran; a step that ran and failed carries `{"error": {"domain": ..., "code": ..., "message": ...}}` as its value. TCC answers (`sr_preflight`, `sr_request`, `ax_trusted`, `ax_prompt`, `post_event_preflight`) and `mouse_nudge` are JSON booleans.
- `capture` (spk_sck_stats): `status` (object with `complete`, `idle`, `blank`, `suspended`, `started`, `stopped` counts), `firstFrameMs`, `completeFps`, `encodeLatencyMs` (object with `mean`, `p95`, `max`), `pixelFormat`, `ioSurface`, `width`, `height`, `running`, `error`.
- `encoders` (spk_encoder_list): array of objects with `id`, `name`, `hardware`. `encoder` is spk_encoder_info as pinned in 17-01.
- vmprobe (`r00-vmprobe.json`): `pid`, `hv_vmm_present` (0 or 1), `macos` (object with `version`, `build`), `sr_preflight`, `sr_request` (only with `--request`), `displays` (array of objects with `id`, `width`, `height`), `capture`, `png`, `luma`, `encoders`, `encoder`, `h264`. vmprobe runs every step even after one fails, so outside `--encoders-only` the keys `hv_vmm_present`, `displays` and `encoders` are always present (a failed step holds its error object); `--encoders-only` writes only `pid`, `macos`, `encoders`, `encoder`, `h264`.
- ProbeRecord (`probe`, every `probe-loop` line, and `agent` runs of either): `label`, `time`, `pid`, `ppid`, `pgid`, `sid`, `executable`, `macos`, `managername`, `session` (the CGSession dictionary as an object), `sr_preflight`, `sr_request`, `displays`, `capture`, `png`, `luma`, `ax_trusted`, `ax_prompt`, `post_event_preflight`, `mouse_nudge`, `typed` (keycodes posted by `--type-keycodes`, numbers only). `--no-tcc` omits every key from `sr_preflight` to `mouse_nudge`. A `--stream` loop line adds `delta` (status-count deltas since the previous line), `streamRunning` and `latestError`.
- `probe --preflight-only`: `label`, `time`, `pid`, `sr_preflight`, `ax_trusted`, `post_event_preflight`, and nothing else.
- `register`, `unregister`, `status`: `verb`, `plist`, `status` (one of `Enabled`, `RequiresApproval`, `NotRegistered`, `NotFound`), `error` (only on failure). Written to stdout and, with `--out`, to that file.
- Never touch `~/Downloads` or `/Applications` on the host. Never stop a Tart VM.
- Never write the old product name, the macOS package manager's name or its absolute ffmpeg path into a spike file; keep spike identifiers clear of the vocabulary `internal/release/no_autosave_test.go` and `no_progress_when_off_test.go` forbid.
- Fail loudly: record OS error domain and code, exit non-zero, no silent defaults.
- Stage files by explicit path only; never stage the root `.gitignore`, `.planning/state.json`, `.ignore`, `agenthub`, or `.gitkeep` files under `.planning/milestones/`.
