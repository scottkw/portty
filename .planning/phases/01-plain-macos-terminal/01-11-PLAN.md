## Phase Goal

The app is a plain macOS terminal: new sessions run macOS zsh (`/bin/zsh -l`), no agent-CLI, file-browser, or Windows/Linux code remains, and every kept feature still works. (ROADMAP Goal, verbatim. It is not in user-story form and no story is invented here.)

This plan delivers ROADMAP success criterion 1's fixed-shell half (TERM-01 as reworded: `/bin/zsh -l`, no shell choice, no Settings → Paths), per CONTEXT Amendment 1 ("Shell: always macOS zsh"). It also removes the awaiting-input notification toggle and its settings key, per CONTEXT Amendment 2, because that toggle lives in the same settings plumbing.

<objective>
Fix the spawned shell to /bin/zsh -l. Remove the New Session dialog's shell line, the whole Settings → Paths section, and the shellPath/cliPaths/OpenFileDialog plumbing (engine, daemon routes, client, Wails bindings). Remove the awaiting-input notification toggle with its settings key, routes, bindings and the toggle-only proactive-authorization path. Keep sendNotification as the one native path. Old settings files keep loading, and the removed keys drop on the next save.

Purpose: CONTEXT Amendment 1 (fixed zsh; delete Settings → Paths "including the stale-path filter and the cliPaths override plumbing"; legacy shellPath/cliPaths load and are dropped on the next save) and Amendment 2 (drop the awaiting-input toggle plus its settings key handling; keep a minimal notification path for Phase 6).
Output: constant spawn plus tests, a directory-only New Session dialog, Settings without Paths or the notify toggle, an extended negative route test and legacy settings test, and a slimmer notification plumbing.
</objective>
