## Phase Goal

The app is a plain macOS terminal: new sessions run the user's login shell, no agent-CLI, file-browser, or Windows/Linux code remains, and every kept feature still works. (ROADMAP Goal, verbatim; not in user-story form, no story invented.)

This plan replaces agent awaiting-input notifications with program-agnostic bell / OSC 9 notifications (STRP-01 decision), fixes exit reporting for long-lived and relaunched sessions (TERM-02, resolved question 3), and closes the phase with a full regression and TESTING.md reconciliation (STRP-04, TERM-04).

<objective>
Hook BEL and OSC 9 on the relay hub's existing live VT emulator, carry a per-session bell counter to the GUI, and fire one rate-limited native notification when the window is hidden; emit session:exit for sessions that stop after the 5-minute fast-poll window or were reopened after relaunch; update Settings copy; reconcile TESTING.md and run the full phase gate.

Purpose: CONTEXT "Replace awaiting-input notifications with a generic trigger..." (the user runs Claude Code inside shells), UI-SPEC section 4, resolved questions 2 and 3.
Output: hub bell hooks + BellState, SessionInfo bellSeq/bellText, maybeNotifyBell, tray-poller exit emission, Settings copy, final TESTING.md.
</objective>

- internal/relay/hub.go builds the live emulator in three places: recordFrame eager build (~488), resizeLiveEmulator rebuild (~529), EnsureLiveEmulator empty build (~945); each calls xvt.NewEmulator then SetScrollbackSize(liveEmulatorScrollbackLines). recordFrame holds emuMu and runs on the PTY drain goroutine; callbacks must be non-blocking (atomics or a tiny dedicated mutex; never hub.mu or engine locks). Do NOT wire hooks on internal/daemon/engine.go's styled-tail preview emulator (~793): it replays scrollback and would re-count old bells.
- charmbracelet/x/vt: emu.SetCallbacks(xvt.Callbacks{Bell: func()}) fires only for a C0 BEL in ground state (a BEL that terminates an OSC string dispatches the OSC instead); emu.RegisterOscHandler(9, func(data []byte) bool) receives data including the "9;" prefix (handle with TrimPrefix, not Split, because the text may contain ';'). See RESEARCH Pattern 1 for the helper shape.
- liveEmuQueryStripPattern only strips DA/DECRQM/OSC 10-12 queries, never BEL or OSC 9.
- engine.go ListSessions already calls e.manager.Get(s.ID) for RemoteViewerCount; daemon SessionInfo is the socket JSON; app.go SessionInfo mirrors it via ListSessions mapping (omitting a field silently drops it, see the UAT-bug comments there).

Plan 01-06 removed maybeNotifyWaiting.
- tray.go setDockVisible(visible bool) (darwin, cgo) is called by every show/hide path (domReady, beforeClose, QuitGUIOnly, tray show/hide); initial hidden state matches StartHidden: true. Wails v2 has no WindowIsVisible; do not call WindowIsMinimised from the poller goroutine (RESEARCH A7). "Hidden" in this phase means hidden to the tray (RESEARCH A8; recorded for UAT).
- relay.SanitizeChatContent strips C0 (including NUL), DEL, C1 and bidi overrides; reuse it.
- pollSessionStatus (app.go ~402) polls every 500ms for maxPollWindow = 300s (comment "extended to 5min for long-running agents"), emits session:status on change and session:exit via emitExitEvent when State == "stopped"; only CreateSession starts it, so sessions reopened after relaunch never get exit events. emitExitEvent calls runtime.EventsEmit guarded by a.ctx frontend value. App.tsx handles session:exit for unknown session ids harmlessly.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PTY output (any program, or a read/write web guest typing into the shell) → hub emulator | Untrusted bytes decide bell counts and notification text |
| daemon → GUI notifier → macOS Notification Center | Attacker-influenced text reaches a native notification and a C string |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-31 | Spoofing | OSC 9 notification text | medium | mitigate | Body always prefixed with the session name; toggle default OFF; fires only while hidden; text sanitized with SanitizeChatContent and truncated to 200 runes; read-only guests cannot write to the PTY |
| T-01-32 | Denial of Service | bell flood (e.g. `yes $'\a'`) | medium | mitigate | 30s per-session limit with a stable identifier (replace, not stack); hub callback is an O(1) atomic increment so the drain loop is never slowed |
| T-01-33 | Tampering | NUL/control bytes in the C string passed to UNUserNotificationCenter | medium | mitigate | SanitizeChatContent strips C0 (including NUL) and C1 before sendNotificationFunc; unit test covers control characters |
| T-01-34 | Denial of Service | callbacks running under emuMu on the PTY drain goroutine | medium | mitigate | Callbacks use only atomics and a dedicated tiny mutex, never hub.mu or engine locks; -race run in verify |
