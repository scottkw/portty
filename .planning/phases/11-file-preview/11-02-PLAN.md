## Flagged decisions and assumptions

- **Wire layout (RESEARCH Pattern 1; normative for 11-04 and 11-05):**
  - header: byte 0 `MsgPreview` (0x21), byte 1 `0x01`, then JSON `{"id":<uint32>,"name":"<base name>","mime":"<one of PreviewMIMEs>","size":<bytes>,"key":"<32 lowercase hex>","focus":<bool>}`.
  - chunk: `0x21`, `0x02`, the id as 4 bytes big-endian, then at most `PreviewChunk` (16 << 10) payload bytes.
  - end: `0x21`, `0x03`, the id as 4 bytes big-endian, one status byte: 0 ok, 1 aborted, 2 too large.
  - The id is a per-hub counter starting at 1. `key` identifies "the same file again" for the viewer (UI-SPEC: refresh in place); the CLI derives it from the absolute path and the path itself never leaves the CLI. `PreviewMIMEs` is exactly: `image/png`, `image/jpeg`, `image/gif`, `image/webp`, `image/svg+xml`, `application/pdf`, `text/markdown`.
  - `PreviewMaxBytes = 20_000_000` (CONTEXT after UI-SPEC: "the cap is 20,000,000 bytes so '20 MB' is exact"). `PreviewWindow = 16`. `previewStallTimeout` is a package var (60 s; tests shorten it).
  - Old viewers drop the new type (RESEARCH Pattern 1: JS `unknown`, Go attach loops have no default arm) and the peer proxy copies frames verbatim, so no proxy change.
- **SendPreview shape (RESEARCH Pattern 2; Claude's discretion on names):** `func (h *Hub) SendPreview(p Preview) (PreviewSend, error)` with `Preview{Name, MIME, Key string; Data []byte}` and `PreviewSend{Viewers int; Done <-chan struct{}}`. It validates (`len(Data) <= PreviewMaxBytes`, MIME in the set, key 32 lowercase hex, name non-empty, at most 255 bytes, valid UTF-8, no control characters; else `ErrPreviewInvalid`), returns `ErrPreviewBusy` while a preview streams, and an error once the hub is done. Under `h.mu` it snapshots targets (subscribed, `!replaying`, not `revoked`) and reads `h.owner`; with no targets it returns `Viewers: 0` and a closed Done at once. Otherwise it starts one goroutine per target and returns immediately; Done closes and the busy flag clears when every target finished.
  - Per frame a target goroutine takes `h.mu`, stops if the subscriber is no longer in `h.subscribers` or the hub is closed, and sends only when `len(sub.Msgs) < PreviewWindow` (every producer enqueues under `h.mu`, so that send can never block); otherwise it unlocks and sleeps briefly (a few ms, backing off to about 50 ms). No progress for `previewStallTimeout`: enqueue `end status=1` only if there is room, never kick, stop.
  - It must not call the hub's queue-or-kick helper (sendLocked) or its broadcast: both kick a full queue (hub.go sendLocked).
  - Logs (no file name, which is user content): `viewer-diag: preview start session=<DiagID> id=<n> viewers=<n> bytes=<n> mime=<mime>` and per target `viewer-diag: preview end session=<DiagID> conn=<n> id=<n> status=ok|aborted|left|ended sent=<bytes> elapsed=<d>`. 11-10 greps these in the VMs.
  - Previews are never part of `HubState` (handoff): a preview in flight at a handoff ends when viewers get 1012; viewers discard partial assemblies (11-05).
