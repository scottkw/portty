- **Sanitizer (RESEARCH "Sanitizer configuration", Pitfalls 8-9; UI-SPEC "Markdown").**
  - `new Marked({gfm: true, async: false, renderer: {...}})` with overrides: `html` returns an empty string (raw HTML dropped, layer 1); `image` returns `<span class="md-image">` holding the escaped alt text or `Image`; `checkbox` returns a non-interactive glyph span (`md-task` with ☑ or ☐), so the sanitizer never needs `<input>` while UI-SPEC's "render disabled and checked or unchecked as written, not clickable" holds (CONTEXT "Decided at planning" accepts the glyphs). Confirm the v18 renderer signatures against the pinned version in the tests (Assumption A4).
  - `DOMPurify.sanitize(html, {ALLOWED_TAGS: [h1..h6, p, br, hr, ul, ol, li, blockquote, pre, code, em, strong, del, a, table, thead, tbody, tr, th, td, span], ALLOWED_ATTR: [href, class, title, align], ALLOWED_URI_REGEXP: /^(?:https?:|mailto:|#)/i, ALLOW_DATA_ATTR: false, ALLOW_ARIA_ATTR: false, FORBID_ATTR: [style]})`. No profiles (a profile overrides the allowlists and turns SVG/MathML on), no ADD_TAGS, no hooks, and none of the IN_PLACE, SAFE_FOR_TEMPLATES or RETURN_DOM modes (the 2026 advisories live there: RESEARCH "Why DOMPurify advisory churn is acceptable").
  - MarkdownPreview assigns the sanitized string once (dangerouslySetInnerHTML on `<article class="preview-markdown" aria-label="<name>" tabindex="0">`), then decorates the attached result with trusted DOM calls only: each `a[href]` gets `title` = its href; each `.md-image` gets `role="img"`, `aria-label="Image: <alt>"` and a 14px PhotoIcon built with `document.createElementNS`; each table is wrapped in `div.md-table-wrap` for horizontal scroll. Unsanitized HTML never touches a live or detached DOM node (Pitfall 8).
  - Links (Pitfall 7): one delegated handler for click, auxclick and Enter calls preventDefault for every anchor; `#fragment` scrolls to the first heading whose slug (lowercase, spaces to hyphens, punctuation dropped) matches the decoded fragment, and no id attribute is ever added; otherwise `isAllowedScheme`, then `getRisk(textContent, href)`, then `LinkConfirmPopover` (risky) or `openLink`. Prose link text counts as a display/href mismatch in getRisk (the terminal's existing osc8 rule), so most Markdown links confirm first; that is the existing rule, kept. Anchors without href (stripped schemes) get no link styling: style only `a[href]`.
  - DoS bounds: a 10,000-level nested list or blockquote and a 2 MB single line render without throwing within the test's timeout.
