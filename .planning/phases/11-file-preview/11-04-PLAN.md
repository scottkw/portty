## Flagged decisions and assumptions

- **Route placement (RESEARCH Pattern 3).** `a.mux.HandleFunc("POST /sessions/{id}/preview", a.handlePreview)` in registerRoutes, beside `POST /handoff` (api.go ~199). Never on RelayHandler (127.0.0.1 TCP: any local process and any browser page can reach it) or the share server (tailnet-exposed). The socket's protection is its 0700 parent dir (socket.go DefaultSocketPath), the same as every other mutating route, so no peer-credential check is added (simplicity; parity with create/kill/share).
- **Request shape.** Body = the file's bytes. Headers: `X-Portty-Name` (the base name, percent-encoded with url.QueryEscape so any UTF-8 name survives HTTP header rules; the handler decodes it), `X-Portty-Mime` (one of relay.PreviewMIMEs), `X-Portty-Key` (32 lowercase hex, the CLI's hash of the absolute path). No path field, header or query parameter exists.
- **Handler order:** hub lookup `a.engine.Manager().Get(id)` (missing 404; hub done 409) → MIME (415) → key and name (400; name cleaned: drop everything up to the last `/`, remove C0/C1 controls and U+202A–U+202E and U+2066–U+2069, trim, cap 255 bytes at a rune boundary, empty after cleaning is 400) → `Content-Length` over relay.PreviewMaxBytes is 413 before reading, and the body is read through `http.MaxBytesReader(w, r.Body, relay.PreviewMaxBytes)` (overflow 413) → `hub.SendPreview` (relay.ErrPreviewBusy is 429 with `Retry-After: 1`; ErrPreviewInvalid 400) → 202 with `{"viewers":n}`. SendPreview returns at once and streams on its own goroutines, so the handler (and the freeze gate's write lock it holds for the whole request, api.go freezeGate/enterWrite) is done as soon as the body is buffered (RESEARCH Pitfall 4: a handoff drains writes for only writeDrainTimeout = 1 s).
  - Daemon log on accept: `viewer-diag: preview accepted session=<DiagID> bytes=<n> mime=<mime> viewers=<n>` (no file name). Relay logs the per-viewer start and end (11-02).
- **Frozen daemon:** a POST during a handoff freeze already gets 503 with Retry-After from the freeze gate; `doRetrying` retries mutating calls within frozenRetryBudget and needs a fresh body per attempt (client.go ~308-341): SendPreview's request closure builds a new `bytes.Reader` each time. Extend doRetrying to wait out a 429 that carries Retry-After the same way (only the preview route sends 429), so `portty open` run twice quickly waits for the first preview instead of failing.
- **API version (CONTEXT "Session id": "`APIVersion` goes to 3, with a `PreviewAPI` gate for the CLI").** `APIVersion = 3`, new `PreviewAPI = 3`; `MinDaemonAPI` stays 1 so an older daemon kept with Not Now keeps serving everything else. - **Source gate (RESEARCH "Anti-Patterns"; PREV-03).** A test parses internal/daemon/preview.go and internal/relay/preview.go with go/parser and fails if either imports `os`, `io/fs` or `path/filepath`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local process → daemon socket | any process of the same user can POST; the socket's 0700 parent dir keeps other users out |
| browser page → loopback relay | a web page can reach 127.0.0.1:<relayPort>, so nothing that injects content may live there |
| tailnet → share server | tailnet devices reach the share server with a capability token |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-11 | Information disclosure | daemon/share server routes | high | mitigate | No route takes a path; preview.go and relay/preview.go import no file package (TestPreview_SourceGate); TestPreview_NotOnRelayHandler and TestPreviewRoute_NotOnShareServer prove absence (PREV-03) |
| T-11-12 | Spoofing | preview injection from a web page or another user | high | mitigate | Route only on the unix socket mux (0700 dir); not on RelayHandler, which browser pages can reach; client-to-server 0x21 frames are dropped by both read pumps (no case arm) |
| T-11-13 | Denial of service | request body | high | mitigate | Content-Length check and http.MaxBytesReader at relay.PreviewMaxBytes; one in-flight preview per hub (429); TestPreview_Refusals, TestPreview_BusyIs429 |
| T-11-14 | Denial of service | Phase 9 upgrade handoff | high | mitigate | Body buffered, 202, streaming after the response, so the freeze gate's write lock is released before the drain; TestPreview_HandoffDrainNotBlocked |
