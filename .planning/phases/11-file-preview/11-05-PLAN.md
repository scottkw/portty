## Flagged decisions and assumptions

- **Wire layout** is the Go fixture's (11-02): header `0x21 0x01` + JSON `{id, name, mime, size, key, focus}`; chunk `0x21 0x02` + id (4 bytes big-endian) + payload; end `0x21 0x03` + id + status (0 ok, 1 aborted, 2 too large). The tests read the committed fixture, so the parser cannot drift from Go.
- **Viewer-side MIME map (never the header string verbatim):** `image/png`, `image/jpeg`, `image/gif`, `image/webp` give kind `image`; `image/svg+xml` gives `svg`; `application/pdf` gives `pdf`; `text/markdown` gives `markdown`. The Blob's type comes from the viewer's own constant for that kind. Any other MIME: the header is ignored (no event) and a console warning is logged.
- **Assembler (pure, one per RelayClient connection):** events `start {id, name, kind, mime, size, key, focus}`, `progress {id, received}` (throttled to one per 100 ms, plus the last), `complete {id, blob}`, `failed {id, reason: 'tooLarge' | 'incomplete'}`. Rules: a header with size above PREVIEW_MAX_BYTES (20,000,000) emits `start` then `failed tooLarge` and accepts no bytes; chunks for another id are ignored; received bytes above the cap fail `tooLarge`, above the declared size (but within the cap) fail `incomplete`; end status 2 is `tooLarge`, status 1 or a byte count different from the declared size is `incomplete`; a new header while one is open fails the open one `incomplete`; reset fails the open one `incomplete`. Chunks are kept as an array of the frames' payload views and dropped once the Blob exists (peak about twice the size, transient). The header's `focus` is passed through unchanged; App applies the focus rule (11-09).
- **cleanPreviewName:** remove C0 and C1 controls and U+202A–U+202E, U+2066–U+2069; cap at 255 characters; empty becomes `file` (UI-SPEC "Security of displayed text"; the daemon already cleaned it, this is the viewer's own layer).
- **PreviewStore API (Claude's discretion on details; 11-09 depends on these names):** `PreviewEntry {tabId, ownerTabId, key, name, kind, mime, size, state: 'receiving'|'rendered'|'tooLarge'|'failed', received, blob?, url?, arrivedAt, refreshing}`; `tabId` is `__preview__<ownerTabId>/<key>` (never starts with `__websession__`, which App's render branch matches by prefix). Methods: `subscribe(listener)`, `getSnapshot()` (a new array only when something changed, for `useSyncExternalStore`), `handle(ownerTabId, event)` returning the entry's tabId and whether it is new, `setActive(tabId | null)` (eviction never picks the active tab), `close(tabId)`, `closeAll()`. `createURL`/`revokeURL` and a clock are injectable (jsdom has no `URL.createObjectURL`: RESEARCH Pitfall 10; stub them in tests, not in test-setup.ts).
  - Refresh in place (UI-SPEC "Same file again"): a `start` for an existing (owner, key) keeps the old blob and URL (`refreshing: true`, progress on the entry); `complete` swaps in the new blob and URL in one change and revokes the old URL; `failed` keeps the old content and clears `refreshing`. A `start` for an entry that never rendered restarts it.
  - Limits (CONTEXT after UI-SPEC: 10 preview tabs per viewer, 100 MiB retained): a new entry beyond 10 evicts the oldest by `arrivedAt` that is not active; after a `complete`, while retained bytes exceed 100 MiB (104,857,600), evict the oldest non-active entries. Eviction revokes URLs.
  - Session end, share stop or the owner tab closing do not touch entries (UI-SPEC "Close behavior": previews stay open and viewable).
- **TerminalPanel and WebShareSessionView:** TerminalPanel creates one assembler when it creates its RelayClient (TerminalPanel.tsx ~496), feeds it from `onPreview`/`onPreviewReset`, and calls `props.onPreview?.(event)`; unmounting the panel resets its assembler (an in-flight preview fails `incomplete`). WebShareSessionView gains `onPreview?` and `isActive?: boolean` (default true, replacing its constant `isActive={true}` at ~200) and forwards both. Nothing else in either component changes.
