## Flagged decisions and assumptions

- **CLI copy is the UI-SPEC "CLI Copy" table, verbatim** (`<arg>` is the path as typed, in straight double quotes; errors go to stderr with the `portty: ` prefix, end with a period, exit 1; success prints nothing):
  - no argument or more than one: `usage: portty open <file>`
  - no or malformed `PORTTY_SESSION_ID` (also a 404 or 409 from the daemon, which means the id is unknown or its session ended, for example a stale id inside tmux): `portty: this shell isn't a Portty session. Run portty open in a Portty terminal tab.` (Resolved: sessions started before this build, including ones moved by a Phase 9 upgrade, have no id and get exactly this UI-SPEC line, verbatim; CONTEXT "Session id" and "Decided at planning".)
  - missing: `portty: "<arg>" doesn't exist.`; folder: `portty: "<arg>" is a folder, not a file.`; unreadable: `portty: couldn't read "<arg>": <detail>.`
  - unsupported: `portty: can't preview this file type ("<arg>"). Portty previews PNG, JPEG, GIF, WebP and SVG images, PDFs and Markdown files.`
  - too large: `portty: "<arg>" is too large to preview (34.2 MB; the limit is 20 MB).` with decimal units, one decimal from 1 MB (UI-SPEC "Size display"); the cap is relay.PreviewMaxBytes (20,000,000), checked from stat before reading, and again on the bytes read
  - update needed: `portty: update needed. Portty's background service (version <v>) can't show previews; relaunch Portty to update it.` when `daemon.DaemonAPI(h) < daemon.PreviewAPI`
  - unreachable: `portty: couldn't reach Portty's background service: <detail>.` (dial or health failure, or an unexpected status)
  - zero viewers: `portty: nothing is showing this session, so no preview opened.`
  - busy after the client's retry budget (one addition to UI-SPEC's table, accepted in CONTEXT "Decided at planning"): `portty: another preview is still being sent to this session. Try again in a moment.`
  - `-h`/`--help` as the only argument prints `usage: portty open <file>` and the usage-table description on stdout and exits 0.
- **Type detection (CONTEXT "Type detection"; RESEARCH "Don't Hand-Roll").** `http.DetectContentType` on the first 512 bytes decides PNG, JPEG, GIF, WebP and PDF by content whatever the extension. SVG needs the `.svg` extension (case-insensitive) and an `<svg` root element within the first 1 KiB after an optional BOM, XML declaration, comments and DOCTYPE. Markdown needs `.md` or `.markdown` and valid UTF-8 with no NUL byte; a zero-byte `.md` is allowed (UI-SPEC "empty"), a zero-byte image or PDF is unsupported.
- **Key:** lowercase hex of the first 16 bytes of SHA-256 over the absolute, symlink-resolved path (32 hex characters). The path never leaves the CLI.
- **Daemon contact (RESEARCH Pattern 4).** `open` joins `health` and `version` in cliNeedsDaemon's exclusions (cmd_cli.go ~72), so runCLI never calls ensureCLIDaemon for it (whose mismatch advice would end the very session the user types in); --restart-daemon and --keep-daemon are taken out of the args and ignored. cmdOpen gets the socket path from runCLI (`daemon.DefaultSocketPath()`), calls HealthInfo once, then `client.SendPreview` (11-04) and maps its typed errors.
- **Order inside cmdOpen:** arguments → session id format (32 hex) → stat and cap → read → type → health and API gate → send → viewers. File errors come before any daemon contact, so `portty open missing.png` never touches the socket.
- **Install (UI-SPEC "Install Command-Line Tool"; RESEARCH "PREV-05 detail", Pitfalls 12-13).** App method `installCommandLineTool()` run in a goroutine from the menu callback (like checkForUpdatesCallback), dialogs through the existing `a.dialog` seam (app_update.go). Seams on App (unset means the production value): link path (`/usr/local/bin/portty`), executable resolver (`filepath.EvalSymlinks(os.Executable())`), privileged runner. Order, all unprivileged until the prompt:
  - executable under `/Volumes/` or containing `/AppTranslocation/`: Warning **Move Portty to the Applications folder first.** / **Portty is running from <folder>, so a command installed now would stop working. Move Portty to Applications, open it from there, then try again.** (`<folder>` is the directory that contains Portty.app)
  - `os.Lstat(link)`: a symlink whose `EvalSymlinks` equals the executable: Info **The portty command is already installed.** / **/usr/local/bin/portty already points to this copy of Portty.**
  - any other symlink, dangling included: Warning **Another portty command is already installed.** / **/usr/local/bin/portty points to <link target>. Portty didn't change it. To use this copy instead, remove that link, then choose Install Command-Line Tool… again.** (`<link target>` = raw `os.Readlink`)
  - anything else that exists: Warning, same title / **/usr/local/bin/portty is a file Portty didn't install. Portty didn't change it. To use this copy instead, remove that file, then choose Install Command-Line Tool… again.**
  - absent: the privileged runner runs `/usr/bin/osascript` with three `-e` lines (`on run argv`; `do shell script "/bin/mkdir -p /usr/local/bin && /bin/ln -s " & quoted form of item 1 of argv & " " & quoted form of item 2 of argv with prompt "Portty wants to install the portty command in /usr/local/bin." with administrator privileges`; `end run`) followed by the executable and link paths as argv items. No Go string is spliced into the script; `ln -s` without `-f` fails instead of overwriting if a file appears meanwhile.
  - cancel (exit status 1 with `-128` in stderr; Assumption A2, confirmed in the VM by 11-10): no dialog, nothing changed. Other failure: Warning **Couldn't install the portty command.** / **<error detail>. Try again, or create the link yourself in Terminal: sudo ln -s "<binary path>" /usr/local/bin/portty**. Success: Info **The portty command is installed.** / **/usr/local/bin/portty now points to Portty. Try “portty list” in Terminal.**
  - Every dialog has one OK button. Log the raw osascript stderr on failure (never a password; osascript does not see it).
- **Menu (UI-SPEC "Menu placement"):** `appSub.AddText("Install Command-Line Tool…", nil, …)` right after Settings… (main.go ~170), before the separator; TestAppMenu_Structure gains the item at index 3 and keeps its other invariants (six top-level items).

Nothing GUI starts (the CLI path never calls wails.Run). The VM check in 11-10 repeats it on a real bundle.
