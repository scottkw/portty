## Flagged decisions and assumptions

- **Locked by the user:** only the viewer you typed in switches to the new preview tab; every other viewer gets a background tab (CONTEXT, 2026-11-21). The header's `focus` bit says "this viewer typed last"; App adds the UI-SPEC guard: switch only if the active tab is the owner session's tab or one of its previews (CONTEXT after UI-SPEC: "the typing viewer switches only if it is on that session's tab or one of its previews"). No owner means nobody switches.
- **Tab model (RESEARCH Pattern 6; UI-SPEC "Position").** `Tab.type` gains `'preview'` with `ownerTabId` (the session's tab id: the session id for a local tab, `webSessionTabId(...)` for peer and browser tabs) and the store's `tabId` (`__preview__<ownerTabId>/<key>`, never starting with `__websession__`). A preview Tab carries no `sessionId` that aliases its owner (so the owner's progress underline, font size and removeTabState side effects never apply to it). The local-tabs map skips `preview` tabs as it skips `web-session` ones (App.tsx ~1276), so no TerminalPanel is created for them.
  - App creates one `PreviewStore` (11-05) for its lifetime, reads it with `useSyncExternalStore`, passes `onPreview={(ev) => handlePreview(ownerTabId, ev)}` to every local TerminalPanel and to the WebShareSessionView, calls `store.setActive(activeId)` when the active tab changes, and `store.closeAll()` on unmount.
  - On a `start` event for a new entry, insert the preview Tab after the owner's tab and its existing previews (if the owner's tab is gone, append after the last tab); apply the focus rule; announce in the live region. A refresh keeps the tab in place and follows the same focus rule. Entries removed by the store (eviction past 10 or 100 MiB) remove their tabs.
  - Close (×, ⌘W through the existing `menu:close-tab` path, the Close Tab context item): `store.close(tabId)`, remove the tab; if it was active and the owner's tab is open, activate the owner and focus its terminal; else `nextActiveTabId`. Closing the owner's tab, `session:exit` and share-stopped never touch preview tabs (UI-SPEC "Close behavior").
- **Keep the session view mounted (UI-SPEC "Viewer Connection Requirement"; RESEARCH Pitfall 2).** Compute the session view's tab id as the active tab's `ownerTabId` when a preview is active, else the active id. Render WebShareSessionView for it when it starts with `__websession__`, keyed by that id (not by activeId), inside the existing wrapper with `display: none` and `isActive={false}` while the preview is shown, and render PreviewPanel for the active preview. ErrorBoundary's resetKey follows the same id. `measureFit` returns null for a zero-size container, so a hidden panel never reports or claims a grid (RESEARCH, TerminalPanel measureFit). Local tabs are already all mounted. Accepted limit (UI-SPEC): an inactive peer tab with no active preview is not connected and misses previews.
- **TabBar (UI-SPEC "Anatomy", "Browser Share Viewer").** Preview tab: leading 14px icon by kind (PhotoIcon for image and svg, DocumentIcon for pdf, DocumentTextIcon for markdown, reusing the `.tab__remote-icon` size), the name in `.tab__name` (no rename on double-click), the owner's PeerDot when the owner is a peer tab, tooltip `<name> — <session label>` (peer: `<name> — <session> · <host>`), accessible name `<name>, preview from <session label>` (peer: `… from <session> on <host>`), `.tab__close` with `aria-label="Close <name>"` shown in web mode too (the session pill there keeps none), context menu Close Tab only and none in web mode, progress underline from `received/size` while receiving. Tab label text is React text only.
- **PreviewPanel (UI-SPEC "States", "Accessibility Contract").** Props: the entry and `webMode`, `autoFocus`. `.empty-state`-style stack, `role="status"`, 40px icon, Display heading with `overflow-wrap: anywhere`:
  - Receiving, shown only if still receiving 300 ms after the start: type icon, heading = name, `<progress>` (200×4, `aria-label="Receiving <name>"`), caption **Receiving… <n> of <total>** (decimal units: one decimal from 1 MB, whole KB below; tabular numerals).
  - Too large: ExclamationTriangleIcon, **Too Large to Preview** / **<name> is larger than 20 MB.**
  - Couldn't receive: **Couldn't Receive File** / **<name> didn't arrive completely. Run portty open again.**
  - Couldn't show (renderer onFail or the ErrorBoundary): **Couldn't Show File** / **<name> may be damaged, or its format isn't supported.**
  - Refreshing: the old content stays; a failed refresh changes nothing.
  - Rendered: `image`/`svg` → ImagePreview, `pdf` → PdfPreview, `markdown` → MarkdownPreview (11-06 and 11-07 contracts), wrapped in `ErrorBoundary label="preview"`. On a focused arrival focus moves to the pane's first target (image toggle, article, PDF frame).
- **Live region:** one visually hidden `aria-live="polite"` element in App; the text **Preview opened: <name>** per arrival (focused or background). A `.visually-hidden` class goes into style.css.
- **Toolbar, sidebar, shortcuts (UI-SPEC "Anatomy", "Keyboard").** Sidebar's `activeTab` gets the owner tab while a preview is active; the toolbar's existing `isLocal` / `web-session` checks show nothing for a preview tab, and an open Share popover closes when a preview becomes active; the font-size and find handlers ignore preview tabs.
