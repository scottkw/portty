# Phase 11 Spike: PDF and SVG from `blob:` URLs (Wails web view and Safari)

Evidence for plan 11-01 (PREV-02, PREV-04; ROADMAP Phase 11 SC2 and SC4): does WKWebView's own PDF view show a `blob:` PDF inside the real Wails v2 web view, and does Safari show it on the real share page under the share CSP? Result is exactly `PASS` or `FAIL`; a variant that does not render is evidence, not a FAIL. FAIL means the check itself could not be carried out.

## Spike patch (throwaway worktree only)

- `frontend/src/main.tsx` renders a spike page (`Spike.tsx`) instead of App, so both the Wails window and the share page `/app/` show it.
- Fixtures embedded as base64 constants and turned into Blobs with `URL.createObjectURL` (no fetch, so `connect-src` plays no part): a 3-page text PDF made on the host with `cupsfilter` (20,536 bytes, sha256 `95e0b464…57716`, `file`: "PDF document, version 1.3, 3 pages", `application/pdf`) and an SVG (`image/svg+xml`, sha256 `65133733…65213`): an orange rounded rect, a blue circle, the text "SVG fixture", a `<script>` and an `onload` handler that each set `top.document.title` to `SVG-…-RAN` and `fetch` the beacon, and an `<image href>` pointing at `http://127.0.0.1:8765/svg-beacon`.
- Sections: `<iframe src=blob:>`, `<object data=blob: type=application/pdf>`, `<embed src=blob: type=application/pdf>` side by side, and `<img src=blob:svg>`; load and error listeners on each, a document-level `securitypolicyviolation` listener; `<pre id="spike-log">` plus `document.title` summarise the results (`SPIKE <key>:<event> … viol:<n>`). Buttons show one variant at a time; an Open PDF button calls `window.open(pdfUrl, '_blank', 'noopener')`.
- `internal/webserver/csp_mw.go`: img-src becomes `'self' data: blob:`, and the trimmed contents of `/tmp/p11-spike-csp` (re-read on every request; absent or empty adds nothing) are appended as extra directives before `frame-ancestors 'none'`, which stays last and unchanged.
