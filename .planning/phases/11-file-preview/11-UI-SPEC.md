# Phase 11 — UI Design Contract

> Visual and interaction contract for Phase 11 (File Preview, PREV-01..05). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Sources, in priority order:**
1. `11-CONTEXT.md` locked decisions. The most important one comes from the user (2026-11-21, "Only the viewer you typed in"): only the viewer that last typed into the session switches to a new preview tab. Every other viewer gets it as a background tab.

3. Project constraints and memories: macOS-native look, radical simplicity, light and dark following the system live, rock-solid (the office Mac runs unattended).
4. Approved prior contracts: `02-UI-SPEC.md` (tokens, tabs, dialogs, copy rules) and `04-UI-SPEC.md` (web page and CLI copy style).
5. Existing code, scanned 2026-11-21: `TabBar.tsx`, `App.tsx` (tab panels; only the active web-session tab is mounted), `lib/tabs.ts`, `lib/peerSnapshots.ts`, `SessionEndedBanner.tsx`, `EmptyState.tsx`, `LinkConfirmPopover.tsx`, `lib/openLink.ts`, `style.css` tokens, `main.go appMenu()`, `app_update.go` (`a.alert` / `a.dialog` native NSAlert seam), `cmd_cli.go` and `cmd_share.go` (CLI copy style).

## Preview Tab

### Anatomy

| Part | Contract |
|------|----------|
| Type icon (leading, 14px, `aria-hidden`) | PNG, JPEG, GIF, WebP and SVG: `PhotoIcon`. PDF: `DocumentIcon`. Markdown: `DocumentTextIcon`. It inherits the tab's text color |
| Label | The file's base name only (for example `diagram.png`), cleaned (see Security of displayed text). Single line with an end ellipsis (existing `.tab__name`). The icon carries the type when the extension is cut off. No rename: double-click does nothing |
| Peer origin | A preview from a peer session adds the host's `PeerDot` after the name, as on its peer tab. The dot is decorative. The tooltip and the accessible name say which Mac |
| Tooltip (`title`) | Local: `diagram.png — build`. Peer: `diagram.png — build · office-air`. The session part is the session's tab label, shown with the same "session · host" split as peer tabs |
| Close button | Existing `.tab__close` (20×20, `XMarkIcon` 12px), always visible, `aria-label="Close diagram.png"`. Shown in the browser share viewer too (the session pill there still has none) |
| Progress underline | While bytes arrive: the existing `.tab__progress` element at received/total, using the same 200ms ease-out `scaleX` transition. It goes to 0 when the file has arrived or failed |
| Active / inactive | Exactly like other tabs: neutral `--color-tab-active` pill, weight 600 when active |
| Toolbar right side while a preview is active | Nothing: no Share button and no "On <host>" chip. Today's `isLocal` and `type === 'web-session'` checks already give this. The Share popover closes if it was open |
| Sidebar while a preview is active | The preview's session row stays selected, as if its terminal tab were active. Clicking that row activates the terminal tab (existing behavior) |
| Context menu (right-click, Shift+F10) | **Close Tab** only. None in the browser share viewer (existing web-mode rule) |

### Position and relation to the session's tab

- A new preview tab goes immediately to the right of its session's tab. That is the local terminal tab, the peer tab `<host> › <session>`, or the browser viewer's session pill. If that session already has preview tabs, the new tab goes after them, so a session's previews stay grouped in arrival order.
- Previews of one session never sit between another session's tab and its previews.
- **Same file again:** a second `portty open` of the same file (same session, same absolute path on the host) refreshes the existing preview tab in place. No second tab opens. The old content stays visible while the new copy arrives, with the tab underline showing progress, and the new content replaces it in one swap when complete. The refresh follows the same arrival rule (focus or background) as a new preview. The key is derived from the absolute path; the path itself is never displayed.
- **Limit: 10 preview tabs per viewer.** An 11th arrival first closes this viewer's oldest preview tab (by arrival time) that is not the active tab. This keeps the unattended office window from growing without bound. Nothing else is ever closed automatically.

### Arrival: focused vs background

| Viewer | Result |
|--------|--------|
| The viewer that last typed into the session (the daemon's last `NoteTyping` viewer, flagged in the preview header), **and** its active tab is that session's tab or one of that session's preview tabs | **Focused arrival.** The new tab becomes active and keyboard focus moves to the preview pane |
| That same viewer, but it is looking at a different session's tab | Background arrival. Switching would yank the user away from unrelated work |
| Every other viewer (for example the unattended office window), and every viewer when nobody has typed yet | **Background arrival.** The tab is added in its position. The active tab, focus, scroll position and any open dialog are untouched |

Rules for every arrival:
- Portty never raises, un-hides or un-minimizes the window and never steals app focus. No sound, no macOS notification, no Dock bounce.
- Open dialogs and sheets stay open. A focused arrival switches the tab behind them.
- A polite live region announces each arrival (see Accessibility).
- No unread or "new" indicator. A background preview tab looks like any other inactive tab. This fits radical simplicity, and native macOS tabs have no unread badge.

### Close behavior

| Action | Result |
|--------|--------|
| × button, ⌘W (desktop, existing `menu:close-tab`), or context menu **Close Tab** | Closes the preview in this viewer only. Other viewers keep theirs. The bytes and the `blob:` URL are released (`URL.revokeObjectURL`) |
| Closing the **active** preview tab | Activates its session's tab if that tab is still open in this viewer, and focuses that terminal, so `portty open x.png`, look, ⌘W puts you straight back at the prompt. Otherwise the standard `nextActiveTabId` rule applies (right, else left, else the empty state) |
| Closing the session's terminal or peer tab | Its preview tabs stay open. Once a preview has arrived it is self-contained |
| The session ends, or Share stops, while a preview is open | The preview stays open and fully viewable, with no banner on the preview pane. The terminal tab behaves as today (a local tab disappears; a peer or browser tab shows `SessionEndedBanner`). If it happens while the file is still arriving, see "Couldn't Receive File" |
| App quit or relaunch, browser reload | Previews are gone (ephemeral, memory only, by decision) |
| A viewer that connects later | Doesn't receive earlier previews (by decision) |

### Keyboard

| Key | Where | Result |
|-----|-------|--------|
| ← / → | Tab strip | Moves between tabs, preview tabs included (existing ARIA tabs pattern) |
| Enter / Space | Focused tab | Activates it |
| Shift+F10 / context-menu key | Focused preview tab (desktop) | Opens the Close Tab menu |
| ⌘W | Desktop, preview tab active | Closes it (see Close behavior). In the browser, ⌘W belongs to the browser, so the × button (reachable with Tab) is the way to close |
| Tab | From the tab strip | Moves into the preview pane: the image toggle, the Markdown article, or the PDF frame |
| Enter / Space | Image toggle focused | Switches between Fit and Actual Size |
| Arrows, Page Up/Down, Space | Focused scrollable pane (image at actual size, Markdown, PDF) | Native scrolling |
| ⌘+ / ⌘− / ⌘0 | Preview tab active | Nothing (they stay terminal font-size keys and only act on terminal tabs) |
| ⌘F | Preview tab active | Nothing (no find in previews this phase) |
| ⌘C / ⌘A | Markdown pane focused | Copy / select all within the document only |

## Preview Pane (per type)

The pane fills the tab panel: the same area as a terminal, below the toolbar and the app-level banner stack. It has no header, toolbar or footer of its own, because the tab carries the name. It is `role="tabpanel"` with `id="tabpanel-<tabId>"`, labelled by its tab.

### Images (PNG, JPEG, GIF, WebP)

- An `<img>` from a `blob:` URL, centered on `--color-window`, with 16px padding.
- **Fit (default):** the image scales down to fit the pane (`object-fit: contain` behavior) and never scales up past its natural pixel size. A small image shows at natural size, centered.
- **Actual Size:** offered only when the natural size is larger than the fitted size. Clicking the image (or Enter/Space on its toggle) switches between Fit and Actual Size. At Actual Size the pane scrolls on both axes and opens scrolled to the top-left. The cursor is `zoom-in` at Fit and `zoom-out` at Actual Size, and plain `default` when there is nothing to toggle. No zoom slider, no pinch-zoom handling, no zoom percentage.
- **Transparency checkerboard:** the `<img>` element's own background, so it fills exactly the image box and shows only through transparent pixels: 8px squares of `--color-checker-a` / `--color-checker-b` (a CSS `conic-gradient`, 16px tile). Opaque images cover it completely.
- Animated GIF and WebP play as the web view plays them. There is no pause control this phase.

### SVG

- Rendered by the same `<img>` from a `blob:` URL. Inside an `<img>` an SVG runs no script and fetches nothing (locked decision).
- Always fit to the pane, minus the 16px padding, scaling up as well as down (it is vector). No Actual Size toggle. Default cursor.
- Same checkerboard as other images.

### PDF

- WKWebView's built-in PDF view, from a `blob:` URL in a full-bleed frame (iframe, embed or object, whichever the spike proves). It fills the pane edge to edge with no padding.
- Portty adds no PDF toolbar, page counter or zoom control. Only the native viewer's own controls and gestures appear (scrolling, pinch-zoom, its own page HUD if it shows one). The page background is whatever the native view draws, and PDF pages stay white in dark mode. That is the native viewer's look, accepted.
- The frame's `title` is the file name, for VoiceOver.
- **Gate (locked):** the Wails v2 spike must prove this works before anything is built on it. If it doesn't, stop and report options (for example pdf.js). Do not improvise a fallback.

### Markdown

- Rendered and sanitized (no script, no raw HTML beyond the sanitizer's safe set, no remote fetches). It goes inside `<article class="preview-markdown" aria-label="<file name>">` in a pane that scrolls vertically, with the system overlay scrollbar.
- Column: `max-width: 720px`, centered. Pane padding 32px top and bottom, 24px on the sides. Background `--color-window`. Text `--color-text`, with `user-select: text`.
- Typography: the Markdown document scale above.

| Element | Style |
|---------|-------|
| Links (`http:`, `https:`, `mailto:`) | `--color-accent`, no underline, underline on hover and focus. `title` = the target URL. A plain click (no modifier; this is a document, not the terminal) runs the same `urlSafety` check as terminal links. A risky URL shows `LinkConfirmPopover`; otherwise `openLink` opens it in the default browser (desktop) or a new tab with `noopener,noreferrer` (browser viewer). Never navigates the pane |
| In-document links (`#heading`) | Scroll the pane to that heading if it exists, else do nothing |
| Any other link (`javascript:`, `file:`, `data:`, relative paths) | Rendered as plain text in the body color. Not a link, not focusable |
| Images (`![alt](…)`, any source: remote, relative or `data:`) | Never fetched or decoded. Replaced by an inline placeholder: `PhotoIcon` 14px + the alt text (or **Image** when there is none), in `--color-text-secondary`, `role="img"`, `aria-label="Image: <alt>"`. If the image was inside a link, the link still works around the placeholder |
| Inline code | 12px mono, `--color-chip` background, padding `0 4px`, radius 4px |
| Code block (`pre`) | 12px/18px mono, `--color-chip` background, padding 12px 16px, radius 6px. Scrolls horizontally inside the block and never wraps. No syntax highlighting (deferred) |
| Blockquote | 3px left bar in `--color-separator`, 16px left padding, text `--color-text-secondary` |
| Lists | 24px indent. Task-list checkboxes render disabled and checked or unchecked as written. They are not clickable |
| Tables | 1px `--color-separator` borders, cell padding `4px 12px`, `th` weight 600, left-aligned. A table wider than the column scrolls horizontally in its own wrapper |
| `hr` | 1px `--color-separator`, 24px vertical margin |

## States

All message panes use the `.empty-state` layout: centered on `--color-window`, 32px above center, max-width 320px, text centered. Stack: 40px icon in `--color-text-secondary` (`aria-hidden`), 8px, heading (Display 17/600, `overflow-wrap: anywhere` so a long file name wraps), 8px, body or bar (Body 13/400, secondary). They have no buttons: the × on the tab closes, and fixes happen in the shell.

| State | When | Pane | Tab |
|-------|------|------|-----|
| Receiving | From the preview header until the last chunk arrives. The stack appears only if bytes are still arriving 300ms after the header, so small files don't flash | Type icon, heading = file name, then the 200×4 progress bar (track `--color-separator`, fill `--color-selection-fill`, width = received/total), 8px, caption **Receiving… 4.2 MB of 18.6 MB**. The bar is a `<progress>` element with `aria-label="Receiving <file name>"` | Label + icon + progress underline |
| Rendered | The last chunk arrived and decoded | The type's renderer. On a focused arrival, focus moves into the pane if it was on the receiving pane | Underline back to 0 |
| Too large | The size cap was crossed mid-stream (the normal over-cap case is refused by the CLI and viewers get nothing) | `ExclamationTriangleIcon`, heading **Too Large to Preview**, body **<file name> is larger than 20 MB.** Nothing of the file is ever rendered | Underline 0. The tab stays until closed |
| Couldn't receive | The stream stopped before the end marker: the CLI was killed, the session ended, Share stopped, or the viewer's socket dropped or reconnected (a partial preview is discarded, never resumed) | `ExclamationTriangleIcon`, heading **Couldn't Receive File**, body **<file name> didn't arrive completely. Run portty open again.** | Underline 0 |
| Couldn't show | The file arrived but can't be displayed: the image fails to decode, the PDF frame fails to load, the renderer or sanitizer throws, or the `ErrorBoundary` catches | `ExclamationTriangleIcon`, heading **Couldn't Show File**, body **<file name> may be damaged, or its format isn't supported.** | Underline 0 |
| Refreshing (same file again) | A re-open of a file that is already showing | The old content stays. If the new copy fails, the old content stays and nothing else changes | Progress underline during the transfer |
| Session ended / Share stopped while rendered | — | Unchanged (the preview is self-contained) | Unchanged |
| Unsupported type, missing file, normal over-cap | — | No viewer UI at all. These are CLI-only errors (see CLI Copy) | No tab |

**Size display:** decimal units, as Finder counts them (1 MB = 1,000,000 bytes). One decimal place from 1 MB up (`4.2 MB`), whole KB below that (`640 KB`). The cap is shown as **20 MB**. Planner note: to make the copy exact, define the cap as 20,000,000 bytes. If it stays 20 MiB (20,971,520 bytes), the copy still says "20 MB" and only files Finder shows as 20.0-20.9 MB are affected (they pass, which is harmless).

## Viewer Connection Requirement (planner: must hold)

A viewer receives previews only while its connection to the session is open. Today `App.tsx` mounts only the **active** web-session tab (HARD-05, `peerSnapshots.ts`). Activating a preview tab of a peer session, or the browser viewer's own session, would therefore unmount that session's view and close its socket. While it is closed the viewer would miss the next `portty open`, which breaks the focused-arrival flow and SC1/SC4. Contract: **while a preview tab is active, its session's terminal view stays mounted (hidden, `display: none`) and connected.** In other words, the mounted web-session view is the one for the active tab's session, whether that tab is the session's tab or one of its previews. Local terminal tabs are already all mounted, so they are unaffected. Known limit, accepted: an inactive peer tab whose session has no active preview is not connected, so it misses previews (the same as for its terminal output).

## Install Command-Line Tool (PREV-05)

### Menu placement

Portty app menu (`main.go appMenu()`), directly under Settings…, in the same group:

```
About Portty
─
Settings…                      ⌘,
Install Command-Line Tool…
─
Hide Portty                    ⌘H
─
Quit Portty                    ⌘Q
```

The label is **Install Command-Line Tool…** (U+2026, title case; the ellipsis is there because it asks for a password). It has no shortcut and is always enabled. It exists only in the native app menu; the browser viewer has no equivalent.

### Flow and dialogs

All results are native alerts through the existing `a.dialog` / `a.alert` seam (Wails `runtime.MessageDialog`, NSAlert), run off the main thread like Check for Updates…. Each has one button, **OK**. Copy follows the existing alert style: the title is a full sentence ending with a period, and the message is plain sentences.

1. Portty checks `/usr/local/bin/portty` with `lstat` before asking for anything (no privileges needed), and checks where it is itself running from.
2. Only if a link is needed does it show the macOS administrator prompt. It uses `do shell script … with administrator privileges with prompt "Portty wants to install the portty command in /usr/local/bin."` macOS adds its own "Enter your password to allow this." line. The script creates `/usr/local/bin` if needed and runs `ln -s` without `-f`, so a file that appears in the meantime makes it fail rather than be overwritten.

**Amendment (11-REVIEW IN-04, 2026-11-21):** macOS 27.2 shows only its own admin-prompt copy (with Apple's malware-verification warning), never the `with prompt` text (11-VM-CHECKS P-08c/P-08d). So just before step 2, Portty shows one native confirm that says what the password is for. **Continue** goes on to the admin prompt. **Cancel** (also Escape) changes nothing and shows nothing more, like a cancelled admin prompt. `with prompt` stays for older macOS. This is the one install dialog with two buttons.

| Case | Type | Title | Message |
|------|------|-------|---------|
| Before the admin prompt (a link is needed) | Question, buttons **Continue** (default) / **Cancel** | **Install Command-Line Tool** | **macOS will ask for your password to put the portty command in /usr/local/bin.** |

| Case | Type | Title | Message |
|------|------|-------|---------|
| Success | Info | **The portty command is installed.** | **/usr/local/bin/portty now points to Portty. Try “portty list” in Terminal.** |
| Already installed (the link points to this copy's binary) | Info | **The portty command is already installed.** | **/usr/local/bin/portty already points to this copy of Portty.** |
| Foreign link (points anywhere else, including another Portty copy or a missing target) | Warning | **Another portty command is already installed.** | **/usr/local/bin/portty points to <link target>. Portty didn't change it. To use this copy instead, remove that link, then choose Install Command-Line Tool… again.** |
| Foreign file (exists and isn't a link) | Warning | **Another portty command is already installed.** | **/usr/local/bin/portty is a file Portty didn't install. Portty didn't change it. To use this copy instead, remove that file, then choose Install Command-Line Tool… again.** |

## CLI Copy (`portty open`)

Style follows `cmd_share.go`: plain text, no color. Errors go to stderr as one line with the `portty: ` prefix (a lowercase start unless it begins with a name), end with a period, include the next step where there is one, and exit 1. Success prints nothing and exits 0 (the preview tab is the feedback). `<arg>` is the path exactly as typed, in straight double quotes.

| Case | Line |
|------|------|
| No argument, or more than one | `usage: portty open <file>` |
| Not inside a Portty session (no session env var) | `portty: this shell isn't a Portty session. Run portty open in a Portty terminal tab.` |
| Missing file | `portty: "<arg>" doesn't exist.` |
| A folder | `portty: "<arg>" is a folder, not a file.` |
| Unreadable | `portty: couldn't read "<arg>": <detail>.` (for example `permission denied`) |
| Unsupported type | `portty: can't preview this file type ("<arg>"). Portty previews PNG, JPEG, GIF, WebP and SVG images, PDFs and Markdown files.` |
| Too large | `portty: "<arg>" is too large to preview (34.2 MB; the limit is 20 MB).` |
| Daemon too old (API below the preview capability) | `portty: update needed. Portty's background service (version <v>) can't show previews; relaunch Portty to update it.` (Matches the app's Update needed banner.) |
| Daemon unreachable | `portty: couldn't reach Portty's background service: <detail>.` |
| No viewer connected to the session (when the daemon reports zero) | `portty: nothing is showing this session, so no preview opened.` |

`portty open` never starts, restarts or replaces the daemon, and ignores `--restart-daemon` and `--keep-daemon`. Inside a session, the running daemon is the one hosting the shell. The usage text in `usage()` gets one line under Commands: `open <file>` with the description **Show an image, PDF or Markdown file in a preview tab**.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None in the GUI. The phase's action is the CLI command `portty open <file>`, plus the menu item **Install Command-Line Tool…** |
| Empty state | Not applicable: a preview tab exists only once a file is arriving. The "No Open Sessions" empty state is unchanged |
| Preview tab | Label **<file name>** · tooltip **<file name> — <session label>** · close `aria-label` **Close <file name>** · menu **Close Tab** |
| Receiving | Heading **<file name>** · caption **Receiving… <n> of <total>** |
| Error state (too large) | **Too Large to Preview** / **<file name> is larger than 20 MB.** |
| Error state (incomplete) | **Couldn't Receive File** / **<file name> didn't arrive completely. Run portty open again.** |
| Error state (render) | **Couldn't Show File** / **<file name> may be damaged, or its format isn't supported.** |
| Markdown image placeholder | **<alt text>**, or **Image** when there is no alt text |
| Arrival announcement (screen readers) | **Preview opened: <file name>** |
| Menu item | **Install Command-Line Tool…** |
| Admin prompt text | **Portty wants to install the portty command in /usr/local/bin.** |
| Install confirm (amendment, 11-REVIEW IN-04) | **Install Command-Line Tool** / **macOS will ask for your password to put the portty command in /usr/local/bin.** · **Continue** / **Cancel** |
| Install dialogs | See the table above (7 cases, 6 with a dialog) |
| CLI | See CLI Copy (10 lines) |
| Destructive confirmation | None. Closing a preview is not destructive (the file is untouched and can be opened again), so there is no confirm |

Writing rules (from Phase 2): macOS title case for menu items, pane headings and buttons. Sentence case for body text. "…" (U+2026). Curly quotes in GUI copy, straight quotes in CLI output. No exclamation marks. "Couldn't" for failures, plain present tense for facts. Never "Error:" or "Oops".

### Security of displayed text

The file name, the Markdown content and every alt text and URL come from the remote shell and are untrusted. They are rendered only as React text or sanitizer output, never through `dangerouslySetInnerHTML` on unsanitized input and never in `title` without cleaning. Before display, the file name drops C0/C1 control characters and bidi override and isolate characters (U+202A–U+202E, U+2066–U+2069), so `gnp.exe` can't pose as `exe.png`. It is also capped at 255 characters. The CLI's error lines print `<arg>` as the user typed it (their own input).

## Accessibility Contract

- **Preview tab:** `role="tab"`, `aria-selected`, `aria-controls="tabpanel-<id>"`. Accessible name: **<file name>, preview from <session label>**, for example "diagram.png, preview from build on office-air" for a peer. The type icon and peer dot are `aria-hidden`; the name already says it.
- **Pane:** `role="tabpanel"`, `aria-labelledby` the tab. On a focused arrival, focus goes to the pane's first focusable target: the image toggle, the Markdown `<article tabindex="0">`, or the PDF frame. On close, focus returns to the session's terminal (see Close behavior).
- **Image:** `<img alt="<file name>">` inside `<button class="preview-image__toggle" aria-label="Actual Size" aria-pressed="false|true">` when the toggle is offered. Otherwise the `<img>` stands alone with no button.
- **PDF:** the frame has `title="<file name>"`. Inside it, the native viewer provides its own accessibility.
- **Markdown:** `<article aria-label="<file name>">` with real heading levels, lists and tables. Links are real anchors with their visible text as the name. Placeholders are `role="img"` with `aria-label="Image: <alt>"`.
- **Receiving:** a native `<progress>` with `aria-label="Receiving <file name>"`. The caption is not live, to avoid chatter.
- **Error panes:** the stack is `role="status"`, so the heading and body are announced once when the state appears.
- **Arrival announcement:** one app-wide visually hidden `aria-live="polite"` region says **Preview opened: <file name>** for every arrival, focused or background.
- **Focus ring:** the existing `:focus-visible` 3px `--color-focus-ring`. On the tab label it uses `outline-offset: -3px` (existing). It applies to the image toggle and the Markdown links. It never shows on mouse focus.
- **Color is never the only signal** (the user is colorblind): the type is shown by icon and extension, the host by tooltip and accessible name (the peer dot is decorative), and the state by heading text.
- **Motion:** only the existing 200ms underline transition. Under `prefers-reduced-motion: reduce` it has no transition. The zoom toggle is instant.
- **Native alerts** (install dialogs) get NSAlert's own VoiceOver support and keyboard handling (Return = OK).
