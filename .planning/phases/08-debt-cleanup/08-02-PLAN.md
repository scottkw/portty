## Flagged decisions and assumptions

- **Depends on 08-01.** Both plans edit hub.go. 08-01 also built `renderScreenLocked`'s row-by-row join, the wrap guard (no join unless `h.modes[7]` is true or unset) and softwrap-replay.json. Read 08-01-SUMMARY.md first.
- **IN-06 placement: refinement of the CONTEXT decision ("emit the mode loop before the screen text ... as well as before the CUP").**
  - **Restores go before the history, not just before the screen text, in a rendered Join replay.** joinLocked today sends `history + CRLF + screen`. xterm.js 6 homes the cursor on `?6h` and on `?6l` (InputHandler setModePrivate/resetModePrivate case 6, quoted in 07-REVIEW WR-08), and every RIS puts 6 in h.modes. So restores placed between the history and the screen text would home the cursor to the top of the viewport, and the screen rows would overwrite the last screen-height history rows still in it.
    - Before the history, right after the viewer's `resetForFullReplay` RIS, the cursor is already home, so the home does no harm.
    - Rendered replays send no DECSTBM, so the region stays the full screen and the final CUP stays absolute under DECOM (unchanged from WR-08).
  - **Autowrap (?7) is the one restore that stays after the text, before the CUP.** It decides how the replayed text lays out:
    - `?7l` first would truncate history lines rendered before a host narrowing instead of wrapping them, and would break 08-01's wrap joins.
    - After the text it behaves as today. Toggling DECAWM moves no cursor in xterm.js or vt, and `pendingWrapLocked` already requires autowrap on, so the pending-wrap re-print stays after it.
    - 08-01's join guard stays: it is conservative and harmless.
  - **Resulting byte order:**
    - `renderScreenLocked()` (RenderSnapshot and the rebuild seed): restores without 7, then the alt prefix when in the alt screen, then the screen rows, then `?7`, then the CUP, then the pending-wrap re-print.
    - joinLocked: restores without 7, then the history, then the boundary separator (08-01), then the same body.
    - Split the mode loop into a helper (for example `modeRestoresLocked(skip7 bool)`) and the rest into a body helper, so the two callers cannot drift.
    - Excluded modes are unchanged: 47, 1047, 1048, 1049, 2048, 2026.
  - **vt side (the seed):** vt's `setMode` moves the cursor only for 1048/1049/47, all excluded (vt csi_mode.go:71-107). `?6h` before the seed's text is harmless: the new emulator has no region yet, so CR/LF and the seed's own CUP stay absolute. The rebuild's own `?6l ... ?6h` block runs after the seed, as today.
- **IN-06's original symptom (a ?2027 grapheme row wrapping the seed) may already pass.** vt's flushGrapheme always uses GraphemeWidth (vt utf8.go:30-33), and only `WidthMethod()` reads ModeUnicodeCore (emulator.go:164). The ?2027 reference subtest is a guard. The order assertions and the xterm.js history case are the real proof.
- **IN-08 probes (CONTEXT: "probe the G1 designation and the SO state, and re-emit them; track an open OSC 8 link via a vt callback or a probe").** Probes are used because SO/SI are C0 controls whose vt handlers cannot be hooked (`registerCcHandler` is unexported, handlers.go:94, :275-284).
  - After today's current-pen probe `q` (which prints through whatever GL is), print `SI q` and then `SO q` into the old emulator, which is discarded anyway, copying each cell at the position it printed to (CellAt points into the buffer). These are c0 and c1.
    - G0 is line drawing iff c0 is `─`. G1 is line drawing iff c1 is `─`.
    - GL is G1 iff the current probe cell equals c1's content and c0 differs from c1.
    - Re-emit after the seed: `ESC ( 0` if G0 is line drawing, `ESC ) 0` if G1 is, then `SO` if GL is G1. This replaces today's single `ESC ( 0` test.
  - **OSC 8:** vt prints each cell with the cursor's link (handleGrapheme sets `Link: e.scr.cursorLink()`, utf8.go:46-51), so the probe cells already carry it.
    - The current link is the current-pen probe cell's `Link`. Re-open it with `ansi.SetHyperlink(url, params)` after the pen, last.
    - The saved cursor's link is `savedCell.Link`. Emit it before the `ESC 7` in the saved-cursor block, then reset it with `ansi.ResetHyperlink()` before the current link is re-opened. Add a non-empty saved link to the `keepSaved` condition.
    - The seed's rows already carry their links (renderLine emits SetHyperlink/ResetHyperlink per cell run), so only the open link needs re-opening.
  - **Probe ordering constraint:** the SI/SO probes run after the current-pen probe (so it still reads the real GL) and before `ESC 8` (vt's Cursor holds no charset, so DECRC does not undo them). The saved-pen probe then prints with GL = G1. That is fine: only its Style and Link are read.
  - **Still lost, keep in the `shortcut:` list:** tab stops, G2/G3 and single shifts, the UK national set, the saved cursor's visibility, and vt's zero-width cells. Remove SO/G1 and the OSC 8 links from the list.
- **Scope of IN-08: the alt-exit rebuild, per the audit ("SO/G1 charset, open OSC 8 link across rebuild") and CONTEXT ("re-open it around the seed").**
  - A viewer joining through a rendered replay still gets no current charset, pen or open link. That was never part of IN-08, and SO/SI cannot be observed without probing the live emulator, which must not be touched.
  - Recorded so the verifier reads SC2's "keep SO/G1 line drawing and an open OSC 8 link" as the rebuild clause. If the user wants it for viewers too, that is new scope.
