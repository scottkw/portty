## Flagged decisions and assumptions

- **Wire contract with 10-04 (same wave, not a dependency).** Both plans implement exactly Research Pattern 3; 10-05 does not wait for 10-04 (declaring it would serialize wave 2). Any difference between the frame 10-04's hub parses and the frame this plan sends is a phase finding for 10-07's gate and VM rows, not something to adapt to here.
- **Wire (fixed by Research Pattern 3; 10-04 implements the server side).** `encodeClaimFrame(cols, rows)` returns `[MSG_RESIZE2, cols_hi, cols_lo, rows_hi, rows_lo, 0x01]`; `encodeResizeFrame` stays 5 bytes (a report). `sendClaim(cols, rows)` is dropped unless the connection is open, exactly like `sendInput` (in reconnect mode `state === 'open'`, and `readyState === OPEN`), and goes through the private `send`, so DEBT-05's "bytes queued after the paste" accounting counts it. Old hosts read the first 4 bytes or drop the frame (Research back-compat table), so the client needs no version check.
- **The panel model (Research Pattern 6; invariant: reports carry the measured fit, never `term.cols/rows`).**
  - `measureFit(term)`: the measuring half of `fitTerminal` (content box from the parent's client size minus padding, cell size from `_core._renderService.dimensions`, `gridForContentBox`), returning `null` when the cell size is 0 or there is no parent (a hidden panel). Use optional chaining on `_core`: some test terminals have no render service. `fitTerminal` keeps working through it.
  - `serverGridRef`: the last 0x02 grid (null before any). Every panel passes `onResize` to RelayClient: store the grid, then `applyHostGrid(term, cols, rows, recomputeScale)` (stream-ordered, unchanged helper). A restored peer snapshot also sets it from the snapshot's cols/rows.
  - `reportFit()`: when the fit is measurable and differs from the last one sent on this socket, `client.sendResize(fit)`. `onOpen` (every panel; it fires after the join's grid frame and replay in reconnect mode) clears the last-sent value and reports, so every (re)connect reports once.
  - `relayout()` for every container change (ResizeObserver, activation, the theme effect): if `serverGridRef` is null (a never-sized session: the local relay sends no grid frame then, 10-04), `fitTerminal` as today's host path does; otherwise `recomputeScale()`. Then `reportFit()`. The theme effect stops calling `fitTerminal` unconditionally (today it resizes a guest's xterm to its own fit, away from the host grid).
  - Claims: (a) a `window` `resize` listener registered in the existing `[isActive]` fit effect (so only the active panel claims, and it is removed when the panel hides), trailing debounce 150 ms (`CLAIM_DEBOUNCE_MS`), sending `client.sendClaim(measureFit)`; (b) the font effect: when the family or size changed on the active panel, set the options, `relayout()`, then claim. Do not resize xterm optimistically: the panel always shows the server's grid, and the claim's 0x02 echo makes it follow (an old host that ignores claims then leaves the view consistent). Never claim from ResizeObserver: the reconnecting banner and the paste notice change the container height and the sidebar changes its width, none of which is the user taking the size (Research anti-patterns).
  - Remove the `term.onResize` → `sendResize` wiring (it would report a foreign grid).
  - `recomputeScale` applies its scroll-x class and element width to every panel (a local tab that lost the size scales like a guest; at scale 1 it looks as today). `isGuestRef` stays for what is really guest-only: the session-ended banner, the onClose handling and the reconnect verdict.
  - Keep the strings other tests pin: `fitTerminal(termRef.current!)`, `new ResizeObserver`, `MAX_ATTEMPTS = 20`, `tryFit`, `requestAnimationFrame` before the observer in the `[isActive]` effect, `}, [isActive])`, `}, [fontFamily, fontSize, isActive])`, the Shift+= / Shift+- key handler.
  - Rewrite the D-03 / VIEW-04 comments in TerminalPanel and the `onResize` doc comment in relayClient.ts ("host-path callers omit it") for INPT-06.
- **Assumption A8 (Research).** xterm applies a font change to its cell metrics synchronously (today's host zoom relies on it: it calls `fitTerminal` right after setting the option). If a test or the VM shows a claim one step stale, measure inside one `requestAnimationFrame` instead and record it.
- **Peer tab zoom.** App keeps the font size of a peer tab in the existing `fontSizes` map under the tab id (host-qualified since 10-02), passes `fontSize` and `onFontSizeChange` to WebShareSessionView for desktop peer tabs, and `removeTabState` already deletes the entry by id. WebShareSessionView takes an optional `onFontSizeChange` and forwards it (a no-op when absent: the browser viewer zooms with the browser). Local tabs keep their current keying (their id is the session id).
