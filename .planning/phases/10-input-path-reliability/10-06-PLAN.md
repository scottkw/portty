## Flagged decisions and assumptions

- **Classifier (Research Pattern 5, refined by the planner after reading internal/daemon/attach_viewers_test.go's `queryReplies`).** `func IsUserInput(filtered []byte) bool` reports whether any byte is user input. A byte is NOT user input when it belongs to:
  - a CSI sequence (`ESC [` ... final byte 0x40-0x7E) that has a private parameter marker (`<`, `=`, `>`, `?`) or an intermediate byte (0x20-0x2F), or whose final byte is one of `R n c t y I O M m` (cursor and status reports, DA, window reports, DECRPM, focus in/out, mouse);
  - an X10 mouse report: `ESC [ M` followed by three raw bytes;
  - an OSC, DCS, APC, PM or SOS string (`ESC ]`, `ESC P`, `ESC _`, `ESC ^`, `ESC X`) up to BEL or ST;
  - an unterminated sequence at the end of the frame (conservative).
  Every other byte is user input: printable text, CR, LF, TAB, other C0 controls, DEL, `ESC` + character (Alt keys), SS3 keys (`ESC O` + character), and CSI keys without a marker (arrows and Home/End `A-D H F`, `P-S`, `Z`, `~` function keys and bracketed paste markers, kitty `CSI code;mods u`). So a paste claims, and the kitty flags report `ESC [ ? 0 u` does not (it carries the `?` marker; Research's original final-byte list would have let it claim).
  - Conservative on purpose (Research): a false non-claim costs one more keystroke; a false claim makes viewers fight over the grid. Known collision: a modified F3 (`CSI 1;5R`) looks like a cursor report and does not claim.
  - `shortcut:` comment: stateless per frame, so a reply split across two frames can claim once from its tail; xterm.js sends each reply in one onData call, so in practice only a raw terminal behind `portty attach` could split one.
  - It runs on the bytes `InputAbsorber.Filter` returns (OSC 10/11 and DA1 are already gone) and never modifies them.
- **NoteTyping (Research Patterns 4 rule 3 and Pitfall 8).** `func (h *Hub) NoteTyping(sub *Subscriber) error`. Typing is a claim with the viewer's last reported size (CONTEXT; 10-04 rule 1 makes plain reports store-only, so the owner's own typing is how its newer report lands). Add `ownerFast atomic.Pointer[Subscriber]`, set and cleared together with `owner` (one `setOwnerLocked`-style helper used by ClaimGrid, the bootstrap, NoteTyping and Unsubscribe), and `ownerStale atomic.Bool`, set by ResizeClient when the owner reports a size different from the grid target and cleared whenever the target is set to the owner's size. Fast path: `ownerFast.Load() == sub && !ownerStale.Load()` returns with no lock (typing at line rate). Slow path takes `gridMu` then `mu` (the existing order; a fast path that locked `mu` first and then wanted `gridMu` would invert it): read-only → nothing; **no reported size (`sub.Cols <= 0`) → nothing (planner's choice: an older viewer that never reports keeps today's behaviour, never sizing the PTY, so mixed versions degrade as CONTEXT requires; a new viewer always reports on open, before any keystroke on the same socket)**; otherwise `owner = sub`, target = the sub's stored size, apply with `why=input` (frozen: record only; Thaw applies).
- **Pumps.** In both MsgInput cases, after filtering and before `in.Write`: `if relay.IsUserInput(filtered) { _ = hub.NoteTyping(sub) }` (the local pump is inside package relay). Read-only viewers never reach it (their input is discarded first, MC-03). No payload is logged.
- **Attach (CONTEXT "INPT-06 telling a claim from a size report").** `MakeClientClaimFrame(cols, rows uint16) []byte` = the report frame plus `relay.ResizeClaim`. `WatchResize` sends it on every SIGWINCH; the connect-time frame in cmd_attach.go stays `MakeClientResizeFrame` (a report: joins never claim), so cmd_attach.go is not edited. Give WatchResize a testable seam: an unexported `watchResize(ctx, conn, winch <-chan os.Signal, size func() (int, int, error))` that the exported one calls with `signal.Notify` and `term.GetSize`. `shortcut:` comment on the connect report (CONTEXT "Accepted limits"): `portty attach` can show a grid wider than its terminal until its user types or resizes.
- **End-to-end test through the proxy.** `TestCLIAttach_TypingTakesGrid` in attach_viewers_test.go: the scene's local viewer owns 120x40; the CLI (dialed at 80x24, which is a report) types a printable line through its stdin: the host hub becomes 80x24 and guiTab and browser each get a 0x02 80x24 frame; the local conn types a line: back to 120x40. And the `replayed_query_replies` subtest gains `s.checkUndisturbed(t, "guiTab", "browser")` after the fake terminal's answers (no grid frame other than 120x40): the integration pin for "auto-replies never claim".

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| viewer input → grid ownership | any write-capable viewer's keystrokes can now move the PTY size |
| a viewer's terminal → input stream | terminals answer queries automatically, with no human involved |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-20 | Tampering | grid ownership via auto-replies | high | mitigate | IsUserInput excludes reports, mouse and string replies (table, fuzz, and the replayed-query scene's checkUndisturbed); conservative on unterminated sequences |
| T-10-21 | Elevation of privilege | NoteTyping | high | mitigate | Read-only viewers never reach it (MC-03 discard) and the hub ignores them too (TestHub_GridTypingReadOnly); a viewer with no reported size cannot take ownership |
| T-10-22 | Denial of service | typing at line rate | medium | mitigate | The owner's keystrokes take an atomic fast path with no lock; non-owner typing applies once per ownership change |
| T-10-23 | Denial of service | attach SIGWINCH storm | low | accept | One claim frame per signal; signals come from the user's own terminal resizes; the hub clamps and rebuilds only on a size change |
| T-10-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan; package-legitimacy gate not triggered |
</threat_model>
