## Contract with 06-02 (Go). Keep it exact.

- **Status JSON:**
  - `state`: idle | checking | current | available | downloading | verifying | revealed.
  - `current`: the running version, no v.
  - `latest`: the newer version, set while available, downloading, verifying or revealed.
  - `done` and `total`: bytes, while downloading.
  - `error`: readable text after a failed download, verify or reveal. The state is then available. Never a URL or path.
- **Event** `update:status` with one Status, on every change, including checking and progress at most every 100 ms.
- **Bindings:**
  - `GetUpdateStatus(): Promise<UpdateStatus>`.
  - `DownloadUpdate(): Promise<UpdateStatus>`. It resolves when the download, verify and reveal end. The UI follows the events and ignores the result.
  - The old last-update getter and the old check binding are removed from both stubs: the native menu now runs the check, and Go owns its alerts.

## Flagged decisions and assumptions

- **Stubs are hand-maintained.** `frontend/src/wailsjs/go/main/App.d.ts` and `App.js` are tracked, hand-written stubs that call `Call('main.App.<Method>', [])`. App.tsx imports them. `frontend/src/wailsjs/wailsjs/go/...` is generated by Wails, unused by the app, and partly gitignored. Edit only the two hand stubs.
  - `export interface UpdateStatus { state; current; latest; done; total; error }` goes in App.d.ts, with state as the string-literal union.
  - UpdateBanner.tsx re-exports it (`export type { UpdateStatus } from '../wailsjs/go/main/App'`), so App.tsx keeps importing the update type from './components/UpdateBanner' as today.
  - If a Wails CLI build rewrites anything under frontend/src/wailsjs, restore it with `git checkout -- frontend/src/wailsjs` before committing.
- **Banner copy (Claude's discretion; CONTEXT gives "Verifying…" and "Shown in Finder").** "…" is U+2026 and N is floor(done * 100 / total), or 0 when total is 0.

  | State | Message | Extras |
  |-------|---------|--------|
  | available | "Portty {latest} is available." | Download button |
  | downloading | "Downloading Portty {latest}… {N}%" | `<progress className="banner__progress" max={total} value={done} aria-label="Download progress">` |
  | verifying | "Verifying Portty {latest}…" | none |
  | revealed | "Portty {latest} is verified and shown in Finder." | none |
  | available with error | Go's `error` text | Try Again button (calls onDownload), banner--warning variant |

  - Every other state shows the info variant with InformationCircleIcon.
  - Every state keeps the XMarkIcon Dismiss and role="alert" / aria-live="polite".
- **App rules.**
  - The update state is `updateStatus: UpdateStatus | null`.
  - The mount effect:
    - returns early in web mode, as today;
    - calls GetUpdateStatus and applies a non-null result;
    - subscribes `EventsOn('update:status', apply)`;
    - cleans up the subscription.
  - apply ignores state `checking`, so the banner never flickers on the daily re-check.
  - `dismissedUpdate: string | null`. Dismiss records the shown `latest` and keeps the existing 200 ms exit animation (updateExiting, handleDismissUpdate).
  - `showUpdateBanner` is true when the status is available, downloading, verifying or revealed, and either latest differs from dismissedUpdate or the state is downloading. Clicking Download in the native alert brings the banner back.
  - showUpdateBanner replaces the old trigger in the banner-stack INVARIANT gating expression (UI-SPEC order unchanged: Tailscale, WebGL, update, plugin toggles, save feedback).
  - onDownload calls DownloadUpdate() and ignores the result. Go reports the outcome through events.
- **Tokens only in CSS.** `.banner__progress` uses no literal colour, because the Category AK style gates forbid colours outside the token blocks. Use a fixed width (about 120px), `flex-shrink: 0` and `accent-color: var(--color-accent)`.
- **TESTING.md** is updated once, in 06-04.
