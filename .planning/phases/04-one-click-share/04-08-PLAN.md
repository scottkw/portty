<objective>
Make UAT gap 1 diagnosable when it happens live. Plan 04-07 checks the attach path in-process, but the two hypotheses that best fit the UAT symptoms (a host-local tiny grid push, and a first-contact tailnet path stall) have no in-process trigger. The daemon today runs detached with stdio sent to /dev/null, which is why the UAT captured no logs. This plan sends the daemon's output to a log file in its config directory and adds a small set of `viewer-diag:` lines at the exact points each hypothesis would show up. It also adds TESTING.md M-83, the two-Mac repro that says which lines to collect.

This logging is unconditional. Even if 04-07 fixed a reproduced mechanism, only a live log can show that it was the one behind the UAT event.

Purpose: the next blank-viewer report comes with evidence instead of a guess.
Output: internal/daemon/daemon_log.go (plus test), log routing in startDetachedDaemon, `viewer-diag:` lines in the relay hub, webserver read pump and daemon proxy, and the TESTING.md M-83 item.
</objective>
