<objective>
Close UAT gap 4: a viewer joining through another Mac's daemon proxy is dropped once the session has more than 32 KiB of history.

Cause (04-07, deferred-items.md first item): no Go WebSocket reader in the attach path sets a read limit, so coder/websocket's 32768-byte per-message default applies. The host sends the catch-up preamble (Hub.ReconnectPreamble: the raw scrollback ring of up to 256 KiB, or one rendered emulator screen once the ring has wrapped) as one message. The viewing daemon's proxy (remote_ws_proxy.go, copyWS reading the upstream conn) fails on it and tears down the joiner after the grid frame. The CLI reader (attach.WsOutputPump) has the same limit, which also breaks a local `portty attach` to a long session. User decision 2026-11-17: fix it now, before the next two-Mac UAT.

Every production coder/websocket site, and what this plan does with it:
- internal/daemon/remote_ws_proxy.go, the upstream Dial (reads host frames from the peer's share server): RAISE to relay.ViewerReadLimit.
- cmd_attach.go, the runAttach Dial (the CLI conn; reads the preamble from the local daemon over loopback): RAISE, inside attach.AttachSession, which runAttach calls. Setting it there means the 04-07 harness, which drives the real AttachSession on its own conn, tests the production line.
- internal/daemon/remote_ws_proxy.go, the clientConn Accept (reads the local webview's or CLI's input, resize and ping frames): KEEP the default. It only carries viewer input, and the host's share server would refuse an input message over 32 KiB at its own limit anyway, so raising it gains nothing.
- internal/relay/server.go, the handleSession Accept (local relay, reads local GUI or CLI input): KEEP the default. Loopback input frames only.
- internal/webserver/server.go, the handleWSSRelay Accept (host share server, reads tailnet guest input): KEEP the default. This reader faces untrusted cap holders, and its 32 KiB limit is the DoS guard.
- Frontend: the GUI tab and the browser use the browser's built-in WebSocket (frontend/src/lib/relayClient.ts), which has no per-message limit to set. The 04-07 evidence agrees: connected GUI tabs and browsers were unaffected. Nothing changes there.

Bound: ViewerReadLimit = 4 * DefaultScrollbackBytes = 1 MiB. The raw preamble can't exceed the ring (Scrollback.Append caps it at 256 KiB, and the query strip only removes bytes). The wrapped-ring preamble is one rendered screen of the live emulator, which renders only the current screen; 1 MiB covers about 50,000 cells at about 20 bytes per styled cell. A full 32 KiB PTY read plus its 1-byte frame header is 32769 bytes, already over the old default, so live frames are covered too. A bounded limit (not disabled) still caps what one message can make a reader buffer. Tying it to DefaultScrollbackBytes means raising the ring raises the limit.

Purpose: a GUI tab or `portty attach` can join a long-running shared session (a Claude Code session passes 32 KiB in minutes), so the next two-Mac UAT doesn't trip over a known failure.
Output: one constant, two call sites, a RED-first harness variant, TESTING.md and deferred-items.md updates.
</objective>
