## Phase Goal

Sharing is one on/off switch per session: shared means tailnet peers and a tailnet web link at once, always full control, with a clean stop and CLI attach from any terminal. Funnel and read-only links are gone. (ROADMAP Phase 4 goal, verbatim.)

This plan is the viewing Mac's half. One daemon route turns "this host, this session" into a stored capability through the same-account peer routes from 04-03; the CLI and the GUI both use it, and the daemon's proxy now forwards the close reason so both can say "stopped sharing". Two remote paths that are broken today get fixed on the way: `portty attach host:id` (no cap, no Origin) and `portty list` (cap-gated route, no cap). Sequential plans; green at the boundary. The GUI wiring of the new binding lands in 04-06.

Purpose: SHAR-06 ("From any terminal (e.g. Warp), `portty attach <host>:<session>` attaches to a remote shared session with the tmux-style status bar"), SHAR-04 CLI and proxy half, SHAR-01 peer listing (different-account peers hidden), ROADMAP SC5, CONTEXT ▸ portty attach from any terminal (all four bullets), UI-SPEC CLI output and CLI errors.

## Flagged decisions and assumptions

- The CLI no longer dials the peer itself; it goes through the local daemon's relay proxy, which already injects the byte-exact Origin and holds the capability (RESEARCH Pattern 5). WhoIs sees the same source address either way.
- A bare argument to `portty attach` is tried as a local session first (exact name, exact ID, unique prefix), then as a host. A local session named like a Mac shadows that Mac; `<host>:<session>` is always remote. When a bare argument matches neither, the CLI prints the local "no session named" error.
- Connection refused on the host's port 7444 means "not sharing" (the server stops when nothing is shared; RESEARCH Pitfall 5). The "Found: …" list in the unknown-host error comes from the probed peers (Macs running Portty).
- InsecureSkipVerify in the proxy client stays for Phase 5 (STATE concern; research OQ3 resolution).
- The remote session name in the revoke message is the name the daemon returned at connect time; the host is the MagicDNS short name.
