# Phase 04 — UI Design Contract

> Visual and interaction contract for Phase 4 (One-Click Share: SHAR-01..06). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase replaces the Share dialog with a small popover holding a single switch, and deletes the rest of the sharing UI. Phase 2's contract (`02-UI-SPEC.md`, approved) is locked: tokens, type scale, spacing, switch, context menu, banner, dialog rules and copy rules all apply unchanged. Phase 3's naming rules apply too: "Portty" in display text, `portty` in commands. This contract adds no colours, no type sizes and no spacing values.

**Sources, in priority order:**
1. `04-CONTEXT.md` decisions (locked; the user accepted all of them).
2. `02-UI-SPEC.md` and `03-UI-SPEC.md` (locked).
3. Existing code, scanned 2026-11-16: `TabBar.tsx` (Share button), `Sidebar.tsx` + `ContextMenu.tsx`, `SettingsSheet.tsx` (Sharing and Security panes, the CT gate), `Share/*`, `SessionShare/*`, `RemoteJoinCodeModal.tsx`, `ShellWebShareBanner.tsx`, `SessionEndedBanner.tsx`, `WebShareSessionView.tsx`, `web/{dashboard,join}.html`, `internal/webserver/server.go` (routes; `/sessions/{id}` redirects to `/app/`), `capability_mw.go` (plain-text 401/403), `app.go` (`StartWebServer` LAN fallback, `HasCTDisclosure`), `cmd_attach.go`, `cmd_cli.go`.

## Component Contracts

### Share button (toolbar, Phase 2 restated with changes)

| State | Visual | Behavior |
|-------|--------|----------|
| Not shared | Unchanged: transparent, 1px `--color-separator` border, `SignalIcon` 16 + "Share" | Toggles the Share popover |
| Shared | Unchanged: accent fill, label "Shared" | Toggles the Share popover |
| Tailscale off | Its current look (Share or Shared) at `--opacity-disabled`. `aria-disabled="true"`, `aria-describedby="ts-off-reason"`, name stays "Share" / "Shared" (Phase 2 rule) | Does nothing. A shared session can still be stopped from the sidebar menu or `portty unshare` |
| Popover open | No extra visual. `aria-haspopup="dialog"`, `aria-expanded="true"` (otherwise `"false"`), `aria-controls` = popover id | Click, Enter or Space closes the popover |

### Share popover (new; replaces `SessionShareModal`)

| Part | Contract |
|------|----------|
| Element | `role="dialog"`, `aria-label="Share “<name>”"`, non-modal: no scrim, `aria-modal` absent. Portal-rendered above the terminal and banners, below sheets |
| Position | Top edge 8px below the Share button's bottom edge. Right edge aligned with the button's right edge, clamped to at least 12px from the window's right edge. Re-positions on window resize |
| Arrow | 16×8px up-pointing SVG triangle: fill `--color-popover`, 1px `--color-control-border` stroke on the two slanted sides only, horizontally centred on the Share button, base flush with the popover's top edge so the popover border has no seam under it |
| Surface | `--color-popover`, 1px `--color-control-border`, radius 10px, `--shadow-popover`, padding 16px. No visible title, no close "×", no footer buttons (native NSPopover is transient) |
| Switch row | `<label for>` "Share this session" (Body 13/400, `--color-text`) left, Phase 2 Switch right, 12px gap, row min-height 24px, `align-items: center` |
| State line region | Everything below the switch row sits in one container with `aria-live="polite"`, so state changes are announced |
| Motion | Opens with a 120ms ease-out opacity fade, no translate. Closes instantly. No motion under `prefers-reduced-motion: reduce`. The switch knob keeps its Phase 2 120ms slide |

States:

| State | Switch | Below the switch row |
|-------|--------|----------------------|
| Off | off, enabled | Description (Caption, secondary, 8px above): **Macs signed in to your Tailscale account see it in their sidebar, and you get a link for any browser on your tailnet.** If the CT disclosure has not been acknowledged (`HasCTDisclosure()` false), a second Caption line 8px below: **The first share gets an HTTPS certificate for <host>.ts.net. That name is published in public Certificate Transparency logs.** |
| Starting (after the user turns it on) | on, `aria-disabled`, pointer events off, `--opacity-disabled` | Caption, secondary, 12px above: **Getting a link…** |
| On | on, enabled | Link row 12px below: read-only `<input>` (12px mono, `aria-label="Share link"`, `spellcheck="false"`) holding the full link, then the Copy button 8px to its right. Then the warning line 8px below (Caption, secondary): **Anyone on your tailnet with this link has full control.** |
| Stopping (after the user turns it off) | off, `aria-disabled`, pointer events off | Link row and warning removed at once. No status text |
| Start failed | back to off, enabled | Inline error (Caption, `--color-error-text`, 12px above), then the Off description. Copy in the Copywriting Contract |
| Stop failed | back to on, enabled | The link row stays. Inline error under the warning line, 8px above |
| Tailscale goes off while open, session not shared | off, `aria-disabled`, `aria-describedby` = the reason line | Caption, secondary: `TAILSCALE_OFF_REASON` |
| Tailscale goes off while open, session shared | on, **enabled** (turning off is never blocked) | `TAILSCALE_OFF_REASON` replaces the link row and warning |

Link field and Copy:

- Focusing or clicking the field selects the whole link. The field scrolls horizontally like any input; no `title` tooltip.
- Copy writes the link to the clipboard (Wails clipboard API in the desktop app). The label changes to **Copied!** for 2 seconds, then back to **Copy**. The button keeps its width, so set `min-width` to the wider label.
- If the clipboard write fails, show the inline error **Couldn't copy the link. Select it and press ⌘C.** under the warning line, and select the field.
- The link is the same across app and daemon restarts while the session stays shared (persisted capability). Renaming the session does not change it. Turning Share off and on again creates a new link.

Open, close and focus:

| Trigger | Result |
|---------|--------|
| Share button click, Enter or Space | Opens; focus moves to the switch |
| Share button again, Esc, or a click outside the popover | Closes; focus returns to the Share button (Esc and button) or stays where the user clicked (outside click) |
| Tab / Shift+Tab | Moves between switch, link field and Copy, wrapping inside the popover |
| Active tab changes, the session ends, a peer tab becomes active, ⌘, opens Settings, or the window loses key status | Closes. A pending start or stop keeps running; its result shows in the toolbar button and the sidebar icon |
| Space on the switch | Toggles it (Phase 2 `role="switch"` button) |

### Sidebar context menu (Phase 2 menu, two new items)

| Invoker | Items |
|---------|-------|
| Local sidebar row, not shared | Rename · **Share** · ─ · End Session… |
| Local sidebar row, shared | Rename · **Stop Sharing** · ─ · End Session… |
| Local tab | Unchanged (Rename · Save Terminal As… · Close Tab · ─ · End Session…) |
| Peer row / peer tab | Unchanged (no menu / Close Tab) |

- Neither item has an ellipsis: both act at once with no dialog.
- **Share** while Tailscale is off: `aria-disabled="true"`, text at `--opacity-disabled`, no highlight on hover, skipped by ↑/↓, Enter does nothing, `aria-describedby="ts-off-reason"`. `ContextMenu.tsx` gains a `disabled` item flag for this. **Stop Sharing** is never disabled.
- Success feedback is the existing indicators only: the `SignalIcon` (`aria-label="Shared"`) appears on or leaves the row, and the toolbar button reads "Shared" / "Share" if that session's tab is active.
- Failure: a warning banner in the banner stack (Phase 2 banner style, with Dismiss), copy in the Copywriting Contract. It goes away on Dismiss or on the next successful share or stop of that session.
- First share with the CT disclosure unacknowledged: the menu shares directly. The disclosure is non-blocking (see Decisions Made Here).

### Peer sidebar and peer tabs

| Situation | Behavior |
|-----------|----------|
| Click a peer row | Opens (or activates) a `<host> › <session>` tab straight away. No Join Remote Session dialog: access comes from the same-account WhoIs check |
| Peer refuses access (different Tailscale account) or can't be reached while opening | The tab stays open with a warning banner at the top of its terminal area: **Couldn't connect to <host>. Check that it's awake and signed in to your Tailscale account.** The user closes the tab |
| Peer Mac signed in to a different Tailscale account | Its probe returns no sessions, so its group stays hidden (Phase 2 rule "Peer reachable with 0 sessions: Hidden"). No error, no "not authorized" row |
| Peer stops sharing a session, no tab open on it | The row disappears on the next peer poll (≤ 30s). If it was that peer's last shared session, the peer's group header disappears too |
| Peer stops sharing a session with a tab open on it | The row disappears at once. The tab stays, keeps its scrollback, stops taking input, and shows an info banner at the top of its terminal area: **<host> stopped sharing this session.** (Dismiss "×", `aria-label="Dismiss"`). No auto-reconnect. Closing the tab works as usual. No sidebar row is selected while this tab is active |
| Peer's shell exits with a tab open | Unchanged: the existing `SessionEndedBanner` copy |

Branching between "stopped sharing" and "session ended" uses a fixed close-reason value the server sends. The banner text never renders wire text; `<host>` and the session name come from local state (Phase 1 T-175-06-02 rule).

### CLI output (`portty share`, `portty unshare`, `portty attach`)

All output is plain text, no colour. Errors go to stderr with the Phase 3 prefix `portty: ` and exit 1. Success goes to stdout and exits 0.

| Command / case | Output |
|----------------|--------|
| `portty share <session>` | Line 1 **Shared "<name>".** Line 2 the link alone (so it can be copied or piped). Line 3 **Anyone on your tailnet with this link has full control.** If the CT disclosure is unacknowledged, line 4 is the popover's CT sentence (with the real host), and the acknowledgement is recorded |
| `portty share`, already shared | Same three lines with the current link |
| `portty unshare <session>` | **Stopped sharing "<name>". Remote viewers were disconnected.** |
| `portty unshare`, not shared | **"<name>" isn't shared.** (exit 0) |
| `portty attach <host>:<session>` / `<host>` with one shared session | Attaches with the existing banner (`─── <name> │ <host>` / ` Press Ctrl-\ to detach.`) and the tmux-style status bar, unchanged |
| `portty attach <host>`, several shared sessions | **<host> is sharing <n> sessions:**, then one line per session, two-space indent, name then ID padded into columns, then **Run 'portty attach <host>:<session>' to attach.** (exit 0, nothing attached) |
| Host stops sharing mid-attach | Restore the terminal, remove the status bar, print **Portty: <host> stopped sharing <session>.** (locked wording, capital P, stdout), exit 0 |
| Detach (Ctrl-\\) | Unchanged: **Detached.** |
| Usage error | **usage: portty share <session>** / **usage: portty unshare <session>** / **usage: portty attach <session> \| <host>:<session> \| <host>** |

Add `share <session>` "Share a session with your tailnet" and `unshare <session>` "Stop sharing a session and disconnect viewers". `attach` lines become `attach <session>` "Attach to a session on this Mac" and `attach <host>:<session>` "Attach to a session shared from another Mac (e.g., office-air:build)". `--readonly` is removed from attach (SHAR-02: no read-only mode) |

## Interaction Contract

| Action | Result |
|--------|--------|
| Turn Share on (popover switch, sidebar menu, `portty share`) | One step: the session gets a capability, the web server starts if it isn't running, the link appears in the popover, the row's `SignalIcon` appears, the toolbar button reads "Shared", and same-account peers list the session on their next poll. All three entry points flip the same daemon state, so the GUI updates when the CLI changes it |
| Turn Share off (popover switch, "Stop Sharing", `portty unshare`) | Every capability for the session is revoked and every viewer (peer GUI, browser, CLI) is disconnected with the notices above. Indicators clear. The web server stops when no session is shared |
| Turn Share on again | A new link. Old links show "Link No Longer Works" |
| App or daemon restart | Shared sessions stay shared with the same link; indicators restore on launch |
| Tailscale disconnects | Phase 2 behavior (banner, Share button `aria-disabled`, peer groups collapse). Share state is kept. Turning Share off still works; turning it on does not |
| End Session on a shared session | Confirm (with the disconnect line), then viewers see the existing session-ended notices |

## Decisions Made Here (Claude's discretion; the user may override)

| Decision | Choice | Why |
|----------|--------|-----|
| Web server lifetime | Starts on the first share, stops when no session is shared. No UI shows it | Less exposure when idle; CONTEXT leaves it open |
| Different-account peer | Not listed; its group stays hidden. CLI gets a clear refusal message | Phase 2 already hides peers with 0 sessions; no new state to design |
| One-time share warning banner | Removed with its Settings switch | CONTEXT shrinks Settings ▸ Sharing to status plus explanation, so the switch has no home. The always-visible locked warning line in the popover replaces it |
| CT disclosure | Kept, but non-blocking: shown in the off popover until the first share, which records the acknowledgement (also via the CLI). The Security row stays | The Settings Start Server button that enforced it is gone, and a blocking step before the first share would break "one step" (SC1). The disclosure still reaches the user before the certificate is issued from the popover |
| Revocation notice in an open peer tab | Tab stays with scrollback and an info banner; no auto-close | The user can read the last output. Matches the existing "Session ended" pattern |

## Accessibility Contract

- The popover is `role="dialog"` with `aria-label="Share “<name>”"`. The Share button carries `aria-haspopup="dialog"`, `aria-expanded` and `aria-controls`.
- The switch keeps Phase 2's `role="switch"` + `aria-checked` + `<label for>`. While starting or stopping it uses `aria-disabled`, not `disabled`, so focus stays on it.
- State text below the switch sits in an `aria-live="polite"` region, so "Getting a link…", the link appearing, and errors are announced.
- Disabled-with-reason (Share button, switch, menu "Share") uses `aria-disabled` plus `aria-describedby` pointing at visible text, never a tooltip alone (Phase 2 rule).
- The "Shared" state is never colour-only: the row icon has `role="img" aria-label="Shared"` and the button label changes.
- Revocation and failure banners use the Phase 2 banner roles (`role="status"`). Their text is fixed copy plus local names, never wire text.
