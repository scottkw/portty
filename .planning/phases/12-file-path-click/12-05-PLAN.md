## Flagged decisions and assumptions

- **Share pump arm (RESEARCH Pattern 4; PATTERNS "read pumps").** In internal/webserver/server.go's read pump (~950-1010), beside `case relay.MsgInput`, add `case relay.MsgPathClick` that calls `hub.PathClick(sub, payload)` only when `!sub.ReadOnly` (the MC-03 shape). No per-click log line here (a link holder can send these at line rate; the hub logs one outcome line per resolve). Keep the "no case and no default arm" comment for retired bytes. Read-only is enforced at both layers on purpose (RESEARCH Pitfall 9): every minted share is read,write today (SHAR-02), so a read-only subscriber exists only with a legacy or hand-signed capability, and a single check could rot unnoticed.
- **Tests (internal/webserver/pathclick_test.go, new; capability_test.go is the analog).** Use `testServerWithHub` (capability_test_helpers.go: returns the server, client, the PTY output writer and the input reader), `issueCapFor(t, ws, sid, perms)`, `dialWebServerWS` with the Origin header set as TestSecurity_ReadOnlyCapabilityBlocksMsgInput does, and real temp files. Write the printed path into the PTY output pipe before dialing. The read-cap test proves the negative against a positive control on the same hub: the read cap's click gets nothing within 500 ms, then a write cap's click on the same text gets a MsgPreview header (so the hub was able, and only the capability made the difference).
- **API version (CONTEXT "Decided at planning" [Gating]).** `APIVersion = 4` with its comment extended ("4 adds path clicks (PathClickAPI)"), and `const PathClickAPI = 4` beside PreviewAPI with a comment that it is the lowest daemon API whose sessions accept MsgPathClick; viewers do not read it (they follow the capability bit on the stream, which also covers peer and browser viewers that never see /health); it documents the feature for /health and /info readers. Update the two pins: internal/daemon/client_test.go:47 (`DaemonAPI(h) != 4 || APIVersion != 4 || PreviewAPI != 3`, plus PathClickAPI != 4) and internal/daemon/api_test.go:171 (`"api":4`). MinDaemonAPI stays 1 (client_test.go:41 pin unchanged): a daemon on API 3 keeps working, only without path clicks. internal/webserver/listener_test.go is parametric in the API value and needs no change.
- **The review (model: 11-SECURITY-REVIEW.md; RESEARCH "Security Domain" and its "Record in the security review" paragraph).** Sections, in this order:
  1. Scope and parts (12-05 writes these sections; 12-07 appends "VM evidence and verdict"); the no-secrets rule (no link, token, tailnet host or path from a real Mac).
  2. "PREV-03 amended": Phase 11's rule and Phase 12's amendment, word for word as in the must_haves; the three conditions (a), (b), (c) and where each is enforced (pathclick.go printed-token search over History and the live screen; the read-only refusal in both pumps and the hub; previewfile.Open, moved unchanged from `portty open`).
  3. "Why the contract holds" (the PREV-03 argument): no HTTP route or new socket takes a path; the click rides the session's own authenticated WebSocket (share capability and WhoIs gates unchanged in front of it); the host resolves against that session's own directory log; only text the session printed is accepted, as a whole token, from rendered output (not the raw ring, so titles and escape strings do not count); the file must exist, be a regular file and be an allowlisted type under 20,000,000 bytes; the source gate pins that pathclick.go has no file-system imports and is the only relay file using previewfile.
  4. "Honest scope": a write-capable viewer already controls the shell (SHAR-02) and could `cat` any file the user can; the printed check and type allowlist are defence in depth, not the boundary. The real boundary added is: read-only viewers get nothing.
  5. "Accepted risks": a program in the session can print any path or forge OSC 7 (it already runs as the user and can run `portty open`); OSC 7 from ssh peers is ignored by the host check, which is not a security boundary; nested shells, ssh and bash/fish without their own OSC 7 leave the outer directory, so a relative click can name a same-named file in the outer directory; hard-wrapped TUI paths cannot be clicked.
  6. "Shell integration": the shim lives only in Portty's 0700 config dir, is rewritten atomically from the embedded script and verified before ZDOTDIR is set; on failure nothing is set; the user's startup files are never touched; no viewer input reaches it.
  7. "What stays unchanged": the share page CSP is Phase 11's Amendment 3 exactly (no new resource types: the preview renderers already exist); the token gate, WhoIs gate and tailnet-only listener; `web/assets/terminal.js` (out of scope, no preview support).
  8. "Threat register": the T-12-xx rows of 12-01..12-05 with severity, disposition and the test that pins each.
  9. "Tests that pin it": TestPathClick_SourceGate, TestPreview_SourceGate, TestPathClick_TokenTable, TestPathClick_NotPrintedAbsolute, TestPathClick_NotPrintedEdges, TestPathClick_Refusals, TestPathClick_Outcomes, TestPathClick_NeverLogsPath, TestPathClick_CapabilityBit, TestWebPathClick_ReadCapRefused, TestWebPathClick_ReadCapNoCapabilityBit, TestWebPathClick_WriteCapPreviews, TestZshShim_FailureStillSpawns, TestZshShim_UserFilesUntouched, TestParseOSC7, TestHandoffState_CwdValidates, TestCSPHeaders_PreviewDelta (unchanged).
