## Flagged decisions and assumptions

- **Where OSC 7 is parsed (CONTEXT [CWD tracking] "In the daemon, from the PTY output stream"; RESEARCH Pattern 2).** In `newLiveEmulator` (hub.go ~1204), the only emulator constructor, register `emu.RegisterOscHandler(7, …)` beside the OSC 8 handler (~1354). The handler receives `data` including the leading `7;`, runs inside `emu.Write` under emuMu, returns `false` (vt's own default still runs), and parses `data` itself: vt's `Callbacks.WorkingDirectory` drops payloads with a second `;`, so it is not used. While `emu.IsAltScreen()` the report is ignored (a full-screen program is not the shell).
- **Row numbering.** `History` gains `pushed uint64`, incremented once per `Push` (also for a line the byte cap drops at once), never reset by `Clear`; accessors `Pushed()`, `FirstRow()` (= pushed − Len()) and `Snapshot() (lines []string, wrapped []bool, firstRow uint64)` (cloned slices of the retained lines; 12-04 copies under emuMu and searches outside it). The handler's row is `h.history.Pushed() + uint64(emu.ScrollbackLen()) + uint64(emu.CursorPosition().Y)`. History line i has row `firstRow + i`; screen row y has row `pushed + y` after the drain. This stays consistent through scrolling, ED 2, resize (resizeLiveEmulator pushes the visible rows first), alt-screen exit and trimming; RIS drops undrained lines uncounted, so the log is cleared on RIS (the RIS ESC handler ~1335, `h.cwds.clear()`), which is also right semantically: the next prompt reports again. `ESC[3J` (`h.history.Clear()`) keeps both the counter and the log.
- **The log (cwd.go).** `CwdRecord{Row uint64; Dir string}` (exported fields: gob). `cwdLog` holds records with strictly increasing rows and a byte total; `add(row uint64, dir string, firstRow uint64)`: drop trailing records whose row is >= row (a lower or equal row supersedes them), skip if the new last record would have the same dir as the one before it, append, then prune records older than firstRow while keeping the newest record at or before firstRow (the floor), then drop the oldest while over `cwdLogMaxRecords = 1024` or `cwdLogMaxBytes = 64 << 10`; `at(row) (string, bool)` returns the newest record with Row <= row; `clear()`. It is Hub-owned (field `cwds`, like `cs`, `modes`, `wraps`), touched only under emuMu, and survives emulator rebuilds.
  - Caps: 1024 directory changes inside 10,000 history lines is far beyond normal use; when exceeded, the oldest lines lose their directory and relative clicks on them do nothing. 64 KiB fits inside HandoffStateMaxBytes' 1 MiB "rest" margin, so that constant does not change.
- **parseOSC7 (RESEARCH "Code Examples").** Strip `7;`; reject over 2048 bytes; `url.Parse`; require scheme `file`; host (lower-cased, trailing dot trimmed) must be empty, `localhost` or `sameHost` with this Mac's `os.Hostname()` (looked up once with `sync.OnceValue`; `sameHost` also tolerates a `.local` suffix difference); the decoded path must be absolute, at most 1024 bytes, with no control character (Go decodes `%00` and `%0A` into the path); return `filepath.Clean(path)`. A raw unencoded `%` makes url.Parse fail: ignored (third-party emitters that do not percent-encode are not supported; the Portty shim always encodes). Hosts from ssh sessions are ignored by the host check (CONTEXT [CWD tracking]); it is not a security boundary (12-05's review says so).
- **Handoff (CONTEXT "Decided at planning" [Handoff]; RESEARCH Pattern 3).** `HubState` gains `Cwds []CwdRecord` and `HistoryPushed uint64`. `exportLocked` sets both after the seed rebuild (copy of the log). `NewHubFromState` restores the log and sets `history.pushed = st.HistoryPushed` when it is non-zero (after the lines are pushed, which leaves pushed = len(lines) for an older daemon's state). `validate` refuses: HistoryPushed non-zero and below len(History.Lines); more than 1024 records or over 64 KiB; a record with a relative, unclean (`filepath.Clean(d) != d`), over-1024-byte or control-character directory; rows not strictly increasing; a row above `HistoryPushed + maxHandoffGrid`. Older daemons ignore the new gob fields; newer ones see zero values from older ones: additive both ways (rated reversible: no migration, either side tolerates absence).
- **Test helper.** cwd_test.go builds hubs with `NewHub` plus `resizeHub` (history_test.go) and feeds bytes with `feedHubs` (handoff_state_test.go: records frames the way Run does, synchronously). A test-only helper finds the newest row whose ANSI-stripped text contains a marker (history snapshot then screen rows from `liveEmu.Render()`) and returns `h.cwds.at(row)`, all under emuMu. Rows used by tests are computed only through History.Snapshot and the screen, never hard-coded.
