## Flagged decisions and assumptions

- **Security contract (CONTEXT "Security model for path clicks": one-way, settled by the user in discuss; no new checkpoint).** The daemon reads a clicked file only when (a) the text appears in that session's own retained output, (b) the requester can write to the session, (c) the file passes the `portty open` checks. This amends Phase 11's "the daemon never opens a path given to it"; 12-05 writes the review section. There is still no HTTP route or wire message that reads an arbitrary path.
- **Wire (CONTEXT [Transport]; RESEARCH Pattern 4).** `MsgPathClick byte = 0x13` (client to server) beside MsgPing; `PathClickMaxBytes = 1024`; `MakePathClickFrame(text string) []byte`. `MetaPayload` gains `PathClick *bool` (`json:"pathClick,omitempty"`) and `Notice *string` (`json:"notice,omitempty"`), with constants `NoticePathUnsupported = "path-unsupported"` and `NoticePathTooLarge = "path-too-large"`. Old hosts drop 0x13 (both pumps have no default arm); old viewers ignore unknown meta fields (relayClient.ts handleMeta destructures only replay and offset). The 32 KiB input read limit already covers 1024 bytes.
  - Reversibility: costly. A byte value and two meta fields shared by hosts and viewers of different versions; undoing them means retiring the byte (like 0x30-0x37) and tolerating the fields for a release, not a migration.
- **Hub.PathClick(sub *Subscriber, payload []byte) bool** returns whether a resolve started (tests use it; pumps ignore it). Cheap checks first, every refusal silent: sub nil or `sub.ReadOnly`; payload length 1..PathClickMaxBytes, `utf8.Valid`, no control character; under `h.mu`: not closed, not freezing, not previewBusy; then `pathClickBusy` (an `atomic.Bool` field on Hub) CompareAndSwap false to true; then `go` the resolve, which clears the flag when it returns. Never touch disk on the pump's goroutine (a slow disk would stop pong handling and the viewer would be dropped as dead).
- **Resolve (on its own goroutine).** Strip a trailing `:digits(:digits)?` from the text. Snapshot under emuMu only: `h.history.Snapshot()`, the screen rows from `h.liveEmu.Render()` split on `\n` with each row's soft-wrap flag from `screenRowWrappedLocked` (as screenBodyLocked does), whether the history's last line wraps onto screen row 0 (`EndsWrapped` and not alt screen), `IsAltScreen()`, `h.history.Pushed()` and a copy of the cwd log's records; release emuMu before any searching (Run holds emuMu while recording and broadcasting; a 10,000-line scan under it would stall every viewer). Outside the lock: `ansi.Strip` each row, join soft-wrapped rows into logical lines (history rows, then screen rows, with the history-to-screen join), walk newest to oldest, and take the first logical line containing the text as a token; its row is the absolute row of the logical line's first row (history index i: firstRow + i; screen row y: pushed + y). Only when no logical line matches, run the full-row fallback (next bullet; Task 2).
  - **Full-row fallback for soft wraps (CONTEXT "Decided at planning" [Printed check], full-row fallback bullet; RESEARCH Pattern 5 "Soft wraps", Pitfall 7; wraps.go "shortcut" comment).** The hub's wrap marks are a hash heuristic: a wrap is consumed by the first content-identical full row to drain, so a hard full-width row identical to the wrapped row, printed above it while both are on screen, takes the mark. Then the first pass over-joins on screen (both rows test as marked, and the path is preceded by the hard row's last character) and under-joins in history (the hard row carries the mark, the wrapped row does not). The viewer underlines the path anyway (xterm's own wrap flags are exact), so the host must serve it. Build it in Task 2:
    - Strip every row once; both passes use the stripped rows. The snapshot under emuMu also takes the live width and, per screen row, `lineFull(screenLine(h.liveEmu, y), h.liveEmu.Width())` (both helpers are already in package relay; no hub.go change).
    - "Full": a screen row is full by that lineFull flag; a history row is full when its display width equals the live width (`ansi.StringWidth` on the stored row; use the width measure the emulator uses if internal/relay configures one). History keeps no per-row drawn width, so rows drawn before a resize are never full here and rely on the first pass alone (a documented limit; it can only miss, never join a row the live width did not fill).
    - The two passes are separate unexported functions over the copied snapshot, so a test can show the first pass alone refuses a state that the fallback accepts. The fallback runs only when the first pass finds no logical line holding the text as a token.
    - The row sequence is the first pass's (history rows oldest to newest, then screen rows), with no join from the last history row to screen row 0 on the alt screen. Row k joins row k+1 when row k is full and row k+1 is not empty. Row k may start a run unless the row above it is full, carries the wrap mark the first pass used (history `wrapped`, the history-to-screen join, or screenRowWrappedLocked's result) and has different stripped text: that combination means the hub saw that row wrap onto row k, and the only known way it is wrong is a mark traded between identical rows. Walk k from newest to oldest, build the run from row k (stop at the first row that is not full, or once the run holds at least len(row k) + len(text) + 2 bytes: a token starting in row k never needs more, so the pass stays linear in the retained rows), and apply the same token rule to the run (any offset; the character before an offset inside the run is the run's own). The first run that holds the text wins; its row is the absolute row of the run's first row, exactly as in the first pass.
    - Tight by construction: the clicked text must be a whole token of the joined text; rows that are not full are never joined; the tail of a wrap the hub marked never starts a run. Where the hub has no mark for a full row (a traded or evicted mark), both readings count as printed: the row joined to the next, and the next row starting its own run. That is the ambiguity the heuristic leaves, and the viewer's own exact wrap flags decide what it underlines.
    - TestPathClick_WrapJoin proves the ordinary case (first pass); TestPathClick_WrapFallback reproduces wraps.go's documented miss and the refusals that keep the check tight; 12-07 C-09 checks both on a real Mac.
  - **Token rule (CONTEXT "Decided at planning" [Printed check]).** Path alphabet: Unicode letters and digits, `_ . ~ @ % + # -`, plus `/`. A match at byte offset i of length n is a token when the character before i is absent or outside the alphabet, and the character at i+n is absent, outside the alphabet, or a `.` followed by absent or a character outside the alphabet. `=` and `:` are outside the alphabet (so `--out=/tmp/a.png` and `a/b.png:12:3` match). The fixture's `tokens` table is the source of truth for both sides.
  - **Resolution.** Text starting with `/`: as is. `~/`: the home from `userHomeDir()` joined with the rest (a package-level `var userHomeDir = os.UserHomeDir` in cwd.go, so tests can point it at a temp dir and pathclick.go needs no `os`). Bare `~` or `~user`: refused. Anything else: relative; the directory is the cwd log's newest record at or before the match row (alt-screen screen matches use the newest record), none means refused (CONTEXT [Shells]: "relative ones do nothing"; never seed from the spawn work dir). Join and clean with the `path` package. `..` is not a traversal concern: authorisation is "this exact text was printed by this session", not "inside a root" (RESEARCH Pattern 6).
  - **Open and deliver.** `previewfile.Open(p, PreviewMaxBytes)`: `ErrUnsupported` → unicast notice path-unsupported; `ErrTooLarge` → path-too-large; any other error → nothing. Success → `h.SendPreview(Preview{Name: CleanPreviewName(file.Name), MIME, Key, Data, FocusSub: sub})`; a SendPreview error (busy, ended, invalid, zero targets) → nothing.
  - **Unicast notice.** Under `h.mu`, only if sub is still in `h.subscribers` and not revoked: `queueIfRoom(sub, MakeMeta(MetaPayload{Notice: &code}))`. Never broadcast or BroadcastMeta (every viewer would see "Can't preview this file type").
  - **Logging.** One line per resolve: `viewer-diag: path click session=<DiagID> conn=<sub.ID> outcome=<code> bytes=<n>` with codes `preview`, `not-printed`, `no-cwd`, `missing`, `unsupported`, `too-large`, `send-failed`. Never the text, a path or a name (the existing rule: input payloads are never logged). Refusals before the goroutine log nothing (a writer could spam them).
  - **Test seams.** An unexported Hub field `pathClickResolved func(outcome string)`, nil in production and called at the end of every resolve, lets tests wait without sleeps. The loopback relay server never creates a read-only subscriber (server.go:50: "Local subscribers are never read-only; only the webserver sets ReadOnly"), so its pump's read-only arm cannot be reached through a real connection; an unexported `Server` field `testReadOnly bool`, false in production and set only by an in-package test, is copied into the new Subscriber's `ReadOnly` in handleSession. Hub.PathClick refuses read-only subscribers too, so TestPathClick_RelayPumpReadOnly proves the end-to-end refusal through the pump (and covers the arm), while TestPathClick_Refusals isolates the hub check.
- **Focus (CONTEXT "Click UX"; UI-SPEC Planner Notes; RESEARCH Pattern 4).** `Preview` gains `FocusSub *Subscriber`; when non-nil each header's focus is `sub == p.FocusSub`, otherwise today's owner rule. The click must not go through the typing claim, because that claims the PTY grid. TestHubSendPreview_NoOwnerNobodyFocuses and the other Phase 11 preview tests stay untouched and must pass. The viewer side needs no change: App.handlePreview already honours focus only when the viewer shows that session's tab or one of its previews.

Both pumps send Frames, and the peer proxy copies frames verbatim, so local tabs, peer tabs and browser viewers all get it with no extra HTTP.
