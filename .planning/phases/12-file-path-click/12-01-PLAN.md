## Flagged decisions and assumptions

- **What moves (RESEARCH Pattern 6; PATTERNS "previewfile").** From cmd_open.go: the file section of `cmdOpen` (stat through key, cmd_open.go:55-93), `previewMIME` (159-179), `hasSVGRoot` (187-226) and `previewKey` (231-241). In the new package they are `Open(path string, maxBytes int64) (File, error)` with `File{Name, MIME, Key string; Data []byte}` (Name is the base name of the path), `MIME(name string, data []byte) string` and `Key(path string) (string, error)`; `hasSVGRoot` stays unexported. Sentinels: `ErrNotExist`, `ErrDir`, `ErrUnsupported` (not a regular file, or no supported type), `ErrTooLarge`; `TooLargeError{Size int64}` carries the size for the CLI's "(20.0 MB; the limit is 20 MB)" wording and unwraps to `ErrTooLarge`. Any other stat, open, fstat, read or key failure is returned as the OS error itself, unwrapped, so the CLI's `readErr` keeps printing the OS reason only.
  - The order is the CLI's, unchanged: `os.Stat` (ENOENT is `ErrNotExist`; other errors returned as is; folder `ErrDir`; non-regular `ErrUnsupported`; size over `maxBytes` a `TooLargeError`), `os.OpenFile(O_RDONLY|syscall.O_NONBLOCK)`, `f.Stat()` regular re-check (`ErrUnsupported`), `io.ReadAll(io.LimitReader(f, maxBytes+1))`, over the cap after the read (`TooLargeError` with the read length), `MIME` ("" is `ErrUnsupported`), `Key`. An ENOENT from the open (the file vanished after the stat) is returned as the OS error, as today (the CLI then prints the read line, not "doesn't exist").
  - `maxBytes` is an argument (the caller passes `relay.PreviewMaxBytes`): previewfile must not import relay, because relay imports previewfile in 12-04.
  - Not taken: the research's 8 KiB early "unsupported" read. The stat cap already bounds a click's read at 20 MB of local disk, and moving the code unchanged keeps the CLI regression meaningful.
- **cmd_open.go keeps every string.** `cmdOpen` calls `previewfile.Open(arg, relay.PreviewMaxBytes)` and maps: `ErrNotExist` to the "doesn't exist." line, `ErrDir` to the "is a folder, not a file." line, `ErrUnsupported` to `unsupportedErr(arg)`, a `TooLargeError` (errors.As) to `tooLargeErr(arg, size)`, anything else to `readErr(arg, err)`. The file name sent to the daemon stays `filepath.Base(arg)` (now `File.Name`), the MIME and key come from the File. Order in cmdOpen stays: arguments, session id, file checks, then the daemon (a file mistake never touches the socket). The imports cmd_open.go no longer needs go away; nothing else in cmd_open.go changes.
- **Name cleaning moves to relay, not previewfile (Claude's discretion, recorded).** `cleanPreviewName` (internal/daemon/preview.go:84-102, pure string code) becomes exported `CleanPreviewName` in internal/relay/preview.go, and the daemon route calls `relay.CleanPreviewName` (the daemon already imports relay). The research suggested previewfile; relay is chosen because the name is part of the preview wire contract (`Preview.validate` checks it there), it keeps previewfile a pure file reader, and the daemon's preview route then imports no package that opens files. relay/preview.go stays free of `os`, `io/fs` and `path/filepath` (the source gate).
- **Test moves.** cmd_open_test.go calls `previewMIME` (~261, in TestCmdOpen_TypeDetection) and `previewKey` (~359, in TestCmdOpen_SameFileSameKey); retarget those calls to `previewfile.MIME` and `previewfile.Key`, keep the test names and cases. previewfile_test.go is new: the order and sentinel table through real temp files (a missing path, a folder, a FIFO made with `syscall.Mkfifo`, a file one byte over a small `maxBytes` passed by the test, a `.txt`, a valid PNG, a `.md` with a NUL, a symlinked file whose key equals its target's), plus `TestOpen_NoModuleImports` asserting with `go/parser` that previewfile.go imports nothing under `github.com/scottkw/portty/`.
