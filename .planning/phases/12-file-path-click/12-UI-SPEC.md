# Phase 12 — UI Design Contract

> Visual and interaction contract for Phase 12 (File Path Click, PATH-01..02). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Sources, in priority order:**
1. `12-CONTEXT.md` locked decisions: Cmd-hover underlines path-like text, a missing file is silent, an existing file that can't be previewed shows a brief notice in the clicking window only, a plain click still selects, URLs keep their confirm popover, read-only viewers get no clickable paths.
2. `11-UI-SPEC.md` (approved prior contract): tokens, the preview tab, the preview pane and its copy style. Nothing in it is re-decided here. A path click ends in exactly the same preview tab as `portty open`.
3. REQUIREMENTS PATH-01, PATH-02 and the project constraints: macOS-native look, light and dark live, radical simplicity, rock-solid.
4. Existing code, scanned 2026-11-21: `TerminalPanel.tsx` (WebLinksAddon arm, `webLinksConfigRef`, `SessionEndedBanner` slot), `SessionEndedBanner.tsx`, `lib/openLink.ts` (`isModifierPressed`, `ModifierMode`), `style.css` (`.banner`, `.session-ended-banner`, `--color-banner-info-*`), `WebShareSessionView.tsx`, `internal/webserver/server.go` (share links redirect to `/app/?session=…&cap=…`), `web/assets/terminal.js`.

The UI surface is two things: (1) how path-like text looks and behaves under the pointer in xterm, and (2) one transient notice. There are no new components, tokens, icons or dialogs.

## Path Link (hover and click)

### What counts as a path link

Contract (regex details are the planner's discretion, CONTEXT):
- Text starting with `/`, `~/`, `./` or `../`, or a relative form containing at least one `/` followed by a segment with a file extension (for example `docs/diagram.png`).
- A trailing `:line` or `:line:col` is part of the underlined text (what the user sees as the path). It is stripped before the request.
- Trailing sentence punctuation (`. , ; : ) ] } ' "`) is not part of the link.
- A path that wraps across terminal rows is one link and underlines across the wrap.
- Text inside a URL match (`https://…`, `mailto:…`) is never also a path link. The URL provider wins and URL behavior is unchanged.
- Paths with spaces are not detected unless the text has no space (no quote parsing). Folders and non-files are still underlined, because hover makes no host round trip. A click on one does nothing (silent).

### Pointer behavior

| State | Result |
|-------|--------|
| Hover with no modifier held | Nothing. No underline, normal I-beam cursor. A path-looking token never lights up just because the mouse crosses output |
| Hover with the modifier held | The whole token is underlined and the cursor is a pointer. No native `title` tooltip: the resolved path is unknown until the host sees it, and showing the raw text again adds nothing |
| Modifier released or pointer leaves | Underline and pointer cursor go away at once |
| Plain click or drag | Selects text exactly as today. A path link never fires without the modifier |
| Modifier-click | Sends the click to the host (see Click outcomes). Nothing is typed into the shell. Text selection is not changed by the click |

**Modifier:** the same gate as URLs: `webLinksConfig.modifier` through `isModifierPressed`, default `'platform'` (Cmd on macOS and in a macOS browser, Ctrl elsewhere). If a user has set the modifier to `'none'`, the underline shows on plain hover and a plain click opens it, matching URL behavior. Path links follow the existing `webLinks` plugin toggle: when web links are off, path links are off. No new setting and no new Settings row.

**Planner note, hover underline:** if xterm 6 (`@xterm/xterm` 6.0.0 installed) cannot switch a link's decorations on and off with the modifier key while the pointer rests on it, the accepted fallback is the same behavior as URLs today: underline and pointer on plain hover, click still gated by the modifier. Do not add key listeners beyond what is needed. Decide in the plan after a quick check.

### Where it exists

| Surface | Path links |
|---------|-----------|
| Desktop local tab | Yes |
| Desktop peer tab (over the tailnet) | Yes. The preview tab that results is the peer-origin preview tab from Phase 11 |
| Browser share viewer at `/app/` | Yes. Share links redirect to `/app/?session=…&cap=…`, which mounts the same `TerminalPanel`, so one implementation covers all three. Same modifier rule (Cmd in a Mac browser) |
| Read-only viewer (a read-only share link or a read-only subscriber) | No link provider is registered. Nothing underlines, nothing is clickable. The host refuses a request from a read-only viewer in any case (CONTEXT, mandatory). A flag source for read-only is the share-capability claim the viewer already uses, not `term.options.disableStdin`, which also flips on during a reconnect |
| Host or daemon older than the path-click API (`APIVersion` below the new constant) | No link provider is registered, silently. The existing Update needed banner is the only signal |
| `web/assets/terminal.js` (legacy page at `/sessions/{id}`) | Not in scope. `grep -c -i preview web/assets/terminal.js` gives 0, so that page has no preview tab to open. CONTEXT names it as the browser share view, but share links land on `/app/` (`server.go:790`). Planner: confirm before touching `terminal.js`, and do not add path clicking there |

Mouse-only: like URL links, path links have no keyboard equivalent this phase.

## Click outcomes

Every outcome is decided by the host. The viewer shows no spinner and no pending state on its own.

| Outcome | Clicking viewer | Other viewers |
|---------|-----------------|---------------|
| File exists and previews | The Phase 11 preview tab opens by the Phase 11 arrival rule. After a modifier-click the clicking viewer is the one that just interacted with the session, so the planner must make sure the host treats it as the focused-arrival viewer (it switches to the tab). Phase 11 keys that on the last typing viewer, and a click is not typing | Background tab, as with `portty open` (CONTEXT) |
| Path doesn't exist, is a folder, or is unreadable | Nothing at all: no tab, no notice, no dialog, no text in the shell (SC3) | Nothing |
| Path was not printed by this session, or the viewer is read-only | Nothing (refused host-side) | Nothing |
| Exists, wrong type (not PNG, JPEG, GIF, WebP, SVG, PDF or Markdown) | The notice **Can't preview this file type** (see Notice) | Nothing. The notice is sent only to the requester, never broadcast |
| Exists, over 20,000,000 bytes | The notice **Too large to preview** | Nothing |
| A preview transfer is already in flight on this session (one per hub) | Nothing. The tab's progress underline already shows the transfer | Nothing |
| Connection is down or reconnecting | Nothing (no request can be sent). The reconnecting banner is already showing | Nothing |

The preview tab, its receiving state, same-file refresh in place, the 10-tab limit and the close behavior are Phase 11's and are not repeated here.

**Latency, accepted:** a click gives no feedback until the preview header arrives and the tab appears. On a slow tailnet that can be a moment. A pending indicator would break "missing files stay silent", because the viewer can't tell a missing file from a slow one.

## Notice (existing file, no preview)

One transient banner in the clicking window only.

### Anatomy

- The existing info banner: `InformationCircleIcon` (16px, `aria-hidden`), message, dismiss button (`XMarkIcon`, `aria-label="Dismiss"`).
- Placement: the top of the terminal viewport of the pane that was clicked (existing `.session-ended-banner`). A click in a peer tab shows it in that peer tab. Switching tabs unmounts it.
- It is `role="status"` with `aria-live="polite"`, announced once when it appears.
- Fixed copy only. The file name and any host-supplied text are never shown (same rule as `SessionEndedBanner`: wire text is never rendered).

### Behavior

| Rule | Contract |
|------|----------|
| Auto-dismiss | 5000ms after it appears. The × dismisses it sooner |
| A second notice while one is showing | Replaces it in the same slot and restarts the 5000ms timer. They never stack |
| Another banner already in the slot (reconnecting, unreachable, session ended, share stopped, paste interrupted) | The other banner keeps the slot and the path notice is dropped (it is not queued). In practice reconnecting and ended mean no request was sent |
| Exit | Removed at once. Under `prefers-reduced-motion: reduce` there is no transition (existing `.banner` rule). Otherwise the existing 150ms opacity transition is the only motion |
| Focus | Never moves. Terminal keyboard focus is untouched, so the user keeps typing |
| Sound, macOS notification, Dock bounce | None |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None. The action is a modifier-click on a path in the terminal |
| Empty state | Not applicable. There is no view of its own. A missing file is silent by decision |
| Notice, wrong type | **Can't preview this file type. Portty previews images, PDFs and Markdown files.** |
| Notice, too large | **Too large to preview. The limit is 20 MB.** |
| Notice dismiss | `aria-label` **Dismiss** (existing) |
| Error state (path doesn't exist, refused, read-only, busy) | None, by decision. Silent |
| Destructive confirmation | None. A click only reads a file and opens a closable tab. Nothing is changed, deleted or sent anywhere |

Writing rules (Phase 2 and 11): sentence case for body text, no exclamation marks, "Can't" for a refusal, no "Error:" or "Oops". The apostrophe is straight, matching the other strings in `SessionEndedBanner.tsx`. "20 MB" matches Phase 11's size display (decimal, 20,000,000 bytes). The "too large" copy repeats the Phase 11 CLI limit wording so the two surfaces agree.

## Accessibility Contract

- **Path link:** a pointer feature, in step with URL links in the terminal. Terminal text stays selectable and copyable, so the keyboard route to a file is `portty open <file>`. No new keyboard shortcut and no focusable link elements in the terminal.
- **Notice:** `role="status"`, `aria-live="polite"`, fixed visible text, dismiss button with `aria-label="Dismiss"`, reachable by Tab, with the existing 3px `--color-focus-ring`. It never takes focus.
- **Color is never the only signal** (the user is colorblind): the underline is a line shape, and the notice has an icon and words.
- **Motion:** only the existing 150ms banner opacity transition. None under `prefers-reduced-motion: reduce`.
- **Preview result:** announced by the existing Phase 11 live region, **Preview opened: <file name>**. No second announcement for a path click.
