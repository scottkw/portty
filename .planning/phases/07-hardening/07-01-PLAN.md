## Flagged decisions and assumptions

- **Sharing the strip (CONTEXT HARD-03: share it if there is no import cycle).** internal/daemon already imports internal/relay (engine.go uses `relay.MsgOutput`). So the engine can call an exported relay function, and no cycle exists. The hub.go comment that says the copy is needed to avoid a cycle has the direction backwards: relay must not import daemon, but daemon may import relay. Keep the hub's var name `liveEmuQueryStripPattern`, because history_test.go and replay_fidelity_test.go reference it. Add `func StripTerminalQueries(b []byte) []byte` beside it and route every call site (recordFrameLocked, Join, and the engine) through it. No parity test is needed, because there is only one pattern.
- **Added alternatives (each a narrow, anchored regexp, RE2 so linear time):**
  - `\x1b\[1[468](?:;[0-9]*)?t`: XTWINOPS reports 14 (text area in pixels, also `14;2`), 16 (cell size in pixels) and 18 (text area in characters). The set forms (`8;rows;cols t`, `22;0 t`, `23;0 t`) must not match.
  - `\x1b\[=[0-9;]*c`: DA3. The existing DA1 group's `[0-9;]*` does not cover `=`.
  - `\x1bP\+q[0-9A-Fa-f;]*(?:\x1b\\|\x07)`: XTGETTCAP (hex-encoded capability names).
  - `\x1bP\$q[\x20-\x7e]*(?:\x1b\\|\x07)`: DECRQSS. The printable class stops at ESC, so the match ends at the first ST. Sixel `\x1bP...q` has no `$` right after `P`, so it never matches.
  - `\x1b\]4(?:;[0-9]+;\?)+(?:\x07|\x1b\\)`: OSC 4 palette query, one or more `index;?` pairs. A set (`4;1;rgb:..`) never matches. A mixed set-and-query OSC 4 is not stripped; that is a known limit, so document it.
  - `\x1b\]52;[a-z0-9]*;\?(?:\x07|\x1b\\)`: OSC 52 clipboard read. OSC 52 writes are not queries and stay.
- **Known limit kept (CONTEXT):** the ring stores 0x01-framed PTY reads, so a query split across two reads is not matched. Document it in the doc comment and do not try to fix it.
- **Alt-screen rebuild: refinement of "the same path a resize uses" (CONTEXT HARD-01).** The trigger is vt's `Callbacks.AltScreen` hook. It fires inside `emu.Write`, so it only sets a Hub flag (guarded by emuMu). `recordFrameLocked` rebuilds after the write returns, if the emulator is no longer in the alt screen. If the app re-entered the alt screen in the same read, skip the rebuild; the next exit rebuilds. The rebuild reuses `newLiveEmulator` (the only constructor, RESEARCH Pitfall 12) and keeps `h.history`/`h.modes` (Hub-owned).
  - **Deviation from resize:** resize pushes the visible rows into history and starts empty, because the app redraws after SIGWINCH. No redraw follows an alt-screen exit: the shell just prints its next prompt below the restored main screen. So the rebuild re-seeds the new emulator with the old emulator's rendered main screen instead: `renderScreenLocked()` output (rows joined with CRLF, a CUP to the cursor, the pending-wrap re-print and the DEC mode restores), written into the new emulator at the old emulator's Width/Height. Rows stay where the host shows them, and history gains nothing twice.
  - `geomEnd` is untouched, because this is not a geometry change.
- **Bounding growth while still in the alt screen: not possible through the vt API (checked at planning time).**
  - `Emulator.SetScrollbackSize`, `Scrollback()` and `ClearScrollback()` all use `e.scrs[0]`; `scrs` is unexported.
  - `Screen.DeleteLine` pushes into the current screen's scrollback.
  - So while the app stays in the alt screen, growth is capped only by vt's `DefaultScrollbackSize` (10,000 lines × width × cell size). Per CONTEXT, write that down in a `shortcut:` comment and do not fork vt.
- **Fan-out flake analysis (planning time).** The failing payload `"\x01hello world"` carries the ring's 0x01 frame header. Ring bytes only reach a client inside a full replay, so client B's Join ran after the hub recorded the write, and the hub delivered the bytes exactly once, in the replay. The race is in the test: `dialWS` returns at the WebSocket handshake, and the server's Join happens afterwards. Fix: wait until `hub.SubscriberCount() >= 2` before writing. If the reproduction shows anything else (duplicated or missing bytes), treat it as a real hub race: stop and report (RULE 0).
