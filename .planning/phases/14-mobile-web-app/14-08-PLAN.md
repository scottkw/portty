## Flagged decisions and assumptions

- **Key set and behaviour (CONTEXT; UI-SPEC, Key Bar).** Exactly eight keys in UI-SPEC's order with its labels, bytes and accessible names; `role="toolbar"`, `aria-label="Terminal keys"`, `aria-orientation="horizontal"`; real `<button type="button">` elements; arrow icons `ArrowLeftIcon`, `ArrowUpIcon`, `ArrowDownIcon`, `ArrowRightIcon` from `@heroicons/react/24/outline`, 20px, `aria-hidden`. Shift-Tab, `~`, `/`, `-` and Alt are deferred.
- **ctrlMap.ts (pure; RESEARCH Pattern 5).** `ctrlByte(ch: string): string | null` (RESEARCH's table: A-Z and a-z to 0x01-0x1A, `@` and space to 0x00, `[` 0x1b, `\` 0x1c, `]` 0x1d, `^` 0x1e, `_` 0x1f, else null), `arrowSeq(dir, applicationCursor: boolean, ctrl: boolean): string` (`ESC O x` in application mode, `ESC [ x` otherwise, `ESC [ 1 ; 5 x` with ctrl regardless of mode), and constants for ESC, TAB and `|`.
- **Seams in TerminalPanel (ref-held props, so the mount effect's deps do not change).**
  - `keyInputRef?: React.MutableRefObject<{ send(seq: string): void; applicationCursor(): boolean } | null>`, filled in the mount effect with `term.input(seq, true)` and `term.modes.applicationCursorKeysMode`, cleared on dispose. `term.input` is a no-op under `disableStdin`, so a bar key while reconnecting behaves as typing does (RESEARCH; UI-SPEC: no disabled state).
  - `inputTransform?: (data: string) => string` applied in the existing `term.onData` handler before `client.sendInput`.
- **Ctrl state (WebShareSessionView).** `ctrlArmed` React state plus a ref read by the transform. Bar key: compute its bytes with Ctrl applied (arrows) or as-is (Esc, Tab, `|`), disarm, then `send`. Keyboard input through the transform: if armed, map a single character with `ctrlByte` (unmapped characters go as typed), disarm. Disarm also when the view unmounts, the session closes, or `isActive` goes false (a preview takes focus).
- **Where the bar shows.** Rendered by WebShareSessionView after TerminalPanel only when `!remote` (the browser guest, not a desktop peer tab), `usePhone()` is true, `isActive` is true, and `canWrite !== false`. App reads `perms` from the bootstrap info response it already fetches and passes `canWrite` (true when the comma list includes `write`, false when it does not, undefined when the info call failed: the server still discards input from a capability without write, so the bar shows rather than hide on a network error). CSS backstop hides `.keybar` when the phone query does not match.
- **Firing.** `onPointerDown`: `preventDefault()` and fire; `onClick`: fire only when `event.detail === 0`. No repeat, no haptics.
- **Playwright.** Add `{ name: 'iphone', use: { ...devices['iPhone 15'] }, testMatch: /mobile-.*\.spec\.ts$/ }` (the newest iPhone profile in 1.59.1) and `testIgnore: /mobile-.*\.spec\.ts$/` on chromium, firefox and webkit, so existing specs do not run under touch emulation. Playwright's `tap()` in WebKit emulation may not dispatch `pointerdown`; if the bar does not fire on `tap()`, dispatch a `pointerdown` with `pointerType: 'touch'` on the button instead and say so in the spec and SUMMARY. The fixture's `/__test__/input` (14-01) reads the bytes; the lone-Esc flush (14-02) makes a lone ESC arrive without a following byte.
- **Wording gate.** tests/check-share-removal.sh flags read-only wording paired with link, share or tab; say "a capability without write".
