## Flagged decisions and assumptions

- **One decision, two writers (PATTERNS).** Factor `requireSameUser`'s body into `func (ws *WebServer) sameUserStatus(r *http.Request) int` returning 0 (allow), 403 or 503, keeping the 3 s timeout, the fail-closed branches and the numeric-ID debug log exactly as today. `requireSameUser` writes `refuseOtherUser` / `refuseLocalFault` from it (unchanged behaviour); `requireSameUserPage` writes the pages: on 403 the `tailnet.MarkerHeader` marker, `Content-Type: text/html; charset=utf-8`, `X-Content-Type-Options: nosniff`, status 403 and `userRefusedPage`; on 503 the same headers without the marker, status 503 and `serviceRetryPage`. Page bytes are package vars read once from `webfs.WebFS` with a panic on a missing file, like `linkInvalidPage` in capability_mw.go.
- **Wrapping (RESEARCH Pattern 1).** `GET /app/`: `ws.cspHeaders(ws.requireSameUserPage(<the existing handler>))`. `GET /sessions/{id}`: `ws.cspHeaders(ws.requireSameUserPage(ws.requireCapabilityPage(ws.handleTerminalPage)))`. `cspHeaders` stays outermost so the pages get the CSP, no-store and no-referrer, and `/assets/` stays open so they can load `/assets/dashboard.css`. Do not assert the exact CSP string in this plan's tests (14-05 changes it in the same wave): assert the header is present and contains `default-src 'none'`.
- **Copy (UI-SPEC, Refusal Page and Local-Fault Retry Page; CONTEXT gives the refusal copy).** Both pages copy `web/link-invalid.html`'s structure exactly (`<html lang="en">`, the same viewport meta, `<title>Portty</title>`, the dashboard.css link, `.container`, `<h1>Portty</h1>`, `<h2 class="error">`, one `<p>`). Refusal: heading "This link only works on your own devices", body "Open it on a device signed in to the same Tailscale account as the Mac that shared it.", no button, link or script. Retry: heading "Can't check this device right now", body "Tailscale on the Mac that shared this session didn't answer. Wait a moment, then try again.", then `<a class="button" href="">Try again</a>` (a link, because the share CSP blocks inline script; an empty href reloads the current URL with its token). No auto-refresh.
- **dashboard.css (UI-SPEC).** One rule, `a.button`, mirroring the existing `button` rule with `padding: 12px 20px`, `background: var(--color-selection-fill)`, `color: var(--color-on-accent)`, `border-radius: 4px`, `font-weight: 600`, `display: block`, `text-align: center`, `text-decoration: none`, `min-height: 44px`. Read the existing `button` rule first and use the same tokens it uses.
- **/app/ caching (RESEARCH Pitfall 3; Chesterton).** The existing `w.Header().Del("Cache-Control")` exists so Vite's content-hashed bundles stay cacheable under cspHeaders' no-store (Phase 120 WR-02 and Phase 176 comments explain it). Narrow it: when `rel` starts with `assets/` keep the Del; otherwise set `Cache-Control: no-cache`. Update both comments to say which files get which policy and why (the manifest and icons are not content-hashed). `manifest.json` already serves as `application/json` from FileServerFS (RESEARCH Q2b).
- **Playwright fixture (14-01).** `POST /__test__/whois` with `{"as":"other"}` or `{"as":"status-fault"}` switches identity; every spec resets to `same` in `afterEach`. The spec runs in the desktop projects (chromium, firefox, webkit).
