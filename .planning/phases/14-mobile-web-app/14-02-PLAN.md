## Flagged decisions and assumptions

- **Reversibility: costly (CONTEXT).** The filter is shared by every viewer and both pumps (`internal/relay/server.go` local pump, `internal/webserver/server.go` share pump). Only `stateGotEsc` is touched; `stateInOSC` and `stateInCSI` keep absorbing across frames.
- **Why it is safe (RESEARCH Q10, verified in xterm 6.0.0 source).** Every `triggerDataEvent` call sends a whole key or reply as one string; the only frame split is `encodeInputFrames` at 32767 bytes, which only large pastes reach. A raw terminal behind `portty attach` that split a reply exactly between ESC and `]` would now leak the rest as text; that cost is pinned by a test and named in the doc comment (threat T-14-09).
- **No grid claim from a lone Esc.** `IsUserInput` returns false for a trailing lone ESC (its comment says so); INPT-06's conservative rule stays. Arrows, Tab and Ctrl-C still claim.
- **VM first (CONTEXT: "Verify the current behaviour on a VM first (vim, a TUI)").** No build is needed: Phase 13's cleanup left its HEAD build (`dev`, binary sha256 beginning `a01ae0e1`, 13-VM-CHECKS.md Builds) installed and running on both VMs, and it has the hold. Record what each VM actually runs (`/health`, binary sha256) before anything else. If the hold does not reproduce, write the row as FAIL with its evidence, commit it, and stop the plan without changing the filter: the reason for the change would be wrong (CLAUDE.md, notice confusion).
- **The TUI stand-in.** Claude Code needs node, which neither VM has (13-VM-CHECKS.md L-00). A raw key reader shows the timing directly: write `~/p14/keys.zsh` in the office VM (VM-only, never committed): `zmodload zsh/datetime`, `stty raw -echo`, a loop of `read -rk1 c` that appends `"$EPOCHREALTIME <hex of the byte>"` to `~/p14/keys.log` and stops on `q`, then `stty sane`. Confirm it logs `1b` for an ESC on the VM before using it. With the hold, the `1b` line carries the same timestamp (within 0.5 s) as the next key sent 3 s later; without it, the gap is about 3 s.
- **VM rig (13-VM-CHECKS.md header and 12-VM-CHECKS.md; reuse, do not reinvent).**
  - Office `portty-test` (192.168.64.108), home `portty-test-2` (192.168.64.109). Confirm each IP with `tart ip <vm>`; SSH `ssh -i ~/.ssh/transom_demo_ed25519 admin@<ip>`. Never copy the rig key into a VM; never put a VM password in a file or on a command line.
  - The VMs are ephemeral tailnet nodes: never stop, suspend or reboot them, never `tailscale down`, never `tailscale logout`, never create or use an auth key. If a VM is not running or not on the tailnet, stop and report (RULE 0).
  - Keys and clicks: `~/p12/p12ui` real CGEvents inside the VM (typed text; an Esc is a `p12ui type` of the ESC character; a click at an AX element's centre; move the pointer to another cell before a repeated click). Reads: `~/ptest/axdump2` (rows need the DOM renderer, so WebGL is off for the run: `~/p907/webgl.sh off` backs up settings.json, restore it at the end and check with `cmp`).
  - `portty share` prints the session link: send that output only to a 0600 file in a `mktemp -d` directory in the VM and delete it at the end. No link, capability or tailnet host is written to any committed file.
  - Record the sha256 of each VM user's `~/.zshrc` and `~/.zsh_history` before the rows and compare at the end (restore from a private copy if a session appended history).
  - Every key event, click and session runs inside a VM. On the host only `tart ip`, SSH and file writes in this repo. Never touch the user's own Portty or dotfiles.
- **Executor constraints (every Phase 14 plan carries these):**
  - Every Go command runs with `export GOTOOLCHAIN=go1.26.11`.
  - Never run anything on the host that talks to the host's live tailscaled or a 100.x address. Real-tailnet work happens only inside the Tart VMs.
  - Logs live in a private directory from `mktemp -d`, printed by the verify and recorded in the SUMMARY. Save every test output to a file; never pipe a test run through `tail` or `head`. Each full suite runs at most once per plan.
