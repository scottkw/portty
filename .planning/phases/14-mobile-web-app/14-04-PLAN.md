## Flagged decisions and assumptions

- **Refusal screen.** A sibling component `UserRefused` (UI-SPEC lets the planner choose), so `LinkNoLongerWorks` and its test stay untouched: no props, fixed copy, `.link-dead`, `.link-dead__heading` (h1), `.link-dead__body`. Same words as web/user-refused.html.
- **Telling the two 403s apart (RESEARCH Pattern 1).** `requireCapability` writes no marker; `refuseOtherUser` writes `X-Portty: 1`. So `res.status === 403 && res.headers.get('X-Portty') === '1'` is exactly the WhoIs refusal. `shareInfoVerdict(status: number, porttyMarker: boolean)`: the second parameter is required (no default: a forgotten call site fails tsc instead of silently reading as a dead link); 403 with the marker returns `{ kind: 'stop', reason: 'other-account' }`.
- **The stop reason.** `ReconnectVerdict`'s stop reason gains `'other-account'`. relayClient maps it to a client-only close reason `CLOSE_REASON_OTHER_ACCOUNT = 'other account'` exported from closeReasons.ts, documented as never sent by a server (the two wire reasons keep their Go mirror; `isTerminalClose` is unchanged). TerminalPanel's guest `onClose` with that reason disables stdin and calls a new optional prop `onOtherAccount`; WebShareSessionView passes it through; App sets `webOtherUser` and renders `UserRefused` in place of the view (UI-SPEC: final, no redial).
- **pageshow (Pitfall 6).** Add `window.addEventListener('pageshow', this.onWake)` beside the `online` and `visibilitychange` listeners and remove it in the same teardown. The 1 s watchdog's timer-gap path stays the backstop; no single event is relied on.
- **Connect-timeout escalation (Pitfall 5, WebKit bug 308073).** Count consecutive firings of the existing `connectMs` timer; at the second call a new optional callback `onConnectStuck(true)`; the first host frame on a socket resets the count and calls `onConnectStuck(false)` if it was stuck; stop and teardown reset it. Reconnecting continues underneath (no change to backoff).
- **Phone test (UI-SPEC, What "phone" means).** `frontend/src/lib/phoneQuery.ts` exports `PHONE_QUERY = '(pointer: coarse) and (hover: none)'`, `isPhone()` (`window.matchMedia(PHONE_QUERY).matches`, no fallback branch: the test setup already stubs matchMedia) and `usePhone()` (state plus a `change` listener with cleanup, shaped like `useColorScheme.ts`). Never `'ontouchstart' in window` or the user agent. 14-08 and 14-09 reuse it.
- **Reload (UI-SPEC, Reload on Phones).** `SessionEndedBanner` gets an optional `onReload`; it renders a `<button type="button" className="banner__action">Reload</button>` before the dismiss button only for kinds `share-stopped`, `ended`, `unreachable` and `reconnecting`, never for the paste, path or port kinds. TerminalPanel passes `onReload={() => location.reload()}` only when `usePhone()` is true, and for `reconnecting` only while stuck. `location.reload()` keeps the token URL. CSS: under the phone media query `.banner__action` gets `min-height: 44px; min-width: 44px; padding: 0 8px` (visible text stays 12px).
- **ErrorBoundary.** A new optional `webMode` prop: in web mode the fallback message is "This view hit an error. Reload to try again." plus a Reload button when `isPhone()`; App passes `webMode={mode === 'web'}` to the `web-session` boundary only. Keep `role="status"`, the icon and the error-type-only log.
- **Wording gate.** tests/check-share-removal.sh flags phrases that pair read-only wording with link, share or tab; say "a capability without write" in any new comment or test name.
