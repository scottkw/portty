## Flagged decisions and assumptions

- **Headless only (coordinator's instruction).** Create a dedicated device, `UDID=$(xcrun simctl create portty-p14 "iPhone 17" <the iOS 26.5 runtime id from xcrun simctl list runtimes>)`, boot it with `xcrun simctl boot "$UDID"` and wait with `xcrun simctl bootstatus "$UDID" -b`. Never `open -a Simulator`, never AppleScript, never a host mouse or keyboard event. Record `pgrep -x Simulator` at the start and end (expected empty; if the user had it open, record that and do not touch it). Delete the device at the end.
- **TLS, not plain HTTP.** The fixture serves only HTTPS on 127.0.0.1 and the share server's Origin and CSP checks expect https, so instead of http the fixture writes its per-run CA certificate (14-06, `PLAYWRIGHT_FIXTURE_CA_PEM`) and `xcrun simctl keychain "$UDID" add-root-cert <pem>` trusts it inside the throwaway device only. The fixture's certificates last two hours: finish within that window or relaunch the fixture and re-add the new CA (record it).
- **Fixture build (as frontend/e2e/global-setup.ts does).** In `S=$(mktemp -d -t p14-sim)`: `pnpm --dir frontend install --frozen-lockfile --prefer-offline`, `pnpm --dir frontend exec vite build`, replace `cmd/playwright-fixture/dist` (gitignored) with a copy of `frontend/dist`, `GOTOOLCHAIN=go1.26.11 go build -tags=playwrightfixture,wailsassets -o "$S/fixture" ./cmd/playwright-fixture`, launch it with `PLAYWRIGHT_FIXTURE_CA_PEM="$S/ca.pem"` and its stdout to `$S/fixture.out` (0600); parse BASE_URL, CAP and ADMIN_URL. The app link `BASE_URL/app/?session=playwright-test-session&cap=<CAP>` goes into a 0600 file, never printed. The fixture token is a throwaway signed with the fixture's fixed test key, but the no-secrets rule still applies to committed files.
- **Runner (throwaway, never committed).** In `$S/runner`, a `project.yml` for the already-installed xcodegen (no package install): an iOS 26 app target `P14Host` (an empty SwiftUI app, needed as the UI test host) and a `bundle.ui-testing` target `P14UITests` with a scheme; simulator signing ad hoc. `xcodegen generate`, then `xcodebuild build-for-testing -derivedDataPath "$S/dd" -destination "platform=iOS Simulator,id=$UDID"`. Each row is one or more test methods run with `xcodebuild test-without-building -only-testing:P14UITests/P14Tests/<method>` and `-resultBundlePath "$S/results/<method>.xcresult"`; pass the link file's content and the admin URL through `TEST_RUNNER_P14_APP_URL` and `TEST_RUNNER_P14_ADMIN_URL` (xcodebuild strips the prefix). Tests drive `XCUIApplication(bundleIdentifier: "com.apple.mobilesafari")` and `"com.apple.springboard"`, open URLs with `XCUIDevice.shared.system.open(_:)`, read the fixture's admin routes with URLSession (the simulator shares the host's loopback), and dump `debugDescription` to `$S` when an element is not found. If the runner cannot be built or cannot see Safari after three distinct fixes, write S-00 as FAIL with `rig:` evidence, mark later rows FAIL `rig: not run`, clean up, and stop: 14-14 moves those items back to the real phone.
- **Standalone process.** The Home Screen web app may run in a process other than Safari. Find its bundle identifier after the first launch (for example `xcrun simctl spawn "$UDID" launchctl list` filtered for web app processes) and record it; if XCUITest cannot query it, use the fixture's signals (info-hits, input, grid) and host screenshots for that row and say which observations were indirect.
- **Screenshots.** `SHOTS=$(mktemp -d -t p14-shots)`; after each method `xcrun simctl io "$UDID" screenshot "$SHOTS/<row>-<step>.png"`. A row with two visible states is split into methods that each end in one state. Screenshots are not committed (Safari's address bar can show the fixture link); 14-SIM-CHECKS.md lists their file names and sha256, and 14-14 deletes the directory after the checkpoint. Appearance: `xcrun simctl ui "$UDID" appearance light|dark`.
- **Row definitions (`| Check | Result | What was checked | Evidence |`, Result exactly PASS or FAIL; evidence names the screenshots, element frames in points, fixture readings and any indirect observation):**
  - S-00 (preflight): Xcode version, runtime id, device type, UDID created and booted headless, `pgrep -x Simulator` result, fixture up with READY, CA added, runner built, no hardware keyboard bridged (headless boot), the WebKit build in the device if visible from the user agent.
  - S-01 (SC1, key bar in Safari): open the link; the toolbar "Terminal keys" with eight buttons, each frame at least 44 x 44 pt, in one row; tap Esc: the input route's hex contains `1b`; reset, tap Ctrl, focus the terminal so the software keyboard appears, tap the `c` key: `03`, and Ctrl's state returns to off; reset, type `a--`, `"`, and `b` plus two spaces: the hex shows `612d2d`, `22` and `622020` (smart punctuation and the double-space period off, RESEARCH A6).
  - S-02 (SC1, keyboard inset): with the software keyboard up, the toolbar's bottom edge is within 8 pt above the keyboard's top edge and not below it, and the terminal input element (`.xterm-helper-textarea`, accessibility label "Terminal input") sits above the toolbar; the Esc button's frame is the same size as before focusing (no focus zoom, A5); then landscape with the keyboard up: the input element still above the toolbar; back to portrait. Screenshots portrait and landscape.
  - S-03 (SC1, pinch): `pinch(withScale: 2.0, velocity: 1.0)` on the terminal: after 1 s the Esc button's width is unchanged within 1 pt (no page zoom), the grid's resize count rose by exactly 1 and its columns fell; `pinch(withScale: 0.5, velocity: -1.0)`: one more resize, columns rose.
  - S-04 (M-145, SC2, decisive): in Safari, Share, then Add to Home Screen: the name field reads "Portty" and Open as Web App is on; Add.   - S-05 (standalone safe areas, light and dark): in the standalone view, with the keyboard down, in light then dark: the toolbar's bottom edge leaves the home indicator area (at least 20 pt above the window's bottom edge) and the terminal's top edge is below the status bar; arm Ctrl, screenshot, cancel (the armed state readable in both appearances, UI Considerations backstop).
