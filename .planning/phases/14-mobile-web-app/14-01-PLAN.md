## Flagged decisions and assumptions

- **Gate scope (CONTEXT, Same-account gate; reversibility one-way, already settled by the user in 14-CONTEXT, so no new checkpoint).** This plan gates the discovery probe `GET /api/sessions`, the info route, both plugin-config routes and the WebSocket. 14-03 gates `GET /sessions/{id}` and `GET /app/` with the page variant. `/assets/`, `/` and `/dashboard` stay open (no session data). Per-route wrapping, no global middleware, so a per-session hook for invited devices stays possible later.
- **The probe is gated too (user decision 2026-11-22, "Gate it"; 14-CONTEXT updated).** `GET /api/sessions` returns the capability's session name, status and hostname, so another account must not reach it. Wrap it as `ws.requireSameUser(porttyMarker(ws.requireCapability(ws.handleListSessions)))`: `requireSameUser` outermost, so a local tailscaled fault is a bare 503 with no marker (WR-08) and another account gets `refuseOtherUser`'s 403 with the marker; a same-user caller with no capability still gets the 401 with the marker that peer discovery accepts. Probe behaviour (internal/tailnet/tailnet.go `isPorttyProbeResponse`): it accepts only the marker with 200 or 401, so a same-user peer is still found, another account's 403 is not (it should not see this Mac), and a 503 during the host's tailscaled blip is not: the peer drops the host's group until the next refresh, 5-30 s later. That is the accepted cost (CONTEXT); 14-14's review records it (T-14-43). Export the predicate as `IsPorttyProbeResponse` (rename only, its two call sites in tailnet.go) so the gate test applies the probe's own rule to the real server's answers.
- **Size (advisory).** 105,000 tokens, above the 100,000 smart-zone budget; the override was accepted by the plan checker (W6, 2026-11-22), no split.
- **No verdict cache.** RESEARCH Pitfall 1 recommends a positive-only per-IP cache only if a VM measurement shows WhoIs cost matters; the measurement is M-149 in 14-12 and the decision is the user's at 14-14's checkpoint. Building it now would add a stale-allow window with no evidence (Chesterton, CLAUDE.md premature abstraction). Every gated request does its own `StatusWithoutPeers` and `WhoIs`, as `requireSameUser` does today.
- **The fake.** `internal/webserver/webservertest/whois.go`, package `webservertest`, imports only tailscale.com types (`client/local` for `ErrPeerNotFound`, `client/tailscale/apitype`, `ipnstate`, `tailcfg`) and never `internal/webserver` (no import cycle; internal webserver tests can import it). It answers every caller with one identity, mutex-guarded so the fixture can switch it while serving:
  - `const SelfUser tailcfg.UserID = 42`; `type Identity int` with `Same`, `Other` (user 7), `Tagged` (same user, `Tags: ["tag:ci"]`), `SharedIn` (same user, `Sharer: 9`), `NotFound` (WhoIs returns `local.ErrPeerNotFound`), `StatusFault` (StatusWithoutPeers errors), `WhoIsFault` (WhoIs errors with a non-not-found error).
  - `New(id Identity) *WhoIs`, `SameUser() *WhoIs`, `(*WhoIs).Set(id Identity)`, `ParseIdentity(s string) (Identity, error)` for the names `same`, `other`, `tagged`, `shared-in`, `not-found`, `status-fault`, `whois-fault` (an unknown name is an error, never a default).
  - Its methods satisfy the unexported `whoIsClient` interface in whois.go (`WhoIs(ctx, remoteAddr)`, `StatusWithoutPeers(ctx)`), so `ws.SetWhoIsClientForTest(webservertest.SameUser())` compiles from any package.
  - `whois_test.go`'s `fakeWhoIs`, `whoIsAs` and `SameUserWhoIsForTest` stay as they are: they back the existing per-address tests (TestSameUser, portproxy_test.go) and moving them is churn with no gain.
- **The internal helpers move into the test build (Chesterton read).** `internal/webserver/capability_test_helpers.go` is not a `_test.go` file, so its `testServer`, `testServerWithHub`, `selfSignedTLSForTest`, `readPipeWithTimeout` and `dialWebServerWS` (and the `testing` import) are compiled into the release package. Its header says a `phase87_wave2` build tag once guarded it and Plan 87-03 removed the tag; nothing outside `_test.go` files references any of its five functions (checked with git grep at planning). `git mv` it to `internal/webserver/capability_helpers_test.go` so `testServer` and `testServerWithHub` can install `webservertest.SameUser()` without putting the fake into a release build. Keep its header and say why it moved.
- **Defaults.** `NewWebServer` keeps `noLiveWhoIs{}` in test binaries (WR-07, pinned by tailscale_test.go). The helpers (`testServer` and `testServerWithHub` internal, `testServer` in server_test.go external) install `webservertest.SameUser()` after `NewWebServer`, so capability tests describe "the caller is on this account"; tests that check refusals install their own fake after the helper, as whois_test.go and portproxy_test.go do today.
- **Fixture (not a test binary: `tailnet.LiveAllowed()` is true, so without a fake it would ask the host's live tailscaled).** The same-user fake is installed before `ws.Start()` in the same task that first gates a route, and no Playwright run happens before it. Admin routes on the existing plain-HTTP admin listener (loopback only, build tag `playwrightfixture`):
  - `POST /__test__/whois` with JSON `{"as":"<name>"}` calls `ParseIdentity` and `Set`; 400 on an unknown name.
  - A goroutine copies `inputCaptureR` into a mutex-guarded byte buffer (replacing today's blank assignment that discards the reader, so the hub's input writes no longer block); `GET /__test__/input` returns `{"hex":"<lowercase hex of everything captured>"}`; `POST /__test__/input/reset` empties it.
- **Playwright WebKit.** `pnpm --dir frontend exec playwright install webkit` downloads the WebKit build pinned by the installed `@playwright/test` 1.59.1 (`webkit-2272`; only `webkit-2336` is cached, RESEARCH Pitfall 11). No npm package is added.

  - Never run anything on the host that talks to the host's live tailscaled or a 100.x address. Tests use fakes; real-tailnet work happens only inside the Tart VMs (14-02, 14-12).

  - A failure in the single full Go run that is only `internal/pty` `TestKillClean_NoOrphans` (the known G-1 timing flake, user decision 2026-11-22; `internal/pty` untouched by this phase) is re-run alone with `-count=5`; record both results. Any other failure stops the task.
