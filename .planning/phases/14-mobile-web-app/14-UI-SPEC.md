# Phase 14 — UI Design Contract

> Visual and interaction contract for Phase 14 (Mobile Web App, MOB-01..MOB-05). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Sources, in priority order:**
1. `14-CONTEXT.md` locked decisions: the refusal page and share copy, the key bar's keys, one-shot Ctrl and docking above the keyboard, reflow rules (INPT-06 kept), pinch changes the terminal font in memory only, phone chrome, the full-bleed icon, the Home Screen name, and the static launcher copy.
2. `14-RESEARCH.md`: `term.input` for key bytes, `visualViewport` for the keyboard inset, touch-distance pinch, `pointer: coarse` + `hover: none` as the phone test, the `manifest.json` file name, the Reload escalation after repeated connect timeouts.
3. ROADMAP Phase 14 SC1-SC5.
4. Approved prior contracts: `12-UI-SPEC.md` (house style, banner reuse, copy rules) and `11-UI-SPEC.md` (tokens, type scale, spacing).
5. Project constraints and memories: macOS-native look (light and dark follow the system live), radical simplicity, rock-solid (the user cannot reach the remote Mac to fix a stuck view), colorblind user (color is never the only signal).
6. Existing code, scanned 2026-11-22: `style.css` tokens (`:root` at ~1993, dark block at ~2049), `.banner*`, `.link-dead*`, `.tab-bar`, `.terminal-session-container`, `LinkNoLongerWorks.tsx`, `web/link-invalid.html`, `web/assets/dashboard.css`, `SessionEndedBanner.tsx`, `ErrorBoundary.tsx`, `TerminalPanel.tsx`, `WebShareSessionView.tsx`, `TabBar.tsx` (`webMode`), `App.tsx` (`handleFontSizeChange` clamps 6 to 32), `terminalScale.ts` (0.7 floor), `frontend/index.html`, `shareCopy.ts`, `SettingsSheet.tsx`, `cmd_share.go`, `README.md`.

**Scope.** The surface is the browser share view at `/app/` on a phone, plus two static server pages and one markdown file. The desktop browser view and the Wails app are unchanged. Every item marked **[default]** is a detail CONTEXT did not fix; it is the simplest choice that fits the house style. The planner may adjust a **[default]** without asking.

**What "phone" means everywhere below:** the media query `(pointer: coarse) and (hover: none)` (CSS) or `matchMedia` of the same string (JS). Never `'ontouchstart' in window` (true on a desktop browser) and never the user agent.

No new sizes or weights. 4 sizes (12, 13, 16, 17) and 2 weights (400, 600). 12, 13 and 17 are the existing UI scale; 16 is the phone form-control size below.

## Key Bar

### Where it exists

| Surface | Key bar |
|---------|---------|
| Browser share view (`/app/`) on a phone, session pane active, read-write cap | **Shown** |
| Browser share view with a read-only cap | Not rendered. `term.input` is already a no-op under `disableStdin` (RESEARCH T-14-10); the bar is hidden so it does not look like it works. **[default]** within 14-CONTEXT "Claude's Discretion" (key set, bar placement) |
| Browser share view while a preview tab is active | Not rendered (the bar belongs to the session pane; nothing there can take a keystroke). **[default]** within 14-CONTEXT "Claude's Discretion" (bar placement) |
| Desktop browser (mouse or trackpad: `hover: hover`) and iPad with a pointer | Not rendered. CSS backstop: `@media not all and (pointer: coarse) and (hover: none) { .keybar { display: none } }`. The React side also checks the query, so no hidden DOM is mounted |
| The Wails desktop app, local tabs and peer tabs | Not rendered (the bar is mounted by the web-mode session view only) |

### Keys, in order, left to right

| # | Key | Label | Bytes sent | Accessible name |
|---|-----|-------|------------|-----------------|
| 1 | Esc | text `Esc` | `\x1b` | `Esc` (visible text is the name) |
| 2 | Tab | text `Tab` | `\x09` | `Tab` |
| 3 | Ctrl | text `Ctrl`, one-shot toggle | none by itself | `Ctrl`, with `aria-pressed` |
| 4 | Left | `ArrowLeftIcon`, 20px | `ESC [ D`, or `ESC O D` when `term.modes.applicationCursorKeysMode`; `ESC [ 1 ; 5 D` with Ctrl armed | `Left arrow` |
| 5 | Up | `ArrowUpIcon` | `A` in the same table | `Up arrow` |
| 6 | Down | `ArrowDownIcon` | `B` | `Down arrow` |
| 7 | Right | `ArrowRightIcon` | `C` | `Right arrow` |
| 8 | Pipe | glyph `\|`, 17px/400 | `\|` | `Vertical bar` |

Exactly these eight (CONTEXT, SC1). Shift-Tab, `~`, `/`, `-` and Alt are deferred. Bytes reach the shell through `term.input(seq, true)`, so they take the normal `onData` to `sendInput` path and count as typing for INPT-06 (a bare Esc still does not claim, RESEARCH Pattern 2).

### Ctrl, one-shot

| Event | Result |
|-------|--------|
| Tap Ctrl while rest | Armed: filled accent, dot, `aria-pressed="true"` |
| Tap Ctrl while armed | Cancelled: back to rest, nothing sent |
| Next key from the bar (any of keys 1, 2, 4 to 8) | Sent with Ctrl applied (arrows become `CSI 1;5 x`; Esc, Tab and `\|` are sent as they are, since they have no C0 form), then Ctrl releases |
| Next key typed on the iOS keyboard | `a-z` and `A-Z` become `0x01-0x1A`; `@`, `[`, `\`, `]`, `^`, `_` and space become C0 (`0x00`, `0x1b`, `0x1c`, `0x1d`, `0x1e`, `0x1f`); then Ctrl releases. Any other character is sent as typed and Ctrl still releases |
| Session closes, the bar unmounts, or a preview tab takes focus | Ctrl releases |

Ctrl never stays armed past one key and has no timeout. There is no sticky or lock mode.

### Behavior

- **Focus stays on the terminal.** Each key calls `preventDefault()` on `pointerdown`, so the helper textarea keeps focus and the iOS keyboard stays up. A key never takes focus by touch.
- **Firing.** A key fires on `pointerdown` (no 300 ms wait, and one tap sends once). A `click` event with `detail === 0` (VoiceOver activation or a hardware keyboard pressing Space or Enter on a focused key) also fires it, so assistive technology works. A touch tap produces `pointerdown` and a `click` with `detail >= 1`, which is ignored, so it never fires twice.
- **No key repeat.** Holding an arrow sends one byte sequence. Repeat is out of scope. **[default]**
- **No haptics, no sound.** None.
- **Press feedback** is the fill change in the color table, instantly. No animation, so `prefers-reduced-motion` needs no special case.
- **No disabled state.** The bar looks the same while the socket is reconnecting. A key pressed then behaves exactly as typing does today (the reconnecting banner already tells the user). **[default]**
- **Selection:** `user-select: none` and `-webkit-touch-callout: none` on the bar, so long-pressing a key never shows the iOS callout.

### Placement and docking

- **Position.** The bar is the last child of the session column, `flex-shrink: 0`, below the terminal area. It is not `position: fixed`. The column's root is sized by the `visualViewport` hook: height = `visualViewport.height`, top offset = `visualViewport.offsetTop`, recomputed on `visualViewport` `resize` and `scroll` inside `requestAnimationFrame`. So the bar rides directly above the keyboard and the cursor line stays above the bar (SC1).
- **Keyboard down:** the bar sits at the bottom of the screen with `padding-bottom: env(safe-area-inset-bottom)`, above the home indicator. Esc and Ctrl-C are one tap, no keyboard needed.
- **Keyboard up:** the bar gets class `keybar--kb-up` (the viewport is more than 100px shorter than the layout viewport), which sets `padding-bottom: 0`, so there is no gap above the keyboard.
- **Side insets:** `padding-left` and `padding-right` use `env(safe-area-inset-left)` and `env(safe-area-inset-right)`, so landscape notch phones do not clip Esc or `|`. The bar's own background extends under the inset.
- **Surface:** `--color-toolbar`, with a 1px `--color-separator` line on its top edge.
- **Hiding the bar never changes the grid claim.** The bar appears and disappears with the device and cap alone, not with keyboard state, so showing it triggers no resize and no claim. A change in the terminal area's height reaches the host only through the existing `ResizeObserver` report and the next keystroke's claim (CONTEXT, Layout).

## Pinch to Zoom

Pinching changes the terminal font size. It never zooms the page.

| Rule | Contract |
|------|----------|
| Gesture | Exactly two touches on the terminal container. One finger is the existing scroll path and is untouched |
| Mapping | On the first `touchmove` with two touches, record `d0` (finger distance) and `size0` (current font size). Live size = `clamp(round(size0 x d / d0), 6, 32)`. The font updates in whole pixels as the fingers move |
| Bounds | **6 px to 32 px**, the same clamp `handleFontSizeChange` already applies on desktop, so there is one clamp. Default is the host's terminal font size (13 if the host sent none). A pinch stops changing the font at a bound and gives no other signal |
| Page zoom | `preventDefault()` on every two-touch `touchmove` (the listener is `{ passive: false }`) plus `gesturestart` `preventDefault()` as a belt. The page scale stays 1 |
| Claim | One claim when the last finger lifts, debounced 250 ms **[default]**, so a pinch makes one reflow request at the final size, not one per pixel (CONTEXT) |
| Memory | The size lives in memory only (React state in web mode). A relaunch or reload returns to the host's font. Nothing is stored on the phone. Per-device saving is deferred |
| Feedback | The text itself resizing. No on-screen size readout, no toast. **[default]** |
| Read-only viewer | The pinch still changes the local font (it is display only). It makes no claim, because a read-only viewer cannot claim |
| Accessibility | No gesture-free alternative this phase (a Fit or size control is deferred). The iOS system text zoom does not apply to the terminal canvas |

## Refusal Page (MOB-05)

Two places show the same words: the static page the server returns for a page route, and the in-app screen the SPA shows when `/info` or the reconnect probe answers 403 with the `X-Portty` marker. A 403 without the marker keeps meaning "Link No Longer Works".

| Element | Copy |
|---------|------|
| Heading | **This link only works on your own devices** |
| Body | **Open it on a device signed in to the same Tailscale account as the Mac that shared it.** |

**Static page** `web/user-refused.html` (HTTP 403 plus the `X-Portty` marker, served under the share CSP; renders nothing from the request and names no account or host):

- Same markup and stylesheet as `web/link-invalid.html`: `<html lang="en">`, the same `<meta viewport>`, `<title>Portty</title>`, `<link rel="stylesheet" href="/assets/dashboard.css">`, `<div class="container">` with `<h1>Portty</h1>`, `<h2 class="error">` holding the heading, and one `<p>` holding the body.
- No button, no link, no script. There is nothing the person on the wrong account can do from this page, and a retry would only repeat the refusal.
- On a phone the `.container` is the 480px max width with 1rem side padding, so the text wraps at about 343px content width. Nothing else changes.

**In-app screen** (`/app/` bootstrap, and the reconnect probe): the `.link-dead` markup, heading `.link-dead__heading` (17px, 600), body `.link-dead__body` (13px, 400, secondary text). Whether this is a prop on `LinkNoLongerWorks` or a sibling component is the planner's choice. It takes no props from the request and renders nothing from the URL, as `LinkNoLongerWorks` does today.

- At bootstrap the screen replaces the view.
- In the reconnect probe it also replaces the view and is final: the socket is not redialed, because another attempt would be refused the same way. **[default]**
- Safe-area: the screen sits inside the padded root, so it clears the notch.

## Local-Fault Retry Page (tailscaled did not answer)

HTTP 503, no marker, page routes only (`GET /sessions/{id}` and `GET /app/`). API and WebSocket routes keep a bare 503, which the client already retries.

`web/service-retry.html`, same structure as `link-invalid.html`:

| Element | Copy |
|---------|------|
| Heading (`h2`) | **Can't check this device right now** |
| Body | **Tailscale on the Mac that shared this session didn't answer. Wait a moment, then try again.** |
| Action | **Try again** |

- The action is an `<a class="button" href="">` that reloads the same URL, token included, because an empty `href` resolves to the current URL. The share CSP blocks inline script and style, so it is a link, not a `<button>`.
- Add one rule to `web/assets/dashboard.css`: `a.button` mirrors the existing `button` rule with `padding: 12px 20px` (`background: var(--color-selection-fill)`, `color: var(--color-on-accent)`, `border-radius: 4px`, `font-weight: 600`) with `display: block`, `text-align: center`, `text-decoration: none` and `min-height: 44px`. Phone tap target is therefore 44px or more.
- No auto-refresh, no countdown, no spinner. **[default]** The page is static; the person taps when ready.
- It names no account and no host.

## Reload on Phones

On a phone in standalone mode there is no browser reload control, so a stuck view needs one inside the app. A Reload action is added to these states and nowhere else. It runs `location.reload()`, which keeps the token URL.

| State | Where | Change |
|-------|-------|--------|
| Share stopped (`kind: 'share-stopped'`) | `SessionEndedBanner` | Add action **Reload** before the dismiss button |
| Session ended (`kind: 'ended'`) | `SessionEndedBanner` | same |
| Host unreachable (`kind: 'unreachable'`) | `SessionEndedBanner` | same. This kind has no dismiss button, so Reload is the only control |
| Reconnect stuck (`kind: 'reconnecting'`, after 2 consecutive connect timeouts, about 30 s; RESEARCH Pitfall 5) | `SessionEndedBanner` | Reload appears; the message stays **Connection lost — reconnecting…** and reconnecting continues underneath. Before the second timeout the banner is unchanged |
| Component error | `ErrorBoundary` fallback for the web-session pane | Warning banner with Reload (see copy below) |

Rules:
- The action is the existing `.banner__action` (text button, 600 weight, inherits the banner color). On a phone it gets `min-height: 44px`, `min-width: 44px`, `padding: 0 8px`. Its visible text is the accessible name: **Reload**.
- Shown only when the phone query matches. A desktop browser has its own reload, and the desktop app has none of these states in web mode.
- Reload is a prop (for example `onReload`) on `SessionEndedBanner`, so the Phase 12 and 13 notice kinds, which never pass it, are untouched. The banner never renders it for kinds that do not list it.
- Final states (share stopped, ended) can answer a reload with the dead-link page or the refusal page. That is correct: Reload is how the user finds out whether the link still works.

**Web-session error copy** (`ErrorBoundary`, web mode). The current copy, "This tab hit an error. Close it and open the session again.", is wrong where the session tab has no close control. In web mode the fallback reads:

| Element | Copy |
|---------|------|
| Message | **This view hit an error. Reload to try again.** |
| Action (phone only) | **Reload** |

On desktop, local and peer tabs keep the existing copy unchanged. The preview-pane boundary (`label="preview"`) keeps its own "Couldn't Show File" pane unchanged.

## Launcher Copy (`docs/launcher-app.md`, MOB-04)

Static copy for the website repo to render at portty.app/app. The path `docs/launcher-app.md` is the planner's choice. The page holds no token, opens no WebSocket and has no shell access, and nothing in this repo trusts portty.app. The file below is the contract; the planner may tighten the wording but keeps every item.

````markdown
# Portty on your iPhone

Portty is a Mac terminal app. A session you start on one Mac can be opened from another Mac, or from your iPhone, over your Tailscale network. The session keeps running when you close the lid or walk away.

This page only explains the steps. It never sees your link and never connects to your Mac. Your iPhone talks straight to your Mac.

## Before you start

- Portty is running on your Mac, and the Mac is signed in to Tailscale.
- The Tailscale app is on your iPhone, signed in to the **same Tailscale account** as the Mac, and connected.

## 1. Get the link from your Mac

1. In Portty, open the session you want, then click **Share** in the toolbar.
2. Turn on **Share this session**.
3. Click **Copy**.

The link looks like this:

`https://<your-mac>.<your-tailnet>.ts.net:7444/sessions/…`

Treat this link like a password. It only opens on devices signed in to your Tailscale account.

## 2. Move the link to your iPhone

- **Universal Clipboard.** With Handoff on for both devices, copy on the Mac, then paste into Safari's address bar on the iPhone.
- **AirDrop.** Paste the link into Notes on the Mac, select it, choose **Share**, then **AirDrop**, and pick your iPhone. Tap the link on the iPhone to open it in Safari.

Don't send the link to yourself in Messages. Messages keeps a copy in iCloud.

## 3. Add it to your Home Screen

1. With the session open in Safari, tap the **Share** button.
2. Tap **Add to Home Screen**.
3. Leave **Open as Web App** on, keep the name **Portty**, and tap **Add**.

The Portty icon now opens your session full screen.

## When the icon stops working

The icon stops working when you turn Share off, make a new key, or restart Portty's background service on the Mac. It then shows **Link No Longer Works**. Share the session again, copy the new link, and repeat steps 2 and 3. Delete the old icon first.

If the icon shows **This link only works on your own devices**, the iPhone is signed in to a different Tailscale account than the Mac.

## Using it

The row of keys above the keyboard has Esc, Tab, Ctrl, the arrow keys and `|`. Tap **Ctrl**, then another key, to send a Control key such as Ctrl-C. Pinch the terminal to change the text size.
````

Notes for the copy: no input field, no button that posts anything, no QR code, no "check my connection" field (all deferred). The placeholders `<your-mac>` and `<your-tailnet>` are literal text. The Messages and iCloud warning is mandatory (CONTEXT).
