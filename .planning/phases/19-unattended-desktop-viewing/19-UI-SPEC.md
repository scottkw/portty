# Phase 19 — UI Design Contract

> Visual and interaction contract for Phase 19 (Unattended Desktop Viewing: DPRM-01..04, DESK-01..04, DSHR-01/02/08, DVWR-02). Generated by gsd-ui-researcher in auto mode (the user delegated every product and UX choice), verified by gsd-ui-checker.

**Sources, in priority order:**
1. `19-CONTEXT.md`: the locked link, token and launchd decisions, and the "Claude's Discretion" list that already fixes the surfaces and state wording (Desktop group in Settings ▸ Sharing with a switch, a live state line and Copy Link; no QR; reuse of the CT acknowledgement; a static "desktop sharing is off" page; Login Items copy; Accessibility asked now; the permission sheet; one lapse notification; one tray line; no new tray icon state).
2. `19-RESEARCH.md`: state model and precedence (Pattern 2), viewer route and entry (Pattern 9), the iOS tap-to-start fallback (R14), the Chrome local-network prompt hint (R12), the "Can't reach this Mac" fallback after about 30 s (C10), the user decision on AC power.
3. ROADMAP Phase 19 SC1-SC5 and REQUIREMENTS DPRM-01..04, DESK-01..04, DVWR-02, DSHR-01/02/08.
4. Approved prior contracts: `04-UI-SPEC.md` (switch row, Copy button, CT disclosure, inline errors, "no confirm for stop sharing"), `14-UI-SPEC.md` (house style, refusal and retry static pages, `.link-dead` block, phone query, Reload action, Home Screen rules, safe areas), `15-UI-SPEC.md` (preservation rules, banner reuse).
5. Project memories: macOS-native look (light and dark follow the system live), radical simplicity, rock-solid (nobody can get in to fix the office Mac), colorblind user (color is never the only signal), no developer paths in committed text.
6. Existing code, scanned 2026-11-25: `frontend/src/style.css` (token blocks, `.dialog*`, `.settings-*`, `.ts-status*`, `.banner*`, `.link-dead*`, `.button*`, `.switch*`), `SettingsSheet.tsx` (Sharing pane at the `settings-pane-sharing` tabpanel, the `Row` helper, `HasCTDisclosure`), `Switch.tsx` (`blocked`, `saving`), `UserRefused.tsx`, `LinkNoLongerWorks.tsx`, `RegenerateKeyModal.tsx` (dialog shell), `lib/webMode.ts`, `public/manifest.json`, `web/user-refused.html`, `web/service-retry.html`, `web/assets/dashboard.css`, `tray_common.go` (`BuildMenuItems`).

**Scope.** Five surfaces: (1) the Desktop group in Settings ▸ Sharing; (2) the Set Up Desktop Sharing sheet; (3) one tray menu line; (4) the lapse notification; (5) the `/desktop/` viewer page plus two new static server pages. Out of scope and not designed here: input, control and clipboard, display or window choice (Phase 20); the Desktop tab in the Portty app and iPhone touch controls (Phase 21); click-to-share for other people, admit, revoke, the shared-with-N indicator with Stop, the audit log (Phase 22); audio, adaptive quality, unlock (Phase 23). Every item marked **[default]** is a detail CONTEXT did not fix; it is the simplest choice that fits the house style, and the planner may adjust it without asking.

**What "phone" means below:** the media query `(pointer: coarse) and (hover: none)`, the same as Phase 14 (`lib/phoneQuery.ts`). Never the user agent.

## Color

All colors are existing tokens with light and dark values, repainting live when the system appearance changes. One token is added (below).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-sheet-content` and `--color-window` (settings and setup sheet), `--color-viewer-bg` (viewer letterbox, new) | Sheet surfaces; the viewer page behind the video |
| Secondary (30%) | `--color-group` with `--color-group-border` (rows), `--color-toolbar`, `--color-popover` with `--color-control-border` and `--shadow-popover` (viewer chip and state card), `--color-field` (thumbnail placeholder) | Desktop group rows, setup rows, viewer overlays |
| Accent (10%) | `--color-selection-fill` (text on it `--color-on-accent`) | Reserved list below |
| Destructive | `--color-destructive` | Not used. Nothing in this phase is destructive-styled |

Status dots (always paired with words, never color alone):

| Meaning | Token | Used for |
|---------|-------|----------|
| OK | `--color-status-on` | Ready, Streaming to N viewers, permission Granted |
| Needs action at the Mac | `--color-status-warn` | Needs permission, Waiting for approval at the Mac, Waiting for Tailscale, permission Not granted |
| Inactive, no action | `--color-status-off` | Display asleep, Locked |

Text colors on rows: `--color-text`, `--color-text-secondary`, `--color-success-text` (the word "Granted", as "Acknowledged" does today), `--color-error-text` (inline errors).

**New token: `--color-viewer-bg`**, `#000000` in both the light and the dark block. Why it is needed: a desktop picture must sit on a neutral letterbox in both appearances. The existing `--color-terminal-bg` is white in light mode, which makes white bars around a dark desktop. This is the only new color value, and it goes in both token blocks so the Phase 2 "no hex outside the two token blocks" gate keeps passing. Because `--color-text` is dark in light mode, **no text is ever drawn directly on `--color-viewer-bg` or on video**; every viewer message sits on a `--color-popover` surface (chip or card).

Dim layer: when a card or the Reconnecting chip appears over a frame that was already showing, a `--color-scrim` layer covers the video. Before the first frame there is no scrim, only the black letterbox.

Accent reserved for (nothing else):
- the switch track when on (existing Phase 2 rule);
- the Done button (existing default-button fill, `.button--primary`);
- the Tap to Start button fill in the viewer.

Not accent: status dots, the Test Capture button, Copy Link, Open System Settings, Set Up Permissions…, Review Permissions…, Reload Page (all `.button--secondary`), the chip, the card.

Closing the sheet leaves always-available on, and row 2 reads Needs permission. This is one step, not a wizard that blocks the switch.

**Row 2, Status (only while on).** Label `Status`; the control is the existing `.ts-status`: an 8px dot, then Caption text. The text sits in an `aria-live="polite"` region, so changes are announced. Text, dot and the other surfaces' wording come from one table:

| State (daemon enum) | Status text | Dot | Tray line | Viewer shows |
|---------------------|-------------|-----|-----------|--------------|
| `needs_permission` | Needs permission | warn | Desktop: Needs permission | card, Needs permission |
| `awaiting_approval` | Waiting for approval at the Mac | warn | Desktop: Waiting for approval at the Mac | card, Waiting for approval at the Mac |
| `display_asleep` | Display asleep | off | Desktop: Display asleep | card, Display asleep |
| `locked`, no viewers | Locked | off | Desktop: Locked | chip, Locked, over the live lock screen |
| `locked`, N viewers | Locked, streaming to N viewers | off | Desktop: Locked, streaming to N viewers | chip, Locked |
| `idle` | Ready. Nobody is watching. | on | Desktop: Ready | (Connecting until the first frame) |
| `streaming(n)` | Streaming to 1 viewer / Streaming to N viewers | on | Desktop: Streaming to N viewers | the picture; a chip for 3 s |
| `capture_paused` (amendment 2026-11-26: the crash-loop breaker, accepted as shipped) | Paused after repeated errors. Run Test Capture to resume. | warn | Desktop: Paused after repeated errors | card, Desktop paused |
| (GUI-derived, not a daemon state) Tailscale not connected | Waiting for Tailscale | warn | Desktop: Waiting for Tailscale | not reachable (see Unreachable) |
| (no reply from the daemon yet) | Checking… (no dot) | none | no line | not applicable |

Precedence, from RESEARCH Pattern 2: `capture_paused` (amendment 2026-11-26) > `needs_permission` > `display_asleep` > `awaiting_approval` > `locked` / `streaming` / `idle`. "Waiting for Tailscale" wins over all of them in the Settings row and the tray line because nothing else can be reached. Singular and plural: "1 viewer", "2 viewers", never "1 viewer(s)".

When the state is `needs_permission`, row 2 gets a Caption description under the label: **Choose Set Up Permissions below to turn on Screen Recording.** (a pointer to row 4, not a button). When the state is `awaiting_approval`, the description reads: **macOS is asking for approval on this Mac's screen. Someone at the Mac needs to click Allow, or approve Portty in System Settings.** When the own 30-day timer (signal b) is within 3 days of the lapse and the state is otherwise fine, the description reads: **macOS will ask for approval again soon. Someone needs to approve it at the Mac.** **[default]** The 3-day threshold is the planner's to tune.

**Row 3, Link (only while on).** Label `Link`, description Caption: **Open it in Chrome or Safari on a device signed in to your Tailscale account. Treat it like a password.** Control: the **Copy Link** button (secondary).

- Click copies the link (the Wails clipboard API) and the label becomes **Copied!** for 2 seconds, then **Copy Link** again (the Phase 4 pattern, same width rule).
- Disabled (`aria-disabled`, dimmed) while row 2 is Getting a link… or Waiting for Tailscale.
- If the clipboard write fails: inline error **Couldn't copy the link. Try again.**
- The link is never displayed in a field and never as a QR code. The user moves it by Universal Clipboard, AirDrop or Messages (CONTEXT).

**Row 4, Permissions (always visible, on or off).** Label `Permissions`, description Caption **Screen Recording and Accessibility.** Control: `.ts-status` dot plus text, then a button.

| Permission state | Dot and text | Button |
|------------------|--------------|--------|
| Both granted | on, **Granted** (`--color-success-text`) | **Review Permissions…** |
| Either missing | warn, **Needs permission** | **Set Up Permissions…** |
| Not yet read | none, **Checking…** | **Set Up Permissions…** |

The button opens the setup sheet. The ellipsis follows the house rule: only items that open a dialog.

**Row 5, Background service (amendment, USER DECISION 2026-11-25 "Start it anyway").** Shown only while always-available is on and the daemon status reports `launchd: false` (Portty started its background service without launchd, so the desktop is not kept reachable after Portty quits or the Mac restarts). | Repair kind | Description (Caption, secondary) | Button |

The row disappears as soon as status reports `launchd: true`. The tray line and the viewers are unchanged (the viewers keep showing the desktop's normal state).

### Notes (two Caption paragraphs, 8px apart, 16px under the groups)

1. **macOS 27.2 and later show a dialog the first time Portty captures the screen, asking whether it may bypass the system private window picker. Choose Allow. It does not come back.**

## Surface 5: `/desktop/` viewer page (DVWR-02, DESK-01, DESK-03, DESK-04)

The viewer is its own root: `main.tsx` mounts `DesktopView` for the `/desktop/` route and does not mount `App` (CONTEXT specifics: `detectMode` gains a third mode so the Wails shell is never booted, and the `is-desktop` class is not applied). It is the same bundle the Wails Desktop tab reuses in Phase 21.

### Page shell

| Rule | Contract |
|------|----------|
| Page | Served no-store, no-referrer (CONTEXT). `<title>` and the `apple-mobile-web-app-title` meta are set to **Portty Desktop** at boot, so a saved Home Screen link is not named like a terminal link. The shared manifest stays as it is. Whether iOS honours the meta over the manifest name is checked on the phone (M-row); the user can rename it in the Add dialog either way. No `start_url`: a Home Screen launch opens the exact saved link, token included. The token is never stripped from the address bar |
| Background | `--color-viewer-bg` over the whole page, including under the notch and home indicator |
| Layout | One full-viewport container with padding `env(safe-area-inset-top/right/bottom/left)`; the video fills the padded box. `html, body, #root`: `height: 100%`, `overflow: hidden`, `overscroll-behavior: none`, no margin |
| Video | `<video muted playsinline autoplay>`, `object-fit: contain`, `width: 100%`, `height: 100%`. The whole desktop is always visible, letterboxed, never cropped and never stretched. It re-fits as the window resizes or the phone rotates, with no new negotiation |
| Sharpness (DESK-01) | No CSS `transform`, `zoom` or `image-rendering` on the video, no `width`/`height` attributes, no device-pixel-ratio arithmetic. | Chrome | None while streaming: no toolbar, no title bar, no buttons, no cursor change. The pointer stays the default arrow and nothing is forwarded (view only; control is Phase 20). Keys are not captured |
| Selection and callouts | `user-select: none` and `-webkit-touch-callout: none` on the page |
| Zoom | `touch-action: manipulation`: the browser's own pinch-zoom stays available on a phone (to read small screen text) and there is no double-tap delay. **[default]** This differs from the terminal view, which blocks page zoom, because here there is no in-page pinch gesture to protect |
| Multiple viewers | Every viewer sees the same picture. Joining never changes another viewer's view |
| Audio | None. The video is muted |
