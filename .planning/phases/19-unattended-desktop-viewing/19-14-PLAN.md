- `app.go`: refreshTrayState reads `a.client.DesktopStatusAsGUI()` when connected and sets the line (an error clears it); `a.lapseTried int` (the highest LapseSeq this GUI tried to claim); when the status is awaiting_approval with LapseSeq above both LapseClaimedSeq and lapseTried it sets lapseTried, calls `a.client.ClaimDesktopLapse(seq)` and, only on a true result, `a.sendNotificationFunc("portty.desktop-approval-lapse", "Portty", "Portty desktop needs approval at the Mac.")`.
- `internal/daemon/desktop_api.go`: GET /desktop with the query `gui=1` calls Manager.NoteGUISeen (when a Manager runs) before answering; DesktopStatusResponse gains `LapseClaimedSeq int "lapseClaimedSeq"`; `POST /desktop/lapse-claim` with body `{"lapseSeq": int}` (DisallowUnknownFields) answers `{"claimed": bool}` from Manager.ClaimLapse(seq, "gui") (no Manager: claimed false).
- `internal/daemon/client.go`: `func (c *DaemonClient) DesktopStatusAsGUI() (DesktopStatusResponse, error)`, `func (c *DaemonClient) ClaimDesktopLapse(seq int) (bool, error)`; DesktopStatus is unchanged (Settings polls it without marking presence).

## Flagged decisions and assumptions

- **Sender rule is CONTEXT's, not V1's (checker revision 1):** CONTEXT [Permissions] fixes 'the GUI when it runs, otherwise the daemon; one sender at a time'. Research C6 suggested letting V1 pick the sender; that is not followed. V1 only decides whether the daemon path is verified or listed as a known gap (19-16).
- **Presence by polling, not a new channel:** the daemon socket has no push channel, so the GUI's existing 5 s tray poll carries `gui=1`; 12 s of silence means no GUI, and the daemon's 15 s claim wait covers a GUI that quits during a lapse. The claim is atomic in the Manager, so the two never both post.
- **Go and TypeScript both hold the wording table** (the tray in Go, Settings in React); a test pins every Go string against the 19-UI-SPEC table.
