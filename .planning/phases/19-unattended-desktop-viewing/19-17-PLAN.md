## Flagged decisions and assumptions

- **launchd first, fallback spawn (USER DECISION 2026-11-25, "Start it anyway"; CONTEXT amended):** reverses the earlier revision that turned an unusable agent into a terminal-blocking error. The repair state is desktop-only and lives in Settings (19-13); the daemon banner keeps meaning "no daemon at all".
- **Installed bundles only:** a build-tree bundle or dev binary never writes the production agent (it would point every login at a build tree); VM rigs install into /Applications inside the VM.
- **Re-home retry:** one kickstart at startup can be lost while the takeover daemon settles, so the tray tick retries with bounded backoff while health says unmanaged.
- **Login Items URL:** the System Settings extension URL for Login Items on macOS 13 and later; 19-07 row V2(d) checks it opens the right pane.
