<objective>
Lead the phase with one production-quality vertical slice of the always-available desktop link, entirely in-process on loopback: a desktop token minted under its own HKDF key opens `/desktop/` on the existing share server, the viewer's WebSocket at `/desktop/ws` carries the versioned signalling protocol, a pion PeerConnection answers with ICE-lite on one UDP socket, and a synthetic encoded source behind the real capture interface fans H.264 access units into the shared track. A Go pion client receives RTP whose first access unit holds SPS, PPS and an IDR slice.

Purpose: prove the whole media and auth architecture (token, route family, signalling, pion, capture interface) end to end before any layer is widened, using the 17-01 tracer pattern (synthetic frames, loopback). ## Flagged decisions and assumptions

- **Tracer scope:** the tracer uses `SyntheticSource` (pre-encoded fixture NAL units, no VideoToolbox, no capture) so the go test never touches ScreenCaptureKit, TCC or the encoder on the host (safety constraint). The real source arrives in 19-05 and is proven in the VM in 19-12.
- **Loopback media in tests only:** the tracer binds the UDP socket to 127.0.0.1 and lets pion include loopback candidates only through `desktop.allowLoopbackForTest`, an unexported package var flipped by an exported `AllowLoopbackForTest()` that panics unless `testing.Testing()` is true. 19-03 adds the production tailnet-only refusal around the same bind.
- **Interface-first (seam 8, 9):** `screencap.Source` is declared complete here (SelectSurface, Rebuild, per-AU Width/Height) so 19-03, 19-05 and Phase 20 implement or consume a stable shape; Phase 19 only ever selects the main display.
- **State enum declared here, derived in 19-09:** this plan pushes only `idle` and `streaming`; 19-09 owns derivation and precedence. `capture_paused` is a planner-added value for the crash-loop breaker (research C9), worded in 19-13/19-06.
- **No new npm or frontend change here;** the page route serves the existing SPA bundle (`getStaticAppFS()` wiring is the daemon's, 19-08; the test uses an fstest.MapFS).
- **launchd first, detached spawn as fallback (USER DECISION 2026-11-25, "Start it anyway"; CONTEXT amended; research C4-5 adopted):** every start tries `launchctl kickstart` first; a missing, refused or disabled agent or a disk-image path falls back to today's detached spawn so terminals always start (19-02), the GUI records a desktop-only repair kind with Open Login Items (19-17), and the Settings Desktop group shows the background service as needs repair with the unattended guarantee degraded (19-13), derived from /health launchd false (19-08). **Accepted user amendment of DSHR-01:** "the daemon runs under launchd only" is satisfied as "launchd primary; a degraded state is surfaced to the host whenever launchd does not manage the daemon"; 19-16 records this in TESTING.md so it stays human-visible. The corporate-Mac bootstrap policy is observed in M-163 (19-16).
- **File budget accepted (checker revision 2):** 11 files here and 11 in 19-11, each one vertical slice; no split.
- **Coverage floors (80 %, CLAUDE.md):** desktoptoken.go (this plan), internal/desktop (19-09), launchd.go (19-02), desktop_routes.go (19-04), each measured statement-weighted from a coverprofile. Recorded exception: internal/screencap's cgo bridges refuse in tests by design (no capture, assertions or nudges on the host), so their behaviour is measured by the VM rows in 19-12 and 19-15; only frames.go and the refusal paths are unit-tested.
- **Lint base:** `--new-from-rev=89d29266` (last pre-Phase-19 planning commit), scoped to the packages this plan touches; findings in files this plan did not touch are reported in the SUMMARY, not fixed.
- **Canon referrals (recalled, not minted as prohibitions):** token leakage through logs or Referer, path tricks in desktop.json, and injection through signalling JSON are canon security items covered by /gsd-secure-phase and the threat models (T-19-04, T-19-26, T-19-03), not bespoke prohibitions.
