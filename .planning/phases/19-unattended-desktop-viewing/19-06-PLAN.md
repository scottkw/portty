## Flagged decisions and assumptions

- **Check endpoint for classification:** a failed WebSocket handshake hides its HTTP status in browsers, so the client asks GET /desktop/check (19-04) after a failure.
- **capture_paused card is planner-added** (research C9 crash-loop breaker, 19-09); wording above, same card style as the other state cards.
- **Liveness on wake:** a ping on the signalling socket with a 3 s deadline (21-RESEARCH: dead iOS sockets can still read OPEN); no pong means rebuild.
- **CSP e2e checks connection and track, not decode:** the synthetic source's fixture bytes are not decodable; decode in Chrome and Safari is proven with real frames in 19-12 (V7 rows) and the real Mac M-rows (A8, A10, Pitfall 12).
- **Chrome Local Network prompt:** the Connecting card's body names it as "find devices nearby" (R12); the copy avoids the words tests/check-share-removal.sh reserves for the removed LAN server (its lan-server pattern), and the 19-UI-SPEC text was reworded to match (checker final revision).
- **Video rect seam (checker revision 2):** a pure function plus a callback, no context or store; Phase 20 consumes it for pointer normalisation.
- **Depends on 19-04:** the e2e and the client's check classification rely on 19-04's /desktop/check, reason header and static pages.
- **Phase 21's portty:wake** is not listened for here; Phase 21 calls `wake('external')` from its tab.
- **Build-tag deviation:** desktop_csp_e2e_test.go uses `//go:build e2e`, the same exception the existing browser_csp_e2e_test.go already has (it needs installed Chrome and a built frontend); 19-16 records it in TESTING.md Section 2.
- **Debug hook:** opt-in by the `#debug` fragment or a localStorage flag, counts only (no token, no SDP); it exists so the CSP e2e and the VM rows can read frames decoded and CSP violations from a real Safari (safaridriver) and Chrome (DevTools page titles) without screenshots, which WebKit in the Tart VMs cannot produce.
