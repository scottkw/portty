## Flagged decisions and assumptions

- **Media port 7444/udp (research Pattern 8, [ASSUMED] choice):** the same number as the share port, a different protocol; documented beside the share port. 19-15 checks with lsof in the VM that only the tailnet address holds it.
- **Viewer cap 8 and coalescing 1 s (A11, tuning):** constants; the 429 is refused before upgrade so a ninth viewer sees the normal retrying state in 19-06, not a new screen.
- **How the 429 is enforced:** the route needs the Manager's Full() before Accept; 19-01's DesktopBackend gains no method: the daemon adapter (19-08) and the test backend check Full() inside ServeDesktopViewer's caller path. To keep the check before upgrade without touching internal/webserver (owned by 19-04 this wave), the Manager exposes `ServeHTTP`-free `Full()` and 19-04 adds an optional `desktopCapacity interface{ Full() bool }` type assertion in the route. This plan's 429 test therefore drives the route through 19-04's code once both land; until then fanout_test.go asserts Full() and the in-Manager refusal (a viewer accepted past the cap is closed with code 4429 "full"). Recorded so 19-04 and this plan do not edit the same file.
- **Address literals:** the exact boundary addresses live only in bind_test.go (tests/check-brand.sh's tailnet-ip gate allows only 100.64.0.x in .planning and TESTING.md, so the plan names them by position).
- **Loopback in tests:** the tests use 19-01's AllowLoopbackForTest; checkBind refuses loopback whenever the hook is off and panics if the hook is set outside a test binary.
