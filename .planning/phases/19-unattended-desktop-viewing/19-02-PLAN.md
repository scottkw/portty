## Flagged decisions and assumptions

- **No GUI spawn fallback (checker revision 2, orchestrator decision following CONTEXT):** research C4-5 suggested keeping the detached spawn when bootstrap is refused; that is not adopted, because CONTEXT locks "one start path for everyone" and DSHR-01 says "launchd only". A refused or disabled agent is a typed error with a repair message; 19-17 shows it as a repair state with an Open Login Items button. Whether a corporate Mac allows the bootstrap is observed in M-163 (19-16).
- **Chesterton for startDetachedDaemon:** it existed to start the daemon from the GUI and CLI; kickstart replaces every such start, so it is removed. TestWaitForDaemon_DiedAtSpawnFailsFast keeps guarding waitForDaemon's exited channel by starting `false` with a local exec helper in the test. The takeover spawn (startDetachedTakeover via spawnTakeover) is a different function and stays exactly as it is.
- **Kickstart without the kill flag (post-research decision):** plain `kickstart` starting a loaded idle job and being a no-op on a running one is [ASSUMED] (A3) until 19-07 row V2; a contradiction stops the phase there.
- **Managed signal (A4):** ManagedByLaunchd is true when `XPC_SERVICE_NAME` equals LaunchdLabel, or else when `launchctl print gui/<uid>/<label>` reports `pid = <own pid>`; 19-07 row V4 records which one fired.
- **AbandonProcessGroup true (Pitfall 4, A5):** defensive; 19-07 row V3 proves shells keep their pids across a handoff out of a launchd-managed daemon.
- **Re-home generalised:** the launchd daemon takes over any healthy unmanaged daemon that speaks HandoffVersion and is not newer than itself (the re-home after a GUI upgrade, and a v1.2 GUI-spawned daemon found after the first upgrade); a launchd-managed old daemon is never a target.
- **CLI with a stale daemon:** the CLI keeps today's restart question; when sessions would need moving it asks launchd (kickstart) and waits for this build to answer instead of spawning a takeover; if the old daemon is the launchd job itself, the move reports failed and the restart question follows.
- **kardianos left in place:** `internal/daemon/service.go` and its go.mod line stay (go.mod is owned by 19-01 in this wave); `portty daemon install|uninstall|start|stop` move to AgentControl; removing the unused kardianos path is a SUMMARY todo.
- **File budget accepted (checker revision 2, like 19-01 and 19-11):** 11 files, one vertical slice on the daemon start path; the GUI half is split out to 19-17.
- **Coverage:** launchd.go is measured per file (statement-weighted from the coverprofile) with an 80 % floor; internal/daemon as a whole is not held to 80 % by this plan.
- **Lint base:** `--new-from-rev=89d29266`, scoped to `./internal/daemon/...` and the root package.
