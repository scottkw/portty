## Flagged decisions and assumptions

- **Stall timings (A11 tuning):** 5 s first check, 30 s recheck on a confirmed still screen (fewer pointer moves on an idle desktop), 60 s restart cadence while awaiting approval; constants, tuned after M-160.
- **Signal (d) not adopted:** the approval-prompt window detector (research C2 option) is not built; (a), (b), (c) are CONTEXT's locked set. V8 is not run (recorded in 19-12).
- **Signal (a) needs Full Disk Access** per R19 evidence, which Portty never asks for; the read is attempted, and any error means the signal is unavailable, never a lapse.
- **capture_paused is planner-added** (research C9): a hard crash ends every terminal session, so a capture that keeps crashing must stop restarting itself; ResetBreaker is driven by a successful Test Capture (19-11).
- **Separate runtime file:** approval and breaker state go in desktop-state.json, not desktop.json, so the costly config schema stays at the four accepted fields.
- **Lapse sender (CONTEXT [Permissions], checker revision 1):** the GUI when it runs, otherwise the daemon. The GUI's presence is its tray poll calling NoteGUISeen (19-14); a claim is atomic, so the two never both post. Row V1 (19-12) only decides whether the daemon's posting path is verified or recorded as a known gap in 19-16; it does not change who sends.
- **Locked() fails closed (true)** on a read error, documented for Phase 20's input gate.
- **A12 (remote user activity lights a dark display on real hardware):** M-row in 19-16; the VM half is 19-12.
