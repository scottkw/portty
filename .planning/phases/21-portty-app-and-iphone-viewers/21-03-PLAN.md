## Decisions implemented

CONTEXT [iPhone] (client-side pointer math; non-passive container listeners with a gesturestart guard; zoom as a CSS transform, never page zoom), Claude's Discretion iPhone gestures and 1x-5x pinch, UI-SPEC Surface 4 Gestures table and Zoom transform row, research Pattern 7.

Planner note (reversible): a single tap waits out the 300 ms double-tap window before it is emitted. Without the wait, "tap then drag" would reach the Mac as a click followed by a press within the double-click interval, which macOS treats as a double-click drag (word selection). The cost is 300 ms on single taps, the same trade other trackpad viewers make.

Reconciliation with Phase 20 (CONTEXT's planning note governs; not a reopened decision): Phase 20 sends a relative rmove plus a cursor-position report (20-02), so the host-side pointer applies and there is no client virtual pointer. This plan therefore emits relative move intents only; 21-10 sends them as rmove and uses the Mac's cursor report for clicks and pan-follow. UI-SPEC's first-touch re-seed was the client-only fallback for absolute positions and is not built in either plan.
