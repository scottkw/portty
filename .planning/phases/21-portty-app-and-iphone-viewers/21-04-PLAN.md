## Decisions implemented

CONTEXT [Discovery] (lib/sidebarPeers.ts renders the row from the peer meta), [Tab] (Tab.type gains 'desktop' with peerHost and a name, no token; tabLabel and peerTabsRemoved handle the type; nothing persisted), Claude's Discretion (row first in the group, ComputerDesktopIcon, PeerDot colour; row only while the meta carries the header; muted state lines; one tab per peer with id desktop:<fullhost>). Research Pitfall 4 (Nothing shared beside a Desktop row).

Data source and ordering (dependency note): this plan is frontend-only. It declares the optional RemotePeerSessions.desktop field and renders from it; at run time the field is filled by 21-07's GetRemoteSessionsWithMeta (the remotePeersFromGroups mapping in app.go) from 21-01's header reader, and the row only appears once 21-08 wires App's onOpenDesktop. Tests here use fixtures with desktop set, so nothing in this plan needs 21-01 or 21-07, and its tracer is a frontend slice, not a Go-to-UI end-to-end path (21-08's App test and 21-11's VM row D1 cover that).

Planner note (reversible): the row renders only when App passes onOpenDesktop, so no dead affordance exists between this plan and 21-08, which wires App. The tab keeps peerHost as the peer's hostname (the sidebar group key, so the PeerDot colour matches) and connectHost as dnsName or hostname (the unique key the tab id and the binding use), the same split terminal peer tabs use.
