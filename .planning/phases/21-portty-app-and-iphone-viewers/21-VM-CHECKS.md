# Phase 21 VM checks (plan 21-02): key routing, Cmd-held keyup, release chord and window visibility in the real Portty.app

Rig: `.planning/phases/21-portty-app-and-iphone-viewers/rig/p21-rig.sh` (the host builds a scratch export and streams the bundle; every launch, key post, log read and removal runs inside the home VM through ssh). Roles: portty-test is the office guest (not used by this plan), portty-test-2 is the home guest (all rows here), macOS 27.2, console user logged in. Key posting: `rig/key.swift` (CGEvents at the HID tap with explicit flags), built on the host, run only in the VM.

Builds (the throwaway probe applied by `rig/keyprobe/apply.sh` to a scratch `git archive` of the tree; nothing under `frontend/`, `internal/`, `app.go` or `main.go` changes in the repo):

| probe | commit `6662f196` plus the probe files (scratch copy only) | v2.10.2, `-tags wailsassets`, bundle app.portty.Portty | ad-hoc |

Focus target for the "page" rows: a visually hidden `<textarea>` (1 px, clipped, holds the text `probe-text`) whose `onKeyDown` and `onKeyUp` call `preventDefault` and `stopPropagation`, the same kind of target Phase 20's stage uses. A document-level capture listener logs every keydown, keyup, copy, cut, paste, selectstart, beforeinput, visibilitychange, blur, focus and the Wails events `menu:close-tab`, `menu:new-session`, `menu:settings`, `menu:toggle-sidebar` and `app:quit-requested`. "Menu fired" means a MENU line, a COPY/CUT/PASTE/SELECTSTART/BEFOREINPUT line the page did not cause, a `VIS hidden` line, the window gone from the screen, or the GUI process gone.

Evidence files are in `evidence/` (written by `p21-rig.sh matrix2` and `log2`; each line is `seq monotonic-ms event`; home paths shown as `~`, tailnet addresses and tokens never captured; no token is involved in this plan). The probe app, `~/p21` and its key tool were removed from portty-test-2 afterwards (`remove2`: Quit All, bundle deleted, GUI none); both VMs are still running.
