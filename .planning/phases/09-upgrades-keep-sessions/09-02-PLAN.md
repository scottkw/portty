- **Departure from the suggested split (CONTEXT: Claude's Discretion, file names).** The research put the SCM_RIGHTS helpers in internal/daemon/handoff_fds.go and the webserver listener change in 09-04. - **Additive only.** No exported signature that internal/daemon or internal/relay calls today changes (NativePTYBackend.Create/Resize/Kill/List, Session.Read/Write/ExitCode/..., webserver.NewWebServer/Start/Stop/AddGrant). 09-01 and 09-03 compile against this package in parallel.
- **Pollable master (Pattern 2, probe P3; CONTEXT: "PTY reads").**
  - In Create, after `cmd.Start()`: get the go-pty master via the `gopty.UnixPty` interface, read its raw fd inside `SyscallConn().Control` (never the file's Fd method: it switches the descriptor to blocking and breaks deadlines), `unix.Dup` it, `unix.SetNonblock(d, true)`, and wrap with `os.NewFile` while non-blocking, so the result is registered with the netpoller.
  - O_NONBLOCK lives on the open file description, so go-pty's own master file also becomes non-blocking. Nothing may read or write through go-pty's file after this: Session.Read and Session.Write use the dup only (CONTEXT: the "writes must use the same fd" pitfall, pinned by the large-paste test). Resize keeps going through go-pty (its ioctl uses SyscallConn().Control, which works in either mode).
  - `Session.SetReadDeadline(t time.Time) error` delegates to the dup; it returns `os.ErrNoDeadline` for a session with no dup, so 09-03's Freeze fails fast instead of hanging (Pitfall 6).
  - Session gains `pid` (set from `cmd.Process.Pid` at Create, from the handoff at Adopt) and `Pid() int`.
  - closePTY closes the dup too (inside the same once).
- **golang.org/x/sys becomes a direct import** (Research: Package Legitimacy Audit, existing dependency v0.46.0, no version change). Move its go.mod line from the indirect block to the direct require block. Check with `GOFLAGS=-mod=mod GOPROXY=off go mod tidy`: the only go.mod change is that line and go.sum is unchanged. If tidy wants the network, hand-edit the line instead and confirm `go build ./...` and `go mod verify`.
- **fdpass API (Pattern 3; Research "Don't Hand-Roll": UnixRights/ParseSocketControlMessage/ParseUnixRights):**
  - `func Send(c *net.UnixConn, header []byte, conns ...syscall.Conn) error`: for each conn, inside `SyscallConn().Control` take `unix.Dup` of the raw fd (so it stays valid after Control returns), build `unix.UnixRights(dups...)`, `WriteMsgUnix(header, oob, nil)`, then close the dups. `*os.File`, `*net.UnixListener` and `*net.TCPListener` all implement syscall.Conn, so no caller ever needs the Fd method or `File()`.
  - `func Recv(c *net.UnixConn, header []byte, nfds int) (n int, files []*os.File, err error)`: oob sized `unix.CmsgSpace(nfds*4)`; on `MSG_CTRUNC`, a parse error or a count other than nfds, close every fd that did arrive and return an error. Mark received fds close-on-exec (SCM_RIGHTS fds arrive without it on macOS). Wrap with `os.NewFile`.
  - `func PeerUID(c *net.UnixConn) (uint32, error)` via `unix.GetsockoptXucred(fd, unix.SOL_LOCAL, unix.LOCAL_PEERCRED)` inside Control.
  - Messages carry a small fixed set of fds each (09-04 sends per-session batches), so the unmeasured per-message fd limit (A3) never matters.
- **Unit pins for research assumptions:** A4 (flock follows the passed fd) and A5/Pattern 7 (a unix listener passed by fd serves the same path, and the sender's `SetUnlinkOnClose(false)` + Close leaves the path naming the same inode). fdpass tests use pipes, files and unix listeners only (no TCP listener: a new test binary that listens on TCP raises a firewall alert on the user's Mac; the webserver test binary already does).
- **Adopt and exit watch (Patterns 1 and 4; CONTEXT: "Child processes").**
  - `type AdoptMeta struct { ID, CLI string; CreatedAt time.Time; Pid int }` and `func (b *NativePTYBackend) Adopt(meta AdoptMeta, master, slave *os.File) (*Session, error)`: the first step registers the exit watcher (Pitfall 8), then sets the master non-blocking (defensive; the OFD already is) and wraps it as the session's I/O file, keeps the slave open (today's parity: the daemon holds the slave, Pattern 1), registers the session. No exec.Cmd, no go-pty Pty: Resize uses `unix.IoctlSetWinsize(fd, unix.TIOCSWINSZ, ...)` inside Control on the I/O file.
  - `func (s *Session) HandoffFiles() (master, slave *os.File, pid int, err error)` returns the files 09-04 sends: the I/O dup as master and the slave (go-pty's Slave() for created sessions, the kept file for adopted ones).
  - `watchExit(pid int) <-chan int` (exitwatch_darwin.go): `unix.Kqueue`, one `Kevent_t{Ident: pid, Filter: EVFILT_PROC, Flags: EV_ADD|EV_ONESHOT, Fflags: NOTE_EXIT|NOTE_EXITSTATUS}`. EACCES: retry with NOTE_EXIT only and report -1. ESRCH: already gone, report -1 at once. On the event, a normal exit reports `syscall.WaitStatus(data).ExitStatus()`; a signal reports -1, matching `ProcessState.ExitCode()`, which the engine's D-10 normalisation already turns into 0. The kqueue fd is closed after the event.
  - ReapNaturalExit for an adopted session (no cmd): wait up to 500 ms for the watcher (EOF can come first), then cache its code, or leave -1.
  - killSession for an adopted session: only while the watcher has not fired (Pitfall 9: a reused pid is never signalled): SIGHUP to `-pid` (go-pty started it with Setsid, so pgid == pid), close the PTY, wait up to 2 s for the watcher, then SIGKILL `-pid` if it still has not fired. The signal call goes through a package seam so the test can see that no signal is sent after exit.
