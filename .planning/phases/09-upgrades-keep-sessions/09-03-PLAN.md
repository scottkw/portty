## Flagged decisions and assumptions

- **Wave 1, own package.** Only internal/relay files. Additive API: NewHub, HubManager.Create/Get/Remove/Shutdown, Join, Subscribe and the Subscriber fields keep their signatures (09-01 and 09-02 compile against internal/daemon and internal/pty in parallel; internal/daemon calls this package).
- **Freeze/Thaw (Pattern 5).**
  - `func (h *Hub) Freeze() error`: the reader must implement `interface{ SetReadDeadline(time.Time) error }` (09-02's pty.Session does; os.Pipe files do in tests). Otherwise, or when SetReadDeadline returns an error (os.ErrNoDeadline for a blocking master, Pitfall 6), return the error at once and leave Run untouched. Else set `freezing`, `SetReadDeadline(time.Now())`, and wait for Run to close `frozen`, up to 2 s; on timeout clear the deadline and the flag and return an error (the daemon then aborts the handoff toward the old side).
  - Run: record any bytes read first (unchanged), then on an error, if `freezing` is set and `errors.Is(err, os.ErrDeadlineExceeded)`, close `frozen` and return without Shutdown. Every other error keeps today's path (Shutdown, so viewers get session ended and the engine sees the exit). The `defer h.Shutdown()` must therefore move into the non-freeze return path.
  - A shell that exits while the freeze is pending makes Run end with EOF (Shutdown, Done closed) instead of the deadline. Freeze then returns `ErrHubEnded` at once (it watches Done as well as `frozen`), so the daemon treats that session as stopped instead of waiting out the 2 s.
  - `func (h *Hub) Thaw()`: clear the deadline and the flag, make a new `frozen` channel, `go h.Run()`.
  - While frozen, ResizeClient records the subscriber's size but neither resizes the PTY nor broadcasts. Thaw re-runs the host-authority arbiter once, so a resize during a rolled-back freeze still lands. After a commit the viewers reconnect and send their size again.
  - Every byte Run read before the freeze is already in the ring and the emulator: recordFrameLocked runs inline before the next Read. So nothing is buffered in the old daemon at export (CONTEXT: "any PTY output buffered in the old daemon is flushed into the transferred ring before the fds are sent").
- **The seed (Pattern 6; CONTEXT: "refactor rebuildAfterAltExitLocked and carry the main screen behind an alt-screen app").**
  - Split rebuildAfterAltExitLocked mechanically: `seedLocked(tail []byte) []byte` does everything up to and including building the byte string (body, probes into the old emulator, tracker resync, saved cursor, region, pending wrap, pen, charset suffix, link); `applySeedLocked(seed, tail []byte)` builds the new emulator with newLiveEmulator, writes the seed, clears altExited, drains the scrollback and writes the (C0-filtered) tail. rebuildAfterAltExitLocked becomes `h.applySeedLocked(h.seedLocked(tail), tail)`. Keep every comment and `shortcut:` line with the code it explains.
  - Alt-screen extension, used by Export only: when `liveEmu.IsAltScreen()`, render the alt screen first (screenBodyLocked, the alt cursor, then the pen probe, which prints into the alt screen after it was rendered), then write `\x1b[?1049l` to the old emulator (the trick resizeLiveEmulator already uses) and build the main-screen seed with seedLocked. The exported seed is: main seed, then `\x1b[?1049h` (vt saves the main cursor and enters a cleared alt screen), then the alt rows, the alt CUP, the alt pen, the charset suffix. The tail goes last on import.
  - Export then applies the exported seed to its own hub (applySeedLocked), so the old hub keeps exactly the emulator the new one builds. That is the rollback path of Pitfall 7 (the old emulator was mutated by the probes and `?1049l`; it is rebuilt from its own export) and it makes the READY digest (09-04) compare like with like. Prefer this over reading vt's main screen through vtalt.go's reflection (Pitfall 7: it would widen the reflect/unsafe surface pinned by TestVTLayout_AltScreenScrollback).
  - The tail: at export, compute it as recordFrameLocked does for the rebuild, `incompleteTail(StripTerminalQueries(payload))` of the last frame in the ring, so a read that stopped mid-sequence completes on the new side.
  - Accepted seed losses stay exactly the existing `shortcut:` list (tab stops, G2/G3 and single shifts, the UK set, the saved cursor's visibility, zero-width cells). They affect only late joiners' full renders and future history lines; resuming viewers get raw ring deltas. Any other divergence the round-trip test finds blocks the plan: stop and report it (Research Open Question 2).
- **HubState (Pattern 1; CONTEXT "State that moves byte for byte").** An exported, gob-friendly mirror of hub-owned state: SessionID; Ring {Buf, Max, Truncated, End}; History {Lines, Wrapped, MaxLines, MaxBytes} (the retained lines in order); Modes; GeomEnd; MainRegion; Wraps {N, Ring, Next}; LastMove; CS (every charState field, including the vtScan state and the esc flag); PtyCols, PtyRows; EmuCols, EmuRows; HasEmu (false when no emulator was ever built); Seed; Tail. trackWraps and altExited are transient and not exported (false on import). Subscribers and nextConnID are rebuilt empty.
  - `func (h *Hub) Export() (HubState, error)` requires the hub to be frozen, runs under emuMu, and copies every slice (the state must not alias live buffers).
  - `func NewHubFromState(st HubState, reader io.Reader, writer io.Writer, resizeFn func(cols, rows int) error) (*Hub, error)` validates before building anything (CLAUDE.md "let it crash" toward the old daemon): `len(Ring.Buf) <= Ring.Max`, `Ring.Max == DefaultScrollbackBytes` or the hub's configured size, `uint64(len(Ring.Buf)) <= Ring.End`, `GeomEnd <= Ring.End`, History within HistoryMaxLines/HistoryMaxBytes and `len(Wrapped) == len(Lines)`, `len(Wraps.Ring) <= wrapSetMax`, grid and emulator sizes in 1..1000, MainRegion inside the rows. Any failure returns an error and no hub. The hub is staged: no Run until `Start()`.
  - `func (h *Hub) Start()` runs `go h.Run()` exactly once. HubManager gains `AddStaged(id string, h *Hub) error` (error if the id exists) and keeps Create unchanged.
  - `func (h *Hub) Digest() [32]byte`: sha256 over the ring end offset, the ring length, the history line count and RenderSnapshot(), under emuMu. 09-04 compares it in READY.
  - History's comment ("never written to disk ... a daemon restart drops it") gains: a handoff moves it memory to memory over the 0600 socket, never through a file.
- **1012 close (CONTEXT: "Viewers at commit: close with 1012 (service restart), never 1000").** `CloseReasonServiceRestart = "service restart"` in close_reasons.go (a wire value, mirrored nowhere: clients branch on the code, and IsTerminalClose stays false for it). Subscriber gains `Restart func()` (called in its own goroutine; nil falls back to CloseSlow). `func (h *Hub) RestartViewers()` collects all subscribers under mu, releases it, then calls each (the unlock-before-IO rule of RevokeWebViewers, T-157-04). relay/server.go's WS handler sets `sub.Restart` to close with `websocket.StatusServiceRestart` and the reason. The browser share viewer's Restart is set by 09-04 in internal/webserver/server.go (wave 2: this plan cannot reference 09-02's file).
- **Tests use no network.** Hubs are fed with recordFrameLocked or an os.Pipe reader (pollable, takes deadlines); the 1012 test uses the existing relay server test harness (httptest on 127.0.0.1, already part of this package's test binary).
