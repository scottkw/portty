- **Host tab reconnect (Research Pitfall 10; CONTEXT: "Local GUI tabs and local `portty attach` gain reconnect").**
  - Chesterton's Fence: TerminalPanel's comment says host tabs never reconnect because "a local relay drop means the daemon and session died". With the handoff that premise is false: a drop can be the old daemon leaving with 1012 while the session lives on. A real crash still ends the tab, because the respawned daemon lists no such session.
  - `hostReconnectVerdict(sessionId, deps)` in frontend/src/lib/hostReconnect.ts: `GetRelayPort()` fails → `{kind:'retry'}`; `ListSessions()` fails → retry; the session is missing or `state === 'stopped'` → `{kind:'stop', reason:'ended'}`; otherwise `{kind:'ok', port}` (the relay port is unchanged after a handoff, but it changes after a respawn). Both bindings already exist, so no new binding and no stub change.
  - Thirteen component tests `vi.mock` the App bindings module with explicit factories (TerminalPanel.*.test.tsx among them). hostReconnect.ts therefore reads GetRelayPort and ListSessions only inside the function call (never at module load), so those factories need no new entries; RelayClient already turns a throwing beforeReconnect into a retry.
  - TerminalPanel passes `reconnect` for host tabs too, with this verdict; guests keep theirs. A host tab's final close still shows nothing (the App exit flow already reports a session end); the reconnecting state disables stdin and shows the existing reconnect banner, as for guests. The host's onOpen already re-sends its size.
- **Local attach reconnect (Pitfall 10).** attachLocal goes through `attach.Run` like remote attaches: the URL function re-reads the relay port; Reauth checks the session list: present and not stopped → VerdictOK; daemon unreachable → call `ensureLocalDaemon` once (as remoteReauth does for R6) and check again; still unreachable → VerdictRetry; missing or stopped → a new `attach.VerdictEnded`, which ends Run with a distinct error. Local ends keep today's message ("Detached."); remoteAttachEnd stays remote-only. The attach loop's backoff paces the re-auth, so a dead daemon is never respawned in a spin.
